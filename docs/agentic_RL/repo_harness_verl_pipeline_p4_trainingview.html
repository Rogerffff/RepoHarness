episode 跑完之后：怎么变成训练样本

本页讲 episode 跑完后从离散的多轮事件 → 一份训练 batch 可消费的样本的全过程。①_training_view_from_real_episode 怎么把 GenerationRecordCollector.records 跨多轮拼成单个 TrainingView（含 assistant generation 段 + tool observation 段）；② Stage 11.5 加的 6 条 token provenance 严格校验怎么防伪造；③ episode_result_to_agent_loop_output 怎么把它转换成真实 verl AgentLoopOutput；④ AuditRef 怎么投影成 batch-safe opaque refs；⑤ formal_online_rl 强制门怎么挡住非 verl 样本；⑥ verl 自己怎么 postprocess 成 DataProto。

③ 6 条 token provenance 严格校验（Stage 11.5 红线）

Stage 11.5 在 episode.py 加的 model_validator。每个 RepoHarnessEpisodeResult 构造时跑，不可绕过。防止"从最终 transcript 重新分词伪造可训练 token"。

1所有 generation_records 的 model_call_id 必须唯一duplicate_generation_record_model_call_id
2assistant_generation span 数 == generation_records（去除空 token 的）数assistant_generation_span_count_mismatch_generation_records

⑥ formal_online_rl 强制门

最后一道安全闸门：mock / replay / openai / deepseek / local_vllm / local_sglang 等非 verl route 的样本绝不能伪装成正式 online RL 训练样本。

⑦ verl postprocess → DataProto

RepoHarness 调用 episode_result_to_agent_loop_output 返回 AgentLoopOutput 之后，剩下的工作都在 verl 内部。RepoHarness 不直接控制 DataProto 组装，但需要保证 AgentLoopOutput 形状对、字段 visibility 通过。

verl 内部流程（黑盒概述）

[verl AgentLoopWorker 收到 AgentLoopOutput] ↓ _agent_loop_postprocess(output) ├ 注入 extra_fields.raw_prompt # trainer side reconstruct prompt 用 ├ attach kwargs 中允许字段 # 通过 RepoHarness allowlist 的字段 └ 校验 prompt_ids / response_ids 长度 ↓ _postprocess(output) → DataProto ├ tensor batch: │ ├─ prompts: [batch_size, prompt_length] (left-padded) │ ├─ responses: [batch_size, response_length] (right-padded) │ ├─ attention_mask: [batch_size, total_length] │ ├─ response_mask: [batch_size, response_length] (0=tool_obs / 1=assistant) │ ├─ rollout_log_probs: [batch_size, response_length] (assistant 段真实 / tool_obs 段 0.0) │ └─ rm_scores: [batch_size] (reward_score 标量) ├ non_tensor_batch: │ └─ extra_fields: 含 repo_harness_*_ref 等 opaque refs（NOT 绝对路径） └ meta_info: trainer / rollout 元信息 ↓ DataProto 进入 PPO / GRPO trainer loss 路径 ├ calculate_log_probs（如果 use_rollout_log_probs=True） ├ compute_advantages（GAE / GRPO） ├ policy loss update └ reference model KL penalty

RepoHarness 与 verl 的边界

边界位置RepoHarness 负责verl 负责
AgentLoopOutput 之前 workspace、工具执行、agent loop、verifier、reward、artifact、audit ref、token provenance 校验。 提供 rollout worker、推理服务管理器、tokenizer、sampling 参数。
AgentLoopOutput 返回时 保证 prompt_ids、response_ids、response_mask、response_logprobs、reward_score 和 allowlist extra fields 形状正确。 接收每条 episode 输出，并在 worker 侧做 postprocess。
DataProto 之后 不直接组 batch，不直接计算 PPO/GRPO loss，只提供可审计的样本和诊断证据。 padding、batch tensor、advantage、policy loss、reference model KL、optimizer step。

两条 postprocess 路径都通过 visibility

路径RepoHarness 关心的可见性约束
普通 AgentLoopWorker._agent_loop_postprocess 通过 kwargs["raw_prompt"] 注入 extra_fields.raw_prompt。RepoHarness 在 conversion 出口校验所有 extra_fields 都在 REPO_HARNESS_AGENT_LOOP_EXTRA_FIELDS allowlist 中。
main_ppo_sync.py / TransferQueue 路径 verl 通过 field.update(kwargs) 把 raw_prompt 合并成顶层 field（不是 extra_fields）。Stage 10 双路径都覆盖 visibility 测试。

路径可见性分层

runtime-only 层 ├─ 真实 workspace 绝对路径、dependency env 绝对路径、run_dir、setup log └─ 只能被 runtime、tool executor、verifier、artifact writer 使用 ↓ audit ref 层 ├─ rh://workspace-snapshot/<key>、rh://environment/<key>、artifact ref └─ 可进入 RepoHarnessEpisodeResult 和 extra_fields ↓ DataProto 层 ├─ tensor batch 只放 token、mask、logprob、reward └─ non_tensor_batch 只放 allowlist 字段和 opaque refs，不放本机绝对路径

Stage 12.5 在 DataProto 之后能观察什么
