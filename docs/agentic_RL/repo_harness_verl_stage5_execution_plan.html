⚡ Stage 5 的关键加固：online RL 强制门

Stage 1 已经定义"正式 online RL 必须 route=verl"原则，但schema 层之前是靠 PROVIDER_ROUTES 黑名单。Stage 5 改成白名单——强制要求路由事实显式写进 training_view.extra_fields，避免漏判。

① 阶段目标

把 RepoHarness 现有模型调用体系（mock / replay / openai / deepseek）逐步迁移到训练后端无关的 LLMGateway route 体系。同时明确正式 online RL 样本只允许 route=verl，provider route 默认 invalid_for_online_rl=true。

数据流：mock / replay / openai / deepseek → LLMGateway route wrapper → LLMGatewayResponse → GenerationRecord / TrainingView / runtime facade。

② 两个方向的 adapter 接缝

这是 Stage 5 最容易理解错的点。旧 ModelClient 是同步接口，新 LLMGateway 是 async 接口。两个接口之间有两个方向需要打通，分别由 Stage 2 和 Stage 5 提供。

方向 1（Stage 2 已有）：LLMGatewayModelClientAdapter

让旧 ModelClient.generate(...) 接口能调到新 async gateway。

旧同步 generate(...) 调用
  ↓
构造 LLMGatewayRequest
  ↓
asyncio.run(gateway.generate_turn(...))
  ↓
转回 ModelResponse

用途：让旧 AgentLoop（同步逻辑）能不大改地调上 gateway。

方向 2（Stage 5 新增）：ModelClientLLMGateway

让新 async gateway 接口能调到旧同步 ModelClient。

新 async generate_turn(...) 调用
  ↓
构造 ModelRequestContext
  ↓
asyncio.run_in_executor(ThreadPool, model_client.generate)
  ↓
转回 LLMGatewayResponse

用途：让新 runtime / 测试能通过 gateway 调到现有 provider client / replay client。

两个 adapter 不重复：方向 1 让"旧调用方→新被调"（不改 AgentLoop），方向 2 让"新调用方→旧被调"（让 runtime 不必直接持 ModelClient）。

③ 6 个 gateway 类的继承与职责

┌─ ModelClientLLMGateway ── 基类，包同步 ModelClient，受控并发 + 生命周期 │ │ │ ├─ ProviderLLMGateway ── OpenAI / DeepSeek 用，纯继承不加行为 │ └─ ReplayLLMGateway ── Replay 用，纯继承不加行为 │ ├─ MockLLMGateway ── 独立，deterministic tokens (900+turn) + logprobs (-0.01) │ └ 测试用，不依赖任何外部 client │ └─ UnsupportedRouteLLMGateway ── 独立，verl / local_vllm / local_sglang 的结构化拒绝 └ output_token_ids=[], output_logprobs=None, stop_reason="unsupported_route" build_llm_gateway_for_route(route, *, model_client=None, run_dir_root=None, max_workers=1) ├─ route ∈ {verl, local_vllm, local_sglang} → UnsupportedRouteLLMGateway ├─ route == "mock" & no client → MockLLMGateway ├─ route == "replay" & client + run_dir → ReplayLLMGateway ├─ route ∈ {openai, deepseek} & client + run_dir → ProviderLLMGateway └─ 其它/缺参 → UnsupportedRouteLLMGateway（绝不 fallback）
关键设计：未实现 / 缺参的路由统一返回 UnsupportedRouteLLMGateway，绝不静默 fallback 到 provider route。这条由 test_route_builder_returns_structured_unsupported_gateway_without_fallback 锁定。

ModelClientLLMGateway 的关键设计

class ModelClientLLMGateway: def __init__(self, *, model_client: ModelClient, run_dir_root: str | Path, max_workers: int = 1, default_model_id: str = "repo-harness-model-client-gateway", default_timeout_seconds: float = 60.0): ... self._semaphore = asyncio.Semaphore(max_workers) self._executor = ThreadPoolExecutor(max_workers=max_workers, thread_name_prefix="repo-harness-llm-gateway") self._closed = False async def generate_turn(self, request: LLMGatewayRequest) -> LLMGatewayResponse: if self._closed: raise RuntimeError("ModelClientLLMGateway is closed") parsed = LLMGatewayRequest.model_validate(request) async with self._semaphore: loop = asyncio.get_running_loop() return await loop.run_in_executor(self._executor, self._generate_turn_sync, parsed) def close(self): self._executor.shutdown(wait=True, cancel_futures=True); self._closed = True async def aclose(self): self.close() def __enter__(self): return self def __exit__(self, *a): self.close()
并发控制asyncio.Semaphore(max_workers) 限制并发协程数；ThreadPoolExecutor(max_workers=...) 限制底层线程数。两层保险，避免无界创建线程。
关键字调用强制包内对旧 model_client.generate(...) 一律用 generate(request=ctx, recorder=rec)，不用位置参数；这条由 test_model_client_gateway_uses_keyword_call_and_marks_provider_tokens_offline 锁定。
生命周期close() 后再 generate_turn → RuntimeError（防资源泄漏）；aclose() 是 close() 的 async alias。

⑤ Token 与 logprob 策略

这一节解决 Stage 5 最大的风险："看起来有 token，实际不是训练可用 token"。

3 种 token_source 命名

token_source含义
"mock_gateway"稳定 deterministic token，仅测试用。MockLLMGateway 产生。
"provider_text_retokenized_debug_only"把 provider 文本结果重新分词得到的 token ids。不能作为正式 online RL token。可供 diagnostic / SFT export。
"provider_unavailable"旧 client 拿不到 token ids。output_logprobs=None，output_token_ids=[]。
铁律output_logprobs is None → runtime / TrainingView 必须 invalid_for_online_rl=True。route 不是 verl 同样必须 invalid。
禁止不允许把最终 transcript 重新分词后冒充正式训练 token。这条由 test_formal_online_rl_batch_rejects_every_non_verl_route 强制。

⑥ Online RL 强制门（白名单升级）

Stage 1 用 PROVIDER_ROUTES 黑名单挡 provider 路由；Stage 5 把它升级成白名单——必须显式 repo_harness_llm_gateway_route == "verl" 才能进 formal batch。

Stage 1 旧版（黑名单）

if route in PROVIDER_ROUTES: invalid_for_online_rl = True

问题：路由集合扩张时容易漏（新增 local_vllm 时忘了加进 set）。

Stage 5 新版（白名单）

if route != "verl": raise ValueError("non_verl_route_invalid_for_online_rl")

收益：未来新增的 route 默认 非 online RL，必须主动证明才能进 formal batch。
