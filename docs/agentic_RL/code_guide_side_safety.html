Side-A · 安全边界 — 5 道防线（横向贯穿 T4 → T8）

代码导览 · 横向主题 · 主要文件：rl/visibility.py · tools/file_mutation.py · tools/minimal.py · evaluation/episode_projection.py

本侧栏定位：RepoHarness 不是单层"白名单"安全设计，而是分层防御——每层只拦自己那一层的越界。5 道防线都必须存在且独立工作，任何一层被绕过另几层兜底。本页把它们按"模型角度看到的顺序"摆一遍。

L1 · 工具 schema 校验

L1Schema触发点：T4 分派之前 · 位置：每个工具 ToolDefinition

原理：每个工具的 ToolDefinition 用 JSON schema 描述 input 参数，additionalProperties: false 硬禁未声明字段。apply_patch 的 operations 数组里每一项也是 nested schema，含 op 枚举、必填字段、字符串长度上限等。

关键代码：tools/minimal.py:3282（write_file ToolDefinition） · tools/minimal.py:3318（apply_patch ToolDefinition + operations nested schema） · tools/minimal.py:3263+（独立 delete_file / move_file，含 reason 必填）

典型拒绝：{"tool":"apply_patch","input":{"unified_diff":"…"}} → schema 错误（apply_patch 没有 unified_diff 字段）；{"tool":"delete_file","input":{"path":"x.py"}}（缺 reason）→ schema 错误。

为什么独立成一层：在调用 handler 之前就把"语法上明显非法"的请求拒掉，handler 里就可以认输入字段合法，不必每个 handler 都做参数 sanity 检查。

静态黑名单：MODEL_HIDDEN_TOOL_PATH_PARTS（tools/minimal.py:61）含 30+ 项，比如：

动态校验：tools/file_mutation.py:579 _normalize_relative_path：

  • 不能是 str 之外的类型
  • 不能为空字符串
  • 不能超过 STAGE16G2_PATH_MAX_CHARS
  • 不能含 \ 反斜杠（必须 posix 风格 /）
  • 不能含 .. 父目录引用
  • 必须 workspace 相对路径（不能 /abs）

典型拒绝 reason_code：model_hidden_path_denied / path_separator_not_allowed / path_too_long / path_empty / path_not_string

L3 · 敏感 marker 路径变体归一化

L3Sensitive marker normalization触发点：T5 路径校验之后、写盘之前 · 位置：tools/file_mutation.py:56

问题场景：模型可能想绕过 L2 黑名单——比如不用 .hidden_verifier 而用 hidden-verifier、HiddenVerifier.py、hidden.verifier，但这些本质都是想读/写 evaluator-only 资源。L2 黑名单是逐字符串匹配，覆盖不到这些变体。

L3 做法：把路径每段小写 + 去 -/_/. 分隔符，归一成无分隔小写，再和 _SENSITIVE_PATH_MARKERS frozenset 比对：

_SENSITIVE_PATH_MARKERS = frozenset({
    "failtopass", "finalverifier", "goldpatch", "groundtruth",
    "hiddenfeedback", "hiddentestpatch", "hiddentestselector",
    "hiddenverifier", "officialverifier", "passtopass",
    "providersecret", "rewardextrainfo", "rewardmetadata",
    "testpatch",
})

另一个 frozenset _RUNTIME_PRIVATE_PATH_MARKERS 含 repoharnessenvoverlay / repoharnessrun / repoharnessruntime / repoharnesstmp / runtimeprivate。

触发位置：tools/file_mutation.py:603，any(marker in normalized_marker for marker in _SENSITIVE_PATH_MARKERS)

典型拒绝："Hidden-Verifier/result.json" → 归一为 hiddenverifier → 命中 → reason_code=sensitive_marker_path_denied

为什么和 L2 分两层：L2 拦"明显的隐藏文件夹"；L3 拦"故意改写法绕开 L2"。两层逻辑互补。
