Stage 16G.3D · scratch_python + 动态诊断闭环 probe — 执行计划

来源：执行计划 §11 · 前置：3A 共享底座 + 3B/3C 已可用（或 schema-only） · 核心交付：临时 Python 复现工具 scratch_python + mini-SWE-agent 风格闭环 probe

介绍

3D 是 16G.3 的闭环收口子阶段。它新增第三个公开诊断工具 scratch_python，并通过一个跨工具的闭环 probe 证明"读 → 跑 → 复现 → 改 → 验证 → diff"动态诊断链路已用结构化工具实现，覆盖 mini-SWE-agent 的下限能力。

scratch_python 用于让模型写最小复现 / 导入 smoke / 数据结构实验 / 快速验证假设。它不是文件修改工具，不应把临时代码写进仓库最终补丁。

1 · 工具契约（计划 §11.1）

scratch_python(
    code,
    cwd=".",
    timeout_sec=30,
    purpose=None,
)
  • code：脚本字符串内容（第一版上限 64 KiB）
  • cwd：workspace-relative 工作目录
  • timeout_sec：默认 30 秒，最大 120 秒
  • purpose：可选诊断目的（写入审计）
明确边界：scratch_python 是 Python-first 的受控复现工具，不等价于 mini-SWE-agent 的任意 shell 复现能力。语言通用 scratch reproduction、Node / Ruby / Go / Rust 等临时脚本能力不在 16G.3 第一版完成范围内，必须在 evidence 中标记为未覆盖或后续扩展。

2 · 9 条执行边界（计划 §11.2）

这 9 条把 scratch_python 和 3A 底座的隔离要求绑紧。

1脚本字节上限：第一版 64 KiB。超过 → schema 校验拒绝
2timeout 上限：第一版默认 30 秒，最大 120 秒。超过 → 工具预算 timeout（不是命令真实 timeout）
3必须在隔离环境：public projection / 临时复制工作区 / Docker sandbox。不能直接在真实 episode 工作区中跑任意 Python
4无网络 + 无宿主路径 + 无 run directory mount + 无 runtime-private mount。隔离事实必须进 evidence
5源码只读或写入复制区：源码对脚本应只读，或者写入发生在可丢弃的复制工作区中。脚本产生的缓存 / 临时文件 / 输出默认不进 final patch
6可读公开依赖：脚本可以读取公开源码和公开依赖，但不能写共享依赖环境
7禁止访问：hidden verifier / 参考补丁 / 测试补丁 / runtime-private / run directory / 宿主绝对路径 / 网络 / 环境密钥 / 共享依赖写入区
8禁止修改 episode 源码：如需修改源码，模型必须使用 apply_patch 或 write_file
9fallback 处理：若实现无法证明上面隔离条件，scratch_python 不得进入 swe_public_core，只能作为 rejected / planned / diagnostic-only evidence

3 · 输出 + artifact（计划 §11.3）

scratch_python 结果必须和 public command 底座一致：

{
  "status": "ok",
  "exit_code": 0,
  "stdout_preview": "...",                              # 模型可见预览，路径脱敏
  "stderr_preview": "...",                              # 同上
  "timed_out": false,
  "truncated": false,
  "script_artifact_visibility": "runtime_private_or_restricted_audit",
  "model_visible_observation": "redacted_truncated",
  "repository_mutation_performed": false,               # 必须为 false
  "final_patch_pollution": false                        # 必须为 false
}

raw stdout/stderr 落私有 artifact，对应字段 stdout_artifact_ref / stderr_artifact_ref 不返给模型。read_tool_result_artifact 只能读 sanitized artifact，不能读 raw。

4 · 动态诊断闭环 probe（计划 §11.4，必备）

16G.3D 必须提供一个小型真实闭环 probe，证明 RH 已覆盖 mini-SWE-agent 的动态诊断下限，但用结构化工具实现。这个 probe 是 16G.3 整体完成的"看是不是真能跑起来"样本。

▼ 这个 probe 必须通过 run_episode(real_episode) 跑，不能只调工具函数 📂 read_file / grep 观察当前代码结构 ↓ ▶ run_project_test 或 run_public_command 看到失败的公开测试 ↓ ✏ scratch_python 写最小复现，验证 bug 是这一段 ↓ 🛠 apply_patch 修改源码 ↓ ▶ run_project_test 验证公开测试现在通过 ↓ 📋 git_diff / final patch 最终 patch 投影到 final.patch ↓ 闭环完成 run_episode projection 中能看到完整 tool event 序列

4.1 公开 evidence 约束

这个 probe 写出的公开 evidence 只保留：状态 / 计数 / sha256 / 相对路径 / public-safe 摘要。不保留：临时目录 / 本机路径 / 原始完整 stdout / stderr / 隐藏 selector。

4.2 probe 必须证明的事实

  • 所有 7 个步骤都真实跑过（不是 mock 出来的）
  • scratch_python 的输出没有污染 final.patch
  • apply_patch 修改后，run_project_test 的 pass 状态真的从 fail → pass
  • git_diff 出来的 final.patch 不含 scratch script 内容
  • TrainingView 中所有 tool observation span 都 mask=0
  • provider_route_qualification 仍为 policy_loss_candidate=false（mock route）

5 · 非目标（边界澄清）

  • 不是 mini-SWE-agent 的任意 shell — Python-first，其他语言留给未来
  • 不是文件修改工具 — 仓库改动必须走 apply_patch / write_file
  • 不是 REPL 或 persistent shell — stateless，不保留 state across calls（persistent shell 留给 16G.4B）
  • 不是依赖安装工具 — 不能 pip install / poetry install（属于 16G.4A）
  • 不是网络 client — 无网络
  • 不是任意脚本执行器 — 通过 3A 底座的 disposable snapshot 隔离
