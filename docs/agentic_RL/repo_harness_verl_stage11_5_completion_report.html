⑦ _validate_generation_record_token_provenance 6 条严格校验

这是 Stage 11.5 在 episode.py 加的 model_validator。每个 RepoHarnessEpisodeResult 构造时都会跑，不可绕过。

#断言违反时抛的 ValueError
1所有 generation_records 的 model_call_id 必须唯一duplicate_generation_record_model_call_id
2assistant_generation span 数量必须等于 generation_records（去除空 token 的）数量assistant_generation_span_count_mismatch_generation_records
3每个 assistant span 的 model_call_id 必须等于对应 GenerationRecord.model_call_id 且顺序一致assistant_generation_span_order_mismatch_generation_records
4每个 assistant span 内 response_ids[span.start:span.end] 必须 逐 token 等于 对应 GenerationRecord.output_token_idsassistant_generation_tokens_mismatch_generation_records
5当 response_logprobs 非空时，每个 assistant span 的 logprob 必须逐元素等于对应 record 的 output_logprobsassistant_generation_logprobs_mismatch_generation_records
6所有 assistant span 拼接后的 token / logprob 总序列必须等于所有 records 拼接后的序列assistant_generation_token_sequence_mismatch_generation_records / assistant_generation_logprob_sequence_mismatch_generation_records
结果：任何企图从 transcript 重新分词或跨轮拼接错乱来伪造可训练 token 的代码路径，在 EpisodeResult 构造时就会被 pydantic 直接拒绝。即使有人在 11.5 之后改了 _assemble_training_view_from_collector，校验层仍守住底线。
