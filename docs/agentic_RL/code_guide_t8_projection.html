① 角色 + Contract

角色定位

T8 是 RepoHarness 公开 / 私有边界 的关键节点：

  • 之前所有数据（episode_result、generation_records、tool_observation token 流、reward metadata）都是私有的，可以含敏感字段（audit_ref、绝对路径、hidden_test_patch 等）
  • T8 之后的 compat_projection/ 目录是公开 / 训练数据消费侧可见；每个文件都经过白名单字段提取、绝对路径剥离、forbidden marker 扫描

def write_run_episode_compat_projection(*, run_dir, task, request, execution_spec, result,
                                          provider_route) -> ProjectionWriteResult:
    projection_dir = Path(run_dir) / PROJECTION_DIR_NAME
    projection_dir.mkdir(parents=True, exist_ok=True)

    # ① 决出 policy_loss 资格（4 条件 AND）
    route_qualification = _provider_route_qualification(
        provider_route=provider_route, request=request, result=result)

    # ② 构造每个公开文件的 payload（白名单字段提取）
    training_view_projection = {
        "schema_version": "repo_harness_stage16f3_training_view_projection_v0",
        "response_token_count": len(result.training_view.response_ids),
        "response_mask_count": len(result.training_view.response_mask),
        "online_rl_eligible": result.training_view.online_rl_eligible,
        "invalid_for_training": result.invalid_for_training,
        "invalid_for_online_rl": result.invalid_for_online_rl,
        # ⚠ 注意：raw response_ids 不进公开投影，只放 token 计数
        ...
    }
    status = {
        "policy_loss_candidate": route_qualification["policy_loss_candidate"],  # 双绑
        "formal_online_rl_eligible": route_qualification["formal_online_rl_eligible"],
        ...
    }

    # ③ 一次性写盘（14 个文件）
    files = {
        "task_projection.json": task_projection,
        "provider_route_qualification.json": route_qualification,
        "training_view_projection.json": training_view_projection,
        "compat_projection_status.json": status,
        "final.patch": _read_required_text(run_dir / "final.patch"),
        "final.diff":  _read_required_text(run_dir / "final.diff"),
        "final_patch_hygiene_report.json": _public_patch_hygiene_report(...),
        ...
    }
    for filename, payload in files.items():
        _write_projection_file(projection_dir / filename, payload)

    # ④ manifest 把所有文件 sha256 + qualification 一起绑
    manifest = _manifest_payload(execution_spec=..., result=..., route_qualification=...,
                                  files=files, final_patch_text=..., ...)
    _write_json(projection_dir / "compat_projection_manifest.json", manifest)

    # ⑤ 校验：assert_complete=True 表示任何不一致都 raise
    validation_report = validate_run_episode_compat_projection(
        projection_dir, execution_spec=..., result=..., assert_complete=True)
    _write_json(projection_dir / "projection_validation_report.json", validation_report)

    return ProjectionWriteResult(projection_dir=..., manifest_path=..., validation_report=...)

③ provider route 资格判决 _provider_route_qualification（episode_projection.py:610）

这是整个 RepoHarness 决定"这条轨迹能不能进 PPO/GRPO 梯度"的最终守门员。本系列里你会看到它被多处引用。

def _provider_route_qualification(*, provider_route, request, result) -> dict:
    formal_online_rl_eligible = (
        provider_route == "verl"                        # ① 实际推理走的是 verl
        and request.llm_gateway_route == "verl"          # ② 请求侧也声明是 verl
        and not result.invalid_for_training            # ③ 没有 training-level 阻断
        and not result.invalid_for_online_rl           # ④ 没有 online-RL 阻断
    )
    return {
        "schema_version": "repo_harness_stage16f3_provider_route_qualification_v0",
        "provider_route": provider_route,
        "llm_gateway_route": request.llm_gateway_route,
        "result_invalid_for_training": result.invalid_for_training,
        "result_invalid_for_online_rl": result.invalid_for_online_rl,
        "formal_online_rl_eligible": formal_online_rl_eligible,
        "policy_loss_candidate": formal_online_rl_eligible,         # ⚠ 等价
        "qualification_reason": ("route_verl_formal_online_rl_candidate"
            if formal_online_rl_eligible
            else "non_verl_or_diagnostic_route_not_policy_loss_candidate"),
    }

读懂这一段：policy_loss_candidate 与 formal_online_rl_eligible 在 T8 是等价的（同一个布尔值），两者并存只是为了让下游消费者按习惯名读它。任何"我想绕过 verl route 让 mock 轨迹进梯度"的尝试都会在这一个布尔表达式上被卡掉。

④ 公开扫描兜底 _scan_public_projection_for_leaks（episode_projection.py:638）

所有写出来的公开文件再被扫一遍 forbidden marker。这是最后一层防御：

def _scan_public_projection_for_leaks(projection_dir: Path) -> list[str]:
    findings = []
    for path in sorted(projection_dir.rglob("*")):
        if not path.is_file(): continue
        if path.suffix not in {".json", ".jsonl", ".md", ".txt",
                                  ".log", ".yaml", ".yml",
                                  ".patch", ".diff"}: continue
        text = path.read_text(encoding="utf-8", errors="ignore")
        normalized_text = _RUNTIME_PRIVATE_REF_PATTERN.sub("runtime-private:<kind>:<sha256>", text)
        for marker in _FORBIDDEN_PUBLIC_MARKERS:
            if marker in normalized_text:
                findings.append(f"{path.relative_to(projection_dir)}:{marker}")
    return findings

这里的 _FORBIDDEN_PUBLIC_MARKERS 是个静态集合，含 hidden_verifier / gold_patch / accepted_label / provider_secret / evaluator_only_logs / absolute_run_directory 等典型敏感词。详见 side-A 安全边界。

    违例风险：绕过 4 条件门。检测：grep policy_loss_candidate\s*=\s*True 应只出现在该函数内部。
  • I-2manifest 与 status 双绑 · compat_projection_manifest.json 和 compat_projection_status.json 都含 policy_loss_candidate 字段，必须相等。
    违例风险：篡改一个绕过另一个。检测：validation 函数（line 388-403）有 5 处 mismatch 错误码兜底。
  • I-3raw_artifact 私有 by omission · raw token_ids / raw logprobs / raw reward metadata / raw verifier artifacts 都不出现在 14 个公开文件里。
    违例风险：训练数据泄漏 evaluator-only 信号。检测：training_view_projection 字段集只含计数 + flag，无 ids；后续 stage 加字段时必须白名单审。
  • I-4fail closed · validate 失败 raise ProjectionValidationError。不写半成品 manifest。下游 evidence 阶段读不到 manifest 就视为本 episode 不可用。
    违例风险：缺字段被静默通过、模型/训练拿到不完整数据。
  • I-5forbidden marker 出站扫描 · 公开 patch_hygiene_report 不能含 raw 字段（_public_patch_hygiene_report 内做字段剥离）；compat_projection 整体扫一遍 _FORBIDDEN_PUBLIC_MARKERS。
    违例风险：hygiene_report 把 raw 字段写出去；某个 .json 含 "hidden_verifier" / "gold_patch" 字面量。
  • I-6final.patch 与 manifest sha256 一致 · manifest 中的 final_patch_sha256 必须等于 final.patch 文件实际内容的 sha256。
    违例风险：篡改 patch 但忘改 sha；或反过来。validation 函数硬约束。
  • I-7schema_version 显式 · 每个 dict 都有 schema_version 字段，名字遵循 repo_harness_stage<N>_<kind>_projection_v<v>。
    违例风险：消费侧无法识别哪种数据。后续 stage 改字段集时必须升 schema_version。
