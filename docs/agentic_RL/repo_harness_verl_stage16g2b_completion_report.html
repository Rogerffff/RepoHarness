2 · 具体产出详解

① file_mutation.py —— 共享文件变更服务

新增一个底层模块,被 write_file、apply_patch 以及 extended 的 delete_file/move_file/mkdir 共用(避免各写一套路径检查)。它负责:workspace 路径解析、forbidden path 拒绝(.git / runtime_private / hiddenverifier / hiddentestpatch 等)、UTF-8 检查、expected hash 校验、预检+执行、统一 reason_code/result。

② 真实行为 + 事务原子语义

# execute_structured_file_mutation 的骨架（已核）
prepared  = _prepare_operations(...)   # 全部 operation 先预检
snapshots = 快照受影响文件的旧内容       # 为 rollback 准备
try:
    for op in prepared: _apply_prepared_operation(op)   # 全过才逐个真正写
except:
    _rollback_snapshots(snapshots)      # 失败 → 回滚
    return partial_failure=True, rollback_attempted=True,
           invalid_for_training=True, policy_loss_candidate=False   # 整条 episode 踢出训练

真正的写入是 write_text(覆盖/新建)、unlink(删)、rename(移)、mkdir(建目录)。

③ apply_patch 一元 delete/move + reason

验证了 apply_patch 能干净表达单个删除/移动(不只批量),且 delete/move operation 强制带模型 reason(审计/reward attribution)。这正是 16G.2B preflight 设计修正要求的——core 不给独立 delete/move/mkdir,统一经 apply_patch。

④ 独立工具仅 extended + 新 inspector

独立 delete_file/move_file/mkdir 默认不可见,但在 swe_public_extended 中可真实执行(行为也已实现,只是不进 core 默认)。新增 CLI inspect-stage16g2b-file-mutation + safety_denial / file_mutation_probe evidence。acceptance 用 source_digests 绑定 6 个源码文件 sha256(不只 evidence)。

⑤ 训练资格仍等 2C

新文件工具的成功/拒绝事件都不进 policy loss,acceptance 明确 next_required_stage_for_policy_loss=16G.2C —— 行为先做对,训练 linkage(进 final.patch/export、翻开 policy-loss 资格)留给 2C。

3 · 我的审查观察 / 提醒

做得好 O1 · 事务原子性 + "失败就丢整条 episode" 是数据干净度的正确做法

全预检→快照→apply→失败 rollback,而且 partial_failure / 回滚不干净 → 整条 episode invalid_for_training。更关键:连成功的新工具写入也暂不进 policy loss。这意味着"行为正确性"和"训练资格"被干净地分成两步——先在 2B 把行为做对,再在 2C 谨慎接训练。这正是我一直强调的 RL 数据干净优先。

知情·重要 O2 · 这是模型第一次能在默认 scaffold 真改文件

从 2B 起,跑 simple_react 时模型调 write_file/apply_patch 会真的改工作区。但因为训练资格仍关着(policy_loss=false 直到 2C),这些改动暂不喂训练——所以现在适合用于评测/probe,数据还不进 RL。gate(16G.3/17B/20/21 全 false)也天然挡住。结论:可以放心用它做诊断/probe,但 2C 接通 policy-loss 资格前,别把这些轨迹当训练数据。
