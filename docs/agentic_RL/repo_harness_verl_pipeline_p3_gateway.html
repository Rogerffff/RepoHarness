单轮内部：Gateway 推理 · Tool 解析 · Final Verifier

本页详解每一轮内部发生的事——AgentLoop 调一次 adapter.generate 之后，单轮内部如何完成：①VerlLLMGateway 怎么把 LLMGatewayRequest 转成 verl LLMServerClient 调用（真实 vLLM / SGLang 推理）；② TokenOutput 怎么转回 LLMGatewayResponse 含 parse_hermes_tool_calls 解析模型输出的 <tool_call>...</tool_call> 块；③ 工具实际怎么在 lease workspace 内执行；④ episode 结束时 final_verifier_factory 怎么构造真实 PytestVerifier callable，通过 VerifierWorkerPool 跑出 VerifierResult，再用 build_stage7_reward_boundary 算出真实 reward_score。

③ Tool 解析（Hermes 协议 · Stage 12-B）

Qwen Coder 等真实 instruct 模型按 Hermes 风格输出工具调用。RepoHarness 用 parse_hermes_tool_calls 解析为内部 tool_call 字典。tool_parser.py:31-84。

支持的两种格式

① 主格式：<tool_call>{JSON}</tool_call> 块

# 模型输出 我来读一下 calculator.py 这个文件。 <tool_call> {"name": "read_file", "arguments": {"path": "src/calculator.py"}} </tool_call>

② Recovery：整消息 JSON / Markdown fence

# 没有 <tool_call> 但整段是 JSON {"name": "read_file", "arguments": {"path": "src/calculator.py"}} # 或 markdown fence ```json {"name": "read_file", "arguments": {...}} ```

⑥ Reward Boundary（Stage 7）

verifier 跑完后，build_stage7_reward_boundary 整合 verifier 结果 + pool facts → 计算真实 reward_score 并决定 episode status。reward_boundary.py:54-140。

5 步决策流程

  1. 合并 final_verifier 和 pool_result.verifier_result（pool 模式下后者优先）
  2. map_stage7_verifier_status(verifier, pool_result) → (status, status_reason)，按 3 个 error 集合分类（INVALID_TASK / INFRASTRUCTURE / TIMEOUT）
  3. 计算 invalid_for_training = status ∈ {invalid, invalid_task, infrastructure_error, cancelled, timeout, no_progress}
  4. 调 compute_reward_metadata(verifier, ...) → RewardMetadata；用 status 第二层覆盖防止漏判（不可信 verifier reject 不算模型失败）
  5. 注入 4-5 个 extra_fields（reward_metadata_ref / final_verifier_ref / pool_id / worker_id / queue_wait_seconds）
