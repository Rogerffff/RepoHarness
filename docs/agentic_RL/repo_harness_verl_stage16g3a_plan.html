Stage 16G.3A · 共享公开命令执行底座 — 执行计划

来源：执行计划 §6.1 + §7 + §8 · 必须先于 3B/3C/3D 完成的"地基"工程 · 核心交付：src/repo_harness/tools/public_command.py + 22 条设计要求 + Profile schema + Docker isolation gate

介绍

这是 Stage 16G.3 的地基子阶段。它不直接给模型新增任何可调用工具，但规定了后续 3B/3C/3D 三个新工具必须共享的底层执行机制、隔离边界、artifact 可见性、拒绝语义和投影规则。地基如果不稳，后面三个工具会出现三套互不一致的实现，整个 16G.3 会变成"看上去能跑、随机出问题"的不可审计状态。

1 · 为什么必须先做 3A

计划 §6.1 论证：三个新工具都需要 12 项相同的底层能力。如果各自实现，会得到 3 套不一致策略。

cwd 解析                  | 路径黑名单                | 输出截断
workspace-only 路径边界    | timeout                  | raw artifact 私有化
public-safe projection    | 拒绝 reason_code         | safe_alternative_tool
safe_rewrite_example      | TrainingView mask        | run_episode 投影

3A 的职责：把上面 12 项做成一个独立模块（建议 src/repo_harness/tools/public_command.py），3B/3C/3D 在底座之上各自选择不同 command family和 schema。

3 · 22 条设计要求（计划 §7.2）

下面是 22 条的完整列表，按重要性分组。标 🔑 的是本子阶段最容易在实施时被简化或绕过的关键约束（约 7 条），其他为常规要求。

3.1 执行模型与 backend 选择（9 条）

1默认 stateless：一次工具调用只跑一个命令或脚本，不保留 shell session。
2默认不使用 shell：底层 adapter 若只能接字符串，必须由 harness 先解析成安全 argv，禁止任意 shell 语法。
3🔑 必须 workspace-only isolated backend：使用已验证的 workspace-only isolated backend / public projection / 临时复制工作区 / Docker sandbox。普通未隔离 local_process、可见 run-directory mount、无法证明隔离的 backend必须确定性拒绝，不能靠 command classifier 和 cwd 检查替代运行时隔离。
4🔑 必须在 disposable public execution snapshot 中跑：快照必须含模型当前 candidate source patch；命令产生的 __pycache__ / .pytest_cache / 构建目录 / 临时日志 / scratch 文件默认不得写回真实 episode workspace。
5🔑 必须新增 public-command 专用执行接口：不能直接复用现有 workspace_adapter.run_command(...)。可内部复用底层进程能力，但必须先创建 public execution snapshot 并证明：无 run directory mount + 无宿主路径暴露 + 无 raw runtime artifact 可见。
6每次执行生成 snapshot digest：public_execution_snapshot_digest 或等价快照标识，记录 candidate_patch_included / execution_side_effects_discarded / post_run_workspace_digest_matches_pre_run / workspace_mutation_detected / result_valid_for_training / final_patch_pollution=false。
7workspace 污染处理：若公开命令执行后真实 episode workspace 被改，必须 workspace_mutation_detected=true + result_valid_for_training=false，除非该变化发生在明确可丢弃且已丢弃的 snapshot side effect 中。
8🔑 完成最低条件 — 二选一：
(A) Docker 或等价隔离后端可用，机器证据证明：network_policy=deny/none + 无 run directory mount + 无宿主路径暴露 + snapshot side effects 已丢弃
(B) 只完成 schema / profile / classifier / planned_not_enabled evidence，不暴露 run_public_command / run_project_test / scratch_python 进 swe_public_core
9🔑 fallback 必须明示：若实现退回普通本机子进程执行，必须写入 network_isolation_proven=false + core_profile_exposure_allowed=false，不能把 fallback 当 3A 完成态。

3.2 网络隔离 / fail-closed（1 条）

10🔑 必须提供无网络 evidence：不能只靠拒绝 curl/wget 命令名 — 网络也可能来自 Python socket / 测试插件 / 项目脚本 / 二级解释器。Docker backend 的网络策略必须 fail closed：未知策略 / 默认 bridge / 未记录策略 / 非 deny 策略都让 inspector 失败。

3.3 路径 / cwd / 命令分类（3 条）

11cwd 必须 workspace-relative：不能是绝对路径，不能含 ..，不能指向 hidden / runtime-private / 依赖缓存写入区 / evaluator-only 路径。
12命令必须先进 classifier：得到 command_family + public_command_capability + risk_level + policy_decision + safe_argv + reason_code。
13受控环境变量白名单：env 必须来自 PublicCommandProfile 的 env_profile / public_env_overrides，ingestion-time 白名单校验。模型不能通过 shell 前缀 / env 包装 / 工具参数自由设置环境变量。第一版建议只允许 PYTHONPATH / DJANGO_SETTINGS_MODULE / CI / NODE_ENV。注：见总览 O3 — 这个白名单可能不够

3.4 输出结构 + artifact 可见性（5 条）

14工具结果字段：stdout_preview / stderr_preview / exit_code / timed_out / duration_ms / truncated / stdout_artifact_ref / stderr_artifact_ref 或等价私有 artifact 指针。
15模型可见 preview：必须路径脱敏 + 长度受限 + 禁 hidden marker + 禁本机绝对路径 + 禁 raw run directory + 禁 runtime-private ref。
16🔑 截断输出必须双层 artifact：①模型可分页读取的 public-safe sanitized artifact；② 不可直接给模型的 raw stdout/stderr 私有 artifact。read_tool_result_artifact 只能读 sanitized，inspector 必须验证两层没有混用。
17新增 command output artifact schema：至少含 sanitized_model_readable / raw_restricted_audit / artifact_visibility / artifact_kind / source_tool_call_id / truncation_policy / sha256。现有通用 tool result artifact 如果没有 visibility / raw-sanitized 类型字段，必须扩展或包一层 16G.3 专用 manifest。
18raw stdout/stderr artifact 默认私有：runtime_private_or_restricted_audit，不能进 public evidence / 模型可见 transcript / read_tool_result_artifact。必须有 raw-ref 读取拒绝测试。

3.5 拒绝语义 + timeout + 训练投影（4 条）

19统一 denial envelope：所有拒绝必须用 status="denied" + reason_code + policy_version + retryable + safe_alternative_tool + safe_rewrite_example + public_command_capability。
20timeout 必须区分两类：① 命令真实超时；② 工具预算超时。timeout 结果不能进成功验证声明。
21tool observation token 在 TrainingView 中 mask=0。模型的 tool call token 是否进 policy loss 仍由 16G.6 统一决定。
22新工具必须登记到 permission system 的路径字段白名单或等价审计机制，至少覆盖 cwd / profile 派生路径 / scratch 目录 / sanitized artifact 读取路径。不能只在 registry 和 executor 中加新工具。

4 · 完成态二选一 + 决策状态图

把要求 #8 / #9 / #10 串起来看，3A 完成态只能落在3 类合法终态之一，其他都是 inspector 失败：

backend × 网络策略 × profile 暴露 三轴决策图 backend = Docker / equivalent isolated │ ├── network_policy = deny / none │ │ │ ├── snapshot side effects 已丢弃 ────────► 合法终态 A │ │ core profile 可暴露 │ │ stage16g3a_complete=true │ │ │ └── snapshot side effects 未丢弃 ────────► inspector 失败 │ ├── network_policy = 默认 bridge / 未记录 / 非 deny │ │ │ └─────────────────────────────────────► inspector 失败（fail closed） │ └── network_policy unknown ─────────────────────► inspector 失败（fail closed） backend = 本机子进程 / unisolated │ ├── network_isolation_proven=false & │ core_profile_exposure_allowed=false │ 三个新工具都不进 swe_public_core │ 只完成 schema/profile/classifier 和 │ planned_not_enabled evidence │ │ │ └────────────────────────────────────► 合法终态 B │ stage16g3a_complete=true │ 但 3B/3C/3D 行为不放进 core │ └── 试图既用本机子进程 又暴露进 core ─────────► inspector 失败

合法终态 C = 只完成 schema / profile / classifier / planned_not_enabled evidence，连本机子进程都不实现 — 这是"最保守"的完成态，可以让 3A 通过验收但 3B/3C/3D 直接退回到只 schema-only。

7 · Public test source boundary（计划 §8）

原本属于 16G.4D，提前到 16G.3 必须落地。理由：可训练公开测试工具一旦放进 core，"模型先改公开 test 再让 test 通过"是最直接的 reward hacking 路径，不能等到 16G.4D 才堵。

7.1 触发位置

run_project_test 执行前必须判断 public test 文件是否被模型当前 candidate patch 修改。第一版二选一：

策略行为返回字段
策略 A（推荐第一版）拒绝运行public_test_source_clean=false + result_valid_for_training=false + safe_rewrite_example
策略 B（实现复杂）在干净 public test 快照上运行public_test_source_clean=false + ran_on_clean_public_test_snapshot=true

7.2 两条策略共同的硬约束

  1. 不能让"模型先修改 public tests，再运行 public tests 通过"的轨迹进主 policy-loss candidate
  2. tool result 必须含 public_test_source_clean / public_test_snapshot_digest / candidate_patch_included / result_valid_for_training / official_prediction_eligible 等事实
  3. 若 public test 被改但命令仍运行，必须明确运行的是干净测试快照而非被改的文件
  4. 必须有 probe：先改 public test，再调 run_project_test，验收器看到拒绝 OR clean snapshot facts
建议：总览 O2 提到策略 B 实现难度高，建议第一版强制策略 A。这个二选一应在 3A 启动前定。

8.2 Inspector 必须校验 22 项（计划 §15）

挑核心几项强调：

  1. 重新扫 public evidence，不信任旧 path leak report
  2. 绑定 source inventory sha256
  3. 校验三个新工具出现在 registry / profile / scaffold / executor / run_episode projection 中
  4. 校验三个工具共用同一套底座 policy version
  5. 校验每个 reason_code 都有 safe alternative 或明确不可恢复说明
  6. 校验截断输出存在可继续读取的 public-safe sanitized artifact，且 raw artifact 没有返给模型，也不能被 read_tool_result_artifact 读
  7. 校验 public execution snapshot 隔离事实（无 mount / 无宿主路径 / 无 raw runtime artifact）
  8. 校验 workspace_mutation_detected / post_run_workspace_digest_matches_pre_run / final_patch_pollution / result_valid_for_training 组合语义
  9. 校验 Docker / 等价 backend 网络策略 fail closed
  10. 校验 run_public_command 不支持自由裸 argv（raw_freeform_argv_supported=false 等）
  11. 校验 public test source boundary
  12. 校验 PublicCommandProfile/PublicTestProfile 字段完整、digest 绑定、enabled_state 不夸大多语言能力
  13. 校验 mock / non-verl route 不被误标为 policy loss candidate
  14. 校验 stage17b/20/21 仍不放行
  15. 对关键 report 使用字段白名单
