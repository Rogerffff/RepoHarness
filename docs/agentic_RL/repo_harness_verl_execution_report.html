fixture 内容举例

合法训练视图样例

canonical_training_view.json 展示一条最小可训练样本：包含 prompt_ids、response_ids、response_mask、response_logprobs、reward_score、response_spans 和 repo_harness_* opaque refs。

response_ids:       [201, 202, 301, 302, 203]
response_mask:      [1,   1,   0,   0,   1]
response_logprobs:  [-0.11, -0.12, 0.0, 0.0, -0.13]

这里的工具观察 token 使用 response_mask=0，对应 response_logprobs=0.0，不会参与 policy loss。

多轮工具调用样例

canonical_multiturn_tool_episode_result.json 覆盖 assistant 生成工具调用、tool observation、environment observation、下一轮 assistant 最终回答，以及 padding / truncated excluded span。

response_spans:
  assistant_generation
  tool_observation
  environment_observation
  assistant_generation
  padding_excluded
  truncated_excluded

每个 span 都带有 model_call_id、tool_call_id、artifact_ref、response_mask_value、logprob_policy、policy version 和 global steps。

无效样本样例

canonical_response_overflow_invalid_result.json 固定 response overflow 的处理方式：不能静默截断后继续训练，必须写入 status_reason=response_length_exceeded、budget_consumption.stop_reason 和 audit diagnostics。

canonical_empty_response_invalid_result.json 固定空 response 的处理方式：空 response_ids 即使曾经尝试产生 reward，也不能带着普通有效 reward_score 进入训练。

泄漏防护样例

canonical_audit_path_access_denied.json 固定模型工具访问审计路径时的拒绝策略。样例覆盖 read_file、grep 和 read_tool_result_artifact 访问 run directory、reward metadata、final verifier artifact 和 gold patch 的场景。

这些引用使用 rh://audit/... opaque ref，而不是模型工具可直接读取的本地绝对路径。

新增的正式 schema

episode.py 定义 RepoHarnessEpisodeRequest、RepoHarnessEpisodeResult、episode status、invalid reason、diagnostics、budget consumption、reward summary、verifier summary 和 patch summary。

training_view.py 定义 TrainingView、ResponseSpan、结构化 AuditRef、validate_training_view_for_online_rl(...) 和 validate_formal_online_rl_batch(...)。

新增的 gateway contract

gateway.py 定义 LLMGatewayRequest、LLMGatewayResponse、GenerationRecord、async LLMGateway protocol 和 async FakeLLMGateway。

LLMGatewayResponse.extra_fields 和未来 AgentLoopOutput.extra_fields 已经明确区分：gateway 侧可以保留 rollout 侧补充信息；batch 可传播字段只能是扁平 repo_harness_* scalar 和 opaque refs。

新增的 visibility 边界

visibility.py 固定 route 枚举、provider route 默认 invalid_for_online_rl=true、模型可见字段 denylist、batch extra fields allowlist 和 audit opaque ref 校验。

现在会拒绝 hidden verifier、gold patch、accepted label、complete reward metadata、provider secret、evaluator-only logs、本地绝对路径和嵌套 audit ref 进入模型可见字段或 batch 可传播字段。

保留的 Stage 1 边界

本轮没有实现 RepoHarnessRuntime.run_episode(...)，没有实现 training_fast recorder，没有实现 TrainingView -> AgentLoopOutput converter，也没有实现 RepoHarnessVerlAgentLoop、VerlLLMGateway 或真实 vLLM / SGLang / Ray 训练流程。

Stage 1 关键规则落地情况

规则 落地方式 审查意义
Stage 0H fixture roundtrip test_repo_harness_rl_stage1_schema_roundtrip.py 对 11 个 canonical fixture 做正式 schema 构造、序列化和反序列化。 证明 Stage 1 没有绕过 Stage 0H，也没有另起一套样例。
mixed logprob batch 拒绝 单条 TrainingView 只校验自身 token / mask / log probability 对齐；正式 batch 通过 validate_formal_online_rl_batch(...) 拒绝 mixed logprob。 避免把 batch 级 PPO / GRPO 规则错误塞进单条样本 schema。
provider route 默认无效 ProviderRoutePolicy(route="openai") 或 deepseek 缺省时自动补 invalid_for_online_rl=true，显式 false 会被拒绝。 OpenAI / DeepSeek 可以用于评测、teacher data、SFT、preference 和 offline replay，但不能伪装成 online rollout policy sample。
AuditRef 结构化但不进 batch AuditRef 保留在 RepoHarnessEpisodeResult.audit_ref；TrainingView.extra_fields 只允许 repo_harness_* 扁平 scalar 和 opaque refs。 保留完整审计证据，同时防止本地路径、reward metadata 或 final verifier 细节泄漏到训练 batch。
模型可见字段检查 key 和 value validate_no_forbidden_model_visible_content(...) 现在同时收集字典 key 和 value，拒绝 hidden_verifier、gold_patch 等 key-based 泄漏。 防止隐藏字段通过 JSON key 名绕过可见性检查。
gateway extra fields 深层检查 validate_gateway_extra_fields(...) 会递归检查字典和列表中的 key / value，拒绝 ["repo_harness_gold_patch"] 这类嵌套列表泄漏。 防止 gateway 侧开放扩展字段成为 evaluator-only 信息的透传口。
async gateway contract LLMGateway.generate_turn(...) 和 FakeLLMGateway.generate_turn(...) 已改为 async 接口。 与 Stage 2 的 async run_episode(...) facade 和后续 verl AgentLoopBase.run(...) 方向保持一致，避免 Stage 2 刚开始返工接口。
gateway response mask 边界 LLMGatewayResponse.response_mask 现在必须全为 1；工具 observation token 只能在 episode 级 TrainingView 中以 response_mask=0 表示。 明确 gateway 层只返回模型生成 token，TrainingView 层才负责拼接工具和环境 observation。
Stage 2 runtime 状态预留 RepoHarnessEpisodeResult.status 新增 invalid_task 和 infrastructure_error，并要求这些状态必须 invalid_for_training=true、invalid_for_online_rl=true。 Stage 2 可以区分任务无效、基础设施失败和普通模型失败，避免把 Docker、workspace、provider 或 verifier 故障当成可训练样本。
provider allowed uses 放松 ProviderRoutePolicy.allowed_uses 不再要求声明全部离线用途，只要求非空且每一项属于允许的离线用途集合。 保留 provider route 默认不能进入 online RL 的安全边界，同时避免未来只声明 evaluation 或单一离线用途时被 schema 过度拒绝。

Stage 1 sub agent 复查过程

Stage 1 完成后安排了三轮 sub agent 独立检查。sub agent 只检查和报告，不修改文件。前两轮发现的 blocking findings 已经转成负向测试并修复；第三轮复查确认没有新的阻断问题。

复查轮次 发现的问题 处理结果
第一轮 发现 3 个 blocking：batch / gateway extra_fields 可携带 namespaced evaluator-only 字段；raw_prompt / messages 可通过字典 key 泄漏；provider route 缺省没有自动 invalid_for_online_rl=true。 补充负向测试并修复：拒绝 repo_harness_hidden_verifier、repo_harness_gold_patch、repo_harness_provider_secret、repo_harness_complete_reward_metadata、repo_harness_run_dir 等字段；模型可见内容同时检查 key 和 value；provider route 缺省补 true，显式 false 拒绝。
第二轮 发现 1 个 blocking：LLMGatewayResponse.extra_fields 中的列表字符串值没有被递归检查，例如 {"safe_container": ["repo_harness_gold_patch"]} 仍可通过。 补充嵌套 list 泄漏测试，并修复递归遍历，让列表中的 scalar 字符串值也进入 evaluator-only marker 检查。
第三轮 没有 blocking findings。sub agent 确认前两轮问题已经关闭，src/repo_harness/rl 没有 import verl，也没有 Stage 2 / Stage 3 / Stage 10 / Stage 11 越界实现。 结论：Stage 1 可以接受，可以进入 Stage 2。
后续外部检查 另一个 agent 建议进入 Stage 2 前补 3 个小边界：gateway 应为 async；EpisodeStatus 应包含 invalid_task 和 infrastructure_error；LLMGatewayResponse.response_mask 不应允许 0。 已补 follow-up patch 和测试；同时顺手放松 provider allowed_uses 为离线用途子集。
第三轮 sub agent final judgment：Stage 1 可以接受，可以进入 Stage 2。此次复查只做检查和报告，没有修改文件。
