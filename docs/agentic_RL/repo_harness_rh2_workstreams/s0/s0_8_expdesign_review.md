## 3. 遗留给用户拍板的实验层决策

**必须在 S1 冻结题单前定（按紧迫排序）：**

1. **E4 首训数据策略**（最紧迫，S1 题单直接消费）：批准/修改"三段式"——SWE-Gym Lite 234 经 pass-rate [0.1,0.8] 预筛 + 环境验证门起步；扩容叠 SWE-Gym 全量 + R2E-Gym-Subset 上探 1~2K；agent 自产线并行不阻塞。含污染核查清单与"SWE-rebench 默认排除"。
2. **E2 算法配置**：GRPO n=8 + slime 三处显式配置（`--disable-grpo-std-normalization`、核对 clip-high 0.28、动态采样默认开）——建议照单批准；**并显式定训练 rollout 的 top_p**：≠1.0（如 0.95）即激活 top-p tape 硬依赖（slime patch 镜像 + U-H 必须 S1 关闭）；=1.0 可解耦 U-H 但偏离全部前沿采样配方。这一项决定 S1 的镜像与探针清单，不能拖。
3. **E5 评测协议与成功判据预注册**：held-out ≥30 题、Avg@n（n=8）、T=1.0/top-p 0.95~0.97、判据 Δ≥8~10pp、bootstrap CI——判据必须先于首训注册，不允许事后降。
4. **E6 预算 + C3 墙钟上限**：上下文 32k 起步、关 compaction（与 GRPO 绑定）、单轨迹 600~900s、步数 30~50、C3 定"首训 ≤4 天、硬上限一周"。C3 是 §1 硬约束区唯一仍标"待填"的顶层项。

**可在 S1 后、首训前定：**

5. **E3 warm-start**：批准"直接 RL from instruct + 量化回退触发（前 20 步三条件）"预注册；阈值为自建值，首训后校准。
6. **E8 结论形态**：三件套（能力/治理/解耦证据）+ 可选第四件（任务数消融 200 vs 1000~2000）——建议与 E5 一并批准。
7. **E9**：确认用户模拟/权限任务不进首训（草案倾向明确，敲章即可）。

**事实确认项：** C2 的 GPU 到底是租用还是自有 8 卡（本次按执行计划与 S0 租机记录改为"租用"）——影响 C3 墙钟成本敏感度与 E6 杠杆排序的权重。
