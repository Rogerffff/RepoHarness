## 2. 交给 Claude 的窄收尾

### F1（P2）：`agree` 不能代表逐键状态一致，参考账本互核也尚未实现

位置：`rh2/scripts/reconcile_r2e.py:124–130`。

实际 CLI 反例：期望某键 `PASSED`，RH2 日志为 `FAILED`，参考日志为 `ERROR`。两侧 reward 都是 0，`mismatched` 集合也都只有这个键，所以当前 `agree=True`，但 `observed_maps_equal=False`。这会把执行行为的分歧计入最终“一致”数。另一个反例中两侧日志都算 0、M3 账本自报 1，当前也记 `agree=True`；`m3_ledger_rewards` 只是输出，未参与互核或生成明确的矛盾标记。

建议：把逐键状态相等加入总体一致条件；参考账本存在时单列与日志重算值是否一致，有矛盾明确报告，缺失则注明不可互核。允许分别保留 reward 一致、差异键集合一致、状态映射一致几个事实，但不能用前两项宣称第三项。补这两个最小反例即可，无须改变生产评分规则或增加训练准入条件。

**不影响本次六条既有结果**：本轮已绕过总体 `agree`，直接验证全部状态映射相同。建议在 48 题验收之前修工具，不阻塞准备机器和镜像。

### F2（P2，条件为并行共用输出目录）：构建工具目前不能承诺不覆盖

位置：`rh2/scripts/build_r2e_derived.py:352–361`、`:405–418`；runbook §2。

静态可达交错：调用 A 读完仅含 A 的 facts 后暂停；调用 B 完成另一题并把 A+B 写入覆盖表；调用 A 恢复，把旧的仅 A 集合写回。`results.json` 也在每个进程开头读取旧快照，随后整文件写回，存在同类丢条目。非原子读取还可能遇到另一进程正在写的 facts。按目录扫描解决了**串行多次调用**，没有解决并行。

最小处理建议：本次 R-f 对同一输出目录只使用一个构建进程，文档撤回并行安全声明；已有 `--all` 本身就是串行的。若之后需要并行，用独立输出目录，结束后由单一汇总者聚合；不要求本轮增加复杂锁机制。这是工具执行方式修正，不是新的题目过滤规则。

### Runbook 小修（不影响生产评分）

1. §1 只同步 `s2_r2e/` 可以满足 R2E 加载，但随后整文件运行 `test_ingest_r2e_subset.py` 包含两个读取真实 SWE 材料的用例，会在全新机器缺 `s2/` 等材料时失败。机器烟测可选 `test_real_48_tasks_load_through_the_trusted_entry` 加 R2E parser 文件；SWE 不变性留已有完整工作区验证。不要将缺 SWE 资料误判成 R2E 加载回归。
2. §3 将“driver 带异常退出为 4”写成了 shell 退出码。真实缺补丁 CLI 仍退出 **1**，JSON `final_status.exit_code` 才为 **4**。本轮原探针再次确认，修文档即可。
3. §1 的 `sha256sum -c ... | grep ... || echo ALL_OK` 不能可靠传播校验退出码。直接检查 `sha256sum -c` 的退出状态；无需为此另建一套身份机制。
