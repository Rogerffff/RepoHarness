# 09-25 静态复核环境边界

本卡供私有角色引用，非已通过的环境资格。当前任务一只做静态复核，实际actor开发条件与探针接线由任务二负责；本批不重新执行环境实验。

- 本批public/base只代表明确base_commit的Git跟踪源码导出。实际交付镜像HEAD、`git status --porcelain=v1`输出/退出码/采集阶段、来源规定初始改动、忽略资产、准备后且开发命令前的状态均尚未由本批捕获。base导出干净不等于镜像干净，材料未导出不等于实际缺件。
- user_prompt按所核静态模板构造，只是计划输入；public_hints可见字段与实际system message/工具调用呈现分别验证。解释器激活、UID/HOME/cwd/PATH、源码导入、写权限、资产位置/权限、网络与资源均不可从提示词声明推断已通过。
- 私有run_refs定位对应任务的历史noop/gold原账本与日志；原件身份、配方、安装、执行选择器、参考/解析状态、初态差异和清理按任务核读。原环境维修记录不是当前actor资格，也不需据旧标签重跑全池。历史代码/镜像/脚本版本与当前实际入口分开。
- 镜像tag、期望manifest digest、实际image ID不同；未观测实际ID保留null。git show展示基线提交，不能误记为未提交diff。资源字段保留原名和值，单位实现未核不换算或猜测。
- 共用方法：[actor_development_validation.md](../../actor_development_validation.md)。各题给“需要操作/资产→公开依据→证据适用于谁/哪个版本→缺口→最小公开命令及预期”表。优先能够检验题目行为的公开CLI/API/用户流程，内部helper不足时说明；不要求全仓全绿，不为未知制造必然环境阻断。
- 新CPU/actor事实、修复与模型结果由根任务转交任务二；本批只能提出有目的的下一步。审查资料含gold/隐藏测试/旧答案，不能进入独立solver环境。没有本轮runtime证据可据此报告训练或正式评测合格。
