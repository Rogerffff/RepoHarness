## 随后两件事可以并行

**第一件：继续其余 192 题。** 按仓库每包约 8–12 题；优先余下 6 个旧 reject、已有真实模型假阳性/假阴性及较短探针候选，再补普通题。每包仍抽旧 ready，防止只确认旧报告的怀疑。Conan 余 4、Dask 余 6、Pydantic 余 12；其余为 Moto 59、mypy 40、DVC 35、MONAI 26、Modin 5、Pandas 5。这些数字是复核队列，不是已派发任务。

**第二件：先取 3–5 题跑模型全程冒烟。** 从已复核的探针候选里选，先确定下面几项即可，不必先做全池平台：

1. 固定选中题的公开材料、参考测试、环境版本与实际启动入口。Agent 和 grader 都要用到修复后的依赖/资产；只让评分器换镜像不够。
2. 用现有工具确认候选源码确实被测试、补丁投影正确，并保留安装/测试/清理事实。涉及编译的题单独确认产物，不泛化安装退出码。
3. 模型只拿公开材料；审查笔记、gold、隐藏测试与修订答案留在诊断侧。审查 agent 不代替基座求解。
4. GPU 租赁前另核候选模型的真实加载、上下文/KV 开销、工具协议与后续训练兼容性。单卡推理冒烟不等于训练拓扑通过。
5. 使用真实 Claude Code 工作流；比较时任务、权限、工具和预算口径一致，模型各用正确模板。先排除协议/截断/环境故障，再分析解题失败。

冒烟跑通后再扩到约 12–24 题，逐步增加重复采样。先看工具完成率、真实解决/错误接受案例、同题成败混合、每次有效求解的 token/时间及截断，不能用小样本榜单直接定最终基座。题面已给修法的样本保留为较低难度的流程对照，单独标注。

## 哪些题要改，何时改

- **明确环境问题**：沿既有修复配方与证据修；两个 Modin 原材料隔离仍有效，不借本次质量审查宣布修好。
- **合理实现被测试拒绝**：先做可执行反例，再提出新版本的题面/测试修订，并保留原始指标。8801 的本地文案反例还需完整 RH2 对照。
- **错误实现被放过**：先保存失败行为与官方通过的双重证据，再补有针对性的独立行为检查；不把“测试少”本身等同于坏题。
- **只有静态怀疑**：暂作诊断题或待反例，不按审查模型猜测永久淘汰，也不因为某个基座没解出来就改题。

原始题与修订题分别记录；修订可能改变难度与指标，不能把两者得分直接混比。开发探针材料已有反复查看和调试，不冒充独立最终测评集。
