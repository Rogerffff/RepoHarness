# 216 题静态质量复核：查什么，怎样查

2026-09-20 / B Codex · **方法草案；尚未按此扩大派发。** 09-21 已具体化为[首批 12 题计划](quality_batch01_20260921/README.md)，待独立计划审查。本文落实既有 [40 项清单](../environment_screening_checklist_20260915.md)的静态审查部分，沿用[记录与处置约定](../environment_screening_definition_20260915.md)，不另建流水线平台或训练准入规则。

**目标：独立判断一道题的公开要求、可行解答和评分依据是否相符，再核对旧调查；不是替 Claude 的结论逐项背书。** 每题都做基础语义复核，不能只审旧报告标出的异常。允许发现清单外的问题，最后才用清单检查遗漏。

## 1. 上一批做到哪里

上一批按 Conan/Pydantic/Dask 各 8 题分包，审查者同时能取得旧报告、题面、精确 base、私有测试和 gold；核对了关键源码与既有环境证据，并做少量局部反例。它纠正了旧结论，但**没有统一的逐题需求—测试映射，也没有严格隔离、预先保存的公开视角审查**，不称盲审或完整质量验收。13 个探针候选仍是初选名单，先补以下缺项；保留已核实证据，不重做环境维修。

## 2. 每题固定检查八方面

| 方面 / 原清单编号 | 必须回答的问题与具体读法 |
| --- | --- |
| **公开需求**（3、23） | 实际题面、公共提示、base 文档/调用者/公开旧测试说明了什么目标、约束和允许的解法？区分“需查代码才能知道”与“只能读隐藏材料才能知道”。查新 API 名、错误格式、默认行为、题面多目标及冲突；实际渲染未核验则明确记缺项。 |
| **材料与初始问题**（1、2、27） | 题面/base/test_patch/gold/环境版本是否对应？原问题在此 base 的哪条路径成立，还是已修、错版本或无关故障？读对应源码，核对已有 noop 失败位置；没有实际复现的不能只靠 gold 差异断言初态有 bug。 |
| **测试是否测到要求**（18–20、25、32） | 读完 test_patch 新增/修改的断言及其 fixture/helper，逐项追到调用、输入和断言；核对每个 F2P，以及相关 P2P 是否实际参与评分。题面原例、关键分支、默认/非默认值有没有覆盖？是否只测文件/文案、双方相同异常、无操作或硬编码也能过？日志解析不等于测试体已执行。 |
| **是否误拒合理解**（24、28） | 精确字符串、内部 helper 名、Mock 调用形状、执行顺序等要求，在公开材料/已有接口中有无依据？考虑至少一条不同于 gold 的合理实现路线；有具体疑点才设计可执行替代解，不把所有精确断言都判错。 |
| **回归与 gold 完整性**（26、27） | 沿受影响 API 的调用者、数据类型和边界找关键旧行为，确认 P2P 是否保护；gold 是否也漏修原例、破坏旧行为、依赖未交付改动或混入另一需求？gold 是待检查实现，不是唯一答案。不要求全仓穷举，也不把同文件测试数当覆盖证明。 |
| **agent 的开发条件**（6–15） | 公开工作区能否读到必要说明、运行相关复现/公开测试、构建和提交？按准备/解题/安装/测试分开记依赖、资产、网络、权限与资源需求。复用最新维修账本并确认适用版本；grader 已过不代表 actor 条件已验。静态阅读只能提出资源/稳定性疑点，不能宣布已复验。 |
| **交付与评分边界**（4、16–17、21–22、29–31） | 合法修复涉及的文件会不会被投影忽略或官方恢复覆盖？test_patch 是否混入普通源码？题目特有 helper/配置能否改变验收而不修业务？可见资产是否含答案？共享 parser、清理和隔离机制引用现有审查，逐题只核适用性/特例，不重复做整条平台安全审计。 |
| **题目关系与用途**（5、29–30、37–40） | 记录同问题/补丁派生、修复已出现在另一题 base 等具体关系，不能只因同文件就并簇。标注题面给修法、外部答案可达线索、任务类型与审查暴露；不从静态阅读猜基座成功率或学习价值。发现未知新类型单列，不能被八类目录限制。 |

**每题的核心证据是一张小表：**`公开要求/合理回归 → 依据位置 → 对应测试ID及关键断言 → 覆盖/部分/缺失/冲突 → 运行证据或待做实验`。同时反查关键测试要求：它来自哪条公开规格或旧行为？不需要给几千条无关 P2P 逐行写评语，但必须注明实际阅读/抽查范围。

## 3. 给 agent 的材料与顺序

1. **协调者准备两份材料。** 公开包只有实际题面/提示、精确 base 的可见源码/文档/旧测试、工具和权限说明；私有包含 test_patch、gold、参考集、最新配方/运行证据及旧调查。未来 Git 历史、审查笔记和答案不能混进公开包。优先干净 base 导出，缺实际运行消息就标“计划输入”，不冒称已核对渲染。
2. **公开视角先行。** 新上下文 agent 不继承旧讨论，也不接收 Claude 标签或 gold；先读公开包，独立写目标行为、约束、疑义、合理解法范围和可用验证路径，保存后再进行下一步。已读过答案的上下文不能承担这一步；这只是控制审查信息，不能证明模型预训练没见过题。
3. **私有材料调查。** 负责人先按八方面完成需求—测试映射，读关键源码和 gold，追查最新事实；**最后才打开 Claude 和本轮旧记录**，处置遗漏、冲突或过时结论。允许把新的猜想展开到相关代码，不围绕旧 finding 数量交作业。
4. **独立复核。** 另一新上下文复核者先看原材料和决定性证据，再看主审结论。首包所有题的处置建议都复核；后续重点复核改题/拒绝及重要分歧，同时预先抽取普通候选检查漏项。不用多数票或一致同意代替事实；争议列出最小可区分实验。

公共角色只获得公开路径，并记录实际读取范围；若读取了私有材料，应标记暴露并另开公开审查。共享工作区内仅靠提示词不是文件权限隔离，不宣称完成了技术隔离验收。可按仓库复用公开版本知识，不能把另一题的未来修复摘要传给公开审查者。

## 4. 静态结论与实验怎样衔接

- **本轮能做：**材料、公开规格、调用链与断言对照；复读既有日志；设计有理由的正/负对照。缺证据写未知，未检查写未检查，不能把“没有看到问题”改成“所有合法解均接受”。不为凑数每题生成攻击或强制两个新候选。
- **需要 CPU 定点验证：**怀疑误拒，做满足公开要求的非 gold 解；怀疑漏测，做仍违反某条要求的部分/错误解；怀疑回归，对照 base/gold/candidate。分别核题面行为与实际 RH2 得分，才能说明误判。局部函数实验也保留其范围；不重跑无关的 216 题安装/资源实验。
- **需要真实模型：**工具交互能否完成、能力不足还是协议/环境阻塞、成功与失败混合度、token/时间成本，属清单 33–36，静态 reviewer 不代答。求解上下文只用公开材料，审查者写的验证补丁不算独立求解成功。
- **需要修订时：**先说明改变的是环境、公开规格还是测试标准；以原需求/合理旧行为为依据，保存独立版本和触发反例。不能为了保住 gold 放宽标准，也不能把测试要求全抄进题面。新断言同时检查合理替代解与已知错误解；gold 本身有错时允许指出，不要求它强行通过。

## 5. 每题交付与第一包

沿既有 `screening_record.json` 的 `checks / issues / disposition / usage / revision_refs` 记录；上一批异形 JSON 作为证据引用，不另造生产 schema。小表和公开审查产物可引用外部文件。每题给用户看的一张短卡只写：**题目目标；八方面覆盖与未查项；关键映射；具体问题及证据级别；建议处置；唯一最值得先做的下一步**。机器状态与人工判断分开，不粘贴几十条旧 finding。

**建议先用 12 题校准该方法：**从已审 24 题取 6 题（候选和争议各 3），另从尚未新审的 192 题按仓库预先抽 6 题、至少覆盖两个新仓库；选择理由登记，不告诉公开审查者旧标签。已有 24 题补缺项即可，不清零既有有效证据。私有调查每包 3–4 题起步，产物可用后再扩大到 8–12 题；公开视角保持与私有材料隔离，不按题库规模一口气派完。

第一包交付**3–5 道优先基座探针候选及条件、需先做 CPU 反例/修订的题、仍未知项**。候选需有可追溯的公开要求、可解释的参考测试、适用的既有环境证据，且未解决问题不妨碍本次诊断解释；不要求没有任何覆盖限度。进入小批模型探针后仍检查通过补丁，不能靠筛掉所有疑难题得到漂亮分数。

租卡前列清选中题的实际 actor/grader 环境消费、公开材料、模型服务与采样条件；独立 harness→RH2 重放和正式 actor 全链分别标范围。不必先完成 216 题、完整数据平台或证明全无漏洞。这里的候选不自动变成训练题或最终评测题，也不等于前一份定义中的运行条件已验 `ready_for_probe`。

## 6. 外部依据与采用边界

- [专题 01：OpenAI 两类审计、SWE-rebench](../../../../harness_improve/external_paper_references/environment_processing_survey_20260915/01_swe_tasks_and_quality.md)：规格不足/误导、过严与过宽测试分开调查；环境执行成功不能替代题意审查。采用这些问题分类，不照搬多个 judge 必须一致的过滤阈值。
- [专题 02：FrontierCode](../../../../harness_improve/external_paper_references/environment_processing_survey_20260915/02_model_environment_recipes.md)：正确替代解与错误解双向校准。采用有目的对照，不承诺仅静态阅读达到其人工 QC 水平，也不为每题规定大量候选。
- [专题 05–06：构建、反捷径、维护者与协议审计](../../../../harness_improve/external_paper_references/environment_processing_survey_20260915/README.md)：复用环境仍需核当前题；功能正确、可合并性、答案泄漏分开。风格偏好不自动成为 reward 条件，网络能力不一刀切。

以上组织方式是本项目建议，尚未验证其漏检率。旧报告举过的题属于已知案例校准，不能宣称盲测检出率；普通抽查与定向疑难样本分别统计。本轮仅编写方法，未派发新复核、修改正式题目或执行机器任务。
