## 2. 按什么顺序执行

| 顺序 / 负责人 | 动作 | 交付与继续条件 |
| --- | --- | --- |
| S0 · 新任务协调者 | 读本页、交接卡；核对材料清单与当前代码状态，登记实际角色和写入目录。 | 材料缺失明确标记；不让公开角色读私有目录或本页的已知案例提示。 |
| S1 · 统一环境负责人（协调者兼任） | 补齐[解题环境卡](actor_environment_card.md)，区分代码设置、已跑证据、待选配置。 | 逐题 reviewer 共用同一份说明；缺实际 actor 证据不阻塞静态阅读。 |
| S2 · 每题公开读者 | 只读该题公开包和中性任务卡；写需求、疑义、合理解法范围、公开验证路径。 | 先保存 `public_read.md`；不得先看 gold、评分测试或旧结论。不要求解题。 |
| S3 · 仓库私有主审 | 先自行核题面/base/测试/gold/运行原件，按八方面完成需求—断言双向映射；最后才读旧调查。 | 保存 `analysis_before_history.md` 后再写 `old_findings_delta.md`，防止只核旧 finding。 |
| S4 · 独立 reviewer | 新上下文先读原件，保存独立初判，再看 S2/S3 结论；首批 **12 题全部复核**。 | 核关键断言、每个 F2P、有关 P2P/缺口、开发需求及处置。分歧用证据或最小实验解决，不按票数。 |
| S5 · 协调者 | 合并短卡、记录覆盖/分歧；形成候选与验证队列，报告本批结果。 | 给出 **目标 3–5 道**优先模型探针候选及条件；不足就如实报告，不凑数。第一波即交接已有候选的 CPU 清单，不等 12 题全部收口。 |

**分两波派发：**先 Conan/Dask 两包共 4 题，检查产物是否真的读了源码、断言和开发需求；协调者只校正文档方法与遗漏，再按相同标准执行另 8 题。不因第一波标签调整第二波名单。一个新协调任务即可管理五包；可同时跑不同题的公开阅读、私有调查和复核，必须遵守同题依赖。并发按工具实际容量，勿为凑线程数绕过顺序。

第一波完成后立即交接已成熟单题的最小 CPU 验证条件；取得对应运行授权与机器后，可与余八题审查并行。3–5 是目标数量，不是必须凑齐才能开始单题探针的门槛。

## 3. 开发条件如何检查

| 层次 | 谁做、具体检查 | 允许的结论 |
| --- | --- | --- |
| 共用环境事实 | 协调者核真实入口、镜像/配方身份、解释器、UID、可写路径、资产、四段网络、资源、公开材料；引用原件。 | 当前设置/已有运行证明了什么；不能把 grader 成功写成 actor 已验。 |
| 每题静态需求 | 读公开复现、base 代码、文档/旧测试，逐项填“需要什么 → 公开依据 → 环境证据适用性 → 缺口 → 最小命令”。 | 需求已知、代码配置支持、运行已验、未知、不适用分别写。无需每人重读整套 RH2。 |
| 选中题 CPU 验证 | 后续在实际解题准备路径下，以 **agent/54321** 验解释器/源码导入、复现、窄公开测试、写入/构建与资产读取。 | 指定条件下开发操作可行；原 bug 导致的失败是预期现象，须与依赖/权限错误分开。 |

隐藏验收测试不必提供给解题者，也不要求 agent 能跑全仓测试。没有运行证据时写“待验”。`public_hints` 区分题目需求、harness 指令与待验环境声明：旧“conda 已激活”和“所有测试修改永不计分”不能当当前运行事实。原指令是否继续采用另行明确，不由审查者静默取消。bundle 在解题容器可见；不在渲染消息中不等于不可见。详见 v2 中性说明。

## 4. 每题查到什么程度、交什么

每题都覆盖八方面：**公开需求、材料/初始行为、测试覆盖、误拒合理解、回归/gold、开发条件、交付/评分边界、关系与用途**。读完新增/修改断言及决定性 helper，逐个解释 F2P；P2P 按受影响行为选读并列出范围，不能按条数宣称完整覆盖。新增功能题核初态是否缺所需能力，不强套“已有功能出 bug”。先自由调查，再以八方面检查遗漏。

按[角色任务卡](coordinator_handoff.md)执行；每题交一张短卡、需求—断言表、开发需求表、沿既有约定的 `screening_record.json`，原始调查与 reviewer 意见另存。引用精确文件/行或测试 ID；引用运行须有本地账本位置和角色、版本、条件。缺项保留未知，未跑命令标“建议”，别用 parser 状态代替执行证明。

首批同时列三张清单：①静态候选及 actor/评分待补条件；②需 CPU 替代解、错误解、回归或开发条件对照；③需讨论的题面/测试修订。**先修环境还是改题，以缺陷证据决定；不自动把隐藏要求补进题面，不把 gold 当唯一正确解。** 语义修订另存父版本与反例，未经该项授权不改原题或 reward。原始/修订分数、特权诊断补丁/独立模型解答分开。

## 5. 何时可以准备租卡

不用等 216 题或本批 12 题全审完。已有成熟单题就可先交接，用 CPU 补齐实际 actor 配方消费、候选代码生效和必要公开验证操作；已有完全适用的证据可复用。之后另定模型/服务、Claude Code 版本、预算和解题入口，再租单卡做能力探针，逐步组成 3–5 题。若选独立 harness→RH2 重放，明确其范围；不能称正式 actor 全链验收。

本批用于**开发诊断**，不作为未接触的最终留出评测；静态清晰不预测基座成功率。少量模型探针用于早发现协议/环境/能力问题，不作可靠的跨模型排名或最终基座定案。
