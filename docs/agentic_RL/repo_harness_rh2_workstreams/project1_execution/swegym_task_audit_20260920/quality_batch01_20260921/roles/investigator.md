# 私有调查角色卡（同仓 2–3 题）

协调者填写 `TASKS`、每题 `PUBLIC_DIR / PRIVATE_DIR / OUTPUT_DIR`、公开阅读产物位置。新上下文；不要读主计划中的选择理由或旧总结。共用方法只读[八方面协议](../../quality_review_protocol_20260920.md)、[环境卡](../actor_environment_card.md)与[记录模板](../record_template.md)，先不读历史调查。

**对每题独立完成以下顺序，再进行下一题；可复用版本知识，不能把前题结论当后题证据。**

1. 核 `public_bundle.json` 的精确 base 和当前公开提示；先读公开源码和 S2 产物，明确它尚未捕获的真实消息/容器条件。`private/` 的 grading、test patch、validation、gold 都是特权材料，只在此阶段使用。
2. 展开每个新增/修改测试：调用路径、输入、fixture、helper、Mock 和最终断言。逐个 F2P 解释实际测什么、依据来自哪条公开要求；P2P 追受影响接口和边界，注明读到和没读到的范围。大 P2P 列表不必逐条写评语，但不能只看 test patch 就判断“无回归”。
3. 形成双向映射：公开要求/合理旧行为 → 测试及覆盖程度；关键验收约束 → 公开依据/缺失/冲突。考虑一种不同于 gold 的合理路线，以及一种可能蒙混的部分实现；**有疑点才提出可区分反例，不强制写两份补丁**。
4. gold 也按公开要求检查：原例是否修到、依赖是否交付、有无未测回归或无关改动；判定理由不能只写“与 gold 不同”。结合真实运行原件核初态、参考命中/缺席、安装和退出情况，区分源码推断、解析状态和执行证据。需要原始日志而未读到时记缺项。
5. 根据共享环境卡填写逐题开发需求；必要导入、依赖、资产、权限/可写位置、网络阶段、编译、提交文件分别查适用性。grader 记录只证明其条件；actor 待验就写待验。题目特有投影/官方恢复、泄漏和评分控制面另列，不重复平台总审计。
6. 先保存 `analysis_before_history.md`：八方面覆盖、核心映射、缺口和暂定处置。**之后**协调者才提供本题历史引用，写 `old_findings_delta.md`：确认、推翻、过时、未核实，各引用新的决定性证据。不得为了覆盖旧结论放弃新发现。
7. 输出 `card.md` 与 `screening_record.json`，按 record_template.md。历史环节有改变时保留前稿与改变理由，不回写原件。不凭旧标签给当前版本 pass/reject。

**零 P2P 的具体处理：**本批 mypy-10424、mypy-16963 各为 F2P=1/P2P=0。沿公开调用者、现有测试及旧行为核回归范围，并检查 F2P 内是否已有正负/多行为断言。没有 P2P 既不表示回归已通过，也不自动证明坏题；有具体未保护行为才提窄回归反例。这条信息仅给私有角色，不向公开读者预告。

仅静态读材料/已有证据；新反例、环境验证和修订写入建议队列。不要运行项目代码、修改共享镜像克隆、改生产/原题/原测试/参考或执行付费模型。需要跨题关系只引用具体 commit/补丁/需求，不能按同文件自动聚类。

没有查看完整或关键原件时，不以“无问题”收口；用未知与唯一最值得做的下一实验。每题报告尽量短，详细证据另附。调查草稿与 reviewer 的独立初判都是本题暴露记录，未来 solver 不得收到。
