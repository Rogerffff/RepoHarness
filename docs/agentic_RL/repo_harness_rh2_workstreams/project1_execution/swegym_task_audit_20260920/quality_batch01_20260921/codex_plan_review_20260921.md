## 1. 已经做对的部分

- 公开读者先独立理解需求，私有主审完成八方面调查后才看旧结论，reviewer 先形成独立初判。这满足“完整调查，再对照 Claude”的要求。
- 核心产物是公开需求与测试断言的双向对应，并检查合理替代解、错误解和 gold 自身；不以模型投票或 gold 一致性代替正确性。
- 评分环境证据与实际解题环境分开；缺失项进入针对性的 CPU 验证，静态审查不能代替模型运行。
- 六道已知案例与六道固定抽样分别报告，首批只用于开发诊断。3–5 道小探针有助于发现运行问题，不能据此最终选择基座或推算全池质量。

## 2. 派发前补清：旧公开指引不能直接当成当前环境事实

**事实与影响。** 12 题的 `public_bundle.json` 使用同一份 `public_hints`，含“conda 已激活”和“禁止改测试，因为所有测试改动都会被评分恢复”。[公开角色卡](roles/public_reader.md)第 5 行要求阅读该字段，但[中性说明生成处](prepare_materials.py)第 118 行起只提醒它不一定进入 system message，未说明这些内容的适用性。如果审查者据此推断开发操作可用，或将涉及测试类文件的任务判为题目不可用，就会混淆任务要求、harness 指令与实际机制。

当前代码给出了更窄的事实：

- `bundles.py:render_user_prompt` 只渲染 issue；`generate.py:_materialize_rollout_sandbox` 仍把完整 public bundle 写到 `/rh2/public_task_bundle.json`。**没有进入用户消息，不等于解题者不可见**；本轮没有捕获实际 CC 请求。
- `prepared_task_face.py:build_grading_spec_from_host_view` 的 `hygiene.test_globs=()`，官方恢复范围由 `test_patch` 触碰路径生成。“所有测试修改永不计入”的机制说明已不准确；是否保留禁止改测试的解题指令是另一件事，不能只凭代码替用户决定。
- 共享环境卡已指出 conda 激活需要实际 actor 验证，不能同时把旧 hints 的承诺当成已验证事实。

**最小修订。** 在公开角色卡及中性环境说明中补充：题目需求、harness 操作指令、待验环境声明分别记录。遇到旧提示与机制不一致，登记为共享输入/运行条件问题；分别说明在该指令适用和不适用时的影响，不直接归因于原题缺陷，也不静默忽略指令。保留原 bundle；如改材料包说明，按既有版本约定保存新说明并更新引用。实际消息和工具环境留给选中题的 CPU/CLI 检查。

**核销方式。** 派发卡明确上述分类；公开结果不能仅引用旧 hints 宣布激活成功或测试文件一律无法交付。不需要等待实际 CC 请求捕获才开始静态审查。复核锚点为上述三个函数和任一题公开包的 `public_hints`，12 题该字段已核对相同。

## 3. 执行时的三个小调整

1. **第一波就交接 CPU 清单。** [计划 S5](README.md)第 28 行目前写“CPU 清单到此才按收益排序”，容易让整个 12 题审完成为等待条件。建议四题完成后立即交付已有候选及最小待验项；后八题继续审。获得执行授权的 CPU 工作可与它们并行，已有证据充分的题不等待另一题的争议。3–5 是目标数量，不是必须凑齐才能开始单题运行的门槛。
2. **把零 P2P 的回归范围写实。** `mypy-10424`、`mypy-16963` 的参考集各为 F2P=1、P2P=0。主审应追受影响的公开调用者、测试与旧行为，说明评分实际保护了什么、遗漏了什么；有具体疑点再安排窄回归对照。零 P2P 既不是“回归已通过”，也不自动证明坏题；F2P 内部也可能包含多个行为断言。此项只给私有审查者，不向公开读者预告结论。
3. **更正交接卡路径。** [交接卡第 4 步](coordinator_handoff.md)第 20 行写的是 `history_refs.json`，实际文件为 `runs/swegym_quality_batch01_20260921/history/<id>/refs.json`，由 manifest 的 `history_refs` 字段定位。按实际字段交接即可。

建议顺序：**补清公开说明 → 四题独立审查与复核 → 候选 CPU 验证 / 余八题审查并行 → 小批真实模型解题。** 每道题都检查八方面，但已完成的静态检查、仍待运行的检查须分开。正式模型测试继续使用干净求解上下文；审查笔记和诊断补丁不进入其输入。
