## 阶段二（核对）

1. **评分有效**：`reward=0.0`、`RESOLVED_PARTIAL`、解析 17 项无缺失，`RH2_INSTALL_RC=0`；评分容器 `git status` 显示 `models.py` 已改。同一镜像 `9f94e614…` 的 P0 对照为 noop 0 / gold 1。
2. **失败项（重点 ③）**：`tests/test_events/test_event_pattern.py::test_event_pattern_with_exists_event_filter`，第 27 行 `assert not foo_exists.matches_event({"detail": {}})` → `AssertionError: assert not True`。测试补丁新增的 null 断言（第 26 行）已通过；失败的是 base 上就有的公开断言，模型读过 3 次、看它失败 9 次。另一个 F2P（Logs 集成）通过。
3. **成因**：gold 用 `UNDEFINED = object()` 作 `event.get(k, UNDEFINED)` 的缺省，再判 `item is not UNDEFINED`；候选只放宽了判断，没有区分缺键。本地重写三函数对照：候选与 gold 只在"缺键"一列不同，`exists:true` 得 True、`exists:false` 得 False，两个方向都反了。要求可由公开仓库既有断言直接推出，**不是参考测试误拒**，属能力失败。
4. **参考测试未覆盖的额外破坏**：`models.py:1441-1442` 给每个 archive 规则追加 `"replay-name": [{"exists": False}]`；候选下普通事件永不匹配 archive 规则（本地对照得 False）。actor 侧 7 个失败 = 1 个 exists + 3 个 archive / replay（候选引入）+ 3 个 SQS（基线既有）。依据：同环境下 DeepSeek a1 的正确修复只剩 3 个 SQS 失败，且其 stash 对照在 base 上同样失败。"P2P 无失败"低估了这份补丁的破坏面。
5. **测试文件处置**：候选未碰官方测试文件。4 个根目录 `test_*.py` 记入 `candidate_test_like_paths`，`classification=projectable`、`ignored_paths=[]`，12 个路径全部投影进评分容器；评分命令只跑两个官方文件（collected 17），临时脚本未被收集，不影响判分。
6. **环境差异（重点 ④）**：失败的 F2P 不经过 boto3，两侧报错逐字相同，结论不受影响。版本差只在过程里添了噪声：3 个 SQS 既有失败与 3 个真实回归混在同一次输出里，被模型一并当作无关。但它此前（#89）已决定带着已知失败交付，噪声不是失败原因。"同一候选在 1.35.9 下也得 0"由 actor 侧同一断言失败直接支持。
7. **题卡风险**：review.md:16 与 analysis_before_history.md:46 静态预言"只去掉 None 判断会违反旧缺键断言"，并注明没运行过这类候选；本轨迹是第一个实际执行的实例，预言成立。public_read.md:38 登记的 `NoRegionError` 也出现了。
