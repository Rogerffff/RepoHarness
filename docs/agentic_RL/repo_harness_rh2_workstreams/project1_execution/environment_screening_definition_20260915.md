# 环境筛查的最小记录与处置约定

2026-09-15 · Codex / B 线。**设计补充，汇总脚本尚未实现；正式题池与筛选阈值未在本稿批准。** 回应 [Claude 的 S1–S9](environment_screening_checklist_claude_review_20260915.md)，与[40 项清单](environment_screening_checklist_20260915.md)、[试运行安排](environment_screening_pilot_20260915.md)配合。本页定义运行后如何留下可聚合记录，不新增训练运行期闸门、公共契约或权限规则。

## 1. 三类记录，复用现有运行产物

| 记录 | 第一版保存什么、由谁写 |
| --- | --- |
| 已有 driver 账本、sidecar、日志和冻结工件 | 保留原件。运行引用用 **账本相对路径＋行号**，附 `run_id/task_id/attempt/candidate` 辅助核对；`run_id` 是批次标记，不能单独唯一定位一次评分。 |
| `facts.json`：每题/代码变体的机器汇总，拟新增 | 小型只读汇总器消费上述产物与指定版本的来源参考、静态预检；写来源引用、实际条件、逐测试对照、异常线索、缺项。只归纳，不重跑、不改原账本、不裁定 reward 或题目去留。 |
| `screening_record.json`：每题审查记录，拟新增 | 负责人记录题目/来源版本、配方与代码快照引用、`facts_ref`、检查结论、问题、B 文件规则、修订关系、处置建议及复核者；复核者核验关键证据。报告正文仍集中在工作包 MD。 |

题级记录采用普通 JSON，字段约定如下；**不增加生产必填字段或每次 rollout 的 LLM 审查**：

```text
task_id, task_revision, source_adapter_ref, recipe_ref, code_snapshot_ref
facts_ref
checks: {检查编号: {status, evidence_refs, by}}    # 稀疏记录，未列项 = not_checked
issues: [{category, scope, evidence_refs, proposed_action, status}]
file_rules: {additional_exclusions: [], rationale, evidence_refs, applied_version}
revision_refs: [{type, parent, changes_ref, reason, verification_refs, reviewer}]
disposition: {state, scope, reason, evidence_refs, reviewer}
usage: {intended_use, exposure_notes}             # 用途与质量状态分开
costs: {container_wall_seconds, agent_tokens, human_decisions, source_refs}
```

`checks.status` 为 `not_checked / pass / issue / unknown / not_applicable`，不适用写理由。事实字段保留 `observed / missing / not_applicable` 及来源；缺失不填 0，未报错不自动填 pass。模型和调用成本可获取时记录，无法获取时为 null。原始 parser 项数、测试实际执行、参考缺席后的判分是不同事实，例如 `ERROR tests/test_x.py` 摘要不证明测试体执行过。

机器汇总也要注明来源可信度：宿主侧观测、候选侧输出、parser 推导或静态分析。候选输出的导入路径/版本、运行器检查字符串是观测线索，不能自动变成不可伪造的证明。汇总器不要求每题所有指标均可观测才允许调查。

## 2. 配方与来源适配各引用一份记录

每个来源保留一张短卡：**输入字段与初态、agent 可见/私有材料、真实入口、测试选择/收集方法、parser 与版本、评分规则及计数、提交/可信测试恢复方式、已知限制和代表对照**。SWE 的 F2P/P2P 与 R2E 精确映射分开；这具体化原清单的来源级检查，不额外造一层运行服务。

每个仓库/适用版本的 `recipe_ref` 指向可重建的配方记录：来源安装/测试命令引用、任务特例、资产清单与来源/实际镜像 ID、锁文件或安装清单、实际用户/路径、四段网络、资源与期限。已有 ingest、锁文件、manifest 能表达的内容直接引用，不复制成第二份权威脚本，也不为本流程再发明一个 policy digest。

配方变更保存新版本，题级记录引用确切版本。依 `source_adapter_ref / recipe_ref / code_snapshot_ref / applied_version` 可枚举受影响题；任务特例另有引用。`pip freeze` 可作为相应环境的安装快照，不能替代系统依赖、锁文件或候选安装生效证明，不要求每题重复导出同一份快照。

## 3. 先汇总线索，再调查；不由触发表直接淘汰

**当前输出缺口：**本轮核查 `manager._diagnostics` / `ReplayGrader._fill_from_report`，sidecar 有计数、reference missing/skipped、阶段和观测，但未保存完整逐 ID 状态表；P-B 新观测也须等实际落地。首版汇总器需用记录对应的来源/parser 版本离线解析保存的日志，注明推导来源；缺日志、版本不明或没有收集证据就标缺失。日志解析出的状态不冒称实际测试体执行事件，已有汇总计数也不能反推缺失明细。

| 线索（来源字段或原件） | 调查内容及限制 |
| --- | --- |
| gold 未满足该来源预期，或 no-op 已完成目标/没有有效测试证据 | 查初态、准备、选择器、parser 与参考解。SWE 看规定 F2P/P2P 的含义；R2E 看完整 expected/observed 映射，包括额外键，不能套同一个 F2P 集合相等条件。 |
| `reference_missing`、skip、额外 ID、收集错误 | 查原始日志、收集与实际执行，按来源解释状态；mypy 等不是普通 pytest 文件选择。可利用来源已有 JUnit/CTRF，不为全部任务强行替换 runner/parser。 |
| 安装非零、安装产物无法对应候选，尤其 `install_rc != 0` 同时 resolved | 查完整安装步骤、导入/编译产物及候选因果关系。最后命令的 RC 不等于全部安装结果；`.dirty` 只对特定构建有意义，合法安装也可能位于 site-packages。 |
| 运行器变化、候选触碰 conftest/插件、投影影响合理解答 | 查第四组 B，区分纯观测与实际规则。official 之外的忽略可能是已批保留命名空间，先读分类依据，不自动报作弊或新增排除。 |
| 相同版本/条件重复后状态改变，或出现资源/服务异常 | 查 flaky、资源、重置、网络。初态脏文件先存基线，不能盲目清空。只比较条件可比的重复，原因未定时保留未知。 |
| 权重/wheel/缓存/镜像层可能带入目标库修复或答案 | 查实际包来源与代码、安装解析及可见性。仅发现缓存或版本号较新不足以确认泄漏；补资产时同步检查候选是否仍是执行目标。 |
| 通过候选在有依据的扩展回归中失败；轨迹有下载/取答案线索 | base/gold/candidate 对照，检查具体内容与访问条件；保留正常成功。测试选择记录具体 ID/命令和需求/调用关系理由，不机械限定同目录。 |
| 同 PR/补丁派生、`test_patch` 混入源码、实际输入遗漏 | 查重复关系、评分材料职责与公开信息；按具体任务修订，不能只靠文件名或相似度标签裁定。 |

**全体试点题保留简短的公开需求与题意—测试—gold 对照。** 自动触发决定深查方向，独立全文复核、替代解/错误解、较宽回归按风险和随机样本投入；纯执行异常无法筛出所有欠明确或弱测试题。新鲜盲解不是每题准入的先决条件。

## 4. 试点处置：说清证据范围，暂不定正式训练过滤阈值

| 状态 | 试点层的依据和动作 |
| --- | --- |
| `ready_for_probe` 可进入能力探针 | 实际材料/公开输入和开发侧基本条件已核对；真实 no-op/gold 的文件、逐测试与来源结果可解释；有题意/测试简查及 B 规则记录，未解决问题不影响当前可用性结论。注明 `scope`：仅评分/开发条件已验，还是完整 harness 也已探测；不等于通过全部 40 项或批准训练使用。 |
| `needs_repair` 修复待验 | 已有可复现的环境/接线/材料缺陷，记录修复与影响范围；保留原结果，新变体另验。 |
| `needs_review` 待核 | 语义分歧、重复波动或关键证据不足；说明下一实验。暂缓该题在本批的接受结论，不触发训练运行期 DROP_GROUP。 |
| `unsupported_conditions` 当前条件不支持 | 明确需要目前没有的资源、服务或能力；不宣称题目本身无效。 |
| `reject_revision` 不接受该版本 | 充分证据说明当前版本材料不可恢复地错配、目标已成立或任务自相矛盾等；记录依据和复核。暂时安装失败不直接进入此类。 |

**重复次数建议：**先各跑一次 no-op/gold 定位明显问题，拟接受的试点题再各确认一次；已有完全同条件记录可计入。此处 ×2 只是试点执行建议，×3 也不是评测有效性的保证；正式次数/稳定率待成本和故障分布校准。确定故障无需重复凑数。flaky 先诊断，不重试到绿、不静默删 P2P；查明无效断言后才讨论带版本的测试修订。

`usage.intended_use` 可为未分配、训练候选、开发、保留评测候选，**与上述状态正交**。技术资格审计、修题和按模型表现调参分别记录暴露历史。用于选择模型、prompt、配方或针对性策略的题不能再声称未接触留出；修订过的任务可成为明确标注版本的自建评测，不能冒充原 benchmark。是否仓库分离取决于测哪种泛化，当前不追加统一要求。

## 5. 默认条件与参考版本

- **评分参考**沿当前来源和已批 RH2 规则：SWE-Gym 原 F2P/P2P、R2E 原 expected 精确映射。诊断发现不会自动改写 reward 参考，也不默认生成一套新 expected。
- **修订分三类**：环境/资产修复且参考不变；有证据、无碰撞且语义不变的 ID 映射；改变题面、测试或预期状态的任务修订。保存原版、父版本、差异、理由、复验与复核者；涉及尚未批准的题意/评分语义时交用户决定。修订后的任务与旧任务分别计数、评分。
- **准备阶段**按已批环境准备方式联网获取固定资产；候选代码仍按既有非 root 边界执行。外部构建代码放隔离构建环境，不将“准备联网”泛化为在宿主 root 执行任意候选代码。
- **agent 解题**沿真实 rollout profile，模型代理和已经批准的内网服务按实测配置记录；不默认新增包源访问。**候选安装/构建与测试**沿现有 grader 非 root、deny_all 和预置资产。服务桩也需先核对语义，不能默认给所有外部服务换 mock。来源生成参考时的网络/依赖条件另记。
- **新盲解**记录实际 CC、代理、身份、网络、Git/材料隔离与预算，先验证模型端点及工具闭环。若另用 runner，应明确已验证的等价范围；未证明时只算该条件下的调查材料。旧 24 条 DeepSeek 轨迹仍可查补丁/题意，不能混入新受限条件的独立能力成绩。目标基座需要对应模型的真实推理服务，不要求先接完整 GPU 训练链；DeepSeek 不能代替 Qwen 的能力测量。

## 6. 汇总什么、先实施什么

试点统计只做五组：**关键字段可观测率和缺项；调查触发数/原因；已知反例复现与发现数；独立复核分歧/裁定；成本与耗时。** 每项带分母；并行容器 wall time 不等于付费机器时间。拿不到 agent token 不估成 0。

已知反例校准与随机抽查分开统计。worker 若拿到含案例答案的清单，就称“已知反例回归”，不称盲测检出率。要测盲检，另给干净上下文和不带问题标签的材料。小样本报告发现数，不据此宣称全库漏检率/误杀率；不同模型复核有益但不强制品牌不同，独立证据与裁定更重要。

B 线负责收集后续求解/RL run 的评分异常、状态漂移、疑似漏洞与未测回归，形成下一批复审候选；持续全失败、罕见成功都可作调查线索，**不是自动隔离条件**。低成功组里出现一次高 reward 本来可能是有效学习信号；不把它直接称为错误评分。成功、失败和随机正常项共同抽查。

**下一实施片建议只有一个小工具：**只读汇总 driver 账本、sidecar、工件索引及指定参考版本，生成 `facts.json` 与来源对账摘要；直接复用同一次解析的数据，不另写一个与之重复的 `reconcile` 系统。尚未实现时第一题可人工按相同形状试填并标 manual，随后补脚本再扩工作包。

验收用已有正常评分、零/部分解析、取消、missing reference、非零安装与旧/新变体样例：正确关联运行，保留原值与未知，不混配方，不伪造逐测试事实，不修改 reward/原件；脚本重跑不覆盖人工审查记录。无需租新机器或先跑全池。P-B、P-A 等实际代码状态按第四组与接线最新记录核对；P-C 可暂缓，R2E 等自身真实适配，不要求全部 P-A/C/D 完成才能读取 e1、整理事实或做有限诊断。
