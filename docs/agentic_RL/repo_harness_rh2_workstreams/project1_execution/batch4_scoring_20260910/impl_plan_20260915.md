## 1. 代码事实（2026-09-15 核对）

### 1.1 契约与消费者（P-A 的改动面）

- [contracts/grading.py](../../../../../rh2/src/repoharness2/contracts/grading.py)：`GradingFailureCategory` 五值（`infra_failure`、`test_log_parse_failed`、`patch_apply_failed`、`tests_failed`、`test_execution_timeout`）；校验器要求 `unresolved` 归因必须是后三者之一；`resolved`/`tests_failed` 四计数齐全；`patch_apply_failed`/`test_execution_timeout` 四计数必须为 None；infra 族 reward 必须 None；`reward_scale_version="binary_v1"`。
- 产出方：`envpack/scoring.grading_outcome_fields`（只按 verdict 翻三种）；`grading/manager.py` 在 apply 失败分支直接构造 `patch_apply_failed`，零解析分支抛 `GradingInfraError(category="test_log_parse_failed")`（I5 后 verdict 已存 `record.parsed_verdict`）。
- 消费者：`governance/gate.py` 维度 6 `clean_grading`（`failed_to_grade` 失败；模型负样本通过）；`contracts/outcome_crosswalk.py` 的 `FAILURE_CATEGORIES_EXECUTION_FACT`（v1 `failure_category` 不在集合内 → 视为准入/控制面材料，`legacy_unmappable`）；`adapters/miles/group_admission.py` 只核对 reward 与 `grading_reward` 一致；`adapters/slime/generate.py` 的 outcome producer 用 `task_resolved`。新增类别必须同时进 `FAILURE_CATEGORIES_EXECUTION_FACT` 与 gate 的"模型负样本通过"集合，否则会被当准入材料或降级。
- R2E 方案 A（用户已选）：同一次契约升级加 `grading_semantics: Literal["swe_f2p_p2p", "r2e_expected_map"] = "swe_f2p_p2p"` 与 `expected_match_count / expected_total_count: int | None = None`；`r2e_expected_map` 下四个 F2P/P2P 计数为 None、两个 expected 计数齐全。新字段全部带默认值，旧报告反序列化不变；`digest()` 若覆盖报告字段需在 Brief 里核对。

### 1.2 I08 默认通配（P-B 的改动面）

- 定义：[manager.py:552](../../../../../rh2/src/repoharness2/grading/manager.py#L552) `DEFAULT_SWE_TEST_GLOBS = ("*tests/*", "*testing/*", "test_*.py", "*/test_*.py", "*_test.py", "*/*_test.py")`；由 `grading/__init__.py` 导出。
- 注入点两处：v1 `build_swe_grading_spec`（manager.py:647）与 v2 actor/driver 共用的 `prepared_task_face.build_grading_spec_from_host_view`（prepared_task_face.py:315）。
- 语义：`classify_control_plane_path` 先精确 official 文件，再 glob，再保留命名空间；命中即"控制面、不重放"。S1-p 预检显示 24 条 DeepSeek 候选里 6 条只因 glob 被忽略路径（如 `pandas/tests/series/indexing/test_setitem.py`、`modin/numpy/test/test_array_math.py`），A 线 §7.3 指出移除后候选对 `tests/conftest.py`、autouse fixture、tests 目录插件的修改会完整重放并生效——这是与 D3 运行器通道不同的另一条影响判分的路径，`test_patch` 通常不含这些文件，恢复步骤盖不住。
- 现有测试：`tests/adapters/test_w3a_trusted_projection.py` 用 `DEFAULT_SWE_TEST_GLOBS` 断言 `tests/test_new.py`、`pkg/tests/helpers.py`、`test_root.py`、`pkg/mod_test.py` 归 `test_glob`（机制测试，规则显式传入，可保留但要改成显式常量而非 SWE 默认）；fixture 的 `FIXTURE_HYGIENE.test_globs=("tests/*",)` 是 fixture 自己的规则，不受影响；`test_b5_finalization`、`test_w1b_delivery_face` 用 `HygieneRules` 替换 spec，需核对是否依赖默认 glob。

### 1.3 baseline 政策（P-C 的改动面）

- [contracts/baseline_manifest.py](../../../../../rh2/src/repoharness2/contracts/baseline_manifest.py)：`BaselineManifestPolicy(policy_version, excluded_namespaces)`，v1 = `(".git/", ".harness/")`，语义是**根锚定目录前缀**；`compute_policy_digest` 进 manifest 身份。
- census（`adapters/slime/baseline_census.build_census_script`）：`find . -path './ns' -prune -o …`；排除区另做独立 census（`EXCL` 行）→ `excluded_census_digest` → 导出时 `excluded_pathset_changed = post.excluded_census_digest != baseline.excluded_census_digest`。
- 同一政策对象在四处生效：rollout 基线 census、导出 post census、grader `_verify_baseline_rebuild` 的重建 census（从 `baseline.policy` 取）、`classify_frozen_patch`（排除命名空间内出现 entry → unsafe）。因此新规则只要写进政策对象并让 census 脚本消费，四处自动一致；风险在脚本里 `find` 表达式与 Python 侧判断（分类器）必须逐字同语义。
- `__pycache__/`、`.pytest_cache/`、`*.pyc` 是**嵌套**模式，v1 的根前缀表达不了；且它们每次执行都会变化，若并入 `excluded_census_digest` 会让 `excluded_pathset_changed` 几乎恒为真、失去审计意义。

### 1.4 文件变目录（P-D 的改动面）

- [contracts/frozen_patch.py:96–130](../../../../../rh2/src/repoharness2/contracts/frozen_patch.py#L96)：`FrozenPatchArtifactV1._check` 对 entries 做父子前缀冲突校验（任一路径是另一路径的祖先即拒），不看 operation，所以"delete `config` + add `config/default.json`"在构造时被拒（README §5 已对照）。
- 应用侧已具备条件：`_apply_frozen_delta` 两遍应用（先全部 delete 再写入），`build_delta_write_command` 写入前 `rm -f` 旧对象并建父目录；baseline 中祖先是 symlink 的路径被拒绝跟随写出（Falsifier F6）。
- `classify_frozen_patch(artifact, baseline)` 持有 baseline，可在那里核"被删祖先在基线中是 regular"；`split_trusted_scoring_projection` 无路径结构假设。

## 2. 各片的改动、验收与测试

### P-B · 移除默认通配，测试样路径改为观测

改动：
1. `prepared_task_face.build_grading_spec_from_host_view` 与 `manager.build_swe_grading_spec`：`test_globs=()`；`DEFAULT_SWE_TEST_GLOBS` 保留但改名为 `TEST_LIKE_OBSERVATION_GLOBS`（或保留旧名并加注释"仅观测"），不再注入 hygiene。
2. 观测出口：manager `_diagnostics` 增加 `candidate_test_like_paths`（frozen delta 投影内路径与观测 glob 的命中列表）与 `candidate_touched_conftest_or_fixture`（`conftest.py`、`*/fixtures/*`、`pytest.ini`、`tox.ini`、`setup.cfg`、`pyproject.toml` 命中）。只进 sidecar 与 driver 账本，不改判定、不剔除。
3. S1-p 预检脚本按新规则重跑，`precheck.md` 更新（"忽略路径"只剩 official 精确文件与保留命名空间）。
4. 旧 oracle：`test_w3a_trusted_projection.py` 改用显式的机制用常量；新增测试断言两个 SWE spec 构造入口的 `hygiene.test_globs == ()`，且 `pandas/_testing/_io.py`、`pkg/tests/helper.py` 在 SWE 规则下归候选、`tests/test_official.py` 仍是 `official_test_file`。

验收：单测；`precheck.md` 重跑；e2 对账账本统计触碰 conftest/fixture 的候选数（A 线 §7.3 要求）。仍如实保留的边界：`test_files` 来自 `test_patch` 全部触碰路径，混入的正常源码仍会被恢复覆盖（README §6.5 已登记，流水线检查）。

### P-C · baseline 政策 v2（可再生缓存省略）

改动：
1. `BaselineManifestPolicy` 加 `regenerable_cache_patterns: tuple[str, ...] = ()`，语义分两类：`excluded_namespaces`（运行时私有，独立 census 记 digest，进 `excluded_pathset_changed`）与 `regenerable_cache_patterns`（可再生非答案缓存，**只省略并计数**，不进 digest）。`BASELINE_MANIFEST_POLICY_V2 = (version="baseline_policy_v2", excluded_namespaces=v1, regenerable_cache_patterns=("__pycache__/", ".pytest_cache/", "*.pyc"))`；v1 对象保留供旧证据。
2. census 脚本：目录模式 `-name __pycache__ -prune -o -name .pytest_cache -prune -o`，文件模式 `! -name '*.pyc'`；另输出 `CACHE_OMITTED=<n>` 计数行，`parse_census_output` 读入 `omitted_cache_count`（manifest 新字段，带默认 0）。
3. `classify_frozen_patch`：排除命名空间判定不变；对 cache 模式命中的 entry（理论上不会出现，因为 census 已省略）视为契约矛盾（producer/grader 政策不一致）而非 unsafe。
4. 生效点：rollout 基线 census 与 driver 的 `generate_baseline_manifest` 默认政策切到 v2；grader 重建 census 沿用 `baseline.policy`（自动一致）。
5. 不排除：`build/`、`dist/`、`*.egg-info`、`.so`——编译型仓库（pandas、mypy 的 mypyc）这些是解答产物或安装产物；不按 `.gitignore`。

验收：单测（政策 digest 变化、v1/v2 互不影响、census 表达式与 Python 分类同语义）；fixture Docker 往返：基线后在工作区生成 `__pycache__/x.pyc` 与 `.pytest_cache/`，导出 entries 为空、`excluded_pathset_changed=False`、评分 resolved；e2 账本记录每题 `omitted_cache_count`。

### P-D · 删普通祖先文件 + 增子文件

改动：
1. `FrozenPatchArtifactV1._check`：允许祖先路径 `p` 的 entry 为 `operation="delete"` 且 `object_type="regular"`，其全部后代 entry 为 `add`；其余父子冲突（祖先 add/modify、祖先是 symlink、后代含 delete、目录反向变文件）仍拒。
2. `classify_frozen_patch`：对这类祖先要求 baseline 中该路径存在且 `object_type="regular"`，否则 unsafe（`file_to_dir_ancestor_not_regular`）。
3. 应用侧不改（先删后写已满足）；`expected_candidate_paths` 不改。
4. Docker 往返测试：fixture 基线含普通文件 `config`；候选删除它并新增 `config/default.json`，经 census → 导出 → 分类 → 投影 → fresh grader 应用 → 测试通过；反向（目录变文件）仍被构造期拒绝并有测试钉住。

### P-A · 契约升级：候选执行失败 + R2E 方案 A

改动：
1. `contracts/grading.py`：新增类别 `candidate_execution_failed`（名称待 Brief 确认）——`outcome=unresolved`、`reward=0.0`、四计数 None，与 `patch_apply_failed` 同一校验分支；新增可选字段 `execution_failure_stage: Literal["test_collection", "test_import", "test_run"] | None`、`execution_failure_evidence: list[str]`（触发判定的日志行/路径，≤ 20 条）、`grading_semantics`、`expected_match_count`、`expected_total_count`（R2E-A）。全部带默认值。
2. producer（manager 零解析分支，替代直接抛 infra）三条件同时成立才产出该类别，否则维持 `test_log_parse_failed`：
   - 环境资格：`GradingEnvSpec.env_qualified: bool = False`（由 taskset/流水线从筛查账本注入：同镜像 digest、同配方下 gold 或 noop 至少一次在正式链得到可信判定；driver 校准期用 `--env-qualified` 显式给出并写入账本）；
   - 失败在测试段：`RH2_TEST_RC != 0`（I7）且解析 0 条；安装段退出码不作候选失败证据；
   - 定位到候选：测试段日志里 `ERROR collecting <path>`、`ImportError`/`SyntaxError` 回溯的 `File "/testbed/<path>"` 命中 `projection.included_entry_paths`（候选改动的路径），至少一条。
   保护性资源终止（OOM、墙钟）、容器死亡、shm 类信号仍归 infra；`SyntaxError` 文本单独不构成证据。
3. 消费者：gate 维度 6 把新类别列入"模型负样本通过"；`FAILURE_CATEGORIES_EXECUTION_FACT` 加入新类别；`group_admission` 无需改（reward 一致性）；`outcome_producer`/termination facts 若按 `failure_category` 枚举则同步；contract 测试补正反例（三条件缺一 → infra）。
4. R2E-A 的产出方留到第二片（R2E 适配器），本片只把字段与校验分支落进契约并加测试。
5. A 线 §7.2 的空白：`install_rc ≠ 0 ∧ resolved`（编译型仓库候选改坏构建输入、测试对着旧产物通过）在 e1/e2 对账中列为必须解释的例外；是否让它阻止 resolved 是 reward 语义，留用户决定，不在本片实现。

验收：contract 单测；manager 单测用 FakeDocker 构造三条件各缺一的日志；fixture Docker：候选把 `src/thing.py` 改成语法错误 → `candidate_execution_failed`、reward 0、sidecar 有证据行；同一日志在 `env_qualified=False` 下仍是 `test_log_parse_failed`。

## 3. 需要用户或 A 线确认的点
