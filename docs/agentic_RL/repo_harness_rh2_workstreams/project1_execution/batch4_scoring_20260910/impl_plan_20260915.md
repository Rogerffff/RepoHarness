### 1.3 baseline 政策（P-C 的改动面）

- [contracts/baseline_manifest.py](../../../../../rh2/src/repoharness2/contracts/baseline_manifest.py)：`BaselineManifestPolicy(policy_version, excluded_namespaces)`，v1 = `(".git/", ".harness/")`，语义是**根锚定目录前缀**；`compute_policy_digest` 进 manifest 身份。

### R1 · P-A：不要把评分负样本接入执行缺失集合（P1，P-A 实施前修订）

§1.1 / P-A 第 3 条的消费者说明有误。当前 [gate.py](../../../../../rh2/src/repoharness2/governance/gate.py) 的 `clean_grading` 按 `failed_to_grade` 和 hygiene 判断，没有需要扩展的“模型负样本通过集合”。`FAILURE_CATEGORIES_EXECUTION_FACT` 实际定义在 [fa_runtime.py](../../../../../rh2/src/repoharness2/contracts/fa_runtime.py)，表示 `missing` 的执行缺失原因，crosswalk 只在相应 legacy 分支消费它。

当前正式链已是：`GradingReport(unresolved, reward=0)` → `generate._produce_outcome_v2(task_resolved=False, failure_category=None)` → present execution / reward available → admission / group。评分成功却给 Outcome 填运行失败类别，会与 [admission.py](../../../../../rh2/src/repoharness2/governance/admission.py) 的既有约束冲突。

**修订与验收：** 新类别留在 `GradingReport`，删除扩执行缺失枚举的要求；不为不存在的 gate 白名单加一套新集合。补一条真实报告 → RewardFacts / gate → Outcome / admission → group / 训练数据的运输测试：其它资格满足时，新类别保留 reward 0、原有 mask 与成员身份；基础设施失败仍无 reward。此项是减少改动面，不需要用户再批准。

### R2 · P-A：三条件尚不足以覆盖和证明候选执行失败（P1，producer 启用前修订）

**先修入口判据。** [真实 pytest 探针](impl_plan_review_20260915/training_semantics_probe.py) 中，基线通过；候选把 `src/thing.py` 改成语法错误后 pytest 返回 2，测试体没有执行。但当前 SWE-Gym parser 将摘要 `ERROR tests/test_thing.py` 计为一项，manager 的 `num_parsed_tests` 为 1，拟议零解析分支不会进入。只用零项 FakeDocker 日志不能验证本计划承诺的覆盖。

这不证明现有 binary 0 错误：SWE 来源规则允许参考项缺席计为不通过。必须区分**原始 parser 项数、实际观察到的 case 状态、collection/import 全局失败、参考集合缺席后的判分**，不能把参考桶计数描述成测试逐项执行失败。首版应明确支持的失败形态，并覆盖同一收集错误有/无 pytest 摘要、部分测试已运行这几种真实日志；保留实际结果，新增全局失败事实。

**再收紧“已定位”与“已归因”的区别。** 回溯经过候选修改过的文件，只证明路径相交。例如只改注释的文件仍可能在原有 import 行遇到安装缺依赖；`ERROR collecting` 本身也不是候选因果证据。建议首版列少量有正向依据的规则，例如确认候选源文件中的语法错误；ImportError 等原因不清时不据路径相交自动给 0，不要求每次重跑 gold 或先建通用异常分类平台。

以下两项写入同一 producer 验收，不另开新决策：

- 环境资格复用已有筛查证据，列清任务、实际镜像、评分配方及对应报告如何通过正式 `PreparedTaskFace.grading_spec` 注入。仅 driver 的 `--env-qualified` 不等于正式 actor 已接通；镜像/判分配方变化不能继续沿用不匹配的资格。`gold/noop 有一份 verdict` 也应说明具体证明了哪个入口可用，不直接替代候选失败归因。
- P-A 承诺 OOM、墙钟、容器死亡、shm 问题不转 reward 0，就要列清可消费的来源与未知状态。当前 memory peak 只是可选观测，不能证明没有 OOM；包装 shell 返回 0 也不能证明测试子进程正常退出。正向失败规则与资源终止事实冲突、或所需终止证据不足时保持未确定归因。首版可少支持几种失败，不需为覆盖所有异常先造完整资源探测平台。

### R3 · P-C：默认字段会改变旧身份，省略计数也会重新进入身份（P1，政策 v2 启用前修订）

当前 [baseline_manifest.py](../../../../../rh2/src/repoharness2/contracts/baseline_manifest.py) 的两个 digest 函数都哈希完整 `model_dump`。CPU 探针确认：给政策加空默认模式会改变 v1 policy digest；给 manifest 加默认零计数会改变 v1 manifest digest；计数 0 → 1 又会改变身份。因此“字段有默认值、保留 v1 对象”不保证旧证据可读/可重放。

此外，[grader 重建](../../../../../rh2/src/repoharness2/grading/manager.py)比较整份 manifest digest。即使两侧代码完全相同，仅被省略的缓存数量不同，也会因新计数字段触发 `baseline_digest_mismatch`，抵消这次缓存省略的目的。

**修订与验收：** 明确按政策版本保留 v1 的 canonical 字段形态；v2 的规则本身进入政策身份，缓存数量放现有 sidecar/观察记录。不要只在某一处临时从哈希删字段。用一份真实旧 v1 JSON 验证读取和旧锚点保持，用相同候选内容、不同缓存数量验证 fresh grader 重建仍一致。计数明确区分 baseline/post；post census 目前是 exporter 局部值，不会自动出现在 driver 账本。

### R4 · P-C：缓存规则必须保留对象类型与已批的适用范围（P1，政策 v2 启用前修订）

§2 的 `-name __pycache__ -prune` 会连同名普通文件、软链一起省略；`! -name '*.pyc'` 也会吞掉软链和 FIFO。当前 no-follow 边界依赖 baseline 中的软链事实，不能随缓存过滤消失。

[类型探针](impl_plan_review_20260915/p_c_cache_type_probe.py)给出一个具体后果：fresh baseline 中 `alias.pyc` 是目录软链；候选改成真实目录并增加子文件。按拟议名字规则过滤后，只留下子文件新增，现有应用函数失去祖先软链事实并跟随写出 testbed；保留该事实时它会正确拒绝。所有写入均在探针临时目录内，此结果不代表当前题单已出现该形状。

“全部 `*.pyc` 从不作为交付物”也不成立：探针生成一个无 `.py` 源文件的独立 `.pyc`，仍可正常加载执行。这不能证明所选题需要交付它，但足以否定全局保证。

**修订与验收：** 只省略已确认可再生、非答案的缓存，匹配同时考虑对象类型；不因缓存名跳过软链事实和原有 unsupported 类型处理。具体规则由 B 在所选 Python SWE 环境中给依据，不直接把通用 census 默认改成适用于所有来源的忽略清单。首版可撤掉未经确认的全树 `*.pyc`，先做已有依据的更小范围；未知继续保留，无需等待全题池分类。验收至少覆盖真实缓存目录、同名普通文件、软链及已批准适用范围之外的环境。

### R5 · P-D：必须检查投影后还保留必要删除（P2，P-D 实施前修订）

“应用两遍、先删后写”只对完整操作集成立。[投影探针](impl_plan_review_20260915/p_d_projection_probe.py)：`delete config + add config/default.json` 全量应用成功；若 `config` 在精确 official 清单里，真实投影忽略祖先删除，却保留子文件新增，真实应用函数随后报 `GradingInfraError: mkdir ... File exists`。这是 README §3 D 已明确要求检查的接缝，不能只放宽 raw artifact 校验。

**修订与验收：** 支持范围写成“普通祖先删除仍在最终投影中的合法文件变目录”。必要删除被控制面规则排除的混合形状明确维持不支持，并在投影/分类阶段给出准确原因，不留到 Docker 写入后伪装成暂态故障；不偷偷重放受保护删除，也不无记录丢子项。不要求重写两遍应用。配正常往返和上述混合反例即可；baseline 读取后自相矛盾仍按既有内部错误规则处理，不新增“自身 bug 变 unsafe”的通道。

### 5.1 其余需补写的口径，不增加新 T0

1. **编译失败已有授权。** A 已覆盖明确由候选导致的编译/构建失败；不能因发生在 install 段，就把已证失败仍判 resolved 的处理重新挂成待用户决定。普通 `install_rc != 0` 尚不证明原因，继续对账合理。如果首片只实现测试阶段，明确编译形态的后续实现归属和范围；规模筛查前遇到已证候选编译失败、却测了旧产物的情形，应按已批 A 修正，而非当合格结果使用。不是要求把所有安装非零一律改 0。
2. **R2E-A 的最小矩阵。** 有可信结果时用 expected 两计数；infra、apply 失败、无可信测试结果的候选执行失败，允许两计数均 None；不得混填 F2P/P2P。`matched == total` 不是精确映射相等的充分条件，observed 可能多出键，留一个额外键反例给 R2E producer。无需切换到方案 B。旧报告默认字段可读与重序列化字节不变分开验证，不能靠“有默认值”推断后者。
3. **P-B 保持纯观测。** 赞成两个 SWE 构造入口撤默认 glob；不要为了统计触碰测试样路径去设置 `PatchHygieneResult.test_files_modified=True`，它参与 gate。README §7.3 的“当前一触碰就 hygiene 拒绝”混用了旧 diff 路径：当前 frozen 正式链先投影，ignored 条目只作记录，正常 `FrozenApplyPlan` 是 clean。上文 sidecar 方案可以直接沿用。重新预检保存新版本结果，保留原 `precheck.md` 证据，不覆盖历史运行记录。

- **e1 原版本照常完成。** 不热替换其代码/镜像；新规则用于新运行，结果标明版本。无需等上述修订才读取 e1 结果。
