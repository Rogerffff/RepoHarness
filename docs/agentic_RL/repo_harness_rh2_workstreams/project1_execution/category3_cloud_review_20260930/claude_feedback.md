## 3. 后续每题采用的最小完整诊断

1. **先定公开行为。** 用原题、该base的源码/文档/公开测试列需求与允许实现。把事实、推断和仍需选择的目标分开；gold、私有测试和未来上游不是公开要求的替代品。
2. **针对已登记疑点做决定性实验。** 一项问题优先一个能区分原因的对照；精度、类型、异常、目录等候选只是排查提示，不要求每题机械凑齐所有家族。先证明候选真正违例或合理，再解释原评分为何错。
3. **给明确修法和可信对照。** 新测试要接受至少已知的合理实现，拒绝已证错误效果；替身要匹配真实API的签名、返回、异常和副作用。gold不成立时，替代正对照由非作者核实，并保留适用范围。
4. **独立复核最强结论。** 复核者先原件初判，再读作者。重点查要求是否被扩大、错误候选是否真错、合理解是否被误拒、正对照是否成立、失败是否来自环境。已有阻断修正后做聚焦复核，不自动再启动全题审查。
5. **交接全部重要余项。** 问题和修法明确即可交第2类；正式材料落地、真实actor核对、最终候选矩阵与用途验收可以由第2类负责。若仍缺目标选择、可信正对照或决定性证据，留第3类并给唯一具体解除动作。不要只留下“继续诊断”四个字。

“完整”是对已知重要问题有依据、有处置，不是穷尽所有边缘输入。已知坏题也不能依赖事后语义审计进入普通能力比较；特殊诊断试解另列调查目的，不混用原分数。
