2026-09-29 / Codex B。**本夜18题的CPU实验与独立最终复核已完成，逐题结论见[晨间报告](morning_report.md)。** 覆盖6个仓库：14题证实错误候选仍得1，2题证实gold引入回归，另外2题分别保留示例覆盖限制、正确拒绝所测错误。本批按既有疑点选题，不能用这些比例推算全池质量，也没有新增训练资格。执行经过见 [execution.md](execution.md)，后续六题的原计划见 [reserve6_plan.md](reserve6_plan.md)。R2E由原线程负责，GPU预算与统一求解入口另议。

## 4. 每题本夜做到哪里

1. **接续旧证据。** 核对应版本、全部剩余项与已有独立审查；新建本批后续记录引用旧题卡，旧封存结果不回写。
2. **确定性验证。** 正式 actor 身份跑公开命令；已提出且会改变处置的质量疑点做私有对照；按 v1 补缺少的退化探测。CPU 桩不承担模型能力结论。
3. **修复并闭合失败路径。** 已授权的题级环境、资产、依赖与资源修复由本线程推进，并独立核查；不能升级目标项目带入答案。测试／题面需要新接入机制的，形成有证据的修订草案和依赖。
4. **核对正式评分。** 保存候选交付、实际安装／加载、逐参考状态、完整执行与清理。新环境或新执行条件下补必要正负对照，旧结果按适用性复用，不全量重跑。
5. **逐题交付。** 清楚给出：题级 CPU 前置已完成、仍需 CPU、仅诊断／待决定。前置完成题再分别列无已知阻断与有明确限制者；全都仍待公共 GPU 入口验收和预算决定，不写 `GPU 已就绪` 或 `端到端完成`。

**必须保留的边界：**得 0 要证明目标行为确实执行且失败；得 1 要解释本次观察到的其它失败。root 对照不证明 agent 权限可用。仅有样例拟合风险或覆盖不足，按 v1 区分受限比较与训练资格；未解误拒／题意冲突不能作为正常比较题。所有重要剩余项都有负责方和恢复条件。

## 5. 执行、记录与次晨交付

- **一台机器、一个远端派发入口。** 子任务准备题级命令与诊断，统一执行者运行。先 2 路，按实际 CPU、内存、磁盘、PID 和 tmp/shm 使用提高到合适并发；重构建单独排队。正式 CC 桩的端口、剧本、输出和容器归属隔离，不共享进程内 monkey-patch 状态。
- **可靠收尾。** 作业、状态和账本在远端持久化，巡检只负责观察、分析和派发新工作；不靠每次模型唤醒维持长作业。清理失败或执行完整性未知时保存现场，停止受影响的派发，不能把它计成模型／题目失败。
- **记录够用。** 题卡引用材料、镜像、配方、真实代码快照、profile、CC 和命令版本；每次作业记录结果、耗时与可得资源。版本差异标为待核适用性，人工依据变化范围判断复验，不建新的自动准入引擎。
- **定时巡检。** 有机器并启动后再设置本线程 heartbeat，先短间隔验证一次真实触发，再以约 30 分钟巡检；通过官方工具更新。状态不变安静；重要发现、失败或需决定时汇报。证据持续回传，本批收口后暂停巡检。不得复用旧 SSH 地址或把“保存成功”当“已触发”。
- **次晨结果。** 一张逐题表（处理／验证／用途／限制／剩余项）、新增探针候选及适用条件、仍待决定的少数问题、流程改进清单、可恢复工件位置。没有新证据的题不填通过；不用完成数催促跳过复核。

今晚按以上边界无需先决定 GPU 事项，也不需要重新批准 R-d 等已有修复模板。机器 SSH 是实际运行的前置；若希望本夜直接新增 SWE-Gym 正式题面／测试修订机制，则超出当前 D6 实施范围，需另作决定。
