## 本批对流程的具体反馈

- **开发验证必须包含题目实际需要的操作。** Conan 的四项公开测试原本能过，但真实 CMake 配置因缺 Ninja 失败；只验 import 或旧测试无法证明模型能复现问题。环境修复后仍用同一份命令清单，明确失败已推进到原题目标位置。
- **验证错误候选时，应保留被漏测行为的实际输出。** MONAI5932 交换同一整数表达式中两个引用的顺序，Conan 检查请求的 Release 配置，均能区分“题面样例通过”与“公开核心行为正确”。不强制所有题构造同一种错误补丁，也不把未执行的后续断言记为已覆盖。
- **安装、准备和测试资源要分别解释。** MONAI 的4GiB峰值包含 chown 阶段文件缓存与回收；来源测试实际只有数十秒。准备预算不足是运行条件问题，不能算模型失败，也不能直接据此提高整池测试预算。
- **停派之后要有明确恢复依据。** 本轮保留旧队列失败，读到缺 Ninja 的具体错误、验证修复与清理后才续接。其它题可以在同一机器继续，Conan自身的正式结果仍需另行验收；“环境阻断解除”与“整道题处理完成”分开记录。
- **gold必须逐条对应它能证明的行为。** Pyd8567/9066的gold均修好原例并获正式1，却破坏已有公开能力。可以保留其“原例正对照”证据，但补全新回归断言时必须修正gold或验证替代解，不能为了沿用gold删掉合理护栏。诊断脚本捕获并报告预期异常后返回0，也不能被写成gold行为通过。
- **共用修订能力未实现时，题卡必须显式保留限制。** 私有控制已证明多处漏判，却不等于正式测试已补好。D6未实施是当前共同依赖，不能让每题负责人自行修改原参考来凑齐训练合格数。
