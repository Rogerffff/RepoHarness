## 项目与数据背景

项目一面向真实coding agent后训练，主链是miles＋SGLang＋Claude Code＋RH2。任务包含公开需求、仓库基础版本、开发环境，以及独立的评分材料。actor是模型做题环境，grader是评分环境；两者可能使用不同镜像。

当前整理的本地池为 **216道SWE-Gym＋48道R2E，共264题**，不是这两个公开数据源的全部。已做过不同程度的环境修复、题意／测试审查、公开开发检查、真实模型探针和候选分析。

两款主要探针模型是 `Qwen/Qwen3-Coder-30B-A3B-Instruct` 与 `Qwen/Qwen3.6-35B-A3B`；这里“基座”指继续训练起点，二者本身已做过后训练。更早还存在DeepSeek记录，不能混成统一模型成绩。

## 已得到的主要认识

- 不能仅凭首轮高分判定数据饱和。Pandas48106两模型都找到了相关逻辑，却漏掉类别／缺失值语义；NumPy d805暴露输出验证和纠错不足。
- 原评分也会漏问题。Coverage EA69与Pydantic8511在补齐有公开依据的检查后，原通过候选暴露回归；应复用原补丁补评，不能把修订前后成绩混在一起。
- 正确解仍有质量差异。Pandas50319两模型均满足已验目标，但编译、自验完成程度不同，可用于研究rubric，即基于证据的分项质量评价；尚未证明这种奖励能带来训练增益。
- 前期逐题深修、反复交接，以及准备／评分成本影响覆盖速度。性能专项已有预构建、编译缓存、Prime独立评分等验证，**生产入口尚未接线**；具体进展以性能当前入口为准。

现有建议是“最低限度可信检查 → 首轮探针 → 按真实候选分流 → 入选后精修”。中性改写不能靠删必要线索造难；同仓合成应先小试；rubric先分析已有轨迹、与新覆盖并行。三路最多24题、首轮48条及最多16条补采样，是**待讨论建议，未启动**。
