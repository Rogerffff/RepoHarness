# 下一阶段数据筛选与训练信号建议

依据日期：2026-10-04。本文供下一阶段决策，尚未改变现行准入、奖励、预算或启动新实验。当前状态仍看[264题入口](README.md)；原始外部核查与本地案例索引集中放在 `runs/data_signal_strategy_20261004/`，不新增一套调度总账。

**建议保留按仓库端到端负责，把主要投入改为覆盖更多题目和来源：先做最低限度的可信检查，再跑探针，用真实候选决定哪些题值得深加工。** 暂不要求修完剩余181题，也不把本轮52题全量重复作为下一步。二元奖励下的成败差异、通过后的质量差异、最终能否带来训练收益，要分别验证。

## 当前结果支持什么

本地264题中83题找到真实执行记录，本轮52题有双模型首轮及逐题分析；这些是历史覆盖数，不能当作统一语义正确率。下表复用原作者及已有独立核查，本次没有重跑。模型为 `Qwen/Qwen3-Coder-30B-A3B-Instruct` 和 `Qwen/Qwen3.6-35B-A3B`；两者都是后训练模型，这里的“基座”指我们的继续训练起点。

| 已有案例 | 轨迹与结果表明什么 | 下一批优先找什么 |
| --- | --- | --- |
| Pandas48106 | 两模型均定位到类型处理、修好数值示例，但类别与缺失值仍有15项F2P失败。Qwen跑了更多公开测试，仍未检查正确的dtype不变量；两者正常结束，非截断。 | 需要保持类型、状态、兼容语义的修复；不能只看是否找到文件或跑了多少测试。 |

这些案例支持一个**选题假设**：下一批更值得增加约束保持、跨路径一致性、边界验证和错误后恢复，而不只是扩大定位范围。它们不证明所有题都缺这些能力，也不证明某类题必有RL收益。尤其，两模型一次一成一败，只能证明模型间分歧，不能当作同一模型多次采样出现了奖励差异。

外部也不支持“强基座已饱和”：Uni-Agent报告精确Coder在R2E训练后验证指标46.2→52.0、SWE-reBench 47.4→54.2；ROSS报告精确Qwen3.6在另一套OpenSWE／harness中，基础60.8→RL64.2，后续选择性SFT到68.4。不同框架、筛选、预算不能直接移作RH2预期收益。[Uni-Agent](https://github.com/verl-project/uni-agent/blob/main/docs/source/benchmark/rl-training.md)、[ROSS表2](https://arxiv.org/html/2609.35954v1#S4.SS3)

## 把检查投入放到更有价值的位置

现行流程已经允许复用证据、最小修订、三方直接交接。问题不宜全部归因于消息数量；应进一步改变“获得难度信息之前投入多少”。建议下一批采用以下顺序，现行已知错误评分和妨碍合理求解的阻断仍须修复或搁置。

| 阶段 | 做到什么即可往前走 | 不在这一阶段做什么 |
| --- | --- | --- |
| 仓库准备 | 复用已核镜像／配方、工具、评分消费和保护模板。每个新来源先跑通少量代表题；同repo同版本的未变能力不逐题重复核。 | 不为全来源先建齐镜像或逐题写设计报告。 |
| 快速分流 | 读题目、相关变更与已有审查，记录一个能力假设、明显泄漏／歧义、评分与资源风险。常规题先用5–10分钟作投入检查点。 | 不在静态阶段精确预测成功率，不穷举几十种假想错误修法。 |
| 可诊断检查 | 身份与题意明确、可在公开环境开发；未改代码与可信正对照呈现预期差异，日志可解析。保留现有隔离与防答案泄漏要求；已知语义漏洞先处理。 | 不要求全部训练资格、所有反例、所有跨仓质量报告完成后才看第一条真实解题轨迹。 |
| 首轮探针 | 首批来源比较保持两模型各一次、固定材料与各自统一宽预算。自动保存完整候选、结果、关键计时，允许评分与下个求解异步接续。 | 不默认每题三次，不因首轮失败就重复直到通过。 |
| 候选驱动核查 | owner快速核修法、真实验证和结束原因。全部可疑通过、评分矛盾、正常失败优先查；普通通过做简短核查并抽样深审。发现漏洞优先用原FrozenPatch做CPU对照。 | 不重解已有完整候选，不为每条轨迹重写长篇七维文章。 |
| 入选再精修 | 对拟进入训练的题补齐有依据的反例、稳定性与受影响独立核查；新共享模板统一审查。只把已验证的当前版本交训练。 | 不以“可诊断”替代训练准入，不为完成全池比例而无限修复。 |

题级准备一轮诊断加一次定向修正仍不清楚时，记录缺项，暂时让开队列。时间是**投入复盘点**，不强迫通过，也不截断模型求解。源级模板可集中投入；单题重复推翻公开目标、参考解或评分时，通常应先换一题。已标简单的题保留少量分层抽查，防止静态误判把真正有价值的题全部漏掉。

独立核查保留在共享模板、新任务规格、已知评分争议和训练入选材料等风险点；不要求每个未变阶段重新换人全审。现行普通探针的独立核查条件若要调整，应明确采用新流程，不能让题主私自跳过当前要求。

## 每题按模型分别决定用途

- **同一模型已观察到可信成败差异：**优先列入二元奖励候选池，仍需材料可信和预算一致。少量差异不是训练增益证明。
- **只有一次成功或两模型都成功：**标为“暂未见失败”，降低重复优先级；有明确验证／效率差异时进入质量评分观察池。
- **正常失败或多次全错：**先判断可解性和失败机制；少量独立重复能改变选题决定时再补。全错且可解可留作困难题、示范或后续课程，不等于当前组相对二元奖励已经有优势信号。
- **错误评分或基础设施故障：**单独统计并修复／搁置，不当作模型解错；保留原样本及诊断版本。固定预算内未完成仍进入原预算完成率／成功率的分母，不能删掉虚抬结果；模型自身耗尽合理预算可以暴露效率问题，但不能直接当作完整候选的语义错误或任务不可解。外部中断与模型预算耗尽分别归因，必要的预算诊断另列版本。

两模型应维护不同候选用途：对Coder有价值的题，不必因Qwen一次做对而淘汰；对Qwen选出的困难题也可能暂时超出Coder的可学习范围。首轮配对方便比较来源；确定主要训练模型后，可把广覆盖转为该模型优先、另一模型分层配对，以减少无目的的重复。

普通组相对二元奖励中，全1或全0的当前采样组没有该项奖励优势；这不意味着所有loss为零，或该题永远无用。DAPO在数学中采用动态过滤，不能直接推出SWE题应固定50%成功率或过滤没有计算成本。[DAPO第3.2节](https://arxiv.org/html/2503.14476v1#S3.SS2)

## 改写和合成只做有明确目的的部分

**中性改写值得做，但不能靠删正常线索造难。** 可移除答案补丁、逐步修改指令等过量帮助，保留症状、复现、接口和兼容约束。函数名、文件名或堆栈若本来就是合理需求的一部分，不应一律删除。原题与改写版分开记录；改变需求属于新任务，测试必须对应公开目标。比较只选少量本来就依赖答案提示的题，不把全部已通过题重写一遍。

**同仓合成值得小试，不值得先建大生成流水线。** 优先复用成熟环境：①从真实功能规格／新PR形成行为目标；②从健康版本注入可验证bug，复用正确版本作正对照。跨文件或多bug只是候选特征，不自动等于有价值的困难。先消费SWE-smith等现成任务，再选2–4道熟悉仓库的新任务验证单位成本。CodeMidas提供功能实现路线，SWE-smith提供bug合成路线；其论文效果不是本地两模型训练复现。[CodeMidas](https://arxiv.org/html/2609.22068v1)、[SWE-smith](https://arxiv.org/html/2504.21798v2)

训练／验证分割需按来源PR、基础版本、相似补丁、功能或注入bug族追踪关联；同bug的单体和组合版本不能跨集。主要泛化评测保留完整仓库，仓库内时间划分只作另列的评测。生成器和审查者接触过参考解的上下文不能直接作为干净solver。

## Rubric先用现有轨迹校准

MiMo报告确实对高通过率coding子集使用GRS：从多条轨迹形成任务级解法／行为rubric，并与测试结果相乘；GAR则针对混合成败组重分配已有正优势。公开2,698条code任务主要给可执行测试，不能假定附带完整GRS评分规则。[官方报告第4.3节](https://huggingface.co/XiaomiMiMo/MiMo-V2.6-Flash-RL/blob/5711b268169967567844e1e560e8a3966da959b1/MiMo_V2_6_technical_report.pdf)、[公开数据卡](https://huggingface.co/datasets/XiaomiMiMo/MiMo-V2.6-RL-oss)

建议先从已有轨迹选8–12道代表题做shadow评分，即仅记录附加判断，不改实际reward。每题最多3–5项、每项有代码或执行依据：需求与回归保持、真实验证是否支持完成声明、同等正确性下的实现与资源成本。利用Pandas50319的编译完成差异、48106的无效边界验证、EA69的误奖建立反例；不能让动作漂亮抵偿代码错误。

关键正反例先由独立语义核查确定依据，再盲去模型名、原reward并交换候选顺序，核正确替代解是否被误拒、错误解是否被误接收、排序是否稳定。证据不足、轨迹缺失和judge故障独立记未知，不强填0；“未完成自验”不推翻独立确认的最终代码正确性。形式化动作如“写了plan”“用了并行”“测试调用多”不直接奖励；没有并行机会或执行层证据时记不可判断。基础设施等待不罚模型，实际工具／编译成本又不能全部忽略。判断需要花多久、是否能自动核同样纳入成本。稳定后再决定奖励形式与小训练对照，不能为继续利用易题仓库而先造一套主观分数。

## 下一批的具体建议

能力标签复用已有轨迹，rubric观察在本地与来源适配、首轮探针并行，不成为新增覆盖的等待条件。小试建议最多24道本批候选，分三组，每组8题、尽量至少4个仓库；按仓库和任务类型分层抽样，保存进入与暂缓理由。分别报告已有池首次模型覆盖、R2E池外扩展、新增来源任务；不把它们都称为新增数据。

| 来源 | 优先原因 | 本轮边界 |
| --- | --- | --- |
| 已有环境资产中的未覆盖题及R2E扩展 | 复用216＋48池的环境与历史调查；Coder已有同模型外部训练证据。 | 优先有能力假设、少改即可运行的题；不要求先修完51题问题组，不以已知旧易题替代新增覆盖。 |
| Prime SWE-rebench V2筛选集 | 6,272题，提供gold两轮、no-edit和逐题验证日志，可减少重复环境筛查。 | 先验实际镜像运输和评分适配；先用当前链路容易支持的语言，再扩语言。上游难度标签不是本地模型难度。[数据卡](https://huggingface.co/datasets/PrimeIntellect/SWE-rebench-V2-Filtered-Verified) |
| MiMo公开code | 值得检验不同工程任务类型，且已有公开环境映射。 | 先核身份、可行参考解与可信评分。缺参考时需要独立验证可行解，不能用目标模型偶然得1分代替；若准备代价高，暂缓本组，不阻塞其余题。[数据卡](https://huggingface.co/datasets/XiaomiMiMo/MiMo-V2.6-RL-oss) |

SWE-smith作为下一路低环境成本候选；OpenSWE有Qwen3.6证据，但访问／运输未在本项目闭环，不放进第一批必要依赖。Prime数据集接入与Prime托管sandbox采购是不同事项。

**采样建议比外部子报告中的128次方案更轻：**24题两模型各一次，共最多48条初次轨迹；再从最多8题各补两模型一次，最多增加16条。4题在看模型结果前分层预选，另4题按评分已可信的模型分歧／边界失败等明确疑问选择。64条是本轮建议上限，不含单列的必要基础设施恢复；恢复也须记录投入并有复盘点，不无限追加。材料、各模型采样配置与宽预算先固定。2次仍不能证明稳定难度；有疑问保留未知，不继续凑成败混合。MiMo若暂缓，实际范围与分母相应缩小，不悄悄替换成更好看的题。

比较每来源的可运行比例、语义有效结果、同模型重复中的成败差异，以及新覆盖的仓库／能力类型。随机预选与定向重复分开报告，不能合成无偏成功率。成本拆开一次性适配、题级修补、求解、评分、运输／失败恢复；看每单位总成本得到多少可信新任务和可解释差异，而不以“修完多少题”作为主要成绩。8题只能决定下一批投入，不能宣布某来源饱和。

随后只扩量信息产出较好的1–2路，并保留少量对其余来源和静态易题的抽查。只有固定数据与按仓库隔离的保留集上，小规模受控训练产生收益，才能把“疑似有信号”升级为“确有训练价值”。

## 分工与性能配套

仓库owner继续端到端承担筛选、CPU核查、申请探针、候选解释及入选材料；跨来源遇到同仓库仍归同一owner。来源适配只做一次共享工作。发布方负责共用输入与冻结消费，GPU方专注执行及自动回执；研究／管理不恢复普通中转。owner不负责重写通用评分服务，GPU方不承担所有题的语义分析。

沿用总账更新工具，在题目记录内维护能力假设、目标模型、材料版本、最小检查、结果用途及下一步；每仓一个当前摘要，原件自动索引，停止每轮复制长报告。`dataset_status/tasks.json`继续是阅读快照，不充当另一套消息队列。

效率问题也应并行解决。Pandas48106的Qwen求解约96秒，正式评分约1199秒，真正pytest约4.94秒；把全部慢归因于模型复杂度会误判。最新评分优化`next_v2`已有独立复核，Pandas单样本预构建／编译缓存对照737.9→63.1秒，生产入口尚未接线；同容器并非所有题更快。应先集成已证实的窄优化和分段计时、使GPU求解不被独立CPU评分串行拖住，再量扩量成本。不等待所有Prime同sandbox和扩容路线全部完成，也不把一次样本加速当全池收益。[性能当前入口](../grading_performance_next_20261004/README.md)

上述是下一步建议。本轮实际完成外部原始资料核查与本地案例复核，未更改奖励、题目、总账或资源。
