### 0.1 同日实施前反馈：可以推进，修正事实与验收口径

用户报告前批已完成并通过另一任务审查，要求检查 Claude 接下来的实施建议。Codex 在 HEAD `f7521d94` 核对当前入口、指标 producer 和旧 CC 快照，并按黑盒 CLI 边界安排一对 Production Tracer / Falsifier。**结论：I19 窄清理、I20 首版可以按已批方向准备 Brief 并实施；没有需要现在补问的 I18 二选决定。** 本段是实施前反馈，不替代 N1–N4 的验收，也不表示 I19/I20 已实施。没有运行真实 CC、Docker 或 GPU。

1. **撤回“未知字段被忽略，因此 CC 会回退客户端压缩”的推断。** 当前 [AnthropicAdapter](../../../../../rh2/src/slime/agent/adapters/anthropic.py)没有消费顶层 `context_management`，响应也不报告编辑结果；这只能证明该编辑语义未实现，不能证明回退。旧快照 [query.ts](../../../../../reference/claude-code-typescript-src/query.ts) 对缺少 `cache_deleted_input_tokens` 按 0 处理，并不因此调用客户端压缩；[microCompact.ts](../../../../../reference/claude-code-typescript-src/services/compact/microCompact.ts)按功能/模型条件选路径，后续普通 autocompact 可能因上下文压力独立触发。官方 [context editing 文档](https://platform.claude.com/docs/en/build-with-claude/context-editing#context-editing-response)也把实际编辑结果放在响应字段中，并未承诺任意兼容端点上的 CC 回退。目标 CC 是否发这些字段、最终如何压缩，仍归 §0 已登记的真实请求核对。
2. **顶层字段现状测试不应变成长期“压缩兼容”合同。** 如保留测试，只说明当前 pin 对某个具体字段的行为，不断言“所有未知字段永远忽略”或“客户端回退正确”。旧快照还会把 `cache_edits` 放入 user content；若实际发送，当前未知 user block 会经 `flatten_content` 变为文本，与忽略顶层字段不是同一路径。目标构建是否启用尚未证明，不据此新增本批阻塞、拒绝闸门或适配器改造。I19 的主要回归仍是生产接线去掉强制禁用、旧行内拒绝清理，以及摘要生成只训练一次、重注入为 prompt；可复用既有第五案，避免另写一套装配替身。
3. **请求预算按现有守卫实际接纳的模型请求计，不按压缩事件额外加 1。** [autoCompact.ts](../../../../../reference/claude-code-typescript-src/services/compact/autoCompact.ts)可先利用已有 memory，[compact.ts](../../../../../reference/claude-code-typescript-src/services/compact/compact.ts)又有摘要请求失败后的回退/重发；客户端工具裁剪也可能不生成摘要。因此“每次压缩恰好多一次请求”不是通用事实。摘要真实生成仍沿用现有动作/预算语义，不暗中免计，也不把当前 25 次定成正式预算。去掉项目强制禁用不保证每次运行都会触发压缩；实际行为仍受目标 CC 配置和功能开关影响。运行配置应记清这一行为变化，长任务的新旧 spike 不能直接混比。
4. **同意 I20 先交付一个读取既有文件的 run 报告工具。** Brief 应逐面列 producer、启用条件、关联键、统计单位/分母和当前缺口。比如 `rh2_event_log` 未设置 `MILES_RH2_EVENT_DIR` 时不发事件，缺文件不能显示成“没有损耗”；`sample_dis_accounting` 目前只有 accepted/provenance 等身份计数，不能从它补造完整候选信号或 log-ratio 分布。先复用已有 N1/N4、step、发布与对拍记录，确有必要才补少量 producer；“首版不新增设备侧统计”是当前实施范围，不是以后永远禁止有界统计。七面没有采到的内容标为未采集/待补，不伪记完整覆盖。建议同一工具也能人工读取进行中 run 的快照，不要求等正常退出；无需常驻服务或自动轮询。缺失不填零、均值乘 execution 数还原总量、跨 rank 去重、消费与 applied step 区分继续作为验收口径。
5. **I18 保持后续依赖，不变成本次开工条件。** 正式采用受影响的 MoE 训练路由前需要完成该项讨论；基座推理诊断不等于使用该路由做 RL 更新。以后若安排 GPU 训练诊断，再在具体作业中写明当前路由假设、验证目标与产物用途，不在这里新增概括性 GPU 禁令或代用户批准近似。I19/I20 不等这项决定；第四组评分语义也继续独立讨论，I20 只消费已有评分事实、保留未知与分类来源，不先替第四组改 reward。

## I17　DIS accepted ≠ 有训练信号

- **当前方向**：用户已确认纳入 I20 按首版范围推进；不在这里改变 loss、skip 或熔断。
- **代码事实**：单例支持集 token 的 support-renormalized logprob 恒为 0、ratio=1，被 DIS 接受但对应 policy 项对 logits 的梯度为 0；zero-contribution 指标只在 accepted=0 时置 1。N4 已增加单例、候选信号等计数，待另一任务审查/修复；连续 8 个全零梯度 step 熔断仍是既有 spike 值。
- **方案**：A）只加观测（§4.1 已批，见实施 Brief N4）：保留 accepted 口径不变，另记非单例支持集 token 数、**候选信号计数**（`loss_mask=1 ∧ accepted ∧ support>1 ∧ advantage≠0`；不叫"有效梯度 token"——优势为零的 token 没有 policy 梯度，且多样本梯度仍可能抵消，不能替代全局零梯度判定）、支持集大小有界分桶、ratio 两侧拒绝计数；8 步熔断是既有 spike 值，保留不需重批。B）改变 skip / 熔断依据（另谈）。C）改变 loss / 采样支持集构造以减少单例（算法语义，T0，需 GPU 证据）。
- **本轮推进 A**（基础观测已批，不再等本包）；B、C 本轮不改。
- **成本边界**：新增标量与有界分桶应复用现有计算；不能因为输出是少量标量就认定设备同步免费。实际接线与开销由 N4 审查及后续既定作业核对。

## I18　MoE 路由来源

- **要决定什么**：首次训练是否接受"最后一轮整段 tape 的重算路由"作为 replay 路由；用什么度量决定是否要更强的行为保真。
- **代码事实**：多轮叶链取最后一轮整段 tape（含历史 token 的重 prefill 路由），早轮 logprob / version 仍是当时采样值；跨 publish / retract 或冷 engine 时历史 token 会重算，路由可能与行为 forward 不同；逐轮拆分不解决单次请求内的 retract。
- **方案**：A）接受现状 + 度量（**待讨论建议，不能混在纯观测 T1 里批准**）：先写清同一叶 / 动作怎样对齐、B 路线 FORK 后哪些位置仍可比较、比较的是专家顺序还是集合、分母与未知量、现有 tape 能看到什么；已捕获的早 / 晚 tape 一致率不证明单次请求内 retract 的每个行为 forward 都被捕获。B）逐轮 tape 装配（早轮用早轮路由）——试图处理跨轮来源，但拼接后的前缀计算是否仍符合后轮动作的行为上下文尚未证明，也不覆盖单请求内 retract。C）引擎侧按行为 forward 捕获更完整的证据（成本未知，需 SGLang pin 层面设计；有记录仍需确定怎样消费）。
- **度量成本**：逐 token×layer×expert 比较不是免费的，route 位与 trainer DIS 位的关联也不是几个标量；需先给复用 / 抽样 / 有界汇总路径与开销范围，再决定常开程度，不增加全量 tape 副本或新 forward。它是诊断候选，不因草案称"必备"就成为接线与首训门槛。
- **09-10 用户方向**：保留独立深入讨论，当前不要求选择 A/B/C，也不批准现状用于首训。先保留已有逐轮产物；本轮不修改捕获、装配、路由重放或度量接线，见[路由讨论](../tmp/moe路由重放讨论.md)及本轮补充 §3。
- **长期代价**：A 若发现一致率低，首训结果可解释性受影响。

## I19　上下文压缩

- **09-10 用户方向**：不以关闭 Claude Code 压缩解决本问题；若现有消息树与 B 分行能够正常应对，就考虑去掉旧检查。
- **修正后的代码事实**：行内 guard 拿到的是拆训练行后的 trained capture 列表；当前阈值 0 下行内必须延续精确 token 前缀，长度不下降。跨行压缩与短子 agent 都可能只产生 session 审计线索，不能据此声称会被 guard 拒绝。五案正式装配接缝 CPU 探针验证了这一点，详见补充 §2。
- **窄改建议**：清理旧行内拒绝及启动期强制配置，并移除训练守卫中的 `DISABLE_COMPACT=1`；保留另外三项重试/fallback 环境约束与真实 token/身份检查。无需另造压缩管理器。session 记录只作为上下文变化线索，不称压缩次数，也不升级为拒绝。
- **需讲清的行为**：同策略捕获入口生成的摘要沿用现有真实动作与终局 reward；重注入为 prompt 时不重复训练。只有 harness 注入而无捕获生成的摘要，不补造行为 logprob。目标 CC 实际请求、模型与 session 归属仍应随既定诊断窄核对；本次不是完整 CC、采样支持集或 MoE 验收。
