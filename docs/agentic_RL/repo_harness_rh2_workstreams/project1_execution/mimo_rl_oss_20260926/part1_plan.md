## 4. 逐步说明

### 第 1 步：冻结来源

- 现在手里的 2,698 行来自 Hugging Face 的查看 API（27 页 JSON）。这一步下载 revision `639865fd` 的 `code.parquet`，核对它的 sha256 等于 Hugging Face 登记的 `e15733cf…`，再与查看 API 取得的行逐字段比对。
- 为什么要比对：题面类型的判定依赖原文里的 `\r\n`（从 GitHub 网页提交的 issue 带这种换行）。如果查看 API 在转换时改了换行，“issue 原文 331 道”这个数就不可信。
- 2,698 个镜像的 digest 已从 Docker Hub 取得并写进清单。第二部分一律按 digest 拉取，因为 tag 可以被覆盖，而这批镜像 09-25 才推送完。
- SWE-Gym 与 Verified 这次是经查看 API 取的最新版本。要与本地冻结的版本（`swe_gym_full.revision`、`verified.revision`）核对；不一致就记录差异，以本地冻结版本重算重叠。

### 第 2 步：字段定义与风险标记

字段分两类，在清单里分开存放：

- **精确字段**（直接读自数据）：题号、工作目录、评分命令形态（单段，或 base+new 两段）、测试文件清单、是否带构建包、镜像 digest 与体积、题面长度。
- **规则推断字段**（只作分诊线索，不作结论）：语言、仓库线索、题面类型、缺陷或功能、测试来源、评分脚本特征（pip 安装、启动服务、编译、联网下载）。

新增 6 个静态风险标记，对应 v1 审查标准 §7 的“材料与脚本预检”。它们**只决定审查深度，不代替审查**：

| 标记 | 静态判定办法 | 例子与局限 |
| --- | --- | --- |
| 示例拟合风险 | 测试断言里的字面值，大部分能在题面里原样找到 | 000421。按 D1 严格版可能判 S1，要读题确认核心断言是否只用了示例 |
| 题面未提的新名字 | 测试新用到的导入名、配置键、关键字参数，在题面和测试的上下文行里都找不到 | 001505 的 `expire_after`。不拉镜像就不知道 base 仓库里是否已有这个名字，只能算线索 |
| 精确文本断言 | 断言整句报错消息或长字符串 | 容易误拒措辞不同的正确修复 |
| mock 内部名 | `mock.patch` 或 `monkeypatch` 指向私有名（下划线开头） | 修复换一种实现就可能失败 |
| 回归覆盖 | 分三档：只跑新测试、跑整个被修改的测试文件、base 段单独跑回归 | “只跑新测试”表示几乎不检查回归 |
| 评分时依赖网络或服务 | 评分脚本里有 pip 安装、联网下载、启动服务 | 我们的评分默认断网，要在第二部分实测 |

### 第 3 步：规则抽查

- 用种子 20260926 随机抽 30 道 Python 题。我逐题读题面、测试和评分脚本，核对每个推断字段与风险标记，记录“30 道错几道”。
- 每个风险标记另抽 5 道命中题，看它是否真是那种风险。
- 发现系统性错误就改规则、重跑全表，并写明改了什么。已知的两例：
  - 002436 的仓库线索是空的，因为 mypy 的测试放在 `test-data/unit/`，v0 把 `test-data` 当成了通用目录；v1 会把这类已知仓库路径并入仓库线索。
  - v0 只把 `usercase-test-coderl/` 认作 MiMo 自写测试目录，实际还有疑似自写的 `codespec_tests/`、`verifier_tests/` 等目录（全表约 5 道），v1 核实后一并识别。
- 只报告抽查结果，不换算成全表精度。30 道能发现常见错误，发现不了少见的错误。
- 可选：请 Codex 独立抽查另外 30 道，两份结果对照。

### 第 4 步：同 issue 与同仓库分组

- **15 对同 issue 候选逐对确认**：读两边题面，判断是不是同一个 bug 或需求，确认后放进同一个 issue 组。现有证据：14 对题面逐字相同（5-gram 包含度 1.0），1 对大概率是误报（`002233` 与 pandas-52577，包含度 0.72，只共用 pandas 的版本信息模板、主题相近）。
- **v0 的教训**：初版包含度算法把模板高频词从分子剔除、却留在分母，带长版本列表的 pandas 题被压低，`002233` 与 pandas-52470 明明逐字相同却只算出 0.53；修正后阈值 0.7 又放进上面那个误报。所以只靠一个阈值不可靠，要“标题或正文一致”作候选、人工读题定案。
- **规则**：同一 issue 组的题，跨来源必须落在同一个划分里，要么都进训练，要么都进同一个评测集，不能一边训练、一边留出。
- **仓库组**：按仓库线索把同仓题归组，服务于 D3（留出按仓库划分）。Python 里有 237 道完全没有仓库线索，标为“仓库未知”；第二部分进镜像确认之前，它们不进留出集。
- **跨池冲突表**：单列 MiMo 里与我们现有题池同仓的题。SWE-Gym 的仓库约 65 道，R2E 的仓库约 44 道，其中 pandas 的 34 道两边都算。如果 SWE-Gym 或 R2E 的这些仓库进训练，这些 MiMo 题就不能进按仓库划分的留出集，反过来也一样。
- 例：`002436` 与 `python__mypy-16154` 是同一个 issue，放进同一个 issue 组；它的仓库组是 mypy，而 mypy 在我们的 216 题池里，所以如果 216 题的 mypy 题进训练，002436 只能进训练或不用。
