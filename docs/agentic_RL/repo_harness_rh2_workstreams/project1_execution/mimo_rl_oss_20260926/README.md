## 4. 评估结论（建议，未决定）

**不建议用它替换 SWE-Gym / R2E，建议作为第三来源做小样本评估。** 理由：

1. **没有 gold**：原始 gold 对照（noop 得 0、gold 得 1）不能直接做；经独立核实的替代解仍可形成正对照并定位退化候选，但核实成本更高；所有求解都失败时，分不清题太难还是环境坏了。
2. **没有标准化的 F2P/P2P**（09-27 按 Codex 第一部分复核更正，原写“只有退出码，看不到逐测试结果”）：数据只给评分命令与退出码约定，没有“哪些测试应从失败变通过、哪些应保持通过”的清单；原始日志能否提取逐测试结果取决于各题的运行器；官方评分返回完整输出，verl runner 只截取末尾 5,000 字符。是否以及如何接入 RH2 的评分语义是后续设计问题，届时再判断是否涉及 T0 公共契约。
3. **来源匿名**：按仓库划分留出（D3）与查污染只能靠推断，逐题许可证无法核实。
4. **质量声明无法逐题核实**：随机读的 4 道 Python 题里，Home Assistant 那道（`format-code-task-001505`）题面是 601 字符的 issue 原文，没提配置名，隐藏测试却要求必须叫 `expire_after`，是**疑似**题面欠说明（还要核 base 代码与文档里是否已有这个约定，Codex 复核 F5）。第一部分抽查里，issue 原文类题有更多同类线索，见执行记录 §7。
5. **规格类题可能触发 D1 的“示例拟合”**：`format-code-task-000421` 的测试用到题面示例值 `"loves vim"`，但也测了向量、度量、过滤等其它内容，是否构成示例拟合要按 D1 读决定性断言（Codex 复核 §4）。示例拟合标记在 Python 题里命中 101 道，抽查 5 道没有一道按 D1 确认成立（执行记录 §4.2），只作分诊。
6. **集成是新工作**：两种工作目录、每张镜像的解释器位置未知、评分时有服务与 `pip install`；同时现有两个来源已积累了大量环境对照与静态审查。

它确实更好的地方：仓库极分散，便于按仓库切留出；镜像与评分脚本现成；有学习信号的直接证据（MiMo 的 9B 在这批题上 RL 后 SWE-bench Verified 61.1 → 66.2，avg@3），但那是在大规模 SFT、自有 harness 与大集群条件下得到的，不能外推到我们的基座。

## 5. 更正记录

- 09-26 首次口头汇报说“13 道与 SWE-Gym 同 issue”，实为 **14 道**。原因是初版包含度算法有偏差：为去掉模板噪声，把高频 5-gram 从分子剔除，却留在分母里，带长版本列表（INSTALLED VERSIONS）的 pandas issue 因此被系统性压低。例如 `format-code-task-002233` 与 pandas-52470 实际逐字相同（2,757 对 2,760 字符），却只算出 0.53。改为“倒排索引只找候选、完整 5-gram 集合算包含度”后，14 对真实配对都是 1.0；同时 0.7 阈值放进了 1 对模板误报（002233 与 pandas-52577）。所以同 issue 以“标题或正文一致”作候选、人工读题定案，逐对确认留在第一部分第 4 步。
- 同次汇报提到“与我们在用的 R2E 题有一处测试名命中（pandas `4ec87eb9`）”：那是临时正则 `^\+\s*def` 中的 `\s*` 跨行，把下一行的上下文行也匹配进来的误报。脚本改为逐行匹配后，命中为 0，撤回该说法。
