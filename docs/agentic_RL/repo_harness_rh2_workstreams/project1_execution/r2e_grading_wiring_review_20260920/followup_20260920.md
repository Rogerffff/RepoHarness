## 3. CR1 · P2：异常退出时，新摘要仍会宣称成功

位置：`rh2/scripts/replay_grade.py:99–104`。

`finally` 无条件调用 `final_exit_status(halted=halted, …)`；但 `halted` 只在两类受控停批异常中赋值。缺补丁、未知异常或外部取消会继续向外传播，此时 `halted=None`，若容器已经清干净，摘要就写成成功。

**独立反例**：用真实 CLI 子进程、有效 prepared 材料和不存在的补丁路径运行，没有 mock CLI / manager / 文件读取。实际进程返回 **1**、抛 `FileNotFoundError`、账本尚未生成，最后一行却为 `final_status.exit_code=0, reason="ok"`。另在真实后观测 await 上取消，`CancelledError` 正常传播，取消行也已持久化，但摘要仍是 0。

这不是“异常被吞成成功退出”：进程仍失败，现有 `run_install_wave1.py` 用 `subprocess.run(check=True)`，不会因此继续派发。影响是**摘要与真实退出状态矛盾**，容易误导人工对账或将来的摘要消费者，不上调成训练污染或 P1。

**处置建议：`deferred_with_owner_and_gate`。** owner = B 线 driver 实现者；在 R-f 或让派发方消费 `final_status` 前，随下一次 driver 窄改补齐。保留当前异常传播与清理；异常离开时记录失败/取消及清理结果，不生成 `reason="ok"` 的成功摘要即可。无需新增重试、恢复机制或重新决定训练语义。验收用缺文件和取消各一例，并保留 0/2/3 正控。

## 4. CR2 · P2：无报告返回时，诊断事实没有完整进入账本

位置：`rh2/src/repoharness2/adapters/slime/replay_grade.py:588–600, 616–630`。

**独立反例**：评分已完成并写出日志与 sidecar，随后 `grade()` 的 finally 抛 `GradingScopeTerminationError`，覆盖原本准备返回的报告。driver 的 `BaselineIntegrityError` 分支只写 `stage_error`，因此账本的 `log / diagnostics_ref / install / test` 全空；实际落盘 sidecar 已有 `candidate_exec_exit_code=0`、`candidate_segment_completed=true`。探针的 `halt_running` 和 `halt_late_removed` 两案均如此。

取消分支比它完整：日志引用与候选事实会进 `log / diagnostics_ref / install`，但新增的 `test` 块仍为空。两处都不改变停批、取消、reward；scope 分支的缺口此前已存在，是这次新增诊断运输尚未覆盖的路径，不算新的退出码回归。

**处置建议：`deferred_with_owner_and_gate`。** owner = B 线 driver 实现者；在 R-f 异常对账前，复用已捕获的 record 事实，将正常返回、取消、typed 停批中的候选事实用同一口径填入账本。已经落盘的日志引用也应能在 scope 异常时取到；如需在 manager 上保存已有引用，与 A 线串行窄改。不能为了填字段构造一个已成功返回的报告、补 reward 或恢复评分；确实未发生的字段继续 None。无需重跑完整题库。
