# 解题开发条件：共用验证流程

更新：2026-09-25。适用于 SWE-Gym Lite、Full、R2E 的选中题；供协调者、私有审查者与 CPU 执行者使用。**这是可复用的方法，不是某批环境已通过的证明。** 本批任务和结果写在[09-25 交接页](environment_batch_20260925.md)，总体进展写在[环境流水线总入口](environment_pipeline.md)。

## 1. 三类记录各放什么

| 记录 | 内容与维护方式 |
| --- | --- |
| 本页：共用方法 | 怎样提开发需求、运行验证、解释失败和交接结果；不放具体题的当前修复状态 |
| 每批环境卡 | 当批实际镜像/配方、代码版本、解释器、权限、可写路径、网络、资源、公开材料；逐项区分代码配置、实测与未知，附证据。旧卡保留日期，不充当最新状态 |
| 当批执行页／逐题记录 | 具体问题、修订配方、命令、结果、剩余范围与下一步；共用事实引用环境卡即可 |

[09-21 环境卡](swegym_task_audit_20260920/quality_batch01_20260921/actor_environment_card.md)仅是历史快照。新批次由一个负责人核对当批共同条件，各题再补差异，不让每位 reviewer 重读 RH2 或自行猜配置。公开读者和求解模型只收到中性公开说明；本页链接的私有分析不进入其工作区。

## 2. 静态审查者交付什么

从实际公开题面、工作树、README/贡献指南、安装与测试配置找出完成任务自然需要的开发操作。**使用实际交付的初始工作树**，包含来源规定的初始改动；只拿干净 base 导出时，必须明确与镜像初态的差异及未知。不能把材料包没有的文件直接认定为环境没有。

实际容器材料登记增加 `git -C /testbed status --porcelain=v1` 的输出、退出码与采集阶段；空输出也记录，命令失败不能记为干净。保留来源镜像初态，以及准备完成、开发命令尚未运行时的初态差异；有变更则引用内容差异/既有普查证据，不能只保存文件名。不要为使状态为空而 `reset` 掉来源改动；候选应相对实际初态导出。status不包含全部忽略资产，不能替代资产/环境记录。纯静态包暂缺此证据时记待取，不要求先租机器才可阅读。

| 需要的操作／资产 | 公开依据 | 现有证据与适用条件 | 缺口 | 最小命令与预期现象 |
| --- | --- | --- | --- | --- |
| 示例：导入并验证工作区代码 | 题面原例、公开安装说明及相关测试 | grader 安装日志；尚无 actor 证据 | 解题解释器、包来源与测试兼容性 | 用实际 agent shell 打印解释器及包来源，执行原例与相关窄测试；分别预期什么 |

每题说明开发入口、必要导入/构建/工具、资产/服务及获取方式、相关公开验证、提交边界。没有额外需求时引用依据，不强行制造问题。评分侧已有资产而解题侧未验，写“actor 位置与权限待验”，不写环境正常或题不可用。

## 3. CPU 执行与修复：五步

1. **核对当批输入。** 固定题目、初始工作树、镜像和配方版本；采用准备交给 Claude Code 的用户、HOME/cwd、解释器激活、非交互 shell、网络与资源。本批优先复用修复后的正式启动/profile与真实CC，用受控桩端点下发公开命令；不用旧诊断激活变体替代正式注入。独立诊断入口需说明与正式入口共用什么、还缺什么。桩工具往返证明启动与shell路径，不证明绕过的adapter、真实token计数、模型能力或训练链；具体实现交接见[本批§4](environment_batch_20260925.md#4-次晨汇总与-gpu-探针衔接总协调维护)。
2. **运行题目需要的公开操作。** 除能 import 外，确认导入的是工作区代码，相关公开测试实际收集并执行，必要 CLI、编译或本地安装可用。优先有一条经过题目公开CLI/API或等价用户工作流的命令，能区分目标行为修前修后；仅内部helper或Mock结果不足时，明确缺口，不据私有测试编造公开复现。逐题确定性检查无需模型/GPU；仅 root 或 grader 成功不算 actor 验证。
3. **逐命令解释结果。** 保存退出码、执行/收集数量和错误位置，区分目标 bug、环境阻断、既有无关失败、skip/零收集、未检查。总脚本退出 0、成功 import、只做 collect-only，都不能替代功能执行。不要把所有失败改判 infra。
4. **修后复验原路径。** 保存旧失败与新配方的对应证据。base 应仍能暴露题目 bug，不要求它全绿；必要时在独立私有容器用 gold/已知修复做同命令对照，确认不是环境失败。编译型项目核重建后的工作区产物确实被使用。带过答案的容器不交给 solver，求解从干净初态开始。
5. **按影响范围交接。** actor 专属修订复验相关开发路径；若共用依赖、构建、资源或题材同时影响 grader，再补受影响题的真实 RH2 noop/gold。同仓可复用配方与共同证据，逐题入口仍需确认，不从一题通过推导全仓可用。

不要求全仓测试全绿或可执行隐藏验收。容易修的相关环境噪声优先处理；昂贵全仓路径、无关旧缺陷可以保留有范围的限制。若必要验证仍被环境阻断，只能安排明确标注的环境诊断，不能把失败混入公平的模型能力比较。

## 4. 依赖、网络与私有材料的边界

- 预置公开开发底座与“任务要求模型新增依赖”分开。已知框架版本冲突应修好；合理解本来需要增加的依赖，不根据 gold 提前泄漏。验证包管理工具、可写范围与已批准供应路径可用，并让依赖声明随候选交付。
- 区分准备、解题、候选安装、测试执行的网络需求。可固定的公开权重/资产优先预置并核 actor 可读；确需运行期服务则写明具体用途，按当批网络政策验证，不从“需要 pip”推出任意公网可用。
- actor 可共享公共依赖层，但不带入 gold、隐藏测试、私有评分脚本或审查结论；不强制与 grader 使用同一完整镜像。环境说明也不能把隐藏测试的定位提示送给 solver。

## 5. 最小证据与回流

沿用既有逐题记录，不新建资格平台。回填：**题号/材料版本、实际入口与代码版本、镜像 ID/配方、HEAD/初态差异、有效 profile 与 UID/HOME/cwd、工具进程解释器/PATH、必要资产权限、命令/退出码/执行结果、代码生效证据、日志、资源与清理、未验证范围**。共同项可以引用；缺失写未知。脚本已写、命令已跑、修后已验证分别记。

交付示例：“公开复现可跑；相关 6 项测试执行，1 项为 base 目标失败；gold 私有对照同命令通过；其余全仓路径未验”，优于“环境通过”。静态候选、grader 对照成立、actor 开发可用、模型已求解是不同状态。

真实求解仍会遇到未覆盖路径。发现新失败后先与同条件干净 base 对照，再修对应配方、检查同条件受影响题。保留旧结果与修订版本，不能把修前/修后混成同一比较条件。流程降低可预见故障，不承诺穷举模型未来所有操作。
