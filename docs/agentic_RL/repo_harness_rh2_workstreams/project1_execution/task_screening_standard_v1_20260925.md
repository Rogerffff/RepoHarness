## 0. 目标与原则

**首要目标：进入训练的题，reward 能区分题目的核心行为；环境不会让正确解失败。** 不追求每道题完美，也不追求挽救每道题。

1. **按用途下结论**（§2）。"环境合格""needs_review""能力探针通过"都不自动等于能训练。
2. **按根因编号，按影响定严重度**（§3、§4）。类别名只说明问题出在哪一层，严重度由一套判定步骤给出，每一步都要落到可复现的证据上。
3. **共同根因优先，按变化复验**。环境、构建、链路问题修一次；按相同机制与条件扩到受影响题，不按仓库名推广。只复验变化影响到的部分，不因采用新标准重跑已有结论。
4. **便宜的证据先取，深度按风险投入**（§7）。
5. **预授权模板 + 停止条件，不设预算**。模板内修订由 Claude 执行、Codex 复核；超出模板、修订不收敛，或一次聚焦复核仍解决不了的，暂挂该题并写明原因，不反复加人投票，也不逐题上报。
6. **证据分层照旧**：静态推断、历史运行、当前 CPU、真实模型分开写；未查写未查，证据不足写 conditional，不写 yes。

## 2. 每题的用途结论

| 用途范围 | 条件 | 不能推出什么 |
| --- | --- | --- |
| **问题定位** | 无门槛：环境未就绪、题意有争议、评分含义未知的题都可以调查 | 结果不并入能力分数 |
| **能力比较** | 公开开发路径、评分依据、本批有效运行条件已核对；争议与环境阻断单列 | 不等于训练资格。报告必须给出共同题单、实际预算、有效分母；只剔除无效尝试，不因模型没做对而剔题 |
| **训练候选** | 满足能力比较的条件，**且有正面覆盖证据**（见下）；没有未处理的 S1；S2 已登记；跨题关联已登记 | 训练价值另看难度、成败混合和成本 |
| **留出评测候选** | 满足训练候选的质量条件；未用于选模型、调提示或调配方；按 §9 D3 的划分规则与训练集隔离，并核对训练集初态不含其答案 | 修订过的题只能作"标明版本的自建评测"，不冒充原 benchmark |

**训练候选需要的正面覆盖证据**（F5）：
- 核心公开要求 → 决定性断言的对应关系；
- 当前版本上的 noop 为 0、正对照为 1，并注明所用材料与环境版本；
- §4 第 2、3 步的结果；
- 未查范围。

"脚本没扫出风险"不能代替以上证据。

**记录方式**：在 `usage` 下分别写四项，取 `yes / conditional / no`。`conditional` 要写具体差什么条件、对应哪条证据。
- 因成本或资源（机器、长时间运行）暂停的题，保留 `needs_review` / `needs_repair` 并写原因，**不写成"只适合诊断"这类质量结论**（复核 §6.1）；
- 旧版本证据不能解除新版本的条件；
- 这些都是离线题卡字段，不接成 rollout 闸门。

## 4. 严重度判定步骤

按下面的顺序判；**命中任一条即为 S1**（进训练前必须修，修不了就不进训练）。五步都不命中且证据齐全，才是 S2（可进训练，登记并抽查）。证据不足记 conditional，不进训练。

**核心要求**指公开题面标题与"期望行为"所述的要求，**按题面表述的一般性理解**；gold 的实现范围不决定核心要求的范围。

| 步 | 问题 | 证据 | 命中后的去向 |
| --- | --- | --- | --- |
| 1 | 核心要求在参考测试里有没有直接断言？ | 需求—断言表 | 没有 → S1（T2a） |
| 2 | 核心断言是否**只用了题面示例的字面值**（同一个 tag、同一个退出码、同一个输入形态）？ | 对照测试输入与题面示例 | 是 → S1（T2c，示例拟合），走 R-c 补一个**非示例实例**。依据是题面的一般表述；gold 或经核实的替代正对照必须能通过（§5）。本步按严格版执行（D1 已确认） |
| 3 | **退化探测**：在 gold 的修改位置构造 1 个已确认违反公开要求的退化候选，看它能不能得 1 | 违例依据 + 1 次正式评分 | 得 1 → S1（T2b） |
| 4 | 已有的具体候选里，有没有得 1、但在**同一核心要求的其它实例**上违反公开要求，或破坏了**有文档、常用的公开行为**的？ | 真实模型候选，或审查中已构造的候选；只用已有证据，不要求为此另找 | 有 → S1。只影响边缘输入、罕见路径 → S2（T3） |
| 5 | 以上都不命中 | — | S2；登记已知缺口 |

**退化候选**指只凭 gold 的修改位置就能写出来的补丁：
- 关掉检查、提前返回；
- 吞掉错误、抑制症状；
- 写出空产物；
- 与输入无关的固定结果（一律接受或一律拒绝、硬编码输出值）；
- 作用在无关对象上（存到旁路属性、校验错误的连接）；
- 就地改坏被比较的输入。

以上是构造方向，不是仅凭补丁形状判错：提前返回或抑制某个错误也可能是正确实现。须指出候选违反哪条公开要求、在哪种输入下违反；可复用明确的源码推导、已有公开测试或行为对照，不要求另做一套实验。评分证据还要确认该候选确已交付、相关测试确已执行、结果完整有效。应用失败、环境故障、未进入目标路径不能充当“错误解被测试拒绝”的证据；不足时记 conditional。原版与修订版分别留结果，修订验收沿用 §5。

**第 2 步统一了 v0 里判得不一致的情形**：
- datalad 硬编码退出码 3、pillow 只登记 41988 这个 tag、numpy 只特判 None、只处理整数 1，都是"只对题面示例的字面值成立"，归同一类；
- 在原测试只用示例字面值的前提下，它们都由第 2 步判为 S1。

**实时判定**：
- 基座探针中首次触发已登记的 S2 缺口 → 按上表重新评估，不自动升级（F1）；
- 训练中的处理见 §8 与 §9 D2。

**分歧处理**：主审写出公开要求、决定性断言和具体后果，复核只针对这一判断给反证。一次聚焦复核仍不能解决、又没有便宜的辨别实验，就暂挂为 conditional（复核 §6.4）。

## 5. 修订模板与验收（D4：R-a 至 R-f 已一次性授权）

| 模板 | 做什么 | 边界 |
| --- | --- | --- |
| R-a | 处理无效断言、ID 失配 | 先区分三种情况：ID / 解析问题、无效断言、有效但不稳定。改 ID 要有"同一测试、无碰撞"的证据；改期望状态要有独立的语义或环境证据，不复制本次 gold 输出。**R2E 的键集必须严格相等：删 expected 键时，要同时从隐藏测试里删掉对应测试，不能留下 unexpected**。SWE 的 F2P / P2P 按各自来源处理 |
| R-b | 把没有公开依据的实现约束（文案、内部 helper、mock 形状）放宽为有依据的行为断言 | 有依据的行为要求必须保留；任务目标层面的分歧（P5）不在本模板内 |
| R-c | 补有公开依据的断言：非示例实例、核心场景、有文档的常用行为 | **每处修改只针对一个有公开依据的窄问题及其受影响的测试范围**，不按断言条数限定（F6）。一题有多个 S1 缺口时逐个列出、分别写依据，合并在同一轮修订里完成。可复用现成的公开测试，例如把公开测试加入 P2P，或加入 R2E 隐藏测试 |
| R-d | 环境、资产、配方修复，评分参考不变 | 见下方"R-d 验收" |
| R-e | 把 mock 交互测试改成真实行为测试 | 必须同时覆盖正例与反例，例如合法指纹与错误指纹，防止"全部接受"或"全部拒绝"也能通过 |
| R-f | **题面修订**，只做以下三种：删除或改正对 base 代码与公开行为的错误陈述（须在 base 上实跑证实）；删除直接给出答案的内容，换成在 base 上核实过的症状描述；补一句已有公开依据（文档、API、公开旧测试）且解题必需的说明 | **不得**把隐藏测试的细节（精确文案、内部 helper 名、测试输入）写进题面，不得新增没有公开依据的要求；选择任务目标的两种读法（P5）不在本模板内 |

**R-a / R-b / R-c / R-e 的验收**：
- 正对照为 1、noop 为 0；
- 本次要纠正的那个误判已被纠正；
- **已知相关的错误候选仍为 0**；
- 公开核心要求有直接断言，并指出修订后仍受保护的公开要求；
- 保存新版本、父版本、理由和触发反例；
- Codex 复核。

**R-f 的验收**：
- 由一个没看过隐藏测试与 gold 的新公开读者读修订后的题面，推出的需求与核心断言一致，且不需要猜测隐藏细节；
- 逐行核对题面改动：没有复制隐藏测试细节，没有答案内容；
- 评分材料不变，或与同题的测试修订一起按其验收；
- 保存新版本与父版本；修订后的题只作"标明版本的自建题"，不冒充原 benchmark；
- Codex 复核。

两条限制：
- **不追着候选改分**：不要求所有曾被叫作"合理"的候选都变成 1，正对照要先核实确实满足公开要求（复核 §6.2）；
- 没有误拒案例的修订，不必专门造一个。

**正对照**：默认用 gold。有公开依据的新断言让 gold 通不过时，按 §9 D4：
- 若有**经独立核实**的合理替代解，允许用它作正对照做窄修订，并记录原 gold 的失败；
- 否则暂挂。

任何情况下都不为保住 gold 而放宽需求。

**R-d 验收**（复核 §6.2）：
1. 写清改了哪些依赖、资产、权限、资源，适用哪个镜像版本；说明它为什么恢复了能力，并证明没有靠升级被测项目、带入答案或改变目标行为来替代解题。
2. 复验原失败路径，确认用到的是候选工作区或其真实构建产物，且未修源码时公开 bug 仍然存在。只有"import 成功""包路径正确""安装 rc=0""noop=0"都不够。
3. 按影响范围复验：
   - actor 专属的修订先复验 actor；
   - 影响 grader 或共用行为的，再补真实评分的正负对照；
   - 涉及权限、构建、资源归因的，用同身份、同 profile 的定点对照，不从 root 成功推出 agent 成功。
4. 写清修好了什么、没查什么；失败的配方保留。不要求全仓测试全绿，但**本次看到的失败必须解释**：参考键全过而完整测试仍失败，不能直接核销为环境正常（Modin6937）。

**模板外、需要用户决定**：
- 超出 R-f 范围的题面改写；
- 改变任务目标（含 P5）；
- 改通用评分语义（例如评分端代为构建、改 parser 或判分规则）；
- 改网络政策；
- SWE-Gym 修订机制的实现（先按 §9 D6 探索成本）。

用户不决定，不阻塞其它题。

## 6. 环境与开发条件

- **按阶段核能力**（F4）：分准备、解题、候选安装 / 构建、测试四个阶段，引用当批有效 profile。只有完成必要公开操作所需的能力在该阶段缺失，才判不支持。
  - grader 多一个私有测试工具，不单独构成 E1；
  - 经已批准的供应安装公开依赖，不因为联网就构成 E4。
- **目标调用链语义一致**（复核 §7.1(c)）：
  - gold 修改的模块直接依赖的库、相关公开测试依赖的框架，版本必须与 grader 实际解析到的一致（例：DVC4166 的 pathspec 0.12.1 与 0.8.1 对 `.dvcignore` 的匹配语义不同）；
  - 只在评分侧使用的工具记录即可；
  - 一次性比对安装清单只作线索，要以跑公开测试的实际行为为准。
- **交付路径**（复核 §6.3）：沿当题实际采用的路径取证。例：R2E 的正式导出基于文件字节差异，会带上 `.so` 等构建产物，不经过 git。
  - 共用链路做一次代表性验证即可，逐题只补自己的构建与加载缺口；
  - 编译型题要核实"改源码 → agent 构建 → 正式导出 → 全新 grader **实际加载了新产物**"；
  - 其它解释器、构建系统按类型抽查，不从一题推广到全池。
- **环境身份**（复核 §7.2 第 7 条）：每次运行记录镜像 ID 与 RepoDigests、Docker 版本与存储后端、profile 摘要、CC 版本、adapter 装了哪些包装、派生配方哈希。跨后端的镜像标识差异先核对其含义，不能直接当作内容变化或内容相同的证明。
  - Docker 29 的**全新安装**默认使用 containerd 镜像存储，升级安装不一定切换；切换后端会使另一后端的既有镜像与容器暂时不可见。使用当批运行手册已验证的后端；若历史入口依赖 overlay2，在机器准备阶段处理并复验，不把“新机器一律切回”当通用规则，也不在有作业时自动切换。[Docker 官方说明](https://docs.docker.com/engine/storage/containerd/)
- **可取回的产物**（复核 §7.2 第 8 条）：配方引用的自建或改过的产物，要连同 sha256 存档在能取回的位置；否则配方必须能从公开来源加已记录的修改完整复现。
- **公开 / 私有边界不变**：私有审查者按隐藏测试或 gold 写的验证命令，只留在私有对照里，不进解题者的环境说明。

## 7. 流程与深度

### 7.1 每题的顺序（F6）

1. **材料与脚本预检**（秒级，全部题）：期望 FAILED 键、目标测试数量与断言类型、mock / patch 内部名、精确字符串断言、调用后才读输入、gold 改动含编译源码、题面与 gold 重叠、两份跨题比对、P2P 为空、镜像初态有脏文件、解题侧与评分侧依赖差异。**只决定后续审查深度，不代替核心检查**（F5）。
2. **公开读者**：只看公开包，产出需求、合理路线，以及**机器可读的命令清单**（`id / cmd / timeout_s / expect`，与 `devcheck.py` 同一格式）。
3. **开发核对与私有调查**：
   - 原样执行公开命令，不静默改动；命令本身写错时保存原命令和失败，按公开依据修正命令后再验证，不把命令错误判成题目或环境缺陷（例：插 `-p no:cacheprovider` 与 `--failed-first` 冲突）；
   - 记录原例能否复现、替代复现方法、最小公开验证的墙钟时间（用于判断题目是否适配模型的解题回合与上下文预算，不是质量问题）；
   - 书写命令时防这些坑：`| tail` 会吞掉退出码（用 `pipefail` 或 `PIPESTATUS`）、没有 xdist 时用了 `-n`、报错信息的大小写、`PYTHONPATH`、`pkill -f` 误杀自己；
   - 主审先封存"读历史前的初判"，再对照历史，完成 §4 第 1–5 步。
4. **定点实跑**：
   - §4 第 3 步的退化探测，每题 1 次；
   - 另外，只在实验结果会改变处置时才跑候选；每个决定性问题优先用 1 个有代表性的候选回答，不为凑数造候选；
   - 私有行为矩阵（对已有真实候选跑变体）按公开需求判对错，不以 gold 为答案。
5. **独立复核**（§7.3）。
6. **修订与验收**（§5）：一轮修订、一轮验收，不收敛就暂挂。
7. **批次汇总**：分别计数"环境修复""语义修订""未知 / 成本暂缓""可作能力比较""训练候选"，保留仓库与任务类型的分母；不把候选数当成原池的有效率。

已有同版本的命令、环境证据和结论直接复用，不为套新流程而重做。

### 7.2 批次规模与停止条件（不设预算）

- **每批 12 题**。不设会话数、正式评分次数、机器时间的上限（D5）。子代理用 Opus 5.5，推理强度 extra；并发上限沿用 6。
- **执行器配置分开登记**：上述 Opus / extra / 6 是 Claude 侧派发配置；Codex 侧没有该模型调用入口，SWE-Gym 任务一沿用户已指定的 `gpt-6-astra / high`，并发受实际工具上限约束。批次 brief 如实记录模型、强度与并发，不能宣称调用了不可用的模型；每题覆盖、角色独立与验收规则相同。
- **仍然要写进批次 brief 的**：用哪台已批准的机器，先由谁产出命令，复用哪些已有证据，在哪里停。不因为本文没有上限就自动租新机器。
- **成本分层照旧**：开发快检与完整评分的开销不同（MONAI763 完整 gold 5431 秒、pandas48106 安装重编约 709 秒），不把"约 1 分钟"当超时；长跑的题排队执行；共用配方按家族复用，区分"根因定位与配方开发"和"逐题复验"。
- **停止条件**（与预算无关）：一轮修订不收敛、一次聚焦复核仍有分歧且没有便宜的辨别实验 → 记 conditional 或 `needs_review` 并写原因，转下一题。
- 各来源已完成的题复用现有证据，不为统一新流程重做三个角色；新标准尚缺的证据在当前题卡补记，不能直接沿用旧 `ready` 标签作训练资格。

### 7.3 独立复核的覆盖面

- **每题都做独立复核**（不设会话预算后，不再抽样）：公开读者、主审、复核三个角色都是不继承协调上下文的新会话；
- 修订题另由 Codex 复核；
- 以后若扩到全量 R2E、需要抽样，再按仓库、环境类型、风险来源分层并预先登记名单，不宣称比例能保证漏检率。

### 7.4 共用工具（各线程不再各写一套启动器）

- **SWE 与通用**：`rh2/experiments/task2_swegym_dev_20260925/` 下的 `devcheck.py`（正式入口开发核对）、`build_actor.py`（actor 派生）、`semantic_control.py`（私有变体矩阵）、`post_hoc_audits.json`（事后审计）。
- **R2E 扩展**：`rh2/experiments/r2e_actor_20260925/` 下的 `r2e_devcheck.py`（R2E 任务面层）、`private_control_full.py`、`postcheck/*`（结构化 `RH2_POSTCHECK`）、`postcheck/private_regrade_build.py`。
- **权限提醒**：`semantic_control.py`、`private_control*.py` 以 root 身份运行，不套正式 profile；涉及权限、构建、资源归因时，改用 `devcheck.py` 在同身份、同 profile 下对照。

## 8. 探针与训练阶段的抽查（离线，不改在线奖励）

- **后检判定**：原始 reward 与语义核对分列。后检逐项给 PASS / FAIL / UNKNOWN；没有后检或后检异常不算语义通过；打印型脚本要写明读哪一行、什么算失败，不用外层退出码代替判定（F5、Codex 第二批复核 §3）。
- **人工读补丁**：对抽中的真实补丁，保留"对照公开需求读修改"这一步，用来发现未登记的新漏洞；预写的后检只覆盖已实现的检查。
- **抽查时点**：提前到早期训练 checkpoint，以已登记风险加随机正常样本为抽样来源；成功与失败都抽，失败样本用来查误拒。
- **边界**：不新增逐条 rollout 的 LLM 奖励或审查闸门，不静默删样本。
- **训练中已登记缺口被反复钻中**：处理方式见 §9 D2。
- **候选卫生问题（H1）** 交训练设计处理。
