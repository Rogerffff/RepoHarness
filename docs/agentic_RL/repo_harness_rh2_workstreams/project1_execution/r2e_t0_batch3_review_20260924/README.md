## 4. 静态材料可以怎样使用

48 题的公开、私有、历史三类材料与当前摄入面一致；120 个隐藏文件逐个核摘要，未发现新增 gold、expected、隐藏测试或历史结论混入公开包。46 个软链都留在本题工作树内。详见 [材料独立复核](static/README.md)。

需要保持四个限制：

1. 33 题缺 `install.sh`，另外缺 6 个 datasets 软链与 2 个 aiohttp 构建脚本，均已逐题声明。普通源码/题意阅读可以开展；结论如果依赖缺失文件，再针对该题补取，不能由“没看到”推导“不存在”。
2. 15 份镜像记录证明的是所记录镜像的**公开代码树**，不是 15 个最新完整环境。后续修订主要在私有隐藏目录和 venv，当前公开树已独立重建；环境配方应引用对应运行证据。
3. 先读 public 并写问题理解与预期行为，再读 private 审核测试、gold 和替代解，最后读 history 对照既有发现。这是阅读分工约定，同一文件系统并无硬隔离；若派给真实 solver，只给公开包。
4. 四个遗留质量问题仍在：pillow `2b061b68`、scrapy `9a15fcf8`、coveragepy `5dbbe143`、orange3 `9b5494e2` 两个 scorer。不能只审 44 个环境通过题，也不能把它们的环境状态直接改为入池状态。

建议静态首批选 6–8 题校准：覆盖这四类已知问题及普通对照，再按仓库推进剩余题。每题区分题意是否自洽、测试能否接受正确替代解、是否能用明显错误解得分、真实开发条件缺口和训练价值；不要以“像 gold”作为正确性的定义。现在不需要再等 GPU 实验或重跑 48 题。本次仅提出安排，未启动正式静态筛查。
