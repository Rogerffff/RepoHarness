2026-09-21 / Codex B。**讨论稿，未启动模型、容器或付费 API。** 本轮回查当前候选、环境卡及下列官方资料；没有重新全文精读用户列出的所有论文。目标是尽早得到真实求解证据，同时分清模型、环境与评分的问题。沿用独立 RH2 评分；不把三路评分对照、全部效率优化或完整环境流水线设为前置。

## 1. 本轮要回答什么

| 问题 | 具体观察与验证 | 影响下一步什么决定 |
| --- | --- | --- |

| 成功是否来自额外答案渠道 | 轨迹里的网页/上游修复访问、未来 Git 内容、运行器篡改；也看测试通过但公开需求未实现的候选 | 标记污染/疑似误收，定点调查，不把“改了测试”或“与 gold 不同”自动判作弊 |

这些是探针的观测维度，不是新增六道全池准入闸门。现有 21 题是[受限静态候选](swegym_task_audit_20260920/quality_batch01_20260921/night_summary_20260921.md)，不是 21 题已完成真实 actor 验收。

## 2. 模型与对照

- **主比较：Qwen3-Coder-30B-A3B-Instruct、Qwen3.6-35B-A3B。** 前者有 [Uni-Agent 的 R2E-Gym RL 实验](https://uni-agent.readthedocs.io/en/latest/benchmark/rl-training.html)；后者是 [KAT-Coder-V2.5-Dev 的 SFT＋RL 起点](https://huggingface.co/Kwaipilot/KAT-Coder-V2.5-Dev)。这些支持候选资格，不预测本题池通过率，也不证明当前 miles 训练栈兼容。
- **原版 Qwen3-30B-A3B：已有链路回归参照。** 若它能帮助定位协议/运行回归，先做有针对性的少量对照；暂不为三款本地模型各铺一轮完整矩阵。
- **DeepSeek：额外求解对照，不能预设逐题都更强，更不能当正确性裁判。** 可优先考虑 API 的 `deepseek-v4-pro` thinking 配置。当前[官方模型表](https://api-docs.deepseek.com/quick_start/pricing/)将其列为 DeepSeek-V4-Pro-0813；开跑时重新记录实际 API 模型/模式/日期，滚动别名不能冒充可永久复现的权重版本。
- [DeepSeek 的 Claude Code 接入](https://api-docs.deepseek.com/quick_start/agent_integrations/claude_code/)支持云端 Web Search，并有主/辅助模型映射。不能直接复制其宽松默认配置作为受限 SWE 对照：核对实际工具清单与各路模型；容器限网不等于禁用了服务端搜索。供应包的受控网络与找上游答案分开处理。

模型使用正确的 chat template、工具解析器和 thinking 协议；不强迫不同模型套同一序列化方式。固定每款模型实际生效的推理/随机采样配置，第一轮不做参数网格搜索；重复 greedy 不能用来估计策略的探索空间，API 不支持的参数也不能记作已控制。若精度、量化或后端不同，报告为相应部署配置的结果，不能归因为纯模型差异。

前三题分别覆盖配置生成、CLI 数据流与本地服务模拟；具体开发操作、修复配方与剩余限制沿[早晨清单](swegym_task_audit_20260920/quality_batch01_20260921/acceptance/morning_cpu_shortlist.md)。mypy17071 需先收窄语义对照并核实际 actor 条件。42 条 CPU 方案是可选调查，不要求全做。明确规范争议题暂留诊断旁路，不先并入模型比较；候选身份也不保证不存在未发现缺陷。

## 4. 比较条件与两种 DeepSeek 用法

同题固定公开 prompt、仓库初态、actor 配方、权限、工具、网络、资源、CC 版本和 grader 版本。启动前明确上下文、每次生成、总交互/工具和墙钟预算，首轮不照搬论文的 128K/256K。墙钟还受推理速度影响；同时报实际输出量和各段耗时，不能把慢后端造成的截断全部算成能力差。

第一种是**共同条件下独立求解**：DeepSeek 与 Qwen 收相同公开材料和任务预算，不能多给隐藏测试、审查笔记或上一模型的失败总结。不同 tokenizer 的 token 数不严格等价，结合费用与实际交互量解释。没有共享标准答案、跨尝试记忆或临时人工提示。允许的子 agent/辅助调用须固定并记录真实模型，避免静默变成混合模型系统。

第二种是**按问题触发的调查**：全部失败、评分与公开复现冲突、异常通过、反复安装或 fresh 评分失配时，用新的调查上下文看轨迹、gold、测试和静态审查线索。它负责提出并执行可核对的最小证据，不凭一句模型判断改题。需要增预算独立重试时另记条件；增预算、补环境或获得提示的结果不能回填为原预算成功。

先检查独立解题上下文的实际可见内容。准备脚本和 CPU 对照可能接触 gold；其副本、隐藏测试及调查报告不得残留在随后交付的解题工作区中。只保存接口实际返回的推理内容及工具消息，不能承诺取得供应商未提供的隐藏思维过程。模型请求、工具输入输出、patch、环境变更和评分日志应能关联；沿用现有记录，不额外建一套平台。

## 5. 每条轨迹如何变成环境和题目证据

1. **先保留原始事实**：RH2 分数/类别、真实终止原因与 test 退出、逐参考状态、实际候选、安装请求和必要资源。超时后仍可能有可评分补丁，终止原因与评分结论分开记；infra/未知不补成 0。
2. **检查求解过程**：是否建立公开复现、读到相关源码、编辑是否生效、是否运行了合理验证、是否陷入工具或安装循环。没有运行测试本身不证明补丁错误；跑了很多命令也不证明取得进展。
3. **核成功与失败两侧**：成功补丁核需求覆盖、回归和答案渠道；失败补丁逐个看失败断言能否从公开需求/仓库约定推出。首轮数量小可全读，后续全查异常并抽查普通成功/失败。复核可先隐藏模型名/分数，减少结果偏见；不必重做已完成的全套静态角色链。
4. **只做能区分原因的复验**：包缺失用真实 actor 身份最小导入/安装复现；怀疑非确定性，重放同一冻结补丁；怀疑题意错配，给出公开需求对应的行为反例。fresh 失配先比环境变更、被投影文件与安装/构建，不立刻重构评分路线。
5. **回填处置和条件**：真实能力失败、工具使用失误、环境/接口故障、预算限制、任务/测试争议可有多个标签；因果未证实写待查。修复配方后只重跑受影响的控制与尝试，保留原版；题面/测试修订另版本审议，不按当前模型偏好悄悄改原题。

例如 DVC5839 的参考测试有 Mock 实参覆盖限制。**假设**某候选拿到 1，但公开 CLI 精度行为仍不正确，应调查覆盖遗漏，而不是把 1 当完整修复；**假设**另一条轨迹因错误解释器无法导入 DVC，应先核实际 actor 的安装/激活，而不是立刻说模型不会修精度。这里是设计示例，不是已观测的新缺陷或模型结果。

## 6. 输出与判断方式

每个“题目×模型”保留重复结果向量、可评分/执行异常数、终止分布、费用/耗时，以及已证原因。记总派发 N、有完整有效判分的尝试 V、其中原评分为 1 的尝试 S，并列报告 **S/N、S/V、infra/未知/争议数量**；V=0 不计算比例。原始分数与质量审查标签分开，S 不自动等于真实完整修复数；争议排除时明示题单和分母，不能只报删去失败后的高分。保留逐题和仓库分布，分别报平均单次成功与“多次至少成功一次”，不拿后者冒充 pass@1。

对同条件且有效判分完整的重复组记录成功失败混合；不完整组单列。稳定全 0 不自动淘汰题目，稳定全 1 也不代表题目毫无训练价值。样本小只用于提出后续训练配方假设；最终结合覆盖、可靠性和取得信号的成本选基座，不能只挑起点最低或混合比例最高的模型。

本轮交付应包含一张模型比较表、一份真实环境/接口问题及修复清单、每题的保留/再诊断建议。若确有假阳性/假阴性或环境故障，留下原结果、最小证据、修订条件及复验对照。这些可成为项目环境工作贡献；此开发池已被大量审查，后续需另留未用于调参的评测范围。

## 8. 首轮分析后的方向调整（2026-09-24 / Codex B）

**建议并行准备、分批扩大诊断样本。** A 线修复相关运行接口；B 线现在即可准备新题、裁定少量已有候选、检查所选题的 actor 开发条件。修复后的少量旧题校准通过，再运行新的共同题单。不等全部 216 题再审一遍，也不因目前 8 题就否定 SWE-Gym Lite。以下为建议，具体题号、预算与任务修订尚未定案。

### 8.1 如何解释这批分析

本次阅读 Claude 汇总、8 张处置卡与统计；独立子审完整阅读 19 份 cell 报告，另两个子审核对 MiMo 与数据扩量资料。没有重新独立精读全部 67 份原始轨迹，也没有执行处置卡的待跑脚本。

- **67 条有报告，不等于行为指标都有 67 条分母。** `cross_trajectory_stats.json` 的逐尝试结构化记录为 57 条，另 10 条只有任务调查覆盖。Read 不存在路径等行为在不同报告中又被标为不同类别；不能据现有聚合断言“只有 Coder 发生工具错误”。下一轮统一可观察事件定义与已审阅分母，不把缺测填零。
- **Conan 的“五条没修完整”需分级。** 三条有运行证据的需求遗漏，其中两条经独立固定候选复跑、一条来自自身轨迹验证；一条是已见版本修改引出的静态兼容风险；另一条是生成器范围争议。不能合算五条已运行确认的假阳性。其余“源码与 gold 在所审范围等价”也不代表完整交付没有副作用：如 DVC6954 的 `.dvc/config` 被清空、mypy17071 留下 DEBUG 和失败测试。
- **Moto5752 / mypy11236 的拒绝机制已找到，误拒仍需裁定。** 前者的 `BeginsWith`、后者的 `Final` 及消息要求，须同时核公开题意、仓库既有契约与合理替代解；“题面没逐字提到”不自动意味着测试错了。两题先保留争议诊断用途，不批量删断言或给模型补解法提示。
- **预算回看不是反事实实验。** 46 条原 reward=1 中，14 条同时落在旧请求与上下文默认内，不等于在较小预算下只能成功 14 条。CC turn、模型请求与工具调用不是同一个单位；旧 25 次请求 / 32K / 600 秒默认也不自动成为最终训练配方。
- **目前只看到一个混合奖励格子：DeepSeek×DVC5839。** 两款本地模型每格仅 2–4 次，全 0/全 1 不足以判定真实成功率为 0/1。纯组内相对二值任务奖励在同分组里没有这部分优势信号；这不等于所有可能的训练目标都没有梯度，更不支持为了制造混合组而改判。

逐题证据沿 `runs/base_probe_20260922/analysis/<task>/task_card.md` 和各 solver 的 `cell.md`；预算及接口原始计数沿[A 线交接包](base_model_probe_20260922_aline_handoff.md)。上述边界补充旧汇总，不回写历史分数。

### 8.2 外部资料给出的实际启示

[MiMo 精读 §5–6](../../../harness_improve/external_paper_references/reading_notes/mimo_v2_6_technical_report.md)描述了题意—测试核对、每题四次真实求解后的误收/误拒审计，以及另行重复执行检查稳定性。这支持把已有自然候选用于评分审计，**不要求我们给所有题机械增加“四次求解＋八次重跑”**。审查者可以看 gold，独立 solver 不可以；错误实现应失败，合法替代解也应能通过。新增断言应来自可说明的行为要求，不能只针对已见候选，也不能把 gold 实现写成唯一答案。

该报告确实不建议将多个生产 harness 原样用于 RL，理由包括无关工作流义务和组件耦合；公开训练 mini-CC 只有六种核心工具。我们应先固定真实 CC 的工具和上下文配置，检验仍有无系统性干扰；它尚不能证明本项目必须放弃 CC。[固定配置](https://github.com/XiaomiMiMo/verl/blob/e2b9fc03c6e01247f5d93c44201b068ea320b7de/config/agent/code/mini-claude-code.yaml)。MiMo 的质量奖励、多 harness 训练和新模型暂不直接接入；其公开 Code 约 3k 也仍需核实可冻结的实际任务材料。

扩量优先补仓库、修复类型和任务产生方式。[SWE-Gym 原文 Table 2](https://arxiv.org/html/2412.21139v2)中 Full/Lite 平均修改文件为 2.5/1.0、编辑行为 69.8/10.6，可支持补非 Lite 任务，但这些不是模型难度真值。[R2E 原文](https://arxiv.org/html/2504.07164v1)也筛较小 commit，不能预设其比 Lite 更难。[DeepSWE](https://www.together.ai/blog/deepswe)的来源经验支持实测课程适配；其未充分对齐的来源比较不足以替本项目淘汰 SWE-Gym。

### 8.5 看什么结果，再决定什么

- **全 0：**先拆环境、接口、规范、截断与真实能力失败；有明确机制再做预算或强模型对照，不立即删题。
- **全 1：**抽查需求覆盖和回归，确认不是测试过宽；可保留为效率或回归对照，不靠加刁钻测试制造训练信号。
- **混合：**核失败确来自候选行为，必要时重放同一冻结补丁排除评分波动；再记为可继续研究的训练信号。
- **接口/环境错误：**修受影响范围再续跑，保留派发分母与旧结果，不并入模型能力 0 分。

统一看逐题解题能力、公开验证可用性、可信混合组及其取得成本、token/时间、实质补丁缺口与失败机制；混合比例和原始通过率都不单独决定基座。若修复后的 CC 在多道已核题上仍重复出现同种工具/上下文障碍，才增加一个模型、少量题、一个简化 harness 的匹配对照，不立即替换主链。

当前探针题全部归开发诊断池。正式训练前另冻结未参与调参的评测范围，检查仓库/提交/题目重叠；推理可跑也不替代 A 的训练与权重回灌短验证。现在优先让这轮小闭环可靠运转，不先全量修复新来源、造大量 PR 题、加入在线 judge 奖励或多 harness 训练。
