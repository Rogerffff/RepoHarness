## 2. 应修改的六处

### F1 / P1：T3、T4 不能按类别一律判 S2，严重度不能只由原例是否通过决定

**位置：草案 42–44、52、64–66、134、145 行。统一采用前修改。**

当前规则将“某一类输入确实做对”“原例修好但别处回归”直接放入可训练的 S2；只有原例没修或被称为“钻空子”才是 S1。实际会出现同等程度的特判因为代码写法不同而得到不同等级：硬编码 datalad 的退出码 3 是 T2，硬编码某个 Pillow tag 却被概括为 T3。不能从实现形式推断训练会强化哪种行为，也不能把所有公开输入变体都当次要需求。

已有证据：

- [NumPy 复核 NP-2/O-2](r2e_static_batch2_review_20260925/numpy_pillow/README.md)：`5e8301c2` 的普通双操作数、单例求和维调用有公开依据；Pillow 的“零分母 rational metadata”也不只针对示例 tag。是否是核心缺口需要按该公开契约判断，不能只因换了输入或 gold 也失败就降级。
- [Scrapy 复核 S1](r2e_static_batch2_review_20260925/aio_scrapy/README.md)：已有公开支持的 dict、None 和 serializer 返回值路径出现漏修或 TypeError。它们不能未经影响判断就因“回归”二字一律视作可接受噪声。

**建议：问题编号描述根因，S1/S2 单独描述影响。** 先从公开题面、可见 API/文档/旧行为形成简短核心要求，再对照测试。核心要求未实现、关键公开行为被破坏、评分可被绕过，均可为 S1；有限且不破坏核心判断的覆盖缺口才可为 S2。证据不足保留 conditional/未确定，不自动升级或放行。G1 可导向 T2，也可导向 T3/T4。

这不要求穷举所有输入或每个回归都补测；也不直接把上述各题判成 S1。要求的是补上目前被类别跳过的影响判断。§6 的“S2 一旦命中就升 S1”也改为重新评估影响：已登记边缘缺口第一次被真实模型触发，本身不自动改变其严重度。

**验收：** 用空 `.gitignore`、Pillow 仅特判 tag、NumPy 求和维、Scrapy 常用路径 TypeError、一个有明确范围的边缘遗漏各过一遍文字决策。解释须引用公开需求和行为后果，不靠“特判/回归”标签或 gold 的结果裁决；据此重核 §7 的候选表，16 题只是拟议处置数。

### F2 / P1：R-a/R-b 的预授权需要防止删除有效要求；抖动和 XPASS 都不是删键依据

**位置：草案 40、45、51、72–76、78–87 行。统一授权模板前修改。**

E5 将确认抖动且无法稳定直接连到 R-a 删键；T5 将死键、ID 错配、XPASS 同列 S1；P5 建议两种读法都接受。这里混合了运行现象、来源语义与题意修订。

已有[同一 aiohttp 键的反例](r2e_static_batch2_review_20260925/aio_scrapy/README.md)：历史连接未就绪与候选取消顺序回归落在同一测试键。即便该键确有抖动，它仍可能保护有效行为。gold/noop 仍可区分，只能说明另一个目标键还在，不能证明删除这条回归保护合理。XPASS/期望 FAILED 也须按固定来源解释，状态词本身不证明题目有错。

**模板应增加以下边界：**

1. 先区分 ID/解析问题、无效断言、有效但不稳定的断言。修 ID 要有无碰撞、同一测试的证据；改预期状态要有独立的语义/环境证据，不能仅复制本次 gold 输出。
2. 有效断言不稳定时，优先修同步/fixture/环境；仍不能稳定且没有等价覆盖时，暂留诊断。删除须证明该断言无效、已冗余，或已由确定性的行为检查承接。
3. R2E 的键集严格相等。只从 expected 删除但 runner 仍产出该键，会变成 unexpected；要显式说明运行测试与 expected 的对应修订。SWE F2P/P2P 则沿自身来源处理，不把两者合成通用“删键”。
4. R-b 只能放宽无公开依据的实现约束，同时保留有依据的行为要求。两种实现都符合确定需求时可以都接受；若争议是“应合并还是替换”这样的任务目标差异，不能仅把两种相反输出 OR 起来就宣布题意已解决。

**验收：** 规则应保留有效的取消顺序反例；ID 改绑前后是同一测试；R2E 删除例没有遗留 unexpected；每个修订能指出仍被保护的公开要求，并用已知相关正反例确认。无需每题新增固定数量的攻击样本。

### F3 / P1：删除 E3 的统一“infra 并重跑”，保留 A 线现行失败处置

**位置：草案 38 行。跨线程采用前修改。**

权限、导出、清理、答案可达的后果并不相同。既有决定明确：未归因异常/账实矛盾不能靠 ABORTED 补采掩盖，无法确认终止有 run-fatal 处置；候选自身错误也不能因为发生在环境中就免计。出处见[预算 Brief §1/批 A](budget_loop_impl_20260909/README.md)与[失败剩余批](failures_remainder_impl_20260909/README.md)。

**建议替换为：**“题级记录标注受影响的验证范围，保留运行原始结果及既有错误分类；通用链路问题交 A 按已定失败模型处理。修复后按影响范围安排离线复验。本标准不增加在线重试、不改 fatal/infra/reward，也不把历史失败回写成成功。”

答案暴露还涉及能力/留出成绩是否有效，不能只当一次基础设施重试。修好隔离后重新求解的结果另记，不复用已看过答案的求解上下文。

**验收：** 用“容器停止状态未知”“候选破坏导入”“已确认的暂态基础设施失败”“solver 已读到答案”四种情形走规则，结果不得统一为 infra+retry；无需改错误映射或新建判断服务。

### F4 / P2：环境条件应验证任务所需能力，不要求两侧依赖相同或一律离线

**位置：草案 36–39、75、102、115、163–164 行。首批套用前修改。**

actor 与 grader 有私有测试工具、安装阶段、可见文件等合理差异。安装包清单不同是线索，不等于正确解会失败；相同清单也不能证明实际导入候选。一次性比对可以辅助找差异，不能据此给两侧机械补齐全部私有依赖。

E4 的“依赖外网即 S1，只能预置或离线”还会把已批准的受控供包需求也判为不支持。[第六组记录](batch6_efficiency_20260921/README.md)已记网络 1A+2A 批准；[组件复核](batch6_efficiency_20260921/review_supply_components_20260925/README.md)同时明确当时未完成正式消费。应按具体作业实际启用情况核验，不由筛查标准再定一次网络政策。

**建议：** 分准备、解题、候选安装/构建、测试，引用当批有效 profile。只有完成必要公开操作所需能力在该阶段缺失，才判当前条件不支持；已批准但未接好的供应记待验证。E1 检查功能兼容、路径/权限、候选实际生效和合法改动的交付，不要求完整镜像或依赖集合相等。R-d 不得通过预装被测项目的新版本消除原 bug、带入答案，或让 grader 脱离候选工作区。

**验收：** “grader 多一个私有测试工具”不能单独构成 E1；“通过批准供应安装公开依赖”不能仅因联网构成 E4；目标源码修改在两侧确实生效的证据仍保留。

### F5 / P2：训练候选必须有正面覆盖证据；conditional 与后检覆盖范围要可读

**位置：草案 22–26、102–109、130–135 行。大规模套用前澄清。**

“没有 S1”不能由“没有扫描到风险标签”代替。脚本无法完整识别题意、隐式 fixture、动态 mock 和行为旁路。原[八方面协议 §2](swegym_task_audit_20260920/quality_review_protocol_20260920.md)已经要求需求—断言双向映射，应明确保留为每题基础工作；风险信号只决定深入程度，不决定是否理解核心目标。

建议每题沿用现有记录，最少说清：核心公开要求、对应的决定性断言、已有 noop/正对照及适用材料/环境版本、未查范围。缺关键证据仍是 conditional/unknown，不能填 yes。`conditional` 写具体尚未满足的条件与对应证据引用；这仍是离线题卡，不把它接成 rollout 新闸门。

语义后检也不能限于预先写好的 `RH2_POSTCHECK`：它只能覆盖已实现的行为检查。既有脚本需要明确逐项 PASS/FAIL/UNKNOWN；对抽中的真实补丁保留阅读修改与公开需求的环节，以发现未登记的新漏洞。没有后检或后检异常不能当语义通过，不据 LLM 意见即时改奖励。

X2 还须区分“报告引用笔误”与“实际题面/base/测试/版本串题”。后者会影响题目本身，核清前不能沿用资格；前者修引用即可。

**验收：** 无扫描标签但主断言缺失的题不能自动成为训练候选；旧版本证据不能解除新版本条件；全量后检通过只解释为已查项目通过；两种串题有不同处置。不要求重写旧 JSON 或补齐所有未查的边缘项。

### F6 / P2：流程顺序和预算口径目前不能直接执行

**位置：草案 14–15、74、94、100–117、172 行。派发新批前修改。**

- 步骤 1 要原样使用公开读者命令，而公开读者到步骤 2a 才出现。应是“材料/脚本检查 → 公开读者形成需求与命令 → 开发实跑与私有调查 → 按需独立复核”。已有同版本命令和环境证据可复用，不必为顺序重跑。
- “原样使用”应指不静默改动。若命令本身错了，保存原命令及失败，按公开依据修订命令再验证；不能把 reviewer 命令错误判成题目或环境缺陷。此前 `-p no:cacheprovider` 与 `--failed-first` 冲突就是现成案例。
- “约 1 分钟、5–8 次评分”是估计，不是完整预算。应写明每批实际可用的机器/时间或费用额度、候选评分额度，以及超额停止后如何保留结果。共用配方成本按家族核算，避免每题重复计费或全算在第一题上；按批准机器范围执行，不因表内参考值自动租机。
- R-c 的“不超过两条断言”不能可靠限定改动范围；一条循环断言可以覆盖任意大改，而 §7 datalad 已列三个行为。建议限制为一个有公开依据的窄问题及受影响测试范围，按诊断/验收预算止损，不用断言条数作正确性边界。
- 普通题 25% 可以作为首轮成本选择，但按仓库/环境类型/风险来源分层并预先记录抽中名单；不能宣称该比例保证漏检率。抽中后发现共同根因，复查同类而非机械维持比例。全部 S1、修订和争议仍按批准的独立审查范围处理。
- 第二批已有不少 S1，不能用“普通题只抽样”的 26–30 会话估计代表它的真实节省。先按实际分类计数；已完成 20 题复用证据，不为统一新流程重做三个角色。

**验收：** 批次 brief 能回答先由谁产命令、用哪些已有证据、实际最多投入多少、在哪里停止；不再出现未有公开命令就派实跑、超过预算却无判据的情况。数值由本阶段预算决定，不在本报告替用户冻结。

## 3. 三项政策选择：不是都要改成审查阻塞

1. **gold 新断言不通过就只诊断（草案 87 行）**：这是可选择的成本止损政策，不是数学或评分必须如此。可以保留；若已有独立验证的合理替代解，也可以预授权在窄修范围内用它作正对照、保留原 gold 失败记录。没有合适正对照再停止。两种方式都不允许为了 gold 放松需求，不必逐题重新问用户。
2. **留出必须按仓库分离**：可作为项目一的默认评测设计；不是所有同仓题都无法评估。原处置约定把它留给泛化目标决定，本稿应明确这是待批准的项目默认项，并记录审查/模型调参暴露。技术修环境与依据模型表现反复调题区别对待。
3. **与旧文件的关系**：v0 实际改变了独立审查覆盖、用途字段和修订权限，不能只写“不推翻旧协议”。定稿加一小段“本版替代哪些条款、哪些保留、适用哪些来源/版本”；未覆盖的新问题沿原八方面调查，不因目录无编号就忽略。无需重写全部历史文档，只在方法入口指向新有效版本；旧运行与旧题卡保留原始版本。

## 4. 用已有反例验收标准，不再新造一轮题库实验

| 输入情形 | 标准应得出的结论 |
| --- | --- |
| 空 `.gitignore` 满分 | 核心判据失效，修订或诊断；不因存在另一条通过测试而放行 |
| 只修一个输入/标签 | 对照公开适用范围和影响，不能凭“特判”一词自动分 S1/S2 |
| 有效回归键既出现过连接抖动，也能发现候选取消错误 | 分根因调查；不自动删除整键或将所有失败归环境 |
| XPASS / expected 含 FAILED | 按固定来源和具体行为核验，不由状态词直接判死键 |
| R2E expected 删除一个仍被 runner 输出的键 | 修订验收失败，不能误称对称删除已完成 |
| 容器无法确认停止 | 沿 A 的既定终止处置；筛查规则不改为补采 |
| grader 多私有依赖、actor 公共开发链正常 | 差异记录即可，不要求两个环境完全相同 |
| 扫描无标签、核心断言未读或证据版本不符 | 仍待核；“无已知 S1”不能代替已完成核心检查 |
| gold 在合理新增断言失败、独立替代解通过 | 如实记录；按批准的成本政策选窄修或诊断，不缩小题意 |

## 5. 建议定稿与停止条件

保留现有总体结构；修正 F1–F6，由 Claude 更新 v1 并标出与旧方法的替代关系。用户一次确认分类/用途政策、修订模板及阶段预算后，各任务即可按统一规则执行；模板内不增加逐题确认。

定稿复核只核上述边界与已有反例，不要求证明所有题无缺陷、重跑已完成题库、实现新平台或立即完成题面修订系统。§7 的修订是待批准的应用建议，不随本次文档审查自动实施；正式训练用题版本与留出安排仍由对应作业记录承接。

本轮仅新增本复核文档与环境留言板入口；没有修改原草案、生产/测试代码、题面/隐藏测试/expected、历史运行证据，没有操作机器或提交推送。

## 6. B 线经验补充与交叉裁定 / 2026-09-25

**复核者：当前 B 线 Codex。同意 F1–F6，没有需要推翻的结论。** 依据为 216 题真实评分及 166 题维修记录、40＋32 题静态交付、67 次模型尝试的处置卡，以及任务二 21 题开发核对与最新裁决；本次回读这些记录，不冒称重新逐条审完所有历史轨迹。以下补充合并进 v1 即可，不再建一套平行标准；不授权 §7 的逐题修订，也不代验正在修改的探针脚本。

### 6.1 把“可调查”与“可比较能力”分开

草案 §1 的诊断用途同时承载定位故障和观察模型能力，但前者未必已有可解释评分。Modin 原材料缺失、actor 依赖不可用、parser 含义待核，本来就需要诊断，不能因诊断条件要求“环境可运行、0/1 已可解释”而无处登记。

**建议不增加生产状态，只在用途说明中区分：**

| 用途范围 | 可做什么、不能推出什么 |
| --- | --- |
| 问题定位 | 可调查未就绪环境、争议题和未知评分；保留失败与未知，不并入能力分数。 |
| 模型能力比较 | 所选题的公开开发路径、评分依据及本批有效运行条件已核对；争议和环境阻断单列。必须报告共同题单、实际预算和有效分母；只剔除无效尝试，不能因模型没有做对而剔题。 |
| 训练候选／留出候选 | 沿修正后的质量条件分别决定。能力探针通过不自动成为训练资格；训练价值再看难度、成功失败混合和成本。 |

首轮 Dask8597 六次全过仍是有效的工具／环境对照，不能因区分度低判坏题；Moto5752 则继续诊断且不进入比较分母。因预算不足暂停的题保留 `needs_review/needs_repair` 与成本原因，不写成“只适合诊断”这种质量结论。参考[首轮记录 §8.8](base_model_probe_run_20260922.md)、[环境总入口](environment_pipeline.md)。

### 6.2 R-d 要有自己的窄验收；其它模板也不能追着候选改分

草案 §3 的统一验收特意没有包含 R-d，但环境修订是本项目占比最大的工作，不能只靠“参考集合没变”认定保留了任务。166 道维修题中 **144 道原始 gold 已为 1**；当时仍存在安装失败、旧产物及参考集合外的环境故障。见[修复口径与证据](env_recipe_repair_20260919/README.md)。

建议给 R-d 补四条，按受影响范围执行，不要求每题机械跑一套新检查：

1. 记录真正改变的依赖／资产／权限／资源及适用镜像版本；解释为什么它恢复开发或评分能力，没有通过升级被测项目、带入答案或修改目标行为代替解题。
2. 复验原失败路径，确认用的是候选工作区或其真实构建产物；相关公开 bug 在未修源码下仍存在。仅 `import` 成功、包路径正确、安装末 rc=0 或 noop=0 都不足以单独证明这一点。
3. actor 专属修订先复验 actor；影响 grader、候选安装或共用行为时，再补相应真实评分正负对照。版本未变且适用的已有证据可直接引用，私有 gold 容器不得交给 solver；涉及权限／构建／资源归因时用同身份同 profile 的定点对照，不能从 root 成功推出 agent 成功。
4. 结果写清修好了什么、仍未查什么；失败配方保留。共享根因按**相同机制与条件**扩到受影响题，不能只按仓库名或相同测试 ID 推广。

两点要保留：**不要求全仓测试全绿**，但本次已看到的失败必须解释；不能将“参考键全过、完整测试仍有故障”直接核销为环境正常。Modin6937 的 gold 参考全过而全测试仍失败，就是现成校准案例。

对 R-a/R-b/R-c/R-e，再补一句：**验收修订是否纠正了指定误判，不能要求所有曾被称作“合理候选”的补丁都变成 1。** mypy11236 的最新行为裁决确认其中两条还存在其它误报；消除文案争议，不意味着这些实质错误也应被放行。正对照需先确认满足相关公开要求；相关错误对照用已有反例即可，没有误拒案例的修订不强制造一个。见[任务二裁决](task2_swegym_dev_conditions_20260925/t0_decisions_20260925.md)。

### 6.3 补上“合法解能否交付”，并保留公开／私有材料边界

E2 的单一路径不足以概括所有来源。标准应先写明当题支持的是哪些源码／配置／资产／构建产物，以及实际入口如何导出、投影、安装和加载；然后沿**已采用的路径**取证。不能默认所有构建产物都被忽略，也不能默认评分端会重新构建。orange3 的 census 正式导出与旧 Git 探针就曾被混淆，见[R2E 复核 F1](r2e_static_batch2_review_20260925/README.md)。共用链路代表验证可复用，逐题只补自己的构建和加载缺口，不逐题重审导出器。

静态协议中的交付检查应继续属于每题基础检查。例：[MONAI1121 勘误](swegym_task_audit_20260920/quality_expansion_20260925/final_acceptance_errata.md)的公开任务是补神经网络测试，与预定非测试交付范围的边界待核；这不是换依赖能解决的问题。核清前记当前工作流适配待定，不能要求 agent 做完再因交付规则不支持而给它 0，也不能据此宣判来源题无效。

公开读者仍只看公开包；私有审查者根据隐藏测试/gold 产生的验证命令，留在私有对照中。不能为省时把新增验收输入、隐藏测试定位或参考修法加入 solver 的环境说明。公开命令若有错，按 F6 留版本修正；需要判“未公开要求”时，补查当时可见文档／API／旧行为，不把“题面没逐字写”当充分依据。既有[开发流程 §4](actor_development_validation.md)和[八方面协议 §3](swegym_task_audit_20260920/quality_review_protocol_20260920.md)已经规定这些边界，v1 引用即可，不另加角色或平台。

### 6.4 降低成本靠复用与停止条件，不靠把问题改名

- **低风险修订按批预授权，分歧按证据收敛。** 主审指出公开要求、决定性断言和具体后果；复核只对该判断给反证。一次聚焦复核仍不能解决且没有便宜的辨别实验，就暂挂该题，不反复加 agent 投票、不自动把问题交给用户。只有任务目标、批次用途或已批边界确需改变时再集中提问。轻微遗漏是否 S2 按 F1 的影响判断，既不一律放行，也不因首次命中就自动升级。
- **按变化复验。** actor-only 补工具查 actor；参考 ID 修订查映射与对应键；判据修订查正负例；共享 profile 改动查代表场景及已知受影响题。G1 noexec 已通过挂载微对照与 Conan 原失败复验，没有理由为了采用新标准把 21／216 题全部重跑。已有结论保留原版本，新工作补缺口。
- **成本分层，不将“1 分钟”当超时。** 例如 MONAI763 的完整 gold 为 5431 秒，Pandas48106 安装重编约 709 秒；这些是完整评分成本，不是每道开发快检都需要的开销，也说明两者不能混用。选择廉价且相关的公开路径；必须长跑的题按批次资源预算排队。共享维修记录区分“根因定位与配方开发”及“逐题复验”，不反复支付前者。
- **持续检查提前到早期训练 checkpoint。** 保留原 reward 与语义分析分列，不必等训练结束才发现已知漏洞被利用。以已登记风险和随机正常样本作选择性抽查，不新增每条 rollout 的 LLM 奖励或审查闸门。
- **一题一个当前入口，不覆盖历史初判。** 题卡汇总指向适用的公开材料、actor、grader、判据和运行版本；各线程详细证据继续留原目录。批次摘要至少分别计“环境修复”“语义修订”“未知／成本暂缓”“可比较能力”“训练候选”，保留仓库／任务类型分母，不能把进入候选的数量当原池有效率。72 题是已完成静态调查范围，不是 72 道训练合格题。

### 7.1 需要细化或保留不同意见的三处

**(a) F1"按影响定严重度"：同意原则，但要给出可执行的判据，否则会变慢。** 如果只写"按公开需求判断影响"，主审和复核会在"这个遗漏算不算核心"上反复拉锯。这与用户"提速、少决策"的目标相反。建议用三种**证据**来触发 S1，而不是靠类别名或纯粹的判断：

1. **退化候选得 1** → S1（T2b 已经实现）。退化候选是只凭 gold 修改的位置就能构造的"关掉检查 / 提前返回 / 吞掉错误 / 硬编码原例输出"一类补丁。实例：mypy10424 中"把 type 比较收窄整个关掉"的补丁 reward 1（P2P 0 条）；mypy17071 中"直接关掉检查"的补丁 reward 1（P2P 2 条，但都走不到被检查的函数）。
2. **题面标题或原例场景在参考测试里没有直接断言** → S1（T2a）。
3. **真实模型候选里出现了违反公开要求、且位于题目主路径上的得 1 补丁** → S1；如果违反只发生在边缘输入上 → S2。

上述三种都不成立则为 S2；证据不足记 conditional，与 F1 一致。这样保留了 F1"按影响、不按类别"的精神，又让每个判断都能落到一条可以复现的证据上。

**(b) F1 末段与 §6.4"已登记缺口首次被真实模型触发，不自动改变严重度"：在基座探针阶段同意，在训练阶段不同意。** RL 会放大一切拿到奖励的行为。训练 rollout 中，某个登记缺口在得 1 样本里反复出现，梯度就已经在往那个方向推了。建议默认规则是**自动暂停，而不是升级**：同一个登记缺口在一个检查窗口内出现在两条及以上得 1 样本中，就把该题从训练池暂停，等重新评估。暂停可以撤销，成本低，不需要用户逐题决定。基座探针中的首次命中，仍按 Codex 的意见重新评估，不自动变化。

**(c) F4"只看完成必要公开操作的能力、不要求依赖相同"：总体同意，但单看"能力"不够，还要看"目标路径上的行为是否一致"。** DVC4166 就是反例：

- actor 侧的 pathspec 是 0.12.1，grader 配方是 0.8.1。两边的全部公开操作都能正常运行，按能力判据会判"通过"。
- 但两个版本对 `.dvcignore` 的匹配语义不同：`*` + `!scripts` 在 0.12.1 下 `scripts/a.py` 可见，在 0.8.1 下被隐藏。gold 的行为与 0.8.1 一致。
- 也就是说，模型在解题环境里验证通过的行为，到评分环境会变样。

建议补一条：**位于目标行为调用链上的包（gold 修改的模块直接依赖的库，以及相关公开测试依赖的框架）必须与 grader 实际解析到的版本一致；其他只在评分侧使用的私有测试工具，记录即可，不必补齐。** Moto5134（botocore 1.35 对 SQS 改用 JSON 协议）和 Dask8597（pytest 8 不接受旧写法）属于"能力"类，F4 原判据已经能覆盖；DVC4166 属于"语义"类，需要补这一条。

### 7.2 前面没有覆盖到的情况（建议并入 v1）

1. **T6（P2P 为空或过窄）不能直接定为 S2，要先做一次退化候选探测。** 草案把 T6 列为"S2 登记"，但 T2b 恰恰就藏在这里：上面两道 mypy 题都是这样。建议：
   - 对有 T6 信号的训练候选，或 gold 只改了一个检查函数、守卫函数的题，按 gold 的修改位置构造 1–2 个退化候选，各做一次正式评分（mypy 每次约 1–3 分钟）；

2. **对已有的真实候选跑私有行为矩阵，是最便宜的实证手段。** 今天 74 个变体、约 14 分钟机器时间，就把 4 个悬而未决的 T0 问题变成了实测事实：

   建议把它定为每轮探针之后、对有登记风险的题的标准步骤。它不是正式评分，所以**不占 2b"每题评分不超过 3 次"的上限**；正式评分留给校准候选（今天只用了 6 次）。另外一条纪律：**与 gold 不同，要对照公开需求来判断，而不是把 gold 当标准答案。** 例如 DVC6954 中，gold 会跳过 `-(-2)`、`-True`，候选会把它们算出来；这些输入没有公开依据，所以不算候选的缺陷。
3. **新增一类：公开测试与正确修复冲突。** pandas53958 的公开 `test_api.py` 在 base 下 11 项全过，在 gold 下却失败：旧测试写死了原来的 API 名单，隐藏测试已经更新。这不是"照题面做会判 0"（P2），因为评分用的是更新后的隐藏测试。建议定为 S2 并登记；探针分析时，模型改测试名单不算钻空子，"公开测试失败"也不算模型改错。
4. **开发核对要记录"题面原例能否复现"，以及替代复现方法。** mypy15184 的原例在该 base 的任何 Python 目标版本下都不复现（typeshed 在 3.8 及以上把两个名字指向同一类型）；DVC1681 的原例依赖老版本生成的文件，无法原样重跑。这两题都有公开可构造的替代复现。P4 定为 S2 我同意，但应该有这个字段作为证据，探针分析时才能把"没能自己构造复现"和"不会修"区分开。
5. **开发核对的耗时，是判断题目是否适配预算的早期信号。** 记录最小公开验证的实际墙钟时间，例如 mypy 全量 testcheck 75–92 秒，pandas56849 在 2 CPU / 4 GiB 下增量重编约 19 秒。最小验证就接近单次尝试预算的题，会被系统性地截断：首轮 mypy11236 的 6 条尝试全部撞到回合上限，mypy17071 是 6 条中 5 条。这影响的是能力比较用途和训练价值，不是题目质量，不应因此判坏题。
6. **命令书写检查清单**（F6 已给原则，这里补具体的坑）。任务二实际遇到过：
   - `cmd | tail` 会吞掉退出码，要用 `pipefail` 或 `PIPESTATUS`；
   - 镜像里没有 xdist 时用了 `-n0`；
   - 预期报错信息按大小写敏感去匹配（mypy 的消息是 "Non-overlapping"）；
   - 脚本放在 `/in` 下运行时，`/testbed` 不在导入路径上，需要设 `PYTHONPATH=/testbed`；
   - `pkill -f <id>` 会连自己的 shell 一起杀掉。

   这些都是我写错了命令，不是题目缺陷，都已按版本留存并改正。另建议：公开读者直接产出机器可读的命令清单（`id / cmd / timeout_s / expect: zero|nonzero|any`，与 `devcheck.py` 同一格式），省掉一次人工转写。
7. **环境身份要固定下来。** Docker 29 起默认用 containerd 存储镜像，镜像 ID 会变成 manifest digest，和历史记录对不上；新机器要先切回 overlay2 再拉镜像。每次运行都记录：镜像 ID 与 RepoDigests、profile 摘要（G1 已经改变了 profile）、CC 版本、adapter 装了哪些包装、派生配方的哈希。F5 说"旧版本证据不能解除新版本条件"，这组字段就是判断"是不是同一版本"的具体依据。
8. **配方里自建或改过的产物必须能取回。** grader 配方用到的 `networkx 2.3+rh2.1` wheel 找不到了，我只能用 PyPI 源码包加同一处文本修改来重建：代码等价，但包元数据版本不同。规则：配方引用的自建或修改产物要连同 sha256 存档在可以取回的位置；否则配方必须能从公开来源加上已记录的修改完整复现。
9. **候选卫生问题不属于题目质量。** 草稿文件（Coder 候选中占 60–97% 字节）、清空仓库自带的 `.dvc/config`、写进仓库的 `MEMORY.md`、遗留的 `print("DEBUG")`，reward 都看不见。审查时不应因此把题判坏，这类问题归训练设计处理（奖励项或导出过滤）。

另外，v1 应指明各线程共用同一套工具，避免每条线自己再写一套启动器：`rh2/experiments/task2_swegym_dev_20260925/` 下的 `devcheck.py`（正式入口开发核对）、`build_actor.py`（actor 派生）、`semantic_control.py`（私有变体矩阵）、`post_hoc_audits.json`（事后审计）。其中 `semantic_control.py` 以 root 身份、不套正式 profile 运行（Codex 完成复核 §4.3 指出的限制），涉及权限、构建、资源归因时，要改用 `devcheck.py` 在同身份、同 profile 下对照。
