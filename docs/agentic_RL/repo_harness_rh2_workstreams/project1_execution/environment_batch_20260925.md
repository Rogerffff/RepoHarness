## 1. 开工读什么，怎样协作

先读[总入口当前状态](environment_pipeline.md#1-当前状态这些数字分别说明什么) → 本页负责的一条线 → [静态审查实际流程](swegym_task_audit_20260920/static_screening_workflow_20260921.md)和[共用开发验证流程](actor_development_validation.md)。原报告、封存稿与运行日志不回写；新增结论在本页引用具体版本与文件。

- **每条线只在自己的结果小节写链接和三五行摘要**，长题卡/日志留各自目录。写前重读当前文件，只改本节，冲突时重读合并，不整页覆盖；总协调更新跨线汇总，再给总入口追加一行。
- 开工登记负责人、题号与实际材料入口，避免重复审题或同时改同一配方。R2E 沿用已有任务；Lite 可沿用“首批12题质量审查协调”任务，但必须给它最新入口，不能仅凭旧上下文继续。
- 同仓主审/reviewer 可按 2–3 题小包组织。**已读本对话、gold 或旧结论的负责人只做协调/修复，不充当独立审查角色。** 任务一新子 agent 按用户要求显式指定 `gpt-6-astra / high`；公开读者、先原件后历史的主审、独立 reviewer 均另起不继承协调历史的新上下文，不能用默认继承历史的子 agent 冒充 fresh。公开读者只给逐题公开包，明确禁读 gold、评分材料、旧题卡及分析目录；私有主审/reviewer 需读原始私有材料，不能也限制为仅公开包。主审封存初判后读本题历史；reviewer 封存整包初判后再读主审等质量结论。记录实际读取范围，提示约束不是文件权限隔离；已有封存审查不机械重做。
- **两位负责人及原协调任务继续使用当前检出目录。** 开工先确认本页、各自材料入口和需要的 `runs/` 可读；它们尚未随普通 Git worktree 完整带入。只有明确准备了材料副本及路径映射才换工作目录，不为此提交其它任务的改动。不得把私有审查包作为 solver 输入。
