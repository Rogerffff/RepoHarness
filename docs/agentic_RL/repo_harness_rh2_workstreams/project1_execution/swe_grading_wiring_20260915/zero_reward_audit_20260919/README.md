## 参考测试到底有没有运行

**279 条零分均重解析对上原账本，所有 F2P 都有非缺席、非跳过的状态。** 原日志摘要也逐份相符。但 FAILED 可能出现在 setup/下载/依赖调用，不能等同于目标测试逻辑已经完成；上表三题就是具体反例。

9 道 ID 异常题的 noop/gold 共18条零分有 P2P MISSING。原日志能找到对应参数用例的 PASSED，Unicode、反斜杠或空格表示导致参考键不相等；不能把 MISSING 一律解释成测试未执行。**Conan-11594 还实证了另一种有损映射：Ninja Makefiles 的 PASSED 与 Ninja Multi-Config 的 FAILED 被截成同一参考键。** 这次0仍有真实 Multi-Config 断言依据，但来源 parser/参考标识需处理，重解析一致不能证明标识正确。

## 环境问题并不只在零分上

- **主批226条零分中138条有真实安装失败**，全部实验为175/279；包括 pip 失败但安装段末 rc=0。多数随后仍实际测试候选源码并出现目标缺陷；不能都归为安装致分，也不能证明修改依赖/编译产物的候选能生效。旧报告116/432统计的是“段末 rc 非零”，与这里口径不同。
- 46个主批 noop 的目标失败与额外问题共存；不少配对 gold1 也有同样问题。例：Dask-7138 gold仍有92个 `pytest.warns(None)` 兼容失败；MONAI 有 NiBabel/ITK 兼容或 helper fixture 收集错误；DVC 有 networkx/pygit2 API 问题；mypy-10308 缺参考外 fixture。
- 这些参考外错误不自动推翻既定 F2P/P2P 分数，但会干扰 agent 在仓库内的测试反馈。它们应进入环境修复清单，不能因 gold1 忽略，也不能直接扩成新的评分参考集合。
