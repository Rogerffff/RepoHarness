## 新确认的问题与容量读数

**DVC 的僵尸进程积压会把正确补丁误判成 0。** 同机、同代码、同镜像、fresh 容器，只改变 `RH2_GRADER_PIDS_LIMIT`：512 时 gold 两次均为 0、各有 5 个 P2P 失败；2048 时 gold 两次均为 1、noop 两次仍为 0 且 P2P 全部恢复。2048 的进程/线程计数峰值约 742–775，无配额拒绝事件。

最后的 `/proc` 归属扫描把机制进一步定位到**进程回收**：默认 512 条件的 noop/gold 容器各观察到最多 **507/496 个僵尸进程**，父进程全部是容器 PID 1（`sleep`），配额拒绝累计 38/37 次。当前 grader 的 `docker_run_args` 没有 `--init`，rollout 则已有。应优先对照验证 grader 的孤儿进程回收，再决定必要配额；本轮没有实施或验证 `--init` 修复。此前 `docker top` 只显示十几个进程，不能排除僵尸；内核也说明僵尸不列在 `cgroup.procs` 中。[Linux cgroup v2 文档](https://cdn.kernel.org/doc/html/latest/admin-guide/cgroup-v2.html)
