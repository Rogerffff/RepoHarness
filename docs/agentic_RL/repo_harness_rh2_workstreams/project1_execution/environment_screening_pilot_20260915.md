**Claude 复核后的补充：**题级记录、事实汇总/触发、配方引用、修订和处置统一见[最小记录与处置约定](environment_screening_definition_20260915.md)；对其意见的逐项回应见[审查稿 §8](environment_screening_checklist_claude_review_20260915.md#8-codex-复核回应2026-09-15)。下一实施片先补只读事实汇总，具体脚本尚未实现；不把所有拟议字段、阈值当成现有功能。

## 1. 从小批开始，主会话就是协调者

**建议先由主会话完整做一题，再派两个仓库工作包，各 2–3 题。** 可复用已有 e1 运行证据；含正常题、testing/helper 合法修改、影响测试收集的候选、资产或评分质量疑点，不用凑满所有问题类型。缺少某类真实工件就记录缺口。试点用于检验流程，不用于估计全库有效率。

| 角色 / 谁来做 | 具体责任 |
| --- | --- |
| 协调者：用户交任务的 Claude Code 或 Codex 主会话 | 选题和版本，登记工作包、代码基线、输出目录及机器并发；可自己做一个包。汇总问题，安排复核，协调共享代码合入；不另建调度平台。 |
| 工作包负责人：一个会话、线程或 sub-agent | 负责同仓库/适用版本的 2–3 题，从分析到真机执行、问题调查、临时修复验证和交付。可再委派独立子任务，但自己验收执行证据。 |
| 复核者：协调者安排的另一位 agent | 独立核对关键题意/文件规则，复跑决定性反例；通用生产补丁交当批指定的独立审查方。worker 内部 sub-agent 自查可先做，不冒充最终独立验收。 |

**线程选择由接任务的 agent 决定：**短材料核查用 sub-agent；要多轮真机运行、用户参与或单独保留进展时用新线程；小包也可当前会话完成。盲审/求解从干净上下文开始，只给公开材料，不能继承负责人读过 gold 的完整对话。普通调查可共享上下文。

先串行完成示例题，再在资源允许时开两个远端评分槽，每个包最多占一个；这是试点初始安排，不是正式资源定案。子 agent 数量不增加 Docker 配额，长命令用后台日志/轮询让负责人保持可响应。现有 e1 作业由原执行者继续管理，协调者先核对占用，不重复启动或覆盖它。

## 2. 每个包收到什么、按什么顺序做

协调者只需给出：**工作包 ID、明确 task IDs/来源版本、运行代码快照、准备材料位置、独立输出目录、机器访问方式和并发额度**。访问凭据在运行时提供，不放提交文档或任务报告。仓库知识按适用版本共享，任务 gold/隐藏测试只给调查者。

1. **确认输入和起点。** 阅读清单与本页；核对分配题、已有证据和代码状态。记录镜像/配方、实际用户、网络与资源条件。先保存公开视角的任务解释，再看私有材料；可安排干净上下文 sub-agent 做这一步。
2. **跑真实基线、先整理事实。** 用统一 driver 跑完整 no-op/gold，由只读汇总器整理阶段、逐测试对照、投影与缺项，agent 再查原件解释异常。汇总脚本未实现时第一题可人工试填并标 manual；扩工作包前补该小工具。已有完全可比的证据可复用，不相符的代码/条件另建记录。
3. **落实第四组 B。** 按下节检查解答与评分材料边界，额外规则可为空；查看原来被 glob 忽略的路径，也检查官方精确清单的误伤。与题意/测试质量审查一起提出具体假设。
4. **按假设补实验。** 按最小约定的触发表调查 parser/资产、误拒、漏测等线索；每题保留简短的题意—测试对照。需要工作流证据时用已验证运行条件盲解，旧出网未禁轨迹只作该条件下的调查材料。拟接受的试点题在初次 no-op/gold 后各确认一次，异常不重复凑数；正式稳定率门槛后定。
5. **发现 RH2 问题可提出并验证临时补丁。** 按 §4 隔离实现，保存修改前后证据。只暂停受影响题；共享问题告诉协调者，由其暂停受影响包的资格裁定，无关工作可继续。
6. **交付与复核。** 每题几行结论＋证据引用，附文件规则、修复及未解问题。建议先做两轮有不同假设的针对性调查；仍未收敛就交接阻塞与下一实验，不无限重试，也不因调查预算耗尽判坏题。

分析者可决定读哪些代码、做哪些实验、发现新问题；40 项用于核对覆盖，不要求每项调用一次工具。“未检查/证据不足”应如实保留。

## 3. 第四组 B 怎样进入每题检查

**默认额外排除为空，已知官方材料与运行期保护沿既有实现。** 不因路径包含 `test/testing` 剔除候选，不以 gold 改过的路径生成唯一允许修改清单；修改测试样文件仅作为调查线索，不自动扣分或认定作弊。

每题做三个动作：

1. **看实际职责。** 对照真实评分入口、`test_patch` 触碰路径及相关 helper、conftest、插件、构建配置；区分合法解答、官方评分材料和混合职责。特别查 `test_files` 从 `test_patch` 全部触碰路径生成时，有没有把正常源码也恢复覆盖。
2. **说明是否需要额外处理。** 没发现具体依据就写 `additional_exclusions: []`，附一句检查范围。有依据时给出精确路径/最小范围、适用题/版本、可复现的判分影响、为何不是合法解答，以及恢复可信内容/忽略候选修改等具体动作。可再生缓存归第四组 C，不能混入这一清单。
3. **有新增规则时双向验证。** 验证相关合法修复仍被完整交付并正确评分；对同一解答加上评分材料篡改后，不能靠篡改改变判分。保存实际投影、grader 文件和逐测试结果。混合职责不能靠整文件排除解决时，登记具体冲突并提出最小修法，不悄悄删题。

一条记录即可，不新增平台或必填公共 schema：

```text
task / 适用版本：…
额外排除：[]，或 [具体路径]
依据与动作：控制了哪一步；为何不是合法解答；怎样恢复/忽略
证据：合法修复、相关篡改、真实投影与评分的运行引用
状态：无需新增 / 提案待验 / 隔离副本已验 / 已并入统一版本
```

**规则的实际接线还需要补齐，不能把记录文件当成已有功能。** 本轮核查时，两个 SWE spec 构造入口仍传 `DEFAULT_SWE_TEST_GLOBS`；CLI 也没有逐题额外规则选项。默认通配由 P-B 落地。若试点产生第一条额外规则，再由单一评分实现者补最小消费入口，确保真实 rollout、重放 driver、冻结投影与 grader 重算使用同一规则；不能只在诊断脚本 `replace(hygiene=...)` 后就宣称训练已接入。规则未进统一入口前，隔离副本结果标为诊断。

规则按任务版本固定，不能随某个候选得分临时变化。已批 B 范围内的具体路径提案与验证不用逐项重复请示；独立复核后由协调者纳入统一版本。仍无法区分合法解答与评分材料，或需要改变既有评分/权限语义时，带具体例子交用户决定。

第四组其余部分也进入记录：A 保存可信候选失败与实际测试事实，不伪造计数；C 仅处理确认可再生且非交付物的缓存，未知项保留；D 遇普通文件变目录时验证真实交付。资源保护终止与未知原因不自动给 0。实施计划里的待审字段/开关不能先当成已经可用的 API。

## 4. 真机发现 bug、漏洞或低效时，怎样试补丁

**允许 worker 调查并在独立副本中实施、运行修复提案。** 修 parser、重放、观测、清理、重复安装或多余 IO，都可按已有语义具体推进；合入共用生产版本由当批评分实现者协调，不需要每发现一个实现 bug 就重新问能否调查。

1. **先保存问题。** 写明 task、运行引用、代码/镜像/规则版本、实际与预期差异。效率问题先量到具体阶段，区分冷拉镜像、预热和稳态成本；异常不能未经核查归到题目质量。
2. **按修改对象隔离。** 题目候选 patch 放任务工件目录；环境修复用独立 recipe/派生镜像；RH2 代码用独立 Git worktree 和问题分支，例如 `b/envprobe-W01-fix01`。任务仓库中的补丁与 RH2 自身补丁分别标明。
3. **基线必须含本批真实代码。** 当前工作区有未提交的接线修改，直接从 HEAD 开 worktree 会漏掉它们。协调者先建立本任务范围的可重建快照：明确 commit，或 commit＋所需已跟踪差异及指定未跟踪源码/锁文件；由它创建隔离副本。不得用全局 stash/reset 搬走他人改动，也不把整个工作区或凭据打包进去。
4. **远端也隔离。** 基线与补丁各用 `/work/envscreen/<包>/<变体>/code/` 和独立 Python 环境/输出目录；代码运行期间不热更新。可复用不变的数据和镜像层，镜像/依赖由远端直接下载。派生镜像使用新标签并记录实际 ID，不覆盖正在跑的标签；只清理本包拥有的容器，不做全局 prune。
5. **做最小前后对照。** 同候选、同环境条件跑旧版和补丁版；正确性补丁加相关正常对照，规则补丁按 §3 做正反验证。效率补丁保持评分含义、文件状态与逐测试结果，明确测量条件；无需每个小补丁重跑全池。
6. **交可应用补丁与证据。** 给出基线、分支/commit 或 patch、修改文件、复现命令、前后结果、影响范围和剩余问题。新增 reward/准入规则、未批权限/网络改变等交用户决定；既有决定的实现不重问。共享修改仍按[协作协议](../collaboration-protocol.md)及当批独立审查收口。

worker 可以在补丁副本继续调查，但结果保留该变体标识。独立复核后，由共享代码负责人合入统一基线，复验受影响题，再更新其资格；未合入结果不混入原版合格率。同一共享 bug 由一个工作包修，其他包提供反例，避免多人各造一版 manager。

## 5. 使用现有真实评分入口，不让 worker 重写 grader

使用 [S1-e 手册](swe_grading_wiring_20260915/runbook_s1e.md)中的环境安装、`prepare`、`export-gold` 与 [CLI](../../../../rh2/scripts/replay_grade.py)。任务包由协调者准备或明确交给负责人准备；私有材料不挂进盲解工作区。**现有入口主要是 SWE-Gym；R2E 方案 A 已决定，但完整适配不能仅凭契约方案当成已实现。** R2E 先做材料/边界分析，真实接线验过再跑本流程的评分步骤，不回退实验 runner 冒充 RH2。

下面是单题、单变体的调用模板，参数名已与当前 CLI 对照；地址、快照和路径由派发时填写。`prepare` 生成的 summary 含路径，复制后先核对其仍指向本包的正确材料。

```bash
# 在本包、该变体的 code/rh2 下；以下变量由工作包设置
MILES_RH2_RUN_ID="$trial_id" .venv/bin/python scripts/replay_grade.py run \
  --prepared-summary "$prepared_summary" --task-ids "$task_id" \
  --candidate "$candidate_spec" --repeat 1 \
  --candidate-stage-seconds "$candidate_seconds" \
  --grading-deadline-seconds "$grading_seconds" --image-pull-seconds "$pull_seconds" \
  --eval-log-dir "$trial_out/eval_logs" \
  --artifacts-dir "$trial_out/artifacts" --ledger "$trial_out/ledger.jsonl"
```

`candidate_spec` 分别取 `noop`、`gold-dir:<导出目录>` 或 `patch:<候选文件>`；三种运行分别用新的 `trial_id/trial_out`。资源/期限沿本包记录的显式配置与已批 profile，必要对照另开变体。CLI 进程退出 0 也必须检查账本里的任务结果；遇已实现的清理失败停批，先处理本包残留，不用忽略错误继续扩量。

## 6. 可以直接复制的派发卡与交付

```text
你负责环境筛查工作包 {W01}，任务 {明确 IDs / 来源版本}。
先读 environment_screening_pilot_20260915.md 与 40 项清单；第四组已批决定直接沿用。
代码基线 {可重建快照}，代码目录 {独立路径}，材料 {prepared/private/原始来源位置}，
输出 {独立工作包目录}，远端评分额度 {1 路，协调者已分配}，资源/各段期限 {明确配置}。

按本页 §2 完成：实际输入/公开视角分析 → 真实 no-op/gold → B 文件边界 → 有依据的补测/修复。
允许自行完成、开新线程或委派 sub-agent；负责人核验全部证据，不超分配的真机并发。
盲审/真实求解只给公开材料；不向其传 gold、隐藏测试或调查提示。
B 的额外排除允许为空；非空给路径、具体理由、动作及正反验证。
发现 RH2 缺陷/低效可在独立 worktree 和远端变体目录修改、对照，交可应用补丁；
不改共用运行代码，不将未合入补丁的结果混入基线结果，新增未批语义给出具体提案。
每题交简短结论、运行引用、文件规则、修复/未解项；已完成可独立收口，受阻说明下一实验。
```

每包一份 `env_screening_pilot_20260915/W01.md` 报告；小型逐题 `facts.json` 和 `screening_record.json` 放该批证据目录，字段按最小约定。原始日志/工件回传到 `runs/env_screening_pilot_20260915/W01/<trial>/`，记录相对引用。目录是拟用布局，不表示已有运行。协调者在批次 README 登记归属、统一版本与汇总，worker 不互改共享账本；事实汇总重跑不能覆盖人工审查结论。

**试点收口看四件事：**能用真实评分产出可解释的证据；B 的空清单和必要规则都能如实表达；发现问题能隔离修复并由别人复验；主要人工成本和重复劳动已暴露。先优化实际出现的痛点再扩量，不要求首轮建成自动化平台或证明所有漏洞都消失。

同时报告五组数及分母：关键字段可观测率、调查触发、已知反例回归、独立复核分歧、实际成本/耗时。用途与质量分开记录，评测候选的模型选择暴露另记；不直接采用全池 10% 抽查、×3 即评测合格、修题永久不可评测等规则。P-C 优化可后置，P-A 未接通的归因只记限制；有限诊断不等待所有评分切片完成。
