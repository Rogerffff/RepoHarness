# 扩量中的筛查、探针采样与奖励核验

2026-10-05，Codex 独立研究。**这是替代流程的设计建议，未改现行准入、奖励或训练实现，也未运行模型、容器或 GPU。** 已先读现行标准与相关精读，再核一手报告和固定源码；没有读取 `tmp/数据扩大方案设计_claude.md`。计算由同目录 [sampling_analysis.py](sampling_analysis.py) 生成 [screening_sampling.json](screening_sampling.json)。

建议采用“每题短语义核对与必要执行，风险触发候选深审，随机锚样本估计漏检”的扩量流程。**不要求每题另造退化候选，不要求每题先观察到 mixed reward，也不默认每题四次最优。** 普通题可先做同模型两次；追加到四次或八次必须与覆盖新题竞争预算。rubric 先作为离线旁路验证，不阻塞二元奖励任务扩量。

这里区分三种结论：**题目可用性**看题义、评分与 actor 开发条件；**当前可学性线索**看同一模型在固定条件下的成败与成本；**真实训练价值**最终看等预算训练后的留出表现。任一项不能替代另外两项。

## 1. 当前规则与本建议的差别

当前 [统一标准 v1](../task_screening_standard_v1_20260925.md) §2、§4、§7、§9 已要求每题核心要求与决定性断言对应、noop/gold 对照、每题一个退化候选，以及公开读者／主审／独立复核三个新上下文。D5 明确每批 12 题、不设会话或评分预算。当前 [actor 开发验证](../actor_development_validation.md) 要求采用实际初态、身份、profile 与公开开发入口；import 或测试收集成功不等于开发可用。

本建议保留必要的正面证据，**改变检查的覆盖策略**：

| 检查 | 扩量试行建议 | 含义与代价 |
| --- | --- | --- |
| 自动材料、版本、泄漏与测试事实提取 | 每题执行，公共事实按环境家族复用 | 证明被检查的机械事实，不证明题义与测试正确 |
| 公开题义、核心断言与必要 actor 操作 | 每题短审，保存具体依据 | 保留语义判断；不能用一张风险标签表替代 |
| noop/gold 正负对照、公开开发路径 | 每题有适用版本证据；已有证据复用 | 环境或目标路径改变才重跑受影响部分 |
| 普遍构造一个退化补丁 | 改为风险触发、共享缺陷机制反控、随机锚样本深审 | 可能漏掉尚无风险标记的漏洞，用随机锚样本测增量漏检 |
| 每题第三位独立复核 | 改为争议、修订、高风险及随机锚样本 | 减少重复阅读；不是宣称前两角色无误 |
| 每题四／八次真实求解 | 初始同模型两次，后续自适应分配 | 节省成本，同时承认难度估计较粗 |
| 评分稳定性重复运行 | 已知 flaky、新评分家族、可疑结果优先，另留随机样本 | 不因八次无波动就宣布稳定率接近 100% |

这两项覆盖放宽应在本次整体方案中明确选择，不能写成旧 v1 已允许，也不需要逐题重新审批。本文没有自行改变旧标准。

**为何不继续要求每题反控？** 当前 v1 §11 的 20 题是已深入调查、经历规则演进的一小批题，不能作为新来源随机缺陷率或反控边际收益的估计。没有外部受控证据证明“所有题都再造一个反例”比“同等成本覆盖更多题并随机复核”更有效。已知风险仍要查；未知风险靠有分母的抽查，不能靠普遍造一种很容易被拒绝的弱反例制造确定感。

## 2. 可直接采用的最小流程

### 2.1 输入冻结与自动事实层

沿用现有逐题记录和 JSONL，不另建资格平台。每题固定 `source/revision/task_id/repo/base/initial_state/image_digest/recipe/grader_revision/public_material_revision`；给原题和修订题保留父版本关系。actor 初态须以实际工作树为准，不因 source 自带改动而强行 reset。

自动完成：材料可读、键集／F2P/P2P 解析、测试实际收集数、patch 可应用、镜像及依赖版本事实、公开与私有材料边界扫描、近重复／同源派生关系、gold/noop 结果和失败位置。补充风险线索包括 P2P 空、核心路径 mock、精确文案、只覆盖题面字面值、可能修改评分控制文件。**“没有命中线索”只表示没有命中这些规则。**

复用 [`screening_facts.py`](../../../../../rh2/scripts/screening_facts.py)、现有 devcheck、private control 和 postcheck 入口；新脚本只补缺失事实提取。环境家族依据相同镜像、安装／加载方式、评分模板和受影响调用链分组，不能仅按仓库名判断相同。

### 2.2 每题短语义核对

建议保留两个信息边界，压缩产物与重复背景：

1. **公开读者**只看实际公开题面、公开工作树与开发说明，写核心可观察要求、合理解释、必要公开验证命令。共用环境说明按家族引用；不读 gold、隐藏测试或私有审查意见。
2. **私有核对者**将这份解释与决定性测试逐项对应，写明测试接受／拒绝的行为、非示例实例、明显过度约束与未查范围。先写题义判断，再看 gold，避免把 gold 的偶然写法当规范。它不是第三次全仓阅读。

产物以一张短卡为目标，而不是限量删需求。最少字段：`核心要求 → 公开依据 → 决定性断言 → 当前证据 → 风险／未知`。题目有多个核心要求时都覆盖；没法从公开材料判断的写 UNKNOWN。

必要执行仍包括：实际 actor 身份下跑最小公开入口，确认加载工作区代码／实际构建产物、相关测试真正执行；同版本 noop=0、gold 或独立核实的合理正对照=1。执行失败先分环境、命令写错、目标 bug、无关旧失败、零收集；不全记成模型 0。只涉及公开开发验证的操作无需真实模型。

**短审的停止条件：**核心要求已有直接断言、没有发现具体矛盾／核心失效证据、必要执行证据成立、剩余未查范围已列清，就可进入试行候选池；不以“还可能有别的边界条件”为由继续深审。这里的候选池依赖本次覆盖策略获采纳；不是把未做旧 v1 第 3 步的题回写成旧资格。

### 2.3 哪些题值得进一步用 agent 或候选审查

| 触发证据 | 最小追加动作 | 何时停止 |
| --- | --- | --- |
| 核心要求无直接断言、题面与测试冲突 | 指出一个具体核心行为；已有窄模板可修就修，否则暂挂 | 已证实的核心缺陷不能用“允许少量噪声”豁免 |
| 示例字面值独占、关闭校验即可通过的具体怀疑 | 造一个明确违背公开要求的反例，或复用现有自然 patch 做差分 | 只验证会改变处置的假设；不枚举所有坏补丁 |
| 新评分模板、已知家族漏洞 | 每种机制选代表题做强反控；静态核对其余题确实经过相同分支 | 同仓不同机制另看；代表题通过不自动证明所有题语义正确 |
| 原始 reward=1，但 patch 显示缺需求、吞错误、绕开功能 | 先读公开要求，再运行一项有依据的独立行为检查 | 能裁定则登记／修订；不能裁定则 UNKNOWN，不由多数票定正确 |
| 原始 reward=0，但有看似合理替代解 | 核执行是否有效，检查失败断言的公开依据，必要时对照相同输入 | 避免只抽成功样本而漏掉误拒 |
| 重复评分波动、资源／时序特征 | 固定候选、版本、资源和干净状态重评分，必要时跨执行宿主 | 重复的是评分，不是重新生成另一个 patch；根因未明不叫随机噪声 |
| 无风险标记的随机锚样本 | 独立审读、反控、真候选正负两侧核验 | 用于发现风险规则的盲区，不能只抽方便和便宜的题 |

一次聚焦裁定有四种去向：`accepted / rejected_with_evidence / deferred_with_owner_and_gate / no_fix_accept_residual_risk`。已证实改变核心正确性的错误属于先修或暂挂；边缘缺口可明确接受残余风险。审查者必须给出公开要求、具体候选／断言与后果；“可能不完整”不够。

模板内修订沿现行 R-a 至 R-f，仍验证正对照、noop、触发误判和已知相关错误候选，保存原分数、新版本和依据。**最多一轮修订加一次聚焦复核；仍有实质分歧且没有低成本辨别实验就暂挂这题、继续其它题。** 不追求让全部历史候选通过，不靠缩小题义保住 gold。

### 2.4 用一次试行比较新旧审查成本

从新来源各主要家族随机选锚样本，先封存短审结论，再由独立审查补旧流程的反控和完整复核。其它题按新流程继续推进。记录短审未发现而完整复核新确认的核心缺陷、误拒、修订成本、审查 token、CPU 分钟及等待时间。

关键分母是“完成两套流程的随机独立题数”，而不是候选条数、测试断言数或既有高风险题数。低风险锚样本与风险触发题的缺陷率分开；相同模板故障记影响题数，也另记一个根因簇。零命中只能给置信上界，不能证明短审与深审等价。增量代价可写为：

`旧成本 = N·(公开短审 + 私有审查 + 第三人复核 + 构造/评分反例) + 修订`。

`新成本 = N·(公开短审 + 私有短审) + n风险/随机·(复核 + 反控) + 修订 + 抽样成本`。

各项用实测填，不先假定快十倍。新流程若在随机低风险层持续漏掉同一严重机制，应提升该机制的普查范围；不因此恢复全池无限深审。

## 3. 两／四／八次探针到底提供什么

### 3.1 组内信号与误分类

设固定模型、checkpoint、harness、材料与采样配置下，一题每次有效求解成功率为 `p`，先用条件独立 Bernoulli 作计算模型。`G` 次里至少一个成功且至少一个失败的概率为：

\[
M_G(p)=1-p^G-(1-p)^G.
\]

同模型二元组内优势需要观察到不同结果；不同模型各一次的分歧不等于任一模型的组内信号。即使相同模型，复用相同 prefix、缓存、种子或共享环境故障也会造成相关性，实际有效样本量可更低。

| 真实 p（例示） | 两次 mixed | 四次 mixed | 八次 mixed | 四次全失败 | 八次全失败 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 0.05 | 9.50% | 18.55% | 33.66% | 81.45% | 66.34% |
| 0.10 | 18.00% | 34.38% | 56.95% | 65.61% | 43.05% |
| 0.20 | 32.00% | 58.88% | 83.22% | 40.96% | 16.78% |
| 0.50 | 50.00% | 87.50% | 99.22% | 6.25% | 0.39% |
| 0.73 | 39.42% | 71.07% | 91.93% | 0.53% | 0.003% |

这说明 `0/2`、`0/4`、`0/8` 只能标“尚未观察成功”，不能标不可解或无训练价值；全成功同理。若直接把全失败当 p=0，上表就是在该 p 下的错分概率。即便 0/8，在独立固定样本假设下，p 的单侧 95% 上界仍为 **31.23%**：

\[
p_U=1-0.05^{1/n}.
\]

要以零成功支持“p 小于 10%”需至少 29 次，支持“小于 5%”需至少 59 次。**这不是建议每题跑 59 次**，而是说明扩量阶段不应试图给每题作精确极端难度认证。

### 3.2 整体 pass@1 不能决定 mixed 题占比

两个任务总体都有平均 pass@1=73%：

| 总体 | 各题真实 p | 四次 mixed 概率平均值 | 200 题各四次的期望 mixed 题数 |
| --- | --- | ---: | ---: |
| A | 每题 p=0.73 | 71.0703% | 142.14 |
| B | 73% 题 p=1，27% 题 p=0 | 0% | 0 |

因此既有 Coder 约 73% 的平均成绩不能推出“多数题已太易”，也不能推出“200 题只需统一 800 次就能得到多少可学题”。需要题内重复、原始零／全／混合组分布与任务成本。200×4=800 只是某个设计的算术，不是数据需求推断。

### 3.3 广覆盖与重复采样的竞争

如果预算简化为 800 条同成本 rollout：400 题×2、200 题×4、100 题×8 的期望 mixed 题数，在所有题 p=0.2 时分别为 **128、117.76、83.22**；p=0.5 时为 **200、175、99.22**。广覆盖可找到更多有变化的独立题；重复更擅长确认一题的罕见成功、收集替代实现、研究奖励误判和估计 p。

这些是“发现 mixed 题”的计数，不是梯度质量或训练收益的比较。组大小影响优势估计、同题候选多样性、噪声敏感性、调度开销及每步独立题数；G=2 不因此自动优于 G=4/8。实际成本还包括输入／输出 token、CPU 评分、冷镜像、长尾与失败重跑。按 token 或 GPU 时比较，不能假装一条慢题与一条快题同价。

建议在当前选定主模型 **Qwen3-Coder-30B-A3B-Instruct** 上优先广覆盖，同模型初始两次作为起步设计；Qwen3.6 对照在共同题单按其自身冻结配置采样。当前协调者核到的部署值是 Coder `temperature=0.7, top_p=0.8, top_k=20, repetition_penalty=1.05`，3.6 `temperature=1.0, top_p=0.95, top_k=20`；正式 run manifest 再以实际 resolved 配置核定。不同模型配置差异属于所比较系统的一部分，不能声称完全隔离了模型参数效果。

### 3.4 一个可复算的追加采样规则

先两次；已 mixed 就停止该题的难度探测；未 mixed 的题可补两次。若给所有未混合题都补，则：

\[
E[N_{2\to4}]=2+2[p^2+(1-p)^2],\qquad P(\text{最终 mixed})=M_4(p).
\]

| p | 固定四次 | 2→4 期望次数 | 最终 mixed | 停止后的逐题 k/N 期望 |
| --- | ---: | ---: | ---: | ---: |
| 0.10 | 4 | 3.6400 | 34.38% | 13.60% |
| 0.20 | 4 | 3.3600 | 58.88% | 24.80% |
| 0.50 | 4 | 3.0000 | 87.50% | 50.00% |
| 0.73 | 4 | 3.2116 | 71.07% | 68.47% |

继续“未混合四次再补四次”，有 `E[N]=2+2H₂+4H₄`，`H_n=p^n+(1-p)^n`，最终命中 M₈。p=0.1 时平均要 **6.2648** 次；p=0.5 时只要 **3.5** 次。它在极端难／易题上花更多预算，可能挤压新题覆盖。

**推荐不把补四／八次做成全池自动义务。** 每批把“新题首两次”“旧题追加两次”“语义异常核验”作为三个可竞争队列；从尚未 mixed 的题中保留随机追加样本，其余按该题是否代表新家族、结果是否异常、追加成本及疑似罕见成功的价值选。选择概率与理由写入台账；没有先验 p 时不声称知道最优分配。已 mixed 仍可为审奖励质量追加，但要换明确目的标签。

若想使用简单贝叶斯排序，可用分层 Beta-Binomial 平滑后估计“追加两次找到另一结果”的概率／成本；必须同时报告先验敏感性，并保留随机探索。`k/n` 直接排名会过度信任两次 0 或 1；更复杂的 bandit 平台并非本轮必要。

### 3.5 自适应采样的偏差不能只靠“多跑一点”消除

上表最后一列已经显示停止偏差：p=0.1 变成平均 0.136，p=0.73 变成平均 0.684667。完整路径穷举与固定种子 10 万次模拟分别核对了六组情形。

在所有题 p 相同时，把全部 success 除全部尝试的大样本极限可仍回到 p；**任务异质时仍不对**。一半题 p=0.1、一半 p=0.5，真任务平均为 0.3；2→4 后逐题最终比率平均为 **0.318**，按全部 rollout 池化为 **0.280723**。2→4→8 后分别为 **0.33438、0.243372**。后者因难题得到更多尝试而偏低；这两种错误平均甚至方向相反。

实践上保留初始预登记的固定两次作为基线，报告每题平均和 repo/source 分层；追加样本单列为发现／排查数据。若初始题也按风险挑选，它本身不能代表总体，需另有预先随机的锚样本。用逆概率加权只在已知、非零抽样概率和正确抽样单位下才有效，不能补回从不抽取的家族，也不自动解决策略随 checkpoint 改变的问题。

训练期动态过滤会再改变消费分布：固定 G 的可用组大致按 `原始题分布×M_G(p)` 被加权。应同时报告原始分派、有效评分、zero／all／mixed、语义异常与最终训练消费，不能只报留下来的 pass rate。

**RH2 已有零方差过滤。** [`group_admission.py`](../../../../../rh2/src/repoharness2/adapters/miles/group_admission.py) 在全员 `KEEP_FULL` 后检查 reward 标准差，零方差整组 drop。当前路径由后续 prompt 补 buffer，不自动重解当前组。本建议只是用探针改善选择与观测，不能把动态过滤写成待新建能力。普通 GPU probe 的 attempt／评分产物也不因此成为已验收的训练 tape。

离线“发现 mixed 就停”不应直接复制进在线 GRPO 组构建：可变、由结果决定的组大小会改变组分布和优势估计。本轮先保持既定训练组语义；跨 checkpoint 的历史尝试与跨模型尝试也不补进同一训练组。

## 4. 什么叫可接受的有限奖励噪声

### 4.1 先定义对象，再谈百分比

| 对象 | 定义／统计单位 | 如何处置 |
| --- | --- | --- |
| 随机评分波动 | 固定 patch、版本与条件，fresh reset 后评分随机改变 | 查时序／资源／环境；可重复出现不等于可忽略 |
| 语义误接收 | 有效 reward=1，但独立行为证据确认未满足核心公开要求 | 修评分或暂停相关题／机制；不能叫普通随机噪声 |
| 语义误拒 | 有效 reward=0，但有充分证据满足公开核心要求且失败断言不合理 | 修断言／环境；避免训练惩罚合理替代解 |
| 系统性可利用漏洞 | 某种错误策略稳定提高 reward，如关校验、泄漏答案、伪造评分 | 优先处理共享机制；已知漏洞不能靠总体低占比豁免 |
| 有界残余覆盖缺口 | 没有已确认核心失效、可能遗漏边缘行为且记录了范围 | 可分层进入试行并抽查；不能宣称误差为零 |
| 无效执行 | 环境、交付、评分材料或 parser 失效而不能解释 reward | 按既有失败模型处理，不能计入 Bernoulli 解题失败 |

“允许有限噪声”应指**已描述的残余风险、受监测的经验误判与成本取舍**，不是给已知 S1 找一个百分比豁免。本文不声称某个统一 1%、2% 或 5% 误差率能保证 RL 安全或学习收益；具体容忍度需结合漏洞可利用性、消费权重和小训练观察。没有报告的误差不自动为零。

### 4.2 独立随机翻转与可利用漏洞的区别

在理想化对称、独立且与策略无关的翻转噪声 ε 下，真标签 Z 与观测 reward R 满足：

\[
E[R\mid Z]=\epsilon+(1-2\epsilon)Z.
\]

ε<0.5 时它保留期望顺序，但衰减信号、增加方差；含标准差归一化、动态筛选和有限组时仍不能据此保证训练稳定。更一般的误接收 α、误拒 β 给出 `E[R|Z]=α+(1−α−β)Z`，且“常数 α、β”本身就可能不成立。

噪声还会制造假 mixed：真实全同的 G 人组，观测出 mixed 的概率为 `1−(1−ε)^G−ε^G`。ε=1% 时，G=4／8 分别为 **3.94%／7.73%**；ε=5% 时为 **18.55%／33.66%**。因此“mixed 变多”不能单独当 reward 改善或更可学的证据。

系统性漏洞的 α 会随策略改变：模型学会捷径后，错误行为与高 reward 相关性反而上升。一次漏洞影响一个高采样家族，可能比全池随机少量翻转更危险；总体误差均值会掩盖这个问题。跨模型 judge 一致也可能共享盲点。

### 4.3 抽检样本怎么取

建议每个新来源／主要评分家族启动时，先建立少量固定锚题；在可用池变大后，累积一个约 **60 个独立题的随机深审窗口**，并同时保留所有风险触发调查。这是揭示盲区的起点，不是新增 60 题阻塞闸门，也不是逐题低于 5% 错误的认证。小池先抽实际能覆盖的数量，报告宽上界，继续其它工作。

按 source、repo／派生族、评分模板、环境家族、成本档和原始成功／失败分层。随机锚样本从完整 eligible 清单在看补丁前抽；风险富集样本单列。一个题多条候选可用于发现不同错误，但估总体缺陷率时仍是一个 task cluster；同根因共享模板再另列聚类，不能把一次问题重复计成几十个独立发现。

候选层分别报告：

- `reward=1且被确认错误 / 被语义裁定的reward=1候选`，这是**观测通过者中的误接收占比**，不是统计学 FPR 的“所有真负例”分母。
- `reward=0且被确认正确 / 被语义裁定的reward=0候选`，这是观测失败者中的误拒占比，不是所有真正例上的 FNR。
- UNKNOWN／未完成裁定比例、无效执行比例、抽样概率、独立题数、重复候选数、根因簇数。

这两个条件率不能未经加权相加成全池错误率。训练时还要给每个问题家族在**实际消费 rollout 与 token**中的占比，防止低题数、高采样权重的漏洞被平均掉。完整 population 推断依赖随机设计；风险样本用于找问题，不用于估总体比例。

### 4.4 零发现的统计边界

若 n 个独立同分布的审计单位、检测无漏检且零发现，单侧 95% 错误率上界为 `1−0.05^(1/n)`：

| 零错误的独立单位数 n | 上界 |
| ---: | ---: |
| 8 | 31.23% |
| 24 | 11.73% |
| 30 | 9.50% |
| 60 | 4.87% |
| 149 | 1.99% |
| 299 | 1.00% |

多个相关 patch、同一 flake 的重复调用、同一个 reviewer 的一致判定都不能当独立单位扩大 n。分层配额若不按总体比例，先报各层结果再按总体权重合并，不能直接套整体 n 的二项式界。有限总体随机无放回可使用超几何界；有聚类就按簇抽样／估方差，不能把 token 数当样本量。审计者可能漏检时，上界首先约束的是**能被该审计流程发现的问题率**，不是全部语义错误率。

对固定候选，8 次重评分发现 1% flake 的概率仅 **7.73%**，发现 10% flake 的概率为 **56.95%**。八次无异常可作有限稳定性证据，不足以认证极低 flake。MiMo 的八次方案也不提供这种保证。

### 4.5 训练窗口监控与停止

沿当前 v1 §8／D2 在预声明 checkpoint 抽检，不加逐 rollout LLM 闸门。窗口内同时看原始通过率、fixed-anchor 表现、各来源 zero/all/mixed、评分重放差异、确认误接收／误拒、UNKNOWN，以及异常模式的消费占比。成功和失败都抽。

已知缺口一个窗口中在两条及以上得 1 样本反复命中，沿既定可撤销暂停规则重新评估；**一次已确认核心失效或安全／评分边界漏洞也不能等待凑满两条才处理**，按当前严重度规则修复／暂停。孤立边缘缺口不自动升级；抽查误判需保留反证路径。异常源暂停不阻塞其余已合格来源，修复保留版本并只重验相关范围。

## 5. rubric 什么时候有用，怎么避免变成新瓶颈

### 5.1 可用与不可用的边界

rubric 是把公开要求写成可核对的判据。优先用于：测试已通过但实现遗漏明确需求、存在有证据的常用行为回归、任务原本包含开放交付物，或同题多个通过解在任务相关质量上存在真实差异。确定性行为优先编成私有可执行断言；需要主观解释的条目才保留 agent judge。

不适用：给所有全失败组凭印象制造正分；把 gold 风格当唯一正确解；要求固定工具顺序、搜索／测试次数、字数或少改行数；奖赏“我已验证”的自述；用 rubric 掩盖 actor 环境坏、任务含糊或隐藏断言矛盾。测试、搜索、重试次数是诊断特征，不能直接作奖励。

若公开要求确实包括“新增测试”或“提交验证报告”，可评价交付物及其证据质量；仍不能只数 test 调用次数。短轨迹可能有效，也可能没检查；长轨迹可能低效，也可能任务更难。

### 5.2 MiMo 的两种机制与可迁移部分

[MiMo 报告 §4.3.1–4.3.2，pp.17–18](https://huggingface.co/XiaomiMiMo/MiMo-V2.6-Pro-RL/blob/73875d00b30a89ef8cc353a0b60b0e9f9561952d/MiMo_V2_6_technical_report.pdf) 区分：GRS 离线构造任务 rubric，再用 `R_test×S_solution×S_behavior` 评分，可区分全测试通过组；GAR 对 mixed 组比较通过解并重分配优势。**前者不能用乘法解救全失败组，后者需要同组有成功与失败；仅一个通过解时也无通过解之间的质量排序空间。**

这支持先研究“测试通过内部是否有可靠差异”，不支持立即照抄其训练损失。MiMo 未给完整 rank→factor、实际 cap、所有组合分支与筛选顺序。全 raw-pass 是否留下来应以最终分数和过滤顺序定义，不能混淆 raw test reward 与最终训练 reward。其 GAR 小消融是 code-only Flash、batch 128、token-mean，不是我们模型或完整主实验。

[固定 mimoagent `rubric_judge.py`](https://github.com/XiaomiMiMo/mimoagent/blob/467f0a19016f0ac4d63b8d17a1f0da9ba07f232c/src/mimoagent/environments/rubric_judge.py) 已支持原始 programmatic 与 rubric 分列，默认 scalar 保留 programmatic；因此旁路记录具有明确工程先例。judge 在 doer 环境检查结果，要求可逆修改；提示词要求恢复状态本身不构成执行隔离。本项目 shadow 应在保存的候选副本上运行，避免 judge 改变正式评分工件。

### 5.3 最小 shadow 验证，不等待全池 rubric

先挑 **8–12 个已有真实候选的题**，覆盖多种评分／环境家族；若几题足以否定判据，立即停止该候选 rubric。每题复用已有 3–4 个 patch：测试通过正确解、测试通过可疑解、测试失败合理替代解或真实不完整解。补丁不存在不硬凑整齐矩阵。可加入已明确违背公开要求的对抗 patch，但要单列它是人工构造。

步骤如下：

1. 先按公开要求形成可定位证据的参考裁定；判不清保留 UNKNOWN。将 rubric 的开发题与冻结后检查题分开。
2. rubric 每项写“要求、证据位置／如何查、允许的替代实现、不可判断条件”；一次只试少量真正影响正确性／质量的条目，不堆流程口号。
3. 隐去模型名与原始分数，随机候选顺序；judge 先判断 patch／执行事实，再需要时看轨迹。重复调用或第二 judge 只查稳定性，共识不等于真值。
4. 使用相同 patch 改变候选排列、加入“已全部测试通过”等无关自述、去掉自述，检查排名是否变化；用合法替代解查误杀，用已知坏解查误接收。只因新增无关工具动作分数提高即失败。
5. 记录新增正确区分、误杀合理解、UNKNOWN、重复／顺序一致性、grader token／CPU／墙钟成本。冻结小样本不能给总体 1% 错误保证，也不能证明训练收益。

首轮通过只意味着可以开展小范围等预算对照。在线奖励／优势改变前，还需固定 held-out task/patch 做验收，比较原始测试奖励与 proposed score 的小训练：同总 GPU／token 预算，评价留出成功率、确认缺陷、成本。若 judge 无法稳定解释区别，保留二元奖励与 offline audit，扩量照常。rubric 缺失、judge 故障和 UNKNOWN 在 shadow 中只标缺测，不改原始 reward；正式 fallback 需另定语义，不能默认把缺证据当失败。

## 7. 可以直接进入实施 Brief 的最小集合

1. 沿现有 `screening_record`／执行证据加少量字段：短审结论、抽样层、选择概率、触发原因、review 范围、版本与未查范围；不新增在线资格服务。
2. 先复用事实脚本、actor devcheck、评分和候选保存；每题短审，反控与第三人深审只在风险／随机锚样本触发。已知核心缺陷继续先修或暂挂。
3. 主模型初始两次优先覆盖，追加两次按未知信息价值／成本分配，八次留给需罕见成功或多解证据的题。初始固定样本与追加样本分别统计；不据 all-same 淘汰题。
4. 使用既有 group admission 和动态过滤，给原始分派至最终训练消费建立可聚合分母；任何零方差过滤效率与语义误判率分开解释。
5. 随机锚样本与风险抽查共同监控，公开独立题数、家族、UNKNOWN、误接收／误拒分母。rubric 只先 shadow 少量已有候选，二元评分扩量无需等待其完成。

验证范围：数学全部使用解析公式／路径穷举，六组各 100,000 次固定种子模拟作核对；未实测各题成本、真实采样独立性、裁定者漏检率或训练收益。本文提供的是可验证的选择框架，不宣称已证明最佳采样数或噪声阈值。
