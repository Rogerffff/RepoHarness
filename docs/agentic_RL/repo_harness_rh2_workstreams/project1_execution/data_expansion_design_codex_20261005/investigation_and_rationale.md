# Coder 数据扩量调查依据与设计细节

这是首版长稿，保留调查与推导。当前执行顺序和首批范围以[执行方案](proposal.md)为准，本页不是新增任务清单。


整理日期：2026-10-05。作者：Codex 主线程，结合三个独立调查子代理的本地核查、一手外部资料和主线程代码复核。本文供用户与 Claude 讨论，**尚未替换现行规则、派发模型实验、采购资源或更改训练奖励**。本轮以 `Qwen/Qwen3-Coder-30B-A3B-Instruct` 为主要筛选模型，保留 `Qwen/Qwen3.6-35B-A3B` 对照；这是用户当前偏好下的方案前提。

**建议把扩量组织成滚动供题：每题做一次有限的语义检查，复用环境与正负对照，尽早取得 Coder 的两个独立解答，再按实际候选决定补采样、窄修或暂缓。** 每题不再默认经历三轮完整独立审查，也不必先构造一个错误解；修订、共同模板和随机抽样仍有独立复核。首个工作周期登记约 200 个候选，先在前 36 个候选上核方法与成本，然后连续扩展；200 是处理量设计，不是保证产出 200 个合格题。

当前最大的改动是**明确限制每个审查任务要回答的问题和停止点**。自动化承担身份、完整性和执行事实，agent 判断题意与评分是否一致；允许尚未发现或不影响核心目标的边缘缺口，不把已确认的核心误奖、误拒和答案泄漏当作可容忍噪声。

底层调查见 [本地证据](local_evidence.md)、[外部来源](external_sources.md)、[筛选与采样研究](screening_sampling.md)，数字和原件位置另存同名 JSON。原工作账和历史结果保持原位，本目录不是新的任务调度账。

### Coder 是合理的工作起点 但适配性仍需实测

用户倾向 Coder 可以直接作为本轮主模型。支持这一选择的因素是：已有真实 CC 接线与本地失败案例；相对 3.6 更可能在现有任务中观察到能力差异；外部也存在匹配模型的继续训练证据。

Uni-Agent 官方 README 报告 Coder 在 **Claude Code＋SWE-reBench** 下从 40.2 到 46.2；同页的 ReAct＋SWE-reBench 是 47.4 到 54.2，ReAct＋R2E 是 46.2 到 52.0。这三条不能混成同一 harness 的结果。它们支持路线可行，不证明我们的筛选或训练收益。[固定版本官方结果](https://github.com/verl-project/uni-agent/blob/00b20d72d35816a3d66e6137c424a5b60e92d062/README.md#L73-L79)

该 README 的 CC 配方为 200 turns、128K context；其 RL 文档将所报量称为 task validation metric，未明确 SWE-reBench 版本。不能将它标成 SWE-bench Verified 的独立复现，也不能据此指定本项目必须采用 Prime V2。

本次按各题最新可用证据核查，Coder 分为 **32 题已核范围内成功、18 题候选失败、2 题诊断或材料限制单列**。18 题中 16 题有原始或补评 0，另两题原始 null 保留，但候选破坏兼容层有直接证据。3.6 对应为 40/10/2。两组包含不同材料、补评范围与尚未补齐的当前资格，均不构成统一条件下的通过率；具体边界见本地报告。

本地原始分数不能直接用于计算稳定难度。例如 Coder 的若干原始 null 已有同补丁补评；EA69 和 aiohttp `1c1c` 的原通过候选后来暴露遗漏。Pydantic6283 还有当前材料下 Coder 通过、旧 Qwen 候选失败的记录，但两次求解条件差异也必须保留。因此，“Coder 更弱所以必然更适合”和“所有题上 3.6 都占优”都超出了证据。

## 数据来源如何排队

**主供给是现有资产首次覆盖与已接入家族的池外扩展。** 不要求先修完当前池，也不因任务已处理过就优先追加完整双模型实验。

1. **现有池的低增量成本题。** 先接旧 6 题，再从 129 道未找到探针的环境池及诊断集合中选无未解决核心缺陷、配方成熟的题。旧 6 题为 NumPy `5e8301c2/a5ea773e/d89bc4bb`、Pandas `32dd55cb`、Scrapy `75450e75/9a15fcf8`；其中有题需要已核替代正对照，不能统一换回 gold。
2. **R2E 同仓池外题。** 利用现有评分语义与环境经验；按仓库、模块、改动范围和环境类型分层。Prime 的过滤记录可以提供先验，但其 R2E 验证允许 flaky 任务留下，不能当作稳定性证书。
3. **SWE-Gym Full。** 优先当前环境配方最成熟的 `repo×version` 组，同时保留少量新版本。Full 的非 Lite 题是否更难、是否更贵须测；同版本不能免除目标开发路径和评分对照。
4. **一个新家族的备用接入。** 默认选 Prime SWE-rebench V2 的 Python 子集：当前全量统计为 1,952 条 Python／6,272 条总记录，仍须排查与留出及既有任务的重叠。先取少量分布在不同仓库的完整记录，验证镜像可取得、题义与 parser 路径；若运输或评分接缝成本明显高，改试 SWE-smith Python。无需两路同时建完整适配器。

MiMo code 暂不作为主要供给，但保留为任务类型与 rubric 的后续候选。公开 code 资产含题面、镜像映射、测试补丁与执行命令，缺 gold 不意味着不可用；获得可信可行解以及接入其退出码评分需要额外工作。SWE-smith 有单仓镜像摊销优势，但必须处理注入补丁方向、空题面与任务族重复。两者均不凭来源名获得更高或更低的训练资格。

**不整仓排除 pandas、MONAI 或 Modin。** 当前已隔离的具体题继续隔离；其余按构建类型、资产需求和实际成本分流。编译型与重资产题先占小份额，待已预置的镜像和缓存可消费后扩量。这样可以避免速度优化把数据永久偏向纯 Python 小修改。每个低优先级桶保留原因和重新检查条件。

新来源排序以“每单位总投入得到多少质量合格任务、可解释的 Coder 行为和后续实际训练消费”为准。先验优先级可以调整；不能在结果出来后把失败候选从来源分母删掉。

## 每题怎样尽早进入探针

### 仓库负责人先读公开材料 再核私有评分

仍按仓库端到端负责，跨来源同仓不再另建一套所有者。负责人第一次接触题目时先看模型实际会收到的题面、初态和必要开发说明，记下几条核心要求与一个公开执行入口；随后读测试、参考解和历史证据。普通原题可在同一会话分阶段完成；题面发生实质修订时，再由未看私有材料的读者做一次窄核。

每题只维护一张短卡，字段可沿用既有记录：

- 完整 ID、来源与材料版本、初态和实际镜像。
- 公开核心目标，以及对应的决定性评分位置；没有覆盖的目标明确列出。
- 一条实际 agent 身份下的目标开发路径，或可复用的同条件证据。
- 空补丁与可信正对照的结果；正对照可为已独立核实的替代解。
- 当前已知缺陷、适用范围与下一步。
- 探针次数、候选及用途；模型分、语义核查和环境故障分开。

共同身份、依赖和完整性引用模板与机器回执。无需每题复制几百个哈希、重写完整环境说明或七维轨迹文章。

### 各阶段的完成条件

| 阶段 | 必须回答的问题 | 到此即停止的条件 |
| --- | --- | --- |
| 候选预检 | 身份是否完整、是否撞留出或已知重复、材料可取得、是否已有明确阻断 | 得到可接续、缺材料或暂缓的具体结论 |
| 有限语义检查 | 公开目标能否合理理解，核心要求是否被检查，有无现成的答案泄漏、矛盾、误奖或误拒证据 | 没有已确认核心阻断；未穷尽边缘输入按风险登记 |
| 环境与评分检查 | actor 能否操作目标代码；空补丁和可信正对照是否呈现预期差异；评分是否实际执行完整 | 当前版本证据齐全即可派首个探针，不等整批完成 |
| Coder 首轮 | 在干净独立会话、固定模型与材料下，两个候选得到什么结果 | 两次完成或明确无效原因；不能为了得到一次成功无限追加 |
| 候选检查 | 真失败、误拒、误奖还是环境问题；模型是否走了已知捷径 | 普通结果给短结论；争议用一个能改变处置的窄实验回答 |
| 入选材料 | 已知核心问题是否解决、材料可复用、关联与用途是否登记、所需独立复核是否完成 | 发布有限质量保证的训练候选清单，边缘未知不要求穷尽 |

**探针前保留最小语义检查，不使用“noop=0、gold=1就够了”的标准。** 这两个控制只能证明评分有差异，不能保证差异是题目要求。开发验证也不以 import 成功代替模型需要的实际工作路径。

已有同版本对照直接复用。新环境先做空补丁和可信正对照各一次；第二次正对照用于新环境家族、并发/时序/随机性风险以及预先抽定的稳定性样本。出现摇摆时固定候选做重复评分诊断；不能把 grader 的抖动当模型成败混合。gold 两次成功也不能证明任务稳定。

### 控制审查和修订的工作量

建议取消“每题必造一个退化补丁”的默认动作。下面三种情形才新增反控或测试：已知模板有具体漏洞；真实候选出现与公开要求矛盾的通过或失败；该题被抽中做深入质量校准。共享测试控制面由其负责人按模板核验，题级只检查是否落在适用范围。

题主可以按已有 R-a 至 R-f 授权做窄修。**一轮修订包含已发现且同属本题目标的问题，一次聚焦复核后结束；仍不清楚或继续扩张就暂缓，换下一题。** 只有影响一批题的共同根因才单列模板修复任务。这里限制的是工作范围，不用超时迫使 reviewer 给出通过，也不把新发现的严重问题藏起来。

每个 reviewer 的任务必须说明：输入版本、要回答的问题、已有证据、允许新增的验证，以及停止条件。审查者不能仅为提高“覆盖率”自行增加任务目标、公开接口约束或大量假想反例。严重意见必须给公开依据与具体后果；纯可能性记风险，不自动触发修订。对新增题面、测试修订及有争议的正对照保留独立核查。

普通候选先读完整补丁和评分摘要；按重复代码与语义去重后，可复用对相同补丁的判断。完整轨迹只在失败归因、环境修改、测试控制面触碰、完成声明矛盾或被抽中研究时展开。保留原轨迹不等于每轮必须全文重审。

## 采样怎样服务数据选择

### Coder 两次起步 追加采样有明确目的

每个新入队题默认 Coder 两次独立求解。固定同一 checkpoint、harness、公开题面、环境、评分版本与预算；独立会话和干净初态，不把前一答案交给后一会话。当前历史部署中 Coder 采用 `temperature=0.7/top_p=0.8/top_k=20/repetition_penalty=1.05`，3.6 为 `1.0/0.95/20`。新批应核实际消费值；这些是既有采样设置，不是最优性结论。

| 两次观察 | 当前用途 | 是否追加 |
| --- | --- | --- |
| 一成一败，且结果可信 | 二元奖励优先候选 | 已足够支持优先使用，不为凑固定四次而继续 |
| 两次成功 | 质量合格、暂未观察到失败 | 分层抽样及明确行为差异题可补；其余低频保留，不标成永久无用 |
| 两次失败 | 困难或存在未解释问题 | 核正常失败与可解性；部分补两次，其余留在困难/待诊断池 |
| 无评分、材料变化或 grader 摇摆 | 本轮不能当难度样本 | 修复对应原因；同补丁能补评时优先补评，不自动重跑模型 |

另预先选择最多16道分层随机“固定测量题”，Coder 完成四次，不因前两次混合而提前停止。这部分用于观察停止策略漏掉哪些题、测量不同来源的分布；样本较小，不能据此精确比较来源优劣。定向追加只为选题和归因，不与其合并估计总体成功率。3.6 在这组题上两次作为对照，避免每个新题都翻倍跑模型。

首批两次只是低成本分流。组相对二元奖励下，固定成功概率为 p、G 次独立采样的混合概率为：

`1 - p^G - (1-p)^G`

| p | 两次 | 四次 | 八次 |
| ---: | ---: | ---: | ---: |
| 0.1 | 18.0% | 34.4% | 57.0% |
| 0.5 | 50.0% | 87.5% | 99.2% |
| 0.8 | 32.0% | 58.9% | 83.2% |
| 0.95 | 9.5% | 18.5% | 33.7% |

这张表是固定策略、独立采样的数学结果。两次相同不证明 p 接近 0 或 1，四次也不足以精确估计单题难度。若全体题 p 都为 0.73，四次约 71.1% 会混合；若 73% 的题恒成功、其余恒失败，总体单次通过率同样为 73%，四次却没有混合题。不能从现有总通过率推出新一批会产出多少“有效信号”。

若只对前两次同质的题补两次，发现混合的概率与固定四次相同，平均调用数是 `2 + 2[p²+(1-p)²]`；p=0.5 时为3次。但停止后的 `成功数/次数` 不是无偏难度估计，早停也没有评估所有可能的后续缺陷。[可复算脚本](sampling_analysis.py)

### 探针与训练的关系

当前 [miles 组准入](../../../../../rh2/src/repoharness2/adapters/miles/group_admission.py) 已在全员合格后过滤零方差组。**不要求每个任务在离线探针中先出现混合，才有资格成为训练任务。** 质量资格与采样优先级分开；低频保留全同分任务，可避免一次性筛选把困难题和高通过题永久删掉。

探针产物用于选题、修订和分析，不自动成为在线 RL 的训练样本。新训练按当时策略重新采样并沿现有 token、logprob、group、mask、staleness 和 admission 链消费。不得把两个历史 probe 拼成训练组，也不在本数据任务中改组大小或组过滤语义。

建议在首批形成约 32–64 道质量合格、来源有一定覆盖的任务后，向训练负责人交一份小训练用清单，和扩量同时推进。该数量是闭环试运行的工程规模建议，不是效果验证的充分样本量；正式训练配置与效果评测另按既有授权衔接。

## 如何接受有限噪声而保住训练方向

允许不追求全部边缘场景、存在有限未查范围，以及通过抽检逐步发现未知缺陷。**允许未知噪声不等于继续使用已确认方向错误的奖励。** 以下分别处理：

| 观察 | 建议处置 |
| --- | --- |
| 核心目标无断言、已确认错误候选因核心漏洞得1、合理解因无依据限制得0 | 当前题修订或暂缓；查相同缺陷模板，不必停掉无关题 |
| 控制面可改、答案可达、解析/键集错误使奖励失真 | 交相应共享负责人，受影响范围暂停消费；不作为普通边缘噪声 |
| 没有具体违反核心行为的证据，只担心未覆盖边缘实例 | 记录范围与抽查优先级，可继续供题 |
| 有效测试随时序或资源变化 | 固定候选重复评分，定位 grader 不稳定；不能按模型失败处理 |
| 无关草稿、冗余说明或风格差异 | 不改变二元正确性；必要时进入附加质量观察 |

抽检采用两份名单：模型结果出现前就抽定的随机任务，以及结果出现后标记的风险任务。首周期建议从200候选中预选40个随机任务，保存分层规则和各题入选概率。未就绪题保留原抽中状态；如按预先随机顺序续补，应另标“就绪任务补充样本”，不能悄悄替换原抽样分母。原抽样反映整个候选处理过程，补充样本只能描述相应就绪层。初次结果中的通过与失败都核，防止只查假阳性。风险检查另报，不能混入总体误判率。

质量结果同时报任务数、候选数、确认误接受、确认误拒绝、未知，以及每种错误涉及的仓库/模板。重复候选按任务聚类，不把同一题的几十次评分当几十个独立质量样本。审查意见本身也有误差，分歧保留公开依据。

在理想独立等概率抽样、准确判断的假设下，40 个已完成核验样本零发现错误，单侧95%上界仍约7.2%；60个约4.9%。这是公式示例，不能直接套给分层配额、未就绪缺失或补充样本；实际统计须报告权重、缺失与仓库关联，且仍无法排除审查漏检。**现有证据没有给出“5%奖励噪声一定安全”的阈值**；误差估计用于决定加查哪些家族，最终容忍范围仍应由小训练与独立评测验证。[推导和限制](screening_sampling.md)

训练中沿已有 checkpoint 抽查与 D2 暂停规则追踪具体已登记漏洞，不另建逐 rollout 的 LLM 准入门。新任务一旦完成某版本的核验就发布，不等待全200题结案。

## Rubric 与改写如何安排

### Rubric 先做一个有限的旁路试验

使用现有52题中的约8题、已有原候选及正反对照做 shadow 评分，只记录，不改实际 reward。选题覆盖：正确且验证充分、正确但自验未完成、原评分通过而存在真实回归、正常失败，以及合理替代实现。Pandas50319、Pandas48106、EA69、Pydantic6283/8511 是可用的校准来源，不能把它们的所有标签都称为无争议真值。

每题最多选两至三项有明确依据的质量判断：关键需求/常用行为是否保持；候选完成声明是否有相应执行证据；在同等正确性下是否有可证明的额外实现或运行代价。缺证据记未知。必要编译、基础设施等待、无并行机会不处罚模型；“运行更多测试”“先写计划”“必须新增测试”不直接计分。

先用程序判断能确定的事实，LLM judge 补语义解释；隐藏模型名和原奖励，交换候选顺序检查判断是否变化。重点验证合法替代解被错拒、错误解被错接，以及评分成本和未知率。judge 不应为了评分修改候选。只有确实产生可信区分，才另提奖励形式和小训练对照；本轮不预设乘法、加权或惩罚值。

### 改写用于修正具体缺陷

允许现有 R-f 范围内的中性修订：去除完整答案、纠正与 base 不符的说明、补已有公开依据且必要的条件。保留正常的定位线索、复现和接口信息。实质改变目标的题作为新题处理，不能靠删除信息制造所谓难度。

只对被真实问题触发的题做一次修订，并保留原版。重新解题仅在公开信息或开发初态改变且新求解会影响决定时必要；私有评分修订优先给原 FrozenPatch 补评。同仓新合成暂不作为本周期主要供给，但来源不足或特定能力缺口明确时可用少量题检验，不能因“现在题多”永久排除。

## 首个工作周期的具体安排

下表是可讨论的工作量设计，不是已派发题单，也不把固定配额包装成统计最优值。

| 工作 | 建议规模 | 目的和执行方式 |
| --- | ---: | --- |
| 用旧证据校准新的短审查 | 12题，无需新模型 | 覆盖正确、正常失败、误奖、误拒、环境问题；核短流程能识别已知决定性问题。冻结审查模板后停止校准 |
| 首次覆盖候选队列 | 200个候选 | 初始40个来自当前池、80个R2E池外、80个SWE Full池外；未通过的仍计入分母 |
| 第一次流程检查点 | 前36候选，每路约12 | 比较新增工作、actor/评分缺陷、到首条模型结果的延迟；改一次模板后继续，不做整批等待 |
| Coder 初始探针 | 每个就绪题2次 | 单题一就绪就派发，不等所有CPU检查收口 |
| Coder 追加 | 初始Coder调用量的最多约25%，200题都就绪时最多100条 | 优先预选固定测量题的第3/4次，其次具体难度或缺陷疑问；旧52题若补采也计入这份额度 |
| 3.6 对照 | 最多16个预选分层题，每题2次 | 覆盖来源与成本层，不只选Coder失败题 |
| 随机质量深查 | 预选40个任务 | 与风险触发检查分列，检查首轮两候选及参考范围 |
| 新家族备用调查 | 一路，约8–12条完整记录 | 先验证接入资产；后续模型探针另列，不塞进当前运行次数 |

若200题全部就绪，初始Coder400条、追加最多100条、3.6最多32条，合计上界532条；质量不合格或材料未就绪会降低模型调用数，不能把这个上界写成实际预算。若就绪题较少，固定测量题数量与追加额度按比例缩小，不能挤掉新覆盖。候选分配在检查点按实际产出调整，保留原题单、换题理由和层次；40/80/80用于平衡立即供题与真正扩出当前池，不是固定等额来源比较实验。

每轮12题作为已有协作习惯下的工作包，每个工作包内仍逐题发布。未完成包不能阻塞下一仓已就绪题。单个仓库过度集中时，应先补其它仓库和模块；具体比例在取得首批候选分布后登记，不凭元数据大仓占比决定训练采样权重。

### 成本估计必须分清计算量和实际耗时

当前106次历史尝试是经过选择、不同材料/版本的运行集合。尝试时长相加是 attempt-hours，不是整个项目墙钟；评分时长、分段安装和测试可能嵌套，也不能重复相加。原始成本与性能优化后的成本分别报告。

容量估计采用可替换的实测量：

- 一次性成本：完整行取得、来源接入、环境家族配方、镜像构建与运输。
- 题级成本：有限语义检查、开发快检、正负对照、窄修、独立核查。
- 候选成本：求解GPU占用、actor工具CPU、评分CPU、存储与补评。
- 损耗：失败准备、无效attempt、清理、重试和排队。

例如 `模型调用数×平均求解时长/有效并发` 仅在同部署实测并发吞吐后才可作近似；不能用65秒串行中位数除以4，承诺四路并发的总墙钟。CPU也要按槽的CPU/内存/IO实需和尾部任务估算，不能把32 vCPU当32个评分槽。前36候选应形成P50/P90/P95与有效完成吞吐，再给预计完工时间和资源建议。

主要看五个量：首次模型覆盖任务数；质量合格的训练候选数及分布；同模型已见混合的任务数与局限；单位总投入的有效产出；从候选入队到首次模型结果的延迟。实际RL开始后再追加训练消费组数与零方差损耗，不用“文档数”“修复题数”替代成果。

### 镜像交付与性能线程的边界

数据侧负责每个环境配方的公开依赖、工具、可固定资产、基线编译、Git清理和文件所有权。构建时完成可提前的工作，并记录清理后实际初态；保留来源必要兼容改动。基线项目产物不能来自gold，gold验证产生的工件不进入solver镜像。编译缓存必须允许模型改源码后正确失效和重建，不能用旧二进制遮住错误源码。

数据侧交付：不可变镜像身份、配方、初态、公开开发说明、私有评分材料、正负对照和资源观测。通用模板消费、运行期清理、评分异步/并发、缓存机制和Prime部署由“评分性能与 Prime Sandbox 验证 (2)”负责。本方案不另写这些组件，也不以全部性能路线完成作为所有新题的等待条件。

### 对 Claude 初稿的独立回应

赞同其主线：Coder优先；自动检查结合agent审查；重复采样应有一部分固定投入；预构建和链路性能分工；优先复用既有家族。需要改进的是以下推断和执行方式：

- “没有任何题进入训练”不能从盘点字段推出；先核实际训练记录和历史题卡。
- 原始45/53、33/45及“约8%翻转”不是当前统一材料下的模型正确率或随机误奖率。新旧材料、重复尝试、null恢复和被选择深审的样本须分开。
- 当前142题环境池存在已登记题义/测试问题，复跑noop/gold不能整组直接放行。
- 每个候选都先gold两次、所有通过候选再跑更宽测试，不一定最省成本，也可能把不相关环境失败和合理行为改变标成模型错误。建议风险分层的稳定性检查和base/参考/候选的定点差分。
- 普遍固定四次能提供更多信息，但与新增覆盖竞争；建议两次初筛、随机固定四次与定向补采并存。全同分不永久剔除。
- “约200题×4”默认了200个候选全部通过准备；“4路约4小时”默认了串行时延可线性并行外推。先测真实产出率和吞吐，再定扩量时间。
- 缺gold的MiMo需要补可行解证据与评分接入，不宜概括成不能利用；pandas、MONAI、Modin也应按环境类型和具体缺陷分流。

这些差异来自独立核查与本方案取舍；后续应与 Claude 的正式调查逐条比较，不按作者或模型投票。

## 本轮交付与尚待验证的事项

本轮完成本地记录和代码的只读核对、候选规模重算、原始评分抽查、一手外部资料核查与采样数学计算。没有运行新模型、容器、训练或远端作业，没有复验全部旧环境，也没有替换当前任务账。

实施前最关键的未知是：新流程每题实际agent耗时；池外环境复用的成功率；短审查漏掉的决定性问题；不同来源下Coder的同模型成败分布；预构建后的实际吞吐；训练是否利用这些差异获得独立评测提升。前36候选的检查点和早期小训练分别用于回答这些问题，而不是把它们预先写成已知结论。

讨论应集中在三项取舍：是否采用有限逐题检查与分层独立复核；是否采用Coder两次起步与有限追加；是否按约200候选滚动扩量并同步形成小训练清单。来源身份接入和影子rubric的范围已具体列出，之后可直接拆成实施任务。
