## 3. 可选方案

**A. 修订版期望（该题 `expected_v1`）：该键改为 PASSED，其余 14 键不变。**
预计结果（按证据 4 推算，未实跑修订版）：gold 15/15 → reward 1；noop 只剩目标键 `ExecTest.test_unencodable_filename` 不符 → reward 0。不动隐藏测试、gold、镜像、grader 逻辑。载体二选一：新摄入修订（`task_revision` 从 `…/expected_v0` 升到 `…/expected_v1`，重新钉 pins）；或评分期"期望覆盖层"（按 task_id + 来源期望摘要匹配，带出处与证据）。两种都要改可信摄入面或其消费契约，属 T0。

**B. 把该测试移出评分。**
只删期望键不行：该测试仍会运行，观测里多出一个键，按证据 7 仍是 reward 0。要么同时从私有隐藏测试里删掉 / 跳过该测试（隐藏测试树摘要变化，派生镜像复核与覆盖表要随之更新），要么给 grader 加逐键忽略表（公共契约变化）。

**C. 暂不修订，隔离该题**（`dispositions.json` 记 `held_material`），可用题数 48 → 47。

## 4. 推荐：A

- 证据直接（来源自己的日志写明失败原因是宿主机环境缺 `mock`），镜像内 13 次观测无一例外，属于典型的"参考状态来自与发布镜像不同的环境"。

- 该测试在镜像里是正常的回归守卫（检查 coverage 在 `os.path.exists` 被 mock 时仍能工作）；解题补丁若真把这项防护弄坏，得 0 是合理的。B 会丢掉这道守卫，且改动面更大。
