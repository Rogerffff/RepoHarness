## 1. 问题

- 默认条件下 gold 只得 3/4（reward 0）：`r2e_tests/test_1.py::test_alter_interface_docs_for_cmdline` 在 gold 后仍 FAILED。R-f 两次、两个独立 runner（M3、09-09）结论相同。
- 原因链：
  1. 隐藏 `test_1.py`（即上游修复提交里的 `datalad/cli/tests/test_interface.py`，相对导入被改成了绝对导入）从**仓库内**模块 `datalad.interface.tests.test_docs` 导入 `demo_argdoc / demo_doc / demo_paramdoc`。
  2. 上游修复提交同时修改了这个模块：给 `demo_doc`、`demo_paramdoc` 加上带方括号的示例。
  3. gold 按 `is_gold_excluded_test_path` 排除测试路径（有 `tests` 段、`test_` 前缀），所以 gold 不含这个模块。R2E 把它的新版本放进了隐藏测试 `r2e_tests/test_2.py`，却没有把 `test_1.py` 的导入改指向那份副本。
  4. 结果：评分时 `test_1` 拿到的是工作区里**修复前**的 `demo_doc`，其中没有 `multiline cli-only with [ brackets` 这段文字。所以 `assert_in("multiline cli-only with [ brackets\n[] ]", alt)` 在任何源码修复下都不成立。
- 定性：**缺测试支撑材料**，不属于模型该做的改动。依据有三条：
  - 题面只要求修 `[PY: … PY]` / `[CMD: … CMD]` 内含方括号时的解析，没有提到测试夹具。
  - 上游源码改动（gold）本身也不碰这个文件。
  - 要让该键通过，解题者只能去改 `datalad/interface/tests/test_docs.py` 的夹具字符串，并逐字猜中隐藏断言要的文本。R2E 的 hygiene `test_files` 只含 `r2e_tests/*` 与 `run_tests.sh`，候选对这个文件的改动会被重放，所以技术上"能改"，但那等于按隐藏测试反推夹具，不是可以合理期待的解题行为。

## 3. 选项

- **A. 评分面补支撑材料**：把上游修复后的 `datalad/interface/tests/test_docs.py`（sha256 `2a3a29f7…`）作为该题的私有材料，评分 setup 时与隐藏测试一起恢复到原路径，并纳入 official / `test_files`（候选对它的改动不重放）。隐藏测试与 expected 都不变。代价是评分契约要新增一类"隐藏测试目录之外的支撑文件"：grading bundle 字段与摘要、派生镜像把文件放进 `/rh2_private`、`_restore_lines` 的恢复与核验、hygiene。这属于公共契约与生产代码变更，还要重建该题派生镜像。
- **B. 修订隐藏测试（出新的材料版本）**，expected 不变（仍是 4 键 PASSED），评分代码不变。两种写法：
  - B1：把 `test_1.py` 第 1 行的导入改为 `from .test_2 import (...)`，一行改动。
  - B2：把三个常量按上游修复后的值内联进 `test_1.py`。
  
  两种写法都会改变 `hidden_tests_tree_sha256`，要出新的摄入面版本（pins），并重建该题派生镜像（隐藏测试是在派生时搬进 `/rh2_private` 的）。
- **C. 不修材料**：
  - C1：从 expected 剔除 `test_alter_interface_docs_for_cmdline`，剩 3 键，目标键只剩 API 侧的 `test_alter_interface_docs_for_api`。但题面示例恰恰是 cmdline 函数，只修 `datalad/cli/interface.py` 的正确解答仍会得 0，评分与题面错位。

## 4. 推荐与理由

- **推荐 B1；在用户决定前先按 C2 隔离。**
  - B1 与上游修复后的测试语义逐字节等价（`test_2.py` 就是修复后的 `test_docs.py`），只改一行，评分机制和 expected 都不动。dry-run 里 noop 仍是两个目标键 FAILED，保持区分度；gold 4/4。
