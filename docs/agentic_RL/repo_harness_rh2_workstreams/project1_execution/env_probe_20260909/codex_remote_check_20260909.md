## 2. 新发现：MONAI-763 的共享内存故障

追加重复中，`Project-MONAI__MONAI-763 / empty / default / attempt 2` 记录为 `suspicious`。原始日志显示 PyTorch DataLoader worker 收到 `SIGBUS`，异常在 pytest 生成失败报告时传播为 `INTERNALERROR`，测试返回码为 3，没有测试摘要，`parsed_cases=0`。这不是模型解题结果变化。

同题六份 empty/gold 日志都出现了 DataLoader `Bus error`。其余五次仍生成摘要：非参考集内的三维分割集成测试失败，而参考 F2P/P2P 完整，因此仍得到预期 NO/FULL。六份日志的 SHA256 均与账本一致，脚本相同，路径按 attempt 分开；没有发现覆盖导致的伪异常。

远端正在使用相同 runner 的容器实测 `ShmSize=67108864`，即 64 MiB；runner 未设置 `--shm-size`。主线程先保持同题、镜像、脚本、默认网络、8 GiB 容器内存和 3 CPU，仅改为 1 GiB，尝试完整 empty/gold 对照。empty 运行中观察到共享内存实际占用约 435 MiB，原先快速报错的三维 UNet 测试开始真实 CPU 训练。该测试还要重复三轮各六个 epoch，并执行推理；它不在本题参考 F2P/P2P 内。为避免把诊断扩大为漫长的非参考测试训练，于 02:47 UTC 保存现场并中断这次 empty；gold 未启动，**这次完整对照没有评分结论**。

随后在两个 fresh 容器中，保留原测试的 `setUp()`、确定性随机种子、原始数据变换与 DataLoader（4 worker、batch size 2），仅执行前三批数据加载：

| 条件 | 结果 | 数据加载耗时 |
| --- | --- | ---: |
| 共享内存 64 MiB | 0/3 批；共享 tensor 分配报 `No space left on device` | 12.1 秒 |
| 共享内存 1 GiB | 3/3 批；首批观察共享内存约 217 MiB，每批 tensor 约 54 MiB | 15.1 秒 |

这对短复现确认了默认共享内存容量不足，支持原 SIGBUS 的根因解释；没有验证完整评分时长、UNet 测试本身能否通过或最终 rh2 配置。两次诊断容器已清理，原全量作业继续运行。本轮没有改测试选择或将资源条件写成生产默认值。

这条记录不会被原 `load_done()` 自动补跑，因为 `suspicious` 被视为已完成。全量收尾须单列它，不能只看完成标记或汇总成功率。`full216_done.flag` 也只是 shell 在 Python 命令之后写入的标记，不能代替逐题、逐门、逐次的结果核对。

## 3. 原报告需要更正的解释

### 3.1 Prime 的去色规则没有被本次实验推翻

固定 [Prime 源文件](https://github.com/PrimeIntellect-ai/prime-envs/blob/c4d04dfe212c153a587ea4ce072ae6753e74d6e9/environments/swe/r2e_gym/r2e_gym/taskset.py) 的 `_decolor` 正则包含一个真实的 `0x1b` 字节。不可见字符在显示或转录时漏掉，才形成“只删除方括号、不删除 ESC”的误读。

主线程下载固定版本原始字节，用 AST 仅提取 `parse_log_pytest`、`_decolor`、`calculate_reward` 三个纯函数，对 ANSI 最小例子及 144 份 v3 原始日志执行对拍，全部一致。**应保留 expected 与日志键需要同规则规范化的要求，但撤回“发现两套上游实现导致 pillow 必然零分”的结论。**

### 3.2 七题 gold 不一致是比较方法误报

runner 已经对同一组纳入的源文件执行 `git diff`，因此不能归因于被过滤的测试或非 Python 文件。更直接的核查是将两份补丁分别应用到数据行的原始文件，严格检查上下文和行号，再比较完整结果。

coveragepy、datalad、orange3、两题 pandas、scrapy、pillow 的七题三次工件均通过上述核查。此前简单比较 `+/-` 行序列，把空行归属等 diff 表述差别误当成源文件差别。该疑点可以关闭，后续无需为此重跑 Docker。

### 3.3 费用不能相加并发期间的余额差

`cc_probe.py` 对每题读取同一个账户的前后余额。三个并发任务的窗口重叠，例如三题同时以 ¥54.22 为起点，所以逐题差值之和 ¥38.36 重复计数，不能作为总费用或均摊题费。

账本自身观测端点是 ¥55.20 → ¥36.73，净减少 ¥18.47；Claude 报告更宽的观测区间为 ¥55.32 → ¥36.56，净减少 **¥18.76**。主线程最后于 02:49 UTC 通过官方账户接口确认 DeepSeek 余额仍为 ¥36.56，Vast `credit` 约 **$4.88**。这是账户区间净变化，存在其他调用或延迟入账时不等同于本批精确账单。后续记录请求 usage 与独立整批账户窗口，不相加重叠窗口。

另需修正分母：27 条 CC 记录是 24 道题加 3 次 Docker 启动失败，涉及 2 题重试；该 24 题与默认 profile 下 gold 失败的交集为 4 题，原文“22 题里 12 题”的说法已经失效。保留全体 13/24 的观察和逐题原因即可。

### 3.4 探针的投影和运行条件还不等于 rh2

探针 `candidate_projected` 只去掉候选中与官方 `test_patch` 精确同路径的部分。当前 rh2 还按 `DEFAULT_SWE_TEST_GLOBS` 排除其他测试路径；实际 24 个候选里有 **6 题**存在这种差别，其中 4 题在探针中 resolved：

| 题 | 探针保留而当前 rh2 会排除的额外路径 |
| --- | --- |
| dask-7656 | `dask/tests/test_base.py` |
| modin-6298 | `modin/numpy/test/test_array_math.py` |
| pydantic-8793 | `tests/test_create_model.py` |
| pydantic-5706 | `tests/test_edge_cases.py`、`tests/test_types.py` |

另外两题为 conan-13326、pandas-48106，探针结果是 unresolved。**尚未证明这些差异改变分数，但“投影后无翻转”不能证明 rh2 parity。** 最小后续对账应复用这些现成候选工件，优先比较真实投影和 grader，避免重调模型。

MONAI-2454 的候选新建官方同名测试，确实让独立官方 runner 应用测试补丁失败；但是当前 rh2 在 `generate.py` 构造可信投影，`trusted_projection.py` 将官方测试路径归入 ignored，`manager.py` 仅重放 included 路径。候选同名文件本来不会进入 fresh grader；`prepared_task_face.py` 对基线不存在的官方新增路径也已有跳过 checkout 的处理。**现有证据不支持给 rh2 新增“先删除同名文件”的修复。** 应先验证现有链路，而不是据独立 runner 的现象推断生产缺陷。

`offline_noinstall` 与 `grader_user` 也是分别测试的：前者断网、省 install、root；后者默认网络、root 安装、54322 测试。没有运行“断网＋省 install＋非 root＋rh2 控制文件布局”的完整组合。
