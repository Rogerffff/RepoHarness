## 1. 当前代码事实（2026-09-19 核对）

### 1.1 miles 侧：现成可复用的部分

- 驱动：`train_async.py:94–95` 在 `eval_interval` 已设、`start_rollout_id == 0`、未加 `--skip-eval-before-train` 时先做 rollout 0 的 eval；`:198–199` 在每步权重发布之后按 `eval_interval` 调 `eval_dispatcher.dispatch(rollout_id)`；`:212` 结束前 `drain()`。
- 分派：`miles/ray/rollout/eval_dispatch.py:29–31`，`eval_uses_snapshots=False`（即 `--eval-num-gpus 0` 且 eval fn 不是 checkpoint 类）时直接 `await rollout_manager.eval.remote(rollout_id)`，**异常原样上抛给训练驱动**；只有快照分支才把失败降级成 `report_eval_skip`（busy / export_failed / crashed / ckpt_missing / unhealthy / pin_violation）。
- 共享引擎执行：`rollout_manager.py:92` 在 train/eval 函数路径相同时复用同一 rollout fn 实例；`fully_async_rollout.py:188–199` 的 `_call_eval` 清 `_producer_resumed`（worker 不再提交新组）、跑 `run_eval_datasets(self.state, …)`、`finally` 里恢复。**不等待 `_active_groups` 结束**。

- 结果聚合：`miles/ray/rollout/metrics.py:21–59`，`reward is None` 计入 `eval/<name>-none_reward_ratio` 并**按 0.0 计入** `eval/<name>` 均值；NaN 会让均值变 NaN。提供 `--custom-eval-rollout-log-function-path` 钩子（返回 True 可跳过默认日志）。

- 不训练的运行形态：`--debug-rollout-only` 存在（`arguments.py:2097`、`3289–3299`），快照 eval 明确不支持该模式（`:3479–3482`），共享引擎 eval 不受限。

### 1.2 RH2 侧：fa_formal 下 eval 走不通、且结果表达有误

1. **身份**：`adapters/miles/generate_fn.py:144–150` 在非 s1_compat 下无条件调 `_assert_group_admission_filter_wired` 与 `mint_attempt_identity`；后者要求 `sample.group_index` 是非负 int（`identity.py:135`），eval 样本是 `None` → `MilesIdentityError(identity_facts_missing)`。按 §1.1 的异常传播，共享引擎形态下这会**直接停掉训练驱动**。
2. **任务绑定**：prepared 链（`generate_fn.py:158–168`、`bringup.py:1745–1768`）按 attempt 绑定解析任务与评分材料；`PreparedTaskFace.load` 只加载一个产物目录，并把 `args.prompt_data` 与其 `prompts.jsonl` 按内容 digest 绑定（`prepared_task_face.py:410–411`）。eval 题没有对应的产物加载点，也没有 train/eval 题目互斥检查（06 计划 W8 的"eval taskset 身份分离断言"）。
3. **结果表达**：`generate.py` 交付面的 eval 分支写 `base_sample.reward = float(grading_reward or 0.0)`——`failed_to_grade`（reward=None）被写成 **0.0**；`_abort_result` 对一切 abort 写 `reward = 0.0`。训练面靠 admission 载荷与 NaN 占位守住 P4 红线（infra 不落 0 分），eval 面目前没有对应保护：基础设施失败会被统计成模型 0 分。
4. **记录**：`write_execution_audit_record`（`bringup.py`）不区分训练与评测 attempt；[run_report.py](../../../../rh2/src/repoharness2/adapters/miles/run_report.py) 会把 eval attempt 计入训练统计。逐 attempt 的权重版本事实已在 `outcome_v2.turn_weight_versions / current_version_at_finalize` 里，可直接复用，不需要新的模型哈希。

## 2. 设计：一条 eval 分派面，A/B 两种形态共用

### 2.1 评测身份（不套训练组算术）

eval attempt 仍使用六字段身份（正式链的 Outcome v2、receipt、finalization store、termination 事实都按它 join，不改这些消费者），但值在独立命名空间、由**宿主事实**推导：

| 字段 | 取值（例：数据集 `swe_dev`、rollout 20 的 eval、第 3 条 prompt 的第 1 个样本） |
| --- | --- |
| `rh2_prompt_group_id` | `eval-swe_dev-r20-p3` |
| `rh2_group_index` / `rh2_member_slot` | `3` / `1` |
| `rh2_rollout_execution_id` | `eval-swe_dev-r20-p3_m1` |
| `rh2_physical_attempt_seq` / `_id` | `1` / `<execution_id>#p1-<uuid8>` |

规则：数据集名只允许 `[A-Za-z0-9_.-]`（其余拒绝，不静默替换）；eval 只接受 fresh（PENDING）样本，携带任何保留身份键即拒（与训练同一条 F1 规则）；训练身份以 `miles_g` 开头、评测以 `eval-` 开头，两个命名空间互不可达。新增函数 `mint_eval_attempt_identity`（`identity.py`），训练的 `mint_attempt_identity` 不改。

宿主事实来自 fork patch 0018（§3）：miles 在 `inject_metadata` **之后**盖 `metadata["rh2_eval_dispatch"] = {dataset, eval_rollout_id, prompt_index, sample_slot, n_samples_per_eval_prompt, num_prompts}`，数据集 JSON 自带的同名键会被覆盖。缺这份事实（stock pin 树或旧 fork）时 fa_formal 的 eval 明确拒绝（`eval_host_facts_missing`），不猜。

### 2.2 任务与评分：复用 prepared 链，train/eval 两个产物、两个平面

- eval 题用**第二个 prepared 产物目录**（B 线用同一个 trusted-prep 工具对 eval 题单再跑一次）：`RH2_EVAL_PREPARED_TASKS_DIR`、`RH2_EVAL_PREPARED_TASKS_MANIFEST_SHA256`、`RH2_EVAL_HOST_GRADING_ARTIFACT_PATH`、`RH2_EVAL_HOST_GRADING_ARTIFACT_SHA256`。bringup 加载成第二个 `PreparedTaskFace`（类本身不改）。
- `AttemptAssignment` 增加 `evaluation: bool`；注册表的 `verify_dispatch` 按平面选产物：eval attempt 只能绑定 eval manifest 的行，训练 attempt 只能绑定训练 manifest 的行。`_resolve_task` / `_resolve_grading_spec` 同样按平面取 face。
- **启动期校验**（共享引擎形态下 eval 异常会停训练，所以接线错误必须在启动时暴露）：`eval_interval` 已设且非 s1_compat 时，eval 产物缺失、eval 数据集不是恰好一个、其文件内容 digest 与 eval manifest 的 `prompts.jsonl` 不符、train 与 eval 的 task_id 有交集、配置了 `reward_key` / `eval_reward_key`（miles 聚合会对 `reward=None` 取下标而崩）——任一成立即 `StartupCheckError`。
- 不训练的独立评测作业：`RH2_EVAL_ONLY=1` 时训练产物可缺省，此时任何 `evaluation=False` 的派发 fail-closed。
- 评分、沙箱、预算完全走现有 manager / profile / `SWE_AGENT_TIME_BUDGET_SEC`，不另写 grader；评测不挂 `_assert_group_admission_filter_wired`（eval 样本不进 buffer / filter，独立作业也不配置该 filter）。

### 2.3 结果表达：三类分开，不把"已派发"当成功

`RolloutOrchestrator.generate()` 的唯一出口（现在盖 termination 事实的位置）在 `evaluation=True` 且非 s1_compat 时再盖一份 typed 载荷并规范化占位样本，`_deliver` / `_abort_result` 内部不改：

```json
{"schema_id": "rh2.eval_attempt_result.v1",
 "eval": {"dataset": "swe_dev", "eval_rollout_id": 20, "prompt_index": 3, "sample_slot": 1},
 "task_id": "…", "physical_attempt_id": "…",
 "result_class": "graded | reward_unavailable | execution_missing",
 "task_outcome": "resolved | unresolved | null", "reward": 1.0,
 "unavailable_reason": null, "termination_kind": "completed",
 "turn_weight_versions": ["20", "20"], "current_version_at_finalize": "20",
 "model_name": "…", "runtime_profile_digest": "…", "time_budget_seconds": 600, "grader_version": "…"}
```

| `result_class` | 来源 | 占位样本 |
| --- | --- | --- |
| `graded` | 评分报告 resolved / unresolved | `reward = 1.0 / 0.0`，status completed |
| `reward_unavailable` | `failed_to_grade`、unsafe artifact 永久拒绝 | **`reward = None`，status aborted**（miles `generate_and_rm` 对 ABORTED 不调 RM） |
| `execution_missing` | Outcome `completion_class = missing`（harness / sandbox / 代理等已归因故障） | 同上 |

run-fatal 照旧上抛并停 run。s1_compat 冻结路径逐字不变。

聚合用新模块 `adapters/miles/eval_report.py`，经 `--custom-eval-rollout-log-function-path` 接入（返回 False，保留 miles 默认日志）：按数据集统计 planned / received / graded / resolved / unresolved / reward_unavailable（分原因）/ execution_missing、`resolved_rate_graded`、`resolved_rate_all`、观察到的权重版本集合与是否单一版本，发 `eval_point` 事件，其中 `complete = (received == planned 且后两类为 0)`。before/after 对比是否要求 `complete` 由 B 线统计协议定，A 线只保证事实分开；`eval_smoke` 不再被当作评测完成的证据。

持久化：execution audit 行加 `evaluation` 块（eval 身份 + 上表字段的子集）；`run_report.py` 把带该块的行从训练统计中分出，单列 eval 点汇总。

## 4. 共享引擎形态（B）的生命周期核查结论

### 4.1 现成机制实际覆盖什么

| 问题 | 结论 |
| --- | --- |
| 评测期间会不会换权重 | 不会。`dispatch` 在发布之后被 `await`，训练主循环停在这里，期间没有新的 publish；逐 attempt 的 `turn_weight_versions` 是引擎回报的第一手证据，`eval_point` 会标出是否单一版本。 |
| 在飞训练组怎么处置 | 继续跑（只暂停**新组提交**）。它们与评测样本共用 `generate_fn_semaphore`、Docker、评分队列（默认并发 4 / 队列 8）。首版**不排空**：与用户"不把等待所有在飞任务结束预先定为唯一办法"一致；代价是评测窗口内训练 episode 的墙钟截断与评分反压可能升高，用 `eval_window` 事件 + 现有 episode_deadline / 反压观测量化，八卡试运行后再定是否需要排空或限流。 |
| 异常与恢复 | 单个 eval attempt 的已归因故障被编排层收成 `execution_missing`，不影响其它样本；run-fatal 与接线错误上抛 → `_call_eval` 的 `finally` 恢复 producer → 异常到训练驱动 → 走既有 W5a 关停链。这与训练面的 run-fatal 语义一致，不新增"评测失败降级为 skip"。 |
| 取消 / 关停期间 | `RolloutFnClosed("eval")` 已有（`fully_async_rollout.py:175–176`）；不把一次性 shutdown 当可恢复 pause，本批不改。 |

### 4.2 结论

B 只需要 §2–§3 的窄适配，不需要改 miles 的暂停 / 恢复生命周期，建议与公共入口一起实现。

### 4.3 后置：作业内专用 eval 引擎组

`--eval-num-gpus > 0` 时 miles 把 eval 指到独立 router（`EvalFleet.pin` + `retarget_args`），但 RH2 的模型代理 / 网关在 `BringupService` 单例启动时就绑定了训练 router，eval attempt 的模型请求仍会打到训练引擎。要支持需要按调用选择上游，属于明显扩大的生命周期改动 → 后置，不阻塞首训。快照形态的 skip 事件（`report_eval_skip` 补 rh2 事件）随它一起做。

## 7. 需要用户确认的点

1. **eval 下"评不了分 / 没跑成"不再记 0 分**（§2.3）。这是把已有的 P4 红线落实到评测面，但会改变评测数字的口径（现在 infra 失败被算成 0 分），所以请确认。推荐：确认。
2. **fork patch 0018**（宿主侧评测身份事实 + 窗口事件）。不打 patch 的替代是从 `sample.index` 反推并靠数据集 JSON 自报名字，拿不到 eval 的 rollout_id，且身份事实可被输入数据伪造。推荐：打 patch。
3. **eval 题单 = 第二个 prepared 产物目录**，train/eval 题目互斥在启动时强制。替代是单目录双 prompt 文件，需要改 B 线的 prep 工具与 manifest 格式。推荐：第二目录。
4. **共享文件的落地顺序**：`generate.py` 三处与 `bringup.py` 四处小改与 B Claude 当前工作同文件。建议等他的 CR2 余项（`manager.py`）收口、确认这两个文件他手上没有未完改动后由我顺序落地；A 线自有文件与 fork patch 可以先做。
