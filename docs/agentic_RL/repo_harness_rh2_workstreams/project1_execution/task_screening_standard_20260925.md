# 题目与环境审查：成本可控的统一标准与处置规则（草案 v0）

> **已由 [v1 定稿候选](task_screening_standard_v1_20260925.md) 替代**（2026-09-25）。本稿保留原样，供 [三方复核](task_screening_standard_review_20260925.md) 的行号引用。

2026-09-25 / Claude B。**草案，供用户与 Codex 讨论；未批准、未实施。** 以现行做法为基础：[八方面协议](swegym_task_audit_20260920/quality_review_protocol_20260920.md)、[记录模板](swegym_task_audit_20260920/quality_batch01_20260921/record_template.md)、[处置约定](environment_screening_definition_20260915.md)、[开发条件流程](actor_development_validation.md)。本文不推翻它们，只补四样东西：**按用途下结论、按严重度分级处置、预先授权的修订模板与预算上限、分层的审查深度**。目的是让用户不再逐题决定"这题怎么办、环境修不修"。

依据：R2E 首批 8 题与第二批 12 题（[首批](r2e_static_review_20260925/README.md)、[第二批](r2e_static_review_batch2_20260925/README.md)、[Codex 第二批复核](r2e_static_batch2_review_20260925/README.md)），SWE-Gym 首轮 40 题、扩大 32 题、任务二 21 题开发条件、8 题基座探针、166 题环境修复。各线程问题清单的出处见 §7。

## 0. 目标与原则

**首要目标：进入训练的题，reward 能区分题目的核心行为；环境不会让正确解失败。** 不追求每道题完美，也不追求挽救每道题。

1. **按用途下结论**。每题分别回答三件事：能否做诊断，能否作训练候选，能否作留出评测。"环境合格""needs_review"都不等于能训练。
2. **按问题所在层和严重度处置**，不按"有没有问题"处置。主动构造反例时，几乎每题都能找到覆盖缺口；要区分的是缺口是否已让 reward 偏离核心目标。
3. **共同根因优先**。环境、构建、链路问题修一次、扫全池同类，不逐题重新发现。
4. **便宜的先做**。脚本预检和真实启动链开发核对（约 1 分钟/题）先于深度静态审查；深度只投在有风险信号的题上。
5. **预授权 + 预算上限 + 超预算自动降级**。模板内的修订由 Claude 执行、Codex 复核；超出模板或预算的，自动转为"仅诊断"，不阻塞其它题，也不需要用户逐题拍板。
6. **证据分层照旧**：静态推断、历史运行、当前 CPU、真实模型分开写；未查写未查。

## 1. 每题的三个用途结论

| 用途 | 条件 |
| --- | --- |
| **诊断**（观察模型行为、定位环境问题） | 环境可运行；评分结果可解释（知道得 0 / 得 1 意味着什么）。原始 reward 与语义核对分列。 |
| **训练候选** | 满足诊断条件；没有 S1 问题（§2），或 S1 已按模板修好并验收；登记了 S2 问题与跨题关联。 |
| **留出评测候选** | 满足训练候选的质量条件；没有用于选模型、调提示或调配方；与训练集按仓库分离，并核对训练集初态不含该题答案。修订过的题只能作"标明版本的自建评测"，不冒充原 benchmark。 |

记录方式：沿用 `screening_record.json`，在 `usage` 下写 `{diagnostic, train, heldout}`，每项取 `yes / conditional / no` 并附原因码（§2 的问题编号）。`disposition.state` 仍用现有五种（`ready_for_probe / needs_repair / needs_review / unsupported_conditions / reject_revision`），不新造状态。

## 2. 问题目录与严重度（所有线程共用）

- **S1**：不进训练，直到修好。
- **S2**：可进训练，但要登记，并在探针或训练后抽查。
- **S3**：只记录。

| 编号 | 层 | 问题 | 严重度 | 默认处置 |
| --- | --- | --- | --- | --- |
| E1 | 环境 | 依赖、版本、资产缺失；actor 与 grader 不一致 | 视影响：让正确解失败为 S1 | 配方级修复，并扫全池同类；actor 与 grader 同步核对 |
| E2 | 环境 | 构建、编译不可用 | 同上 | 同上；完整链路验证"改源码 → agent 构建 → 正式导出 → 全新 grader 加载新产物" |
| E3 | 链路 | 权限、noexec、导出、清理、答案可达 | S1 | 属 A 线的通用链路，按接缝交接；受影响的尝试记 infra 并重跑 |
| E4 | 环境 | 依赖外网 | S1 | 预置资产或离线版；做不到就标 `unsupported_conditions`，写明恢复条件 |
| E5 | 评分 | 时序抖动 | 确认抖动后为 S1 | 看失败堆栈，做同条件对照；不自动归环境。确认抖动且无法稳定，就用模板 R-a 移除该键，或隔离 |
| T1 | 测试 | **误拒合理解**：精确文案、内部 helper、mock 形状、执行顺序没有公开依据；期望 FAILED 的死键惩罚更完整的修复 | S1 | 模板 R-a / R-b / R-e；超预算则仅诊断 |
| T2 | 测试 | **核心判据失效**：候选得 1，但（a）题面标题或期望行为描述的主场景，直接检查仍是坏的；或（b）靠钻空子通过 | S1 | 模板 R-c；gold 通不过有依据的新断言、或超预算，则仅诊断 |
| T3 | 测试 | **部分覆盖**：主场景确实修好，但题面提到或隐含的变体（其它输入形态、方向、取值、入口）没测到，真实但不完整的实现可得 1 | S2 | 保留为训练候选；登记已知可钻的形态；抽查中被钻中则升级为 T2 |
| T4 | 测试 | **回归漏测**：修好了主场景，但破坏别处行为的补丁得 1 | S2 | 同 T3 |
| T5 | 测试 | 死键、参考 ID 失配、XPASS | S1 | ID 重绑定或删除死键（R-a），做不到则隔离 |
| T6 | 测试 | P2P 为空或回归选集过窄（SWE） | S2 | 脚本批量盘点，登记 |
| P1 | 题面 | 泄漏答案 | S1 | 在题面修订机制建成前不进训练，仅诊断 |
| P2 | 题面 | 与测试矛盾：照题面做会判 0 | S1 | 测试错就走 T1 的修订；题面错就等题面机制，暂仅诊断 |
| P3 | 题面 | 测试要求超出题面、需要猜 | 合理解会被判 0 时为 S1，否则 S2 | 按 T1 处理 |
| P4 | 题面 | 误导、原例不复现、描述不全，但读代码能消解 | S2 | 保留（真实 issue 本来如此，属于题目难度），登记 |
| P5 | 题面 | 两种合理读法，测试只接受一种 | S1 | 用 R-b 让测试接受两种；做不到则交用户决定契约，决定前仅诊断 |
| G1 | gold | gold 不完整或有回归 | 本身不作处置依据 | 转化为测试层问题：测试是否因此放过同类错误（T3 / T4）；不为保住 gold 缩小公开需求 |
| X1 | 关系 | 同仓跨题包含、同源派生 | S2 | 训练可用：登记关联，控制重复采样；留出评测按仓库划分，并查训练初态是否含答案 |
| X2 | 材料 | 串题、引用错误 | 协调者修正 | 不影响题目本身 |

**T2 的 (b)"钻空子"**：对被测的那个输入，行为也没有真正实现，只是让检查通过了。例如：
- 硬编码输出值，而不是按输入算出来（datalad 的 `exit_code = 3`）；
- 吞掉错误、抑制症状（scrapy `75450e75` 的 K3）；
- 写出空产物（coveragepy `ea6906b0` 的空 `.gitignore`）；
- 作用在与目标行为无关的对象上：存到旁路属性（coveragepy `97997d2c` 的 W2）、校验错误的连接（aiohttp `22a12cc2` 的 K3）；
- 与输入无关的无条件行为（aiohttp `22a12cc2` 的 K4，一律拒绝）；
- 就地改坏被比较的输入（pillow `3a61c9e9` 的 W5）。

**只对某类输入特判、但对这类输入确实做对了的**（只特判 None、只处理整数 1、只登记一个标签），不算钻空子，属于 T3。

**T2 与 T3 的分界**：T2 是"题目本身那个场景没修，或靠手段过关"；T3 是"那个场景真修了，只是没修全"。T2 会教模型钻空子，训练风险高；T3 是有限测试的普遍噪声。Codex 引用的外部实验说明：基座一次没钻，不代表 RL 后也不会钻。所以 T2 要在训练前处理，T3 可以靠后续抽查。

## 3. 预先授权的修订模板（Claude 执行，Codex 复核，用户不逐题批）

| 模板 | 做什么 | 适用 |
| --- | --- | --- |
| R-a | 删除死键、改正错误的期望状态；对称处理相关期望键，并确认剩下的测试仍能区分目标修复 | T1、T5、E5 |
| R-b | 把没有公开依据的精确约束（文案、内部 helper、mock 形状）放宽为有公开依据的行为断言 | T1、P3、P5 |
| R-c | 补不超过 2 条有公开依据的核心断言：题面原例的一般形式，或题面明说的行为 | T2 |
| R-d | 环境、资产、配方修复，评分参考不变 | E1、E2、E4 |
| R-e | 把 mock 交互测试改成真实行为测试；必须同时覆盖正例与反例（例如合法指纹与错误指纹） | T1、T2 |

**统一验收**（R-a 到 R-c、R-e）：
- gold 仍为 1；
- noop 为 0；
- 已知被误拒的合理候选变成 1；
- **已知相关的错误候选仍为 0**；
- 公开核心需求在测试里有直接断言；
- 保存新版本、父版本、理由和触发反例；
- Codex 复核。

如果有公开依据的新断言让 gold 通不过，就不做这个修订，该题转为仅诊断并记录事实；不为保住 gold 放宽需求。

**不在模板内、需要用户决定**：
- 修改题面（R2E、SWE-Gym 目前都没有题面修订机制）；
- 改变任务目标；
- 改通用评分语义（例如评分端代为构建、改 parser 或判分规则）；
- 改网络政策；
- 超出批次预算的投入。

用户可以不决定，不决定也不阻塞其它题。

## 4. 审查深度与成本

| 步骤 | 覆盖 | 内容 | 单题成本（参考值） |
| --- | --- | --- | --- |
| **0. 脚本预检** | 全部题 | 期望 FAILED 键；目标测试数量和断言类型；mock / patch 内部名；精确字符串断言；单值断言；调用后才读输入；gold 改动含编译源码；题面与 gold 重叠；两份跨题比对；actor 与 grader 依赖是否一致；P2P 为空；镜像初态有脏文件 | 秒级；输出风险标签，决定后续深度 |
| **1. 开发条件实跑** | 所有拟作训练候选的题 | 真实启动链加桩，跑公开复现与相关窄测试，另做私有 gold 对照。**原样使用公开读者的命令，不改写参数** | 约 1 分钟 |
| **2a. 标准静态审查** | 没有 S1 信号的题 | 公开读者加主审（先封存初判，再对照历史）；输出问题编号、严重度、三个用途结论；只登记漏测，不做多候选证明 | 2 个会话，每个约 20 分钟 |
| **2b. 加深审查** | 有 S1 信号、拟修订、有争议，或被抽中复核的题 | 在 2a 基础上加独立复核；每个决定性问题只跑 1 个代表候选，一题最多 3 个 | 3 个会话，评分不超过 3 次 |
| **3. 修订与验收** | 模板内的 S1 | 做一轮修订、一轮验收；不收敛就自动转为仅诊断 | 验收评分约 5–8 次 |
| **4. 批次汇总** | 每批 | 一页：数量、主要根因、修复收益、需要用户决定的例外 | — |

**独立复核的覆盖面**：全部修订题、全部 S1 判定、全部争议题；其余题随机抽约 25%。当前 48 题 R2E 池剩下的 28 题，按 Codex 建议仍全做三角色，作为筛查方法的校准样本。

**成本对照（第二批 12 题）**：实际用了 36 个会话、81 次正式评分，其中大量评分用来证明"测试偏宽"。按本标准估计：约 26–30 个会话（普通题复核抽样），评分约 25–35 次（主要集中在确认 S1 和修订验收）。

**不重复做的事**：
- 一题一个负责人、一份记录；探针分析、开发核对、静态审查都回写同一题卡，不各起一套；
- grader 侧修好的依赖，必须同步核对 actor 侧；
- 能用脚本查的项不靠人工；
- 封存稿只保存"读历史前的初判"这一份，不为每份产物做哈希链。

## 6. 探针与训练阶段的持续抽查（离线进行，不改在线奖励）

- **探针**：原始 reward 与语义核对分列。语义核对只读结构化的 `RH2_POSTCHECK` 分项；打印型脚本要明确读哪一行、什么算失败，不能用外层退出码代替判定（Codex 第二批复核 §3）。
- **训练后**：
  - 抽查一部分得 1 的补丁，看 T3 / T4 登记的漏洞有没有被钻中；
  - 抽查一部分得 0 的补丁，看有没有误拒；
  - 命中的题回流到修订队列，S2 升级为 S1。
- 不静默删样本，不把后检变成在线 LLM 奖励。
