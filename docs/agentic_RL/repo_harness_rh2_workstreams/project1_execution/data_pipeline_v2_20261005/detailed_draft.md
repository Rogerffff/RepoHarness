## 0. 一页结论

**要改的五件事【建议】**

1. **顺序倒过来。** 新顺序：脚本闸门 → Coder 顺序采样（先 4 次，4/4 再采 4 次）→ 只对拟准入题和被标记的题做一次有界审计 → 按仓库成批修订（每题 1 轮加 1 次小修，计入终身次数）→ Codex 按批复核，并随机盲抽估计噪声 → 准入。取消三件事：进探针前每题三个新会话、严格版示例拟合、“不设预算”。
2. **审查对象从“题”改成“已观察到的候选”。** 静态审查与轨迹解法审查保留【已决定】，合并成采样后的单一“题目审计”。测试加固只能由四种来源的候选触发（§4.0）。每题新增评分键 ≤3，审查者不得自造其他反例。
3. **采样。** 【已决定】第一轮主模型是 Qwen3-Coder-30B-A3B-Instruct，用户本轮再次表示偏向 Coder。Coder 按 4＋4 顺序采样，难度只按 Coder 定。Qwen3.6 只在每批末集中跑一段 FN 探针，次数 ≤本批尝试数的 10%。难度标签绑定下发题面、预算、Claude Code 版本和材料版本。
4. **组织方式改成“工厂”。**
   - 账本只有一个写入者，配事件日志和租约；按家族打包派发。
   - 每个角色有硬预算，超时按角色失败处理，不会变成准入；每题、每家族都有终身次数上限。
   - 取消逐题的 publish/probe 请求与回执。
   - 并行派发和评分队列归链路线程，B 线只出计划、账本和标记。
5. **噪声设显式预算，按区间判定。** 训练池 FP 点估计 ≤10%、FN ≤5%；冻结训练题单时还要求样本量和区间上界达标（§1.3）。同一家族同一根因涉及 ≥2 题时按家族处理；有效 hack 必须为 0。基础设施失败不记分；候选自己弄坏环境记 0 分。

**为什么这样改**

- **慢在编排，不在计算。**
  - Full216 的 noop+gold 共 432 次评分，4.7 小时跑完（`runs/full216_rh2_diagnostic_20260919/analysis_final_1011/campaigns.json`）。
  - 首轮 GPU 探针 105 个作业单次耗时合计 11.28 小时，首尾跨度却有 23.36 小时，最大并发 1。这是串行队列的设计造成的，不是能力上限（`runs/ordinary_gpu_probe_20261002/migration_20261003/coverage_first52_execution_closed_20261004_v1.json`）。
  - 52 题共发出 118 个请求、229 条通知。
- **探针前逐题投入大，真正改变奖励的少。**
  - R2E 单题闭环中，每道新题耗 105–171 agent·分钟（`PE/r2e_lifecycle_20260929/assignments.json`）。
  - 09-25 两批静态审查中，复核改变处置的情况为 0/20。但 09-29 的闭环里复核确实起过作用：aiohttp 4075 撤回初判；scrapy a95a 改判为 S1；pandas 4ec8 补做的复核发现了一个修订后仍得 1 的退化候选（`PE/r2e_lifecycle_20260929/README.md`）。
  - 所以取消逐题复核，是成本与命中率之间的权衡，不是因为复核从不改结论。漏检由 R2 的退化候选和 R6 抽检兜底。
  - 首轮被推翻的 6 次 raw1，都是读真实候选时发现的。探针前构造的 30 个错误候选，与模型真实犯的错命中 0 例【推断：每格只采 1 次】。
- **单次采样定不了难度。**
  - Coder 有效评分中 33/45 得 1。
  - SBPV 中，GLM-5.2（较高温度）在同一环境下各跑一次，未修订的 629 题约 10.7% 结果翻转（由 Table 10 推算）。Coder 的翻转率在 B0 实测。
  - 外部 SWE 做法：Cascade 2 每题离线采 16 次（`RN/E11_nemotron_cascade2.md` §7.2）；MiMo 审计每题 4 次（`RN/mimo_v2_6_technical_report.md` §5.2）；SkyRL 训练时每题 8 条（`RN/O01_skyrl_agent_sa_swe.md` §5.1）。

## 1. 目标与“训练可用”的操作定义

**目标【建议】**：≥300 道训练可用题，作为首个可训练里程碑。外部 RL 每次运行用 2.5K–5K 题。按 SkyRL 的 125 步 × 64 题（`RN/O01` §4.1、§5.1）推算，只有 300 题时每题要被用约 27 轮【推断】。所以请 A 线在 300 题时设步数上限（建议每题 ≤8 轮），或者扩量到约 1,000 题再跑完整训练。

### 1.1 逐题自动条件（全部由脚本判定）

| 编号 | 条件 |
| --- | --- |
| E1 材料冻结 | 以下都已登记：material_version；镜像身份（registry digest，R2E 派生镜像在 L6 交付前用推送后的私有 registry digest 加 recipe_sha256）；原题面 sha；下发题面 sha；测试材料 sha；配方 id |
| E2 划分 | 不属于 {hydra, bokeh, pyramid, tornado}；同一去重组落同一切分；不在开发集；训练题的 base 早于任何开发题的修复 |
| E3 noop | 闸门阶段 1/1 得 0，准入前累计 2/2 得 0；F2P 失败类型已记录（收集或导入错误送 R1） |
| E4 正对照 | gold 闸门阶段 2/2、准入前累计 3/3 得 1，且逐测试状态一致。或用已登记的替代正对照：经 R6 确认的自然解；或者已经复核的历史构造正对照（只限存量已加固题、只限第一轮），打 `constructed_control` 标签 |
| E5 执行完整 | 期望的测试 ID 全部执行；skip 或缺失算未通过；安装确实成功（看返回码，也看日志关键字） |
| E6 相邻基线 | 已算出，或记为 `adj_unavailable` / `adj_partial`；不因此淘汰 |
| E7 阻断标记已处置 | gold_regression、gold_incomplete、answer_leak、expected_conflict、hack_effective |
| E8 账本完整 | 全部尝试、停止原因、budget_used、终身次数都已记录 |

以下情况**都不等于**训练可用：noop/gold 通过；开发条件检查通过；外部数据集标为 Verified（Prime 的 R2E 只要求 10 次里过 1 次，`RN/prime_swe_tasksets_validation.md` §6.1）；单次探针得过 1。

### 1.2 按模型的难度条件（只看 Coder）

- **标签绑定键**：budget_id、Claude Code 版本、material_version、delivered_prompt_sha256。任一变化，标签即失效，重签规则见 §6.4。
- **有效样本**：不包括基础设施失败，即 noop、gold 上也会复现的评分 OOM 或超时、解析失败、工件缺失、补丁应用之前的安装失败、上游断流。
- **候选弄坏环境**：同一材料下 noop 与 gold 都能跑通，而候选应用补丁后出现安装、编译、导入、语法失败，或超时超过 gold 时长的 3 倍——这类尝试记为 scored、reward 0，打 K9 标记。先例：aiohttp 240d 中 Coder 撤回了兼容层，引发 SyntaxError，项目已把它“另判候选失败”（`PE/dataset_status/tasks.json`）。
- **截断**：撞到轮次或上下文上限的记为 truncated，暂按 0 计；训练中怎么算由 A 线定（A2）。

| 标签 | 条件 | 去向 |
| --- | --- | --- |
| learnable | 有效样本 n∈{4,8}，得 1 次数 1≤s≤n−1 | R2 审计后进主池 |
| hard | Coder 0/8；gold 稳定；批末 Qwen3.6 两次中 ≥1 次得 1，且 R2 判该解正确 | 进池，配额 ≤15%；Qwen 阶段跑完前记为 hard_pending |
| too_easy | 8/8 | reserve_easy（留作 rubric 储备） |
| unsolved | Coder 0/8，Qwen3.6 0/2 | reserve_hard；K7 同键的先过 R3 |
| unsolved_fp | Coder 0/8，Qwen3.6 的 raw1 被 R2 判为 FP | reserve_hard，并登记一条 FP 证据 |
| infra | 补派后有效样本仍少于 4 | parked_infra，交链路线程 |

**训练可用**须同时满足：
1. 1.1 的条件全部满足；
2. 标签为 learnable，或为配额内的 hard；
3. R2 结论为 admit 或 admit_noted（admit_noted 合计 ≤10%）；
4. 所在家族没有未关闭的噪声簇；
5. 标签在训练 profile 下仍然成立（§6.3）。

### 1.3 噪声预算与测量【建议，数值待 U1】

| 指标 | 定义（分母） | 预算 |
| --- | --- | --- |
| FP 率 | 随机抽检的 raw1 中确认错误的比例（按设计权重） | 点估计 ≤10%，超过 8% 报警。冻结 train_v1 需累计 ≥200 个随机 raw1，且 Wilson 95% 上界 ≤13%（n=200 时大约相当于点估计 ≤8.5%） |
| FN 率 | 随机抽检的 raw0 中确认正确的比例 | 跨批累计 ≥150 个后再判定，点估计 ≤5% |
| 噪声簇 | 同一家族、同一 root_cause_code 的已确认 FP 涉及的题数 | ≥2 题即按家族处理 |
| 有效 hack | 准入题上确认的 hack_effective | 0 |
| 基础设施误记 | 基础设施失败被记成 0 或 1 的尝试 ÷ 全部尝试 | 0；空值阈值见 §7.2 |

**依据与局限**
- 现有基线：78 次 raw1 中至少 6 次被推翻，约 7.7%（样本不是随机抽的）。
- 外部数字的分母与上表不同，不能直接对比：
  - FrontierCode 的 FP 6.9%、FN 4.1%，是按“维护者是否会合并”判定的、占已分析轨迹的份额（`RN/cognition_frontiercode.md` §7.2）；
  - ScaleSWE 的 94/100 是题目有效率（`RN/O05_scale_swe.md` §4.2）。
- 反向证据：
  - KAT 作者报告约 16% 的轨迹含沙箱故障，约 6–7% 的样本受 verifier 读错影响，两者可能重叠；训练崩溃的原因是作者自己归因的（`RN/N01_kat_coder_v2_5.md` §6.3）。
  - Qwen3-Coder-Next 两次运行的曲线末端分别为 84.6%（伴随作弊）和 75.1%（加强拦截后），两者之差不是作弊造成的精确虚高（`RN/R3_qwen3_coder_next.md` §5.3）。
- 所以 10% 是本方案自己的设定，不是外部证明过的容忍度。本方案只容忍分散的语义噪声，不容忍系统性问题。

**测量方法**
- 每批由 R7 按预登记的随机种子、按仓库分层抽样：raw1 ≥60 个，raw0 ≥30 个；每题 ≤2 个，单个仓库 ≤20%。按设计权重计算点估计和 Wilson 区间。单批结果只用来报警（例如 3/60 的上界约 13.7%）。
- R7 先只凭题面和公开仓库独立列出要求，再看 R2 的要求列表，两份都存档。
- 每批另取 20 个校准样本，由 R6 深审，用来估计 R7 的召回并修正估计值。经三重确认得到的 FP 数只是下界。
- 随机样本与“被标记送审”的样本分开报告（`RN/N13a_swe_verified_audit.md` §4.1）。
- 在 OpenAI 对 SWE-bench Pro 的审计中，agent 分支标出的低覆盖题占全库 4.1%，人工分支为 9.4%。两者都不是真值，不能当作召回（`RN/N13b_coding_eval_signal_noise.md` §4.2）。R7 的投入远小于该 agent 分支，漏检可能更多【推断】。

## 2. 流水线总览

| 阶段 | 输入 → 输出 | 执行 | 单题成本 |
| --- | --- | --- | --- |
| S0 摄入与划分 | 来源行 → 规范记录、家族、去重组、切分 | 自动 | 秒级；R2E 另需拉镜像、采集事实；派生构建（含复核）中位 45.7 s |
| S1 闸门 | 材料包 → G0–G8 结果与标记 | 自动 | gold×2 加 noop×1。当前正式评分单次中位 190.5 s、均值 223 s（`runs/env_pipeline_analysis_20261004/per_attempt.json`，n=105）；pandas 超过 1,000 s；G6 另加 4 次短运行 |
| S2 静态分诊（触发式） | 带阻断标记的题，另抽 5% 随机题 | R1 | ≤20 分钟；触发率约 15% |
| S3 Coder 采样 | 过闸题 → 轮 A、轮 B；批末 Qwen 阶段 | 链路执行器 | 期望约 5–6 次；作业中位 317 s、均值 387 s |
| S4 自动后检 | 每个尝试 → K1–K9 | 自动 | 每个 raw1 的 K1 重评 1–3 分钟（pandas 无编译缓存时约 10 分钟） |
| S5 题目审计 | learnable、hard 候选、被标记的题 → 逐候选判定、整题结论、≤3 条提案 | R2 | 初定 ≤45 分钟，B0 按实测 p80 定稿 |
| S6 失败排查 | Coder 0/8 且 K7 同键 → 失败归因 | R3 | ≤20 分钟 |
| S7 成批修订 | 提案 → 新材料版本、转移矩阵 | R4/R5 加自动 | 每题 ≤8 次评分 |
| S8 复核 | 修订、推翻结论、抽样 → 批复核 | R6（Codex） | 每项 ≤10 分钟 |
| S9 噪声抽检 | 随机尝试 → FP/FN 估计 | R7 | 每个样本 ≤10 分钟 |
| S10 准入打包 | 账本 → 训练清单 | 自动 | 秒级 |
| S11 训练期回流 | 训练轨迹 → 隔离名单 | R7 | 每个 checkpoint 30 条 |

**单题 agent 投入【推断】**：每道过闸题约 36 agent·分钟，算式为 0.55×45（R2）＋ 0.15×20（R1）＋ 0.05×20（R3）＋ 约 4（修订摊销）＋ 约 3（抽检摊销）。对比：旧流程仅静态审查一段就要约 61–80 分钟/题（`PE/r2e_static_review_20260925/` 与 `_batch2_` 的 assignments.json）。

## 3. 自动闸门清单

### 3.1 B 线自有闸门（按执行顺序）

| 编号 | 检查与阈值 | 处置 | 复用 / 新写 |
| --- | --- | --- | --- |

## 4. Agent 角色卡

### 4.0 共同约束（适用于全部角色）

1. **读写范围。** 只读工作包 `inbox/` 里的冻结材料；只写 `outbox/<role>_<task>.json`（≤8 KB，备注 ≤40 行）。宿主拒绝写文件时，在最终回复里返回同一份 JSON，由调度脚本代写，并标注 `written_by=R0`。
2. **“公开依据”只认四种**：原题面；仓库内的文档与 docstring；base 上已有的公开测试；上游公开的 API 文档。以下两类不算依据：被同一修复的 test_patch 或隐藏测试改掉的旧断言；命中 C2–C5 的断言（私有符号、无文档的精确文案、顺序或默认值）。
3. **候选只有四种来源**：
   - Coder 或 Qwen3.6 的真实尝试；
   - R2 为每题写的至多 1 个退化候选；
   - 有正式评分记录、补丁可复现的历史错误候选（historical_executed），它占用该题的退化候选名额；
   - gold 和 noop。
4. **哪些不算证据。** 轨迹里的自述必须对照真实的工具输出（`RN/O03_r2e_gym.md`）。写法与 gold 不同、改了测试文件、访问过 git 历史，都不能单独作为定性依据。
5. **证据指针。** 每条结论都要带证据指针：diff 行、测试 ID 或命令输出的路径。证据不足就写 UNKNOWN。
6. **评分只提请求。** 写进 `pending_checks`，并注明 `if_fail` 时题目的去向；脚本批量执行，角色不等待结果。
7. **预算。** 墙钟是硬上限。核心步骤（R1 的 C1–C9；R2 的要求、覆盖与 raw1 判定；R7 的判定）如果因为到时而写成 UNKNOWN，按角色失败处理。每份输出都附 `budget_used`。同一角色、同一题、同一材料版本只认一份有效输出，最多重派 1 次，再失败就执行 §4.9 的默认去向。
8. **协作方式。** 角色之间只通过账本交接。并发数由脚本计数，起步 12；B0 结束后若输出合格率 ≥90%、超时率 <10%，升到 24。依据：09-25 曾因同时唤醒，实际并发冲到 8，超过上限 6。
9. **召回集隔离。** 角色卡与示例不得包含召回集中的题目（§7.1）。

### R0 调度（脚本加主会话）

- **脚本**负责：收取 outbox、校验、推进状态、组包、派发、发起批量评分、执行默认去向、出批报。
- **派发优先级**：修订 > R2 > R3 > R1 > R7。
- **主会话**不逐题推理，只处理三类异常：熔断、校验器退回率超过 20%、宿主异常。

### R1 静态分诊（采样前，触发式）

- **触发**：
  - 以下标记之一：answer_leak、gold_regression、expected_conflict；
  - noop 中超过 50% 的 F2P 失败是收集或导入错误；
  - P2P 与相邻集都为空。

  另外，从过闸题中随机抽 5%，用来测闸门的漏检。
- **输入**：题面；测试补丁，或期望映射加隐藏测试；gold diff；facts.json；闸门标记。
- **允许**：读代码；pending_checks ≤1（题面原例在 base、gold 上各跑一次）；proposals ≤2（只能是 T1、T2 或 S 类，schema 同 R2）。
- **禁止**：写候选；改材料；评价代码风格。
- **预算**：≤20 分钟、≤40 次工具调用；同家族至多 8 题一包，一包 ≤2 小时。
- **输出**（`static_triage.v2`）：checks{C1..C9}（每项取 pass、issue 或 unknown，附 evidence）、verdict（proceed、proceed_flagged、statement_fix、test_fix、drop 之一）、proposals、reasons（≤5 条）、budget_used。
- **检查项**（来源：`RN/N13b` §5、`RN/N13a` §4.2）：

  | 编号 | 检查内容 |
  | --- | --- |
  | C1 | 题面与测试是否冲突 |
  | C2 | 测试是否调用私有符号 |
  | C3 | 精确文案或空白要求有无依据 |
  | C4 | 顺序或集合语义有无依据 |
  | C5 | 默认值、返回结构或控制流边界有无依据 |
  | C6 | 是否测了题目以外的功能 |
  | C7 | 题面是否泄漏答案 |
  | C8 | gold_regression 所涉行为有无公开依据 |
  | C9 | gold 是否未满足有公开依据的题面要求 |
- **规则**：
  - C3–C6 只是风险标签，不单独触发修订。这一条取代 v1 的严格版 D1。
  - C1、C7、C9 确证：新供给的题 drop；可修订题（§5.1）判 statement_fix 或 test_fix。
  - C8 有公开依据：新供给 drop；可修订题按 T4 进入采样。C8 无依据：驳回该标记。
  - 判 statement_fix 或 test_fix 的题进入 repair_pending，暂不采样；等下一次批末修订并验收通过后，再进入 S3。判 proceed_flagged 的题可以直接采样。
- **复核**：R6 抽查 drop 与 fix 结论。

### R2 题目审计（静态审查与轨迹解法审查合一，采样之后）

- **触发**：learnable 题；Qwen raw1 待判的 0/8 题；too_easy 中带阻断类标记的题。每题终身只有一个审计周期；修订后不重审，只把冻结补丁重新评分。
- **输入**：
  - 题面；测试或期望映射，以及隐藏测试；gold diff；R1 的输出；
  - 存量题的历史结论（压成 ≤5 条账本标记，带证据路径）；
  - 全部尝试的 diff、reward、逐测试状态、K 标记；
  - 用 `condense_trajectory.py` 压缩过的轨迹；
  - 相邻集结果。

  输入集合和步骤顺序参照 MiMo 的审计模板（`RN/mimo` §5.2）。不同之处：MiMo 只输出“潜在 FP/FN”标记，本方案让 R2 直接给结论，没被抽中的 admit 没有第二道审查——这是本方案的取舍。压缩轨迹与完整轨迹的召回差异在 B0 比较。
- **固定六步**：
  1. **列要求。** 至多 8 条，每条写出公开依据。
  2. **标覆盖。** 每条要求标为 covered、partial、example_only 或 uncovered 之一。
  3. **查测试与 gold。** 用 C1–C9 检查；R1 已经做过的直接引用。
  4. **写退化候选（条件触发）。** 题目来自 R2E，或某条核心要求只有题面示例覆盖（example_only）时，写 1 个不超过 30 行的退化补丁。已有 historical_executed 候选的题不再写。命中后的处置见 §8.1。
  5. **逐个判定候选。** raw1 至多深读 4 个：先读带阻断标记的，再读 diff 与 gold 差异最大的。raw0 只读带 K7 的，至多 2 个。没深读的 raw1 记为 not_read，不算 UNKNOWN。
     - **K1 失败判 FP**，须同时满足三条：该测试在 base、gold 上 4/4 通过；断言不命中 C2–C5；R2 列出的要求都不需要改变这项行为。命中 C2–C5 的，判为“偶然行为”，候选 OK，并把该测试写入 adjacency_exclusions。
     - **其他 FP**：diff 明确违反第 1 步的某条要求，并引用原文。
     - **HACK**：K5 命中，且有证据表明拿到的信息被用上了；present（尝试过）与 effective（起了作用）分开记。
     - 以上都不满足，写 UNKNOWN。
  6. **对照 reward，给出整题结论。**
- **允许**：读文件；pending_checks ≤3（含退化候选）；proposals ≤3。
- **禁止**：写退化候选以外的补丁；提出不指向某个已观察到的 FP 或 FN 的断言；改材料；读其他题；联网。
- **预算**：初定每题 ≤45 分钟、≤80 次工具调用（09-25 的静态主审一项中位就要 26–29 分钟，还不含读轨迹）；同家族至多 4 题一包，一包 ≤3 小时；B0 按实测 p80 定稿。
- **输出**（`task_audit.v2`）：
  - requirements、coverage、checks{C1..C9}、degeneracy；
  - candidates[{attempt_id, model, reward, judgement（OK/FP/FN/HACK/UNKNOWN/not_read）, violated_req, root_cause_code（固定枚举）, evidence, hack}]；
  - adjacency_exclusions[{test_id, reason_code, scope=task}]；
  - proposals[{pid, type, target, public_basis, must_fail, must_pass}]；
  - pending_checks、verdict、confidence、rubric_shadow{RB4, RB5}、budget_used。
- **结论规则**：

  | 情形 | 结论 |
  | --- | --- |
  | 深读的 raw1 全部 OK；未读的 raw1 不带阻断标记；没有确证的错误；阻断标记都已处置 | admit |
  | 带阻断标记的 raw1 深读后仍是 UNKNOWN，且没有确证的错误 | admit_noted（≤10%；超出配额时按 confidence 排序，超出部分进 reserve） |
  | 有确证的 FP 或 FN，≤3 个评分键能修，且题目可修订（§5.1） | repair |
  | P5（两种读法都有依据）；需要超过 3 个键；确证的 FP 找不到公开依据来补；题目不可修订 | 新供给 drop，存量 diag_only |
  | confidence 为 low | 送 R6 |

- **相邻排除**：adjacency_exclusions 由脚本写进账本，之后对该题全部尝试重算 K1，不改 reward。家族级的排除只能由 R8 提出。
- **复核**：R6 审全部 FP/FN 推翻、全部 low confidence 结论，并按预登记的种子从 admit 中抽 15%。
- **示例**：Pandas50319 两个模型的解都正确，只是验证做得完整程度不同 → admit；完整度差异只记进 rubric 影子分。

### R3 失败排查

- **触发**：Coder 0/8、Qwen3.6 0/2，且 K7 同键。
- **输入**：失败键对应的测试源码、题面、gold diff、各次尝试的 diff 与逐测试状态。
- **允许**：pending_checks ≤1；proposals ≤1（T2 或 S3）。
- **禁止**：重新求解；提 T3。
- **预算**：≤20 分钟、≤30 次工具调用；同家族打包。
- **输出与去向**（`fn_triage.v2`）：

  | 结论 | 去向 |
  | --- | --- |
  | grader_false_reject | R6 确认后走 T2 |
  | genuinely_hard | reserve_hard |
  | statement_missing | 可修订题走 S3，否则 drop |
  | env | 交 R8 或链路线程，状态 parked_infra |
  | unknown | reserve_hard |

- **依据**：失败键相同，不等于评分误拒。例如 orange3 的 W1 是错解、V1 是合理解，两者都是 12/13（`PE/r2e_static_review_20260925/grader_candidates.md`）。Prime 对 16 次全零的题先重跑 gold 再归因，最终只剔除了 3 题（`RN/prime_swe_tasksets_validation.md` §6.2）。

### R4 测试调整（按仓库成批）

- **触发**：本批某个仓库有 repair(T*) 提案，或已观察到的错误候选按规则触发 T3。每个仓库每批开 ⌈修订题数/12⌉ 个会话，全批只升一次材料版本。现状是约 5 小时内从 v4 升到了 v11。
- **输入**：提案、错误候选、保持门集合、冻结补丁、修订登记（R2E 用【已实现】的 material_revisions；SWE 见 §5.4）。
- **允许**：T1–T4；每题 1 次小修，只修本轮验收失败的那一项。
- **禁止**：加提案以外的评分键；改 gold；改题面；为了让 gold 通过而放宽有依据的断言；开第二轮。
- **预算**：每个会话 ≤120 分钟、≤12 题；每题新增评分键 ≤3，评分 ≤8 次（冻结补丁重评不计入）。
- **输出**：修订条目（sha_before/after、decision_ref＝pid、evidence），以及 `revision_acceptance.json`（0/1/0 结果、保持门、转移矩阵、结论）。小修后仍不过的题按 §5.5 处理，不阻塞同批其他题。
- **复核**：R6 审全部 diff。

### R5 题面改写（含 R5b 公开读者）

- **触发**：有 S 类提案，且题目可修订。**SWE 目前没有题面替换机制**（见 U8）；U8 之前，R5 只用于 R2E（R2E 已有 `statement_text_replace`，`ingest_r2e_subset.py` L242–246）。
- **输入**：原题面；提案（要求文本和公开依据）；公开仓库。**不提供**隐藏测试和 gold diff。
- **允许**：S1–S6。新增不超过 2 句（每句 ≤80 个英文词），或删改 1 段。用 S1 时，须在 base 上实跑证实原陈述有误。
- **禁止**：
  - 写入测试名、测试输入、无依据的精确文案；
  - 写出文件、函数、行号或修法；
  - 扩大题目目标；
  - 用“或”把两种读法并列；
  - 只加难。依据：OT-Agent 的 10K 规模 SFT 实验中，只加难的改写让分数从 15.62 降到 12.34（`RN/task08_openthoughts_agent_2606.24855.md` §3.3）。
- **预算**：≤20 分钟；每题在整个生命周期里只改一次题面。
- **R5b 公开读者**：开一个新会话，不读私有材料，≤10 分钟，回答三个问题：
  1. 能否从新题面推出新增的要求？
  2. 新题面是否指明了修复位置或修复方法？
  3. 新题面与 base 的行为是否矛盾？

  任一问答案不合格，就撤回改写。通过后依次：G3 泄漏扫描 → noop/gold 重评 → 旧样本标为 superseded → Coder 重采 4 次。
- **输出**（`statement_rev.v2`）：新旧 sha、diff、mechanism、basis、info_condition、reader_answers。用 S3 补接口说明时，info_condition 记为 interface_added，作为一种不同的信息条件单独登记（`RN/O11_swe_rebench_v2.md` §6.1）。
- **复核**：R6 全部审。

### R6 复核（Codex，按批）

- **容量**：每批收口时一次，可按仓库拆成至多 3 个会话；每项 ≤10 分钟，每个会话 ≤40 项。
- **输入（按风险排序）**：
  - 全部修订 diff 与验收结果；
  - 全部 R5 改写；
  - R2 的 FP/FN 推翻和 low confidence 结论；
  - 从 admit 中抽出的 15%；
  - R3 的 grader_false_reject；
  - R7 的报告和 20 个校准样本。

  超出容量的条目记为 unreviewed_by_codex，不准入。
- **允许**：重跑给定的命令；对每一项给出 accept、reject 或 minor_wording（minor_wording 占用该题的小修额度）；输出 `review_batch.v2`（items、rule_findings、future_notes）。
- **禁止**：提出新实例或新断言（只能记进 future_notes）；要求重审未被抽中的题（先例：`PE/mimo_rl_oss_20260926/codex_part1_review_20260927.md`）。
- **升级**：
  - reject：撤回该修订，题目转 drop 或 diag_only。
  - admit 抽样中错误 ≥3/15：再抽 15%；仍然 ≥20%：本批 admit 全部降为 diag_only，下一批先改规则。
- **Codex 不可用时**：由未接触过本批的新 Claude 会话复核，标注“独立性降级”，Codex 恢复后再抽查。

### R7 噪声抽检（盲判）

- **触发**：每批准入前一次；训练期每个 checkpoint 一次。
- **输入**：单个尝试的 diff、逐测试状态、相邻集结果、题面。先独立列出要求，再看 R2 的要求列表；**不提供** R2 的判定。
- **预算**：每个样本 ≤10 分钟。
- **执行者**：默认由 Codex 执行。如果一批 90 个样本要超过 1 天，改由未接触过本批的新 Claude 会话执行，Codex 从中盲判 20 个，并报告两者的一致率。
- **输出**：与 R2 的 candidates 字段同一 schema。确认的 FP/FN 送 R6。

### R8 家族配方修复

- **触发**：同一家族 ≥3 题在 G4 或 G5 以相同签名失败；出现有效 hack；出现噪声簇（同一家族、同一 root_cause_code 涉及 ≥2 题，由脚本计数）。
- **允许**：改安装或测试配方、fixture、devcheck 模板、家族配方登记表；做家族级的相邻排除。
- **家族级加测试（F3）**：即把同一个公开测试加入该家族全部题的 P2P 或隐藏测试。这属于奖励语义变更，**U6 批准前不做**。批准后，须对家族内每道题跑保持门和冻结补丁转移矩阵；任一正确解出现 P→F，就整体撤回。
- **禁止**：针对单题特化；改评分语义。
- **预算**：≤2 个会话，合计 ≤4 小时，构建或重评迭代 ≤5 次；每个家族在每个来源版本下终身只做 1 次。
- **验收**：从该家族抽 5 题重跑闸门，全部通过。不过就记为 family_parked（在第一轮内是终态），写进用户日报。
- **依据**：164 题的修复中，有 140 题的问题至少 3 题共有；ScaleSWE 的做法是复用失败就丢弃（`RN/O05_scale_swe.md` §3.2）。
- **复核**：R6；涉及链路的部分交链路线程看接线。

### 4.9 默认去向（重派 1 次后仍失败时）

| 角色 | 默认去向 |
| --- | --- |
| R1、R2 | 新供给 drop；存量 diag_only（超时不会变成准入） |
| R3 | reserve_hard |
| R4、R5 | 撤回修订，按 §5.5 处理 |
| R6 | 本批修订过的题和 admit_noted 的题不准入 |
| R7 | 本批暂不冻结准入 |
| R8 | family_parked |

### 4.10 防止无限发挥的硬规则

1. 审查只由触发条件启动，没有“全量逐题审”。复核只能 accept、reject 或改措辞。
2. 候选只有四种来源（§4.0 第 3 条）；退化候选与历史错误候选每题合计 ≤1。
3. 每个新评分键都必须同时具备两样东西：一个会被它拒绝的、已经观察到的候选；一条公开依据。修订类型是封闭枚举（§5.1），所有触发合并进同一轮修订。
4. 用保持门防止加固过严：所有被判为正确的自然解，修订后必须仍然通过。依据：Hardening 实验（terminal 任务）加固后，正常解通过率从 76.1% 降到 65.2%；只用参考解做保持检查时，曾把正常解压到 0%（`RN/N06_hardening_agent_benchmarks.md` §5.3、§6.2）。
5. 到达任何上限都执行默认去向，不能延长。输出的 schema 与字节上限由 `ingest_outputs.py` 机械拒收。
6. P5（两种读法都有依据）一律 drop 或 diag_only，不进入用户决定队列。09-29 一夜积压的 11 项待决事项中，约 3 项是 P5 类读法分歧；其余是链路、契约和资源事项，按 §11.3 合并进决策包（`PE/r2e_lifecycle_20260929/morning_summary_20260929.md` §3）。
7. **终身次数**：每题至多 1 个“审计＋修订”周期，另加至多 1 次训练回流修订，之后一律 drop；每个家族在每个来源版本下至多 1 次 R8。看门狗按计数拒绝派发。

## 5. 测试调整与题面改写规则

### 5.1 允许的修改与可修订范围

**可修订题**包括两类：所在家族已准入不足 10 题的存量题；稀缺仓的题。
- **稀缺仓**：来源池中该仓库剩余可用（未处理、非留出）的题不足 40 道，在批计划冻结时写死。
- **修订占比上限**：每批修订题数 ≤过闸题的 20%。超出时，learnable 题优先，再按预登记的种子截断，其余转 diag_only。

**测试类**

| 类型 | 触发 | 对应现行模板 | 范围与上限 |
| --- | --- | --- | --- |
| T1 修无效键/ID、不可达 fixture 等脚本可判定的批量修复 | G2 或 R2 发现 | R-a | 全部题。R2E 删期望键时，必须同时删对应测试，保持键集严格相等 |
| T2 放宽无依据的断言（精确文案、私有 helper、mock 形状改成行为断言） | 观察到被它误拒的自然解 | R-b、R-e | 全部题；≤2 处 |
| T3 补有依据的检查 | 已观察到的错误候选（四种来源之一） | R-c，但收窄：不再由示例拟合自动触发 | 优先并入仓库已有的公开测试，只取相关断言，必要时参数化或拆分；≤3 个评分键 |
| T4 处理 gold 回归或 gold 不完整（C8、C9） | 该行为有公开依据 | D4，收窄 | 只限可修订题。正对照为 R6 确认的自然解，或存量已有的 constructed_control |
| F3 家族级加测试 | 噪声簇 | — | 只由 R8 在 U6 批准后做 |
| 环境与配方 | 家族共性根因 | R-d | 只由 R8 做 |

**题面类（S1–S6）**：参照 SBPV §4.4 归纳的六种机制。这六种是作者事后归纳的 FAIL→PASS 原因，不是经过验证的改写清单。

| 类型 | 内容 | 与 SBPV 的对应 |
| --- | --- | --- |
| S1 | 改正与 base 行为不符的陈述 | 本方案新增 |
| S2 | 删去答案，换成症状描述 | 本方案新增 |
| S3 | 补一句解题必需的接口说明 | 第 5 种 |
| S4 | 写明集合或顺序语义 | 第 2 种 |
| S5 | 写明默认值、返回结构或控制流边界 | 第 3、4 种 |
| S6 | 写明公开文档给出的常量 | 收窄第 1 种：原文允许写入测试要求的常量和报错文字，本方案只允许有公开依据的 |

SBPV 第 6 种“修正测试”对应 T2。S4–S6 必须有公开文档或公开旧测试作依据，不能只因为隐藏测试是这样写的。

### 5.2 每题上限

| 项目 | 上限 |
| --- | --- |
| 修订轮次 | 1 轮（一次提交全部提案）加 1 次小修；训练回流另 ≤1 次 |
| 新增评分键 | ≤3 |
| T2 放宽 | ≤2 处 |
| 题面改写 | 整个生命周期 1 次 |
| 评分次数 | ≤8（冻结补丁重评不计入） |

### 5.3 验收（全部自动执行）

在新材料上，下列条件全部满足才算通过：
- noop 得 0。
- 正对照得 1。默认用 gold；gold 通不过新断言时，按 T4 处理。
- 每个触发本轮修订的错误候选得 0。
- 保持门：全部被判正确的 Coder 和 Qwen3.6 自然解（至多 6 个）仍然得 1。

此外还要做三件事：
- **重评冻结补丁。**

### 5.5 何时放弃该题

2. 转移矩阵里出现基线之外、且不属于 FP 的 P→F。
3. gold 通不过新断言，且没有可用的正对照。
4. P5：两种读法都有公开依据。
5. 需要超过 3 个评分键，或需要第二轮修订。
6. 小修后仍然不过。
7. R6 给出 reject。
8. R5b 判定新题面泄漏答案，或推不出新增要求。
9. 同一题第二次被推翻。先例：EA69 经历了 R6→R17→R28 三版；aiohttp 1c1c 经历了 57→58→59 键。
10. 需要改题面但题目不可修订，或 SWE 题在 U8 之前需要改题面。
11. 跨批再改同一目标（U9 之前）；终身次数用尽。

**依据**：

## 6. 采样与难度分层

### 6.1 顺序规则【建议】

| 轮 A：Coder 采 4 次 | 下一步 |
| --- | --- |
| 1–3 次得 1 | 标 learnable，进入 S4/S5，不再加采 |
| 4/4 | 轮 B 再采 4 次。8/8 → too_easy；否则 → learnable |
| 0/4 | Coder 再采 4 次；仍是 0/8 的，进入本批的 Qwen 阶段 |

**批末 Qwen 阶段**
- 单卡同一时刻只能服务一个模型。SGLang 换模型本身约 80 s，但首轮串行编排下 5 次换模型伴随了约 12 小时的作业空档。
- 所以 Qwen 不随题即时派发，而是每批末统一换一次模型，对 Coder 0/8 的题各跑 2 次。
- Qwen 尝试数 ≤本批尝试数的 10%，超出部分按预登记的种子截断，进 reserve_hard。
- Qwen 的 budget_id 与推理模式写进 sampling_plan。

| Qwen 阶段结果 | 去向 |
| --- | --- |
| 2 次中 ≥1 次得 1 | R2 判 Qwen 的解：判正确 → hard；判 FP → unsolved_fp |
| 0/2，且 K7 同键 | R3 |
| 其余 | reserve_hard |

hard 配额按预登记的种子顺序取前 k 个。

**为什么这样设**
- 训练端已经在线丢弃零方差组并补采（【已实现】`group_admission.py` 文件头）。离线分层只为省 rollout，不需要精确估计 p，所以 learnable 题不再加采。
- p=0.9 的题 4 次全过的概率是 0.66，所以 4/4 的题要跑轮 B；p=0.2 的题 4 次全错的概率是 0.41，所以 0/4 的题补采 Coder【推断】。
- 外部做法：Cascade 2 每题离线采 16 次，全失败的题保留 10%（`RN/E11` §7.2）。SkyRL 的 k=4 分桶出自其非 SWE 的 Deep Research 案例（`RN/O01` §7.1）。

**执行纪律**
- 看结果之前冻结 `sampling_plan.json`，写明题单、模型、次数、budget_id、下发模式、随机种子和补派规则。
- 禁止因为失败而加采，禁止“采到成功为止”（`runs/data_signal_strategy_20261004/rubric_research/report.md`）。
- 基础设施失败不计入 n，每题最多补派 2 次。

**成本【推断】**：若单次通过率按 0.73 估，约 28% 的题需要轮 B，期望每题约 5.1 次。预算按每题 6 次做。

### 6.2 Qwen3.6 的角色【已决定：第二轮使用，或只作少量对照】

只做三件事：
- 批末 FN 探针，上限见 §6.1；
- 已有、且被 R2 判为正确的 Qwen 解，进入保持门或作为自然正对照（不为此新采）；
- current52 已有的样本留作历史对照。

Qwen3.6 不参与难度定级。跨模型差异的依据：SkyRL 的表中 Coder-30B 为 45.0、Qwen3-32B 为 24.4（`RN/O01` Table 2）；52 题探针中 Coder 33/45、Qwen3.6 45/53。

### 6.3 预算 profile

- **A1 阻断 B1 采样**：A 线至少要先给出 max_turns 和上下文长度的上界候选。如果 10-07 前给出，B0 起直接按候选 profile 采样。
- **否则**：
  - B0 按 probe-wide-v1 采样，同时在 20 题上按候选 profile 各加采 4 次。
  - 用这 20 题实测“按记录的轮数和上下文重算标签”与真实标签的不一致率；超过 15% 就放弃重算，B1 一律按候选 profile 采样。
  - 理由：Claude Code 的自动压缩窗口低于 100,000 时会被抬到 100,000（`adapters/slime/cc_launch_conditions.py` 注释）。训练上下文小于 100K 时，轨迹不再是同一条轨迹的前缀。
- **profile 会大幅改变难度分布**：09-22 探针的 46 次成功中，只有 14 次落在 25 轮、32,768 上下文之内（`PE/base_model_probe_run_20260922.md` §8.8）。

### 7.4 训练期回流

- 每个 checkpoint 抽 30 条 raw1。样本量由本方案自定，规模参照 OT-Agent 的行为分析（`RN/task08_openthoughts_agent_2606.24855.md` §5.4）。优先抽 admit_noted、修订过和带 loose_test 标签的题。

### 7.5 rubric 第一版（只做影子记录，不改 reward）

| 条目 | 判定方式 |

- **何时影响奖励**：以下三条同时满足才可以——影子指标达标；用户对组合方式作出 T0 决定；完成小规模受控训练对照。U6 决策包给出两种候选：

  - (b) 间隔分离：通过的解落在 [1−β, 1]。这种形式借鉴自 SWE-TRACE，原文未给参数；β≤0.2 是本方案的建议值。它在成败混合组里也会改变优势。

  开启 rubric 后，原本零方差的全通过组，其优势会完全由 rubric 决定。

   - 同版本存量不足 3 题的家族（如 pandas 2.0 只有 50319 一题，同版本候选却有 222 题），先抽 5 题跑闸门验证配方，再扩量。
3. **R2E 剩余 4,080 题**。
   - 理由：对同一个 Coder 的直接证据，是 Uni-Agent 在 R2E-Gym 上做 RL，验证指标从 46.2 升到 52.0（作者报告，不是 Claude Code 下的结果，`PE/base_models_and_data_survey_20261003/research_report.md`）。DeepSWE、SkyRL 的正例基于起点低得多的 Qwen3-32B（24.4，对比 Coder 的 45.0）。Cascade 2 发布的数据约 80% 来自 R2E，但执行式 RL 的独立增益没有被隔离（`RN/E11` §11.2）。R2E 对 Coder 可能偏易，按 §6.4 检查。
   - 顺序：先做 numpy、pillow、scrapy、orange3、coveragepy、datalad。pandas 的 1,437 题等编译缓存进入生产后再做。aiohttp 在 L8 完成、K9 生效后进入：本地遇到过兼容层陷阱，两题得 null；Prime 丢弃的 56 题中有 39 题来自 aiohttp 与 tornado，两者未拆分。
   - **退化候选的处置**：R2E 第二批 12 题全部有错误候选得 1（`PE/r2e_static_review_batch2_20260925/README.md` §3.2）。如果一命中就走 T3，几乎每道 R2E 题都要进 R4。所以：
     - B2 首波（每个仓库 10 题）中，退化候选命中只打 loose_test 标签，训练期由 R7 过采样；
     - 同时实测三个数：退化候选命中率；命中时真实 Coder 尝试有多少会被新断言区分开；修订验收通过率；
     - 之后在批报中请用户二选一：继续走 T3 并接受供给与修订成本，或者保持 loose_test 标签；
     - 真实尝试与历史错误候选的 FP 照常触发 T3。
4. **SWE-Gym 同 9 仓其他版本的 560 题**：先由 R8 修好家族配方。
5. **外部来源**。
   - Uni-Agent 的 SWE-reBench 运行，验证指标从 47.4 升到 54.2；当前 quickstart 用的是 1150 题清单，历史运行与清单的绑定未核实。
   - Prime SWE-rebench V2 的 Python 子集。
   - 两者都在 B2 期间各做 6 题试点，检查四项：镜像能拉取、noop 失败、gold 通过、与上游日志对账一致。接入需要新 TaskSource（与 U7 同类）和解析器。

## 11. 风险、未决问题、需要用户或 Codex 决定的事

### 11.1 风险

1. **K1 召回未知。** EA69 这类“漏了公开要求”的问题，K1 拦不住，只能靠 R2。B0 会实测；召回低时改 R2 的角色卡，不加人工。
2. **Coder 偏易，分布可能被带偏。** learnable 产出可能偏低，按 §6.4 转向，目标日期在 B0 后重算。默认淘汰会让题目分布偏向测试干净、也更容易的题；pandas 和慢题推后，也会改变仓库比例。批报按仓库和 drop_reason 分别报告。
3. **审查 agent 自身会出错。** N06 中约 10% 拿到奖励的攻击轨迹被 judge 判为合法解；被判不合法的 5 个正常解中，1 例是误报、4 例属边界情况（`RN/N06` §6.4，terminal 任务，样本极小）。可见 judge 两个方向都会出错。缓解措施：判定必须带证据指针；R7 独立列要求；R6 深审校准样本。证据层面的独立，只能靠训练期的新样本。
4. **容忍度缺乏依据。** 没有外部数据直接给出 SWE RL 下 FP 比例与学习收益的关系。CodeMidas 整套清洗（含难度筛选）带来 0.6–4.6 pp 的收益（单 seed，`RN/codemidas_2609.22068.md` §8）。
5. **执行与依赖。**
   - 单卡 KV 可能限制并发；吞吐不足时，工期约翻倍。
   - U7、U8、A1、L6 任一延迟，都会推迟 Full 部分或 R2E 准入。
   - Codex 是复核单点（已给降级路径）。
   - 宿主过去出现过拒绝写文件、中止会话的情况（`PE/r2e_static_review_20260925/README.md` §6）。B0 的第一个工作包先测 outbox 能否写入。
