# 精简协作流程：发布侧检查

2026-10-03。依据当前 `coordination_workflow_20261003.md`、更新工具及实际发布回执。

**这版可以执行。** 仓库负责人持续处理题目，直接向发布或 GPU 请求支持；完成后直接回原负责人。发布只检查共用实现、材料消费、冻结与部署，不再重复终审题目语义或轮询全部仓库。普通交接无需经背景梳理线程转发。

沟通中已明确三处边界，现行流程正文已经包含：

| 容易混淆的地方 | 当前规则 |
| --- | --- |
| 发布镜像存在，被理解成解题环境已验证 | 回执分别记录 actor 与 grader。题主仍需以实际解题身份验证公开开发操作；评分侧安装成功不能代替。 |
| 诊断镜像入口，被理解成正式训练接线完成 | 本批可使用已验证的精确 `actor.image_override`，不等待另一个训练接线项目；实际 GPU 镜像仍需回读。正式 typed actor 租约尚未接通，不能混称。 |
| 请求已回执，被理解成题目已处理完成 | `returned` 可以包含失败或部分交付；完成范围看回执。题级阻断不会自动清空，CPU、模型及训练用途也不会自动批准。 |

背景梳理线程仅保留用户另外委托的本批裁定及明确授权的 GPU／调研巡检，不参与普通接单、转发或终审。当前旧退租检查与自动销毁已停用，资源处置按用户新的明确授权。这是限定职责，不新增常设协调层。题主日常按固定 CPU 分组和作业槽自助运行，无需发布者逐次放行。

实际接续已经按这一分工执行：R14 将 DVC 三题、Pydantic 四题的发布回执直接交题主；R15 将 Dask 三题、MONAI 两题直接交题主。发布侧核对固定字节、受影响消费者和真实镜像，再由题主完成正式 CPU 正负对照及非作者核查。累计 producer 的题数表示已经接入的修订数，不能当成可探针或可训练题数。

无需增加新的审批、阶段或文档系统。接下来用同一总账和逐题记录接续；新的共用缺陷单独提出关联支持请求，修复后只验证受影响范围。

本次对最新版本的补审：账本工具的 18 项检查通过。已与流程编写线程沟通，并确认步骤④已补清：探针申请引用 GPU 统一冻结的模型、次数与预算配置版本，遵循用户最新覆盖优先指令；题主只列已批准的题级差异，GPU 核实际派发条件。该补充不新增审批、阶段或当前工作阻塞。
