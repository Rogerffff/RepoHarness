## 正式机制已接到哪里

- **登记并重建修订。** 固定来源、父版本、测试文件摘要与新增参考，正式摄入从原件重放并核清单；修订产物另存，旧材料和历史结果保留。
- **实际执行新增测试。** mypy 选择式包含新增 case，其文件纳入可信恢复、内容核验和权限保护。仅修改参考字符串列表不会被当作完整修订。
- **两侧同源消费。** 正式 prepared／actor 与 replay 共用 spec 构造入口；旧 prepared、新评分材料或任务身份混配会被拒绝。
- **材料身份与资格。** 仅参考发生变化也会产生新的材料及环境包身份，旧资格不能静默沿用。原 F2P、原 P2P、新增 P2P 分区记录，未执行不记成功。

首版操作是 **`append_mypy_p2p`：登记已有公开 mypy 回归测试**。题面替换、任意新测试补丁和其它仓库的选择／绑定方式仍按后续小片实现，不声称已全部支持。奖励仍是 SWE F2P/P2P 二值规则，公共 `GradingReport` 契约不变。216题中只改变这两题的私有评分材料与环境包身份；全部公开题面、原测试补丁及其它214题材料保持原字节。原216题五种历史脚本的1080次逐字兼容检查通过，见[实现审查](../reviews/d6_implementation_review.md)。

## 历史失败、性能与边界

- 原17071首轮 noop 的评分本身有效，但追加观察脚本直接导入 `typetraverser` 触发循环导入。工具按规则停批；确认清理后，仅修观察脚本的标准初始化，在独立目录重验17071。失败和导入小探针保留在[恢复记录](cpu_observation_recovery.md)。
- Git 初态修前 fatal、修后两次原工件直评、旧材料矩阵和最终新版矩阵分别存档，不把旧失败改写成通过，也不把重复验收累计成模型样本。
- 17071 原配置会在2 CPU容器里启动38个 worker，仅运行5项，旧三组测试约97–106秒。本轮保持原命令；另线程同期负载不同，因此不作单变量性能归因。资源终止字段为 `null` 时仍是未知，不当作全程没有 OOM。
- 实际模型工具解析、统一预算、miles训练消费／排空和已另立项的公共评分伪造问题，不由本次材料修订核销；普通比较的共同入口仍由探针负责人统一确认。固定候选的安装／源码观察是诊断证据，不是对任意恶意候选的安全证明。
