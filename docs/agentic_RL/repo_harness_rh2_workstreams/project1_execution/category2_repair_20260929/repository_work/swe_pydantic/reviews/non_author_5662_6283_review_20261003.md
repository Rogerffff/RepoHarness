## 5662：普通对象收到原模型并决定相等结果

材料：[新增测试](../tasks/pydantic__pydantic-5662/extra_tests.py)第4–25行、[有效测试补丁](../tasks/pydantic__pydantic-5662/effective_test.patch)、[题卡](../tasks/pydantic__pydantic-5662/card.md)。

公开题面在 Description、Possible solution及Side Note中明确：模型位于比较左侧时，应支持一般自定义比较对象；接收方应得到模型本身，不能只支持 `unittest.mock.ANY` 或先转成dict。新测试用普通 `Matcher`、新的模型字段与值，依次返回True、False、NotImplemented；第21行检查最终相等结果，第22行检查接收者看到原模型。这是目标行为断言，没有要求必须采用gold的内部重写、固定调用次数或traceback。

NotImplemented分支最终不相等，与不同对象的比较回退一致；它不是要求所有自定义对象都与模型相等。第24–25行的dict／object不等控制仍保留一般委托的边界；旧 `test_comparing` 与 `test_model_equality_dump` 也保留，防止把所有非模型直接判True。原ANY F2P完整保留，新增普通matcher是独立参考。

旧 [CPU结果](../../../../swegym_cpu_preprobe_20260929/tasks/pydantic__pydantic-5662/result.md) 已记录 noop／gold／all_nonmodels_equal／any_only＝0／1／0／1。为核本次新增行为对应关系，本轮读取冻结原件 `runs/swegym_cpu_preprobe_20260929/remote/results/pydantic__pydantic-5662/followup_20260928T182457Z-a73f19/` 下 `private_gold/gold/private_matrix.out` 与 `private_any_only/any_only/private_matrix.out`：gold的true／false／unknown三个matcher结果正确并收到原对象；any_only的true matcher仍False，三个matcher均未收到原对象，旧七项比较回归照常通过。这支持新断言直接针对已证漏判；历史控制的精确一次调用计数**没有**被引入新测试。

新版本四方预期0／1／0／0有充分材料依据，但新函数未在Python3.8/core0.27.0正式评分中执行。正式复核应确认 gold 新F2P通过、any_only 因普通matcher目标失败、all_nonmodels_equal仍由原边界护栏拒绝，并逐ID保留127 P2P；不得把应用、安装或收集失败算作错解被拒。

## 6283：合法字符串补非示例相等，旧无验证护栏仍决定退化拒绝

材料：[新增测试](../tasks/pydantic__pydantic-6283/extra_tests.py)第4–8行、[有效测试补丁](../tasks/pydantic__pydantic-6283/effective_test.patch)、[题卡](../tasks/pydantic__pydantic-6283/card.md)。

公开题面明确说“同一合法、类型正确的值”经RootModel正常构造与model_construct应产生相等实例，42只是示例。新增 `TextRoot` 的 `root: str` 与 `'another'` 是该同一要求的非示例实例，直接比较正常构造与可信构造；没有断言内部 `__dict__`、extra/private占位属性形状、重新验证策略或限定gold代码结构。

该输入沿真实 `RootModel.model_construct()`（base `root_model.py:48–61`）转调基类，与题面同一入口。base `main.py:179–183` 明确可信／预验证数据不再执行其它验证。原 `test_construct`／`test_construct_nested`（公开测试第182–202行）的可信Base64字符串、嵌套可信数据及不自动转换控制仍逐字保留，也仍在原38 P2P中。

本轮读取既有非示例原件 `runs/swegym_cpu_preprobe_20260929/remote/results/pydantic__pydantic-6283/nonexample_v1/{base,gold,validate_construct}/text_root_nonexample.out`：base打印value=another、equal=false并失败在 `TEXT_ROOT_NONEXAMPLE_EQUALITY_FAILED`；gold与validate_construct均equal=true并有PASS标记。与 [旧非示例独立复核](../../../../swegym_cpu_preprobe_20260929/reviews/pyd6283_nonexample_review.md) 和 [旧CPU结果](../../../../swegym_cpu_preprobe_20260929/tasks/pydantic__pydantic-6283/result.md) 一致。该历史运行是私有root行为对照，未被冒称新测试评分或新增actor权限证明。

**新增合法字符串相等断言不拒绝validate_construct，也不应拒绝。** 它调用正常构造器，会满足这条相等要求；真正违例是重新验证可信输入，旧两项构造护栏已在正式评分中正确拒绝。旧0／1／0不属于误奖，本轮没有改变该判断。新正式三方仍预期0／1／0：base在新相等断言失败，gold通过，validate_construct在新断言通过但在旧无验证参考失败。

这条新F2P把非42要求纳入正式参考的准备材料，但不证明所有合法值／类型已覆盖，也不证明某个42特判候选已经得1。当前未增加此类候选或新的对象内部规范，符合窄修范围。
