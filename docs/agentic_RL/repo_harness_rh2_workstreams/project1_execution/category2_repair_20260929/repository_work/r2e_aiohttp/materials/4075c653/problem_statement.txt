**Title:** HTTP Parser Fails to Reject Headers with Invalid Characters and Malformed Status Lines

**Description**
The HTTP parser does not raise errors when encountering headers with invalid characters or improperly formatted status lines, leading to potential mishandling of HTTP requests.

**Example Buggy Code:**
```python
def test_invalid_header(parser):
    invalid_header = "\xffoo: bar"
    request = f"POST / HTTP/1.1\r\n{invalid_header}\r\n\r\n".encode()
    parser.feed_data(request)

def test_malformed_status_line(parser):
    malformed_status = b"GET\n/path\x0cHTTP/1.1\r\n\r\n"
    parser.feed_data(malformed_status)
```

**Expected Behavior**
- The first test should raise a `BadHttpMessage` exception due to the invalid character `ÿ` in the header.
- The second test should raise a `BadStatusLine` exception because the status line contains improper whitespace and control characters.

**Actual Behavior**
- No exceptions are raised when processing the invalid header or the malformed status line, causing the tests to fail unexpectedly.
