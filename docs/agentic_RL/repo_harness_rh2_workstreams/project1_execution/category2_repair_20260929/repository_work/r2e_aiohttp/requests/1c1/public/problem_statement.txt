**Title:** run_app() Logs Exceptions That Are Also Raised, Causing Duplicate Logging

**Description**
When using `run_app()` to start the aiohttp application, exceptions raised within the application context are being both raised and logged. This results in duplicate log entries for the same exception, making logs cluttered and harder to manage.

**Example Code**

```python
import asyncio
from aiohttp import web

async def context(app: web.Application):
    raise RuntimeError("Unexpected error occurred")
    yield

app = web.Application()
app.cleanup_ctx.append(context)

web.run_app(app)
```

**Expected Behavior**
When an exception occurs within the application context, `run_app()` should raise the exception without logging it. This allows for centralized exception handling without redundant log entries.

**Actual Behavior**
The exception is both raised and logged by `run_app()`, leading to duplicate log messages for the same error. For example, raising `RuntimeError("Unexpected error occurred")` results in the exception being printed to the logs and propagated up the call stack.
