## 能力与行为信号

4166的定位差异清楚。Coder在read/readlines错误mock及平面路径模拟中反复试错，最终错误归因groupby顺序；Qwen使用可工作的公开mock，在前30秒发现尾斜杠regex不匹配裸目录，后续纠正自己引入的正向误匹配，但用“只改否定”结束，漏掉文件／目录区别。Qwen比Coder多通过一个目标F，二者仍有正式有效0。这支持将“局部根因正确但修复不完整”与“根因错误”分别分析，不能只归入一个同质失败桶。

4166两者自测都没有增加真正的目录遍历回归。Coder29公开项通过却声明完成；Qwen29公开项加8个mock断言通过，最终陈述也越过了实测范围。Qwen的两次边界预期错误有后续纠正，没有删断言掩盖；它新增的官方测试文件保留在完整FP但被正式投影剔除。Coder完整FP有23项、22脚本；Qwen完整FP两项、投影一业务项。`hygiene clean`表示应用投影通过相应约束，不代表两者完整候选同样最小或未改测试。

6954两模型都定位UnaryOp遗漏并作有效合法负数修复。Coder早期复现缺参，真实CLI成功，但未读／断言lock数值，二元表达式自测失败后改成无断言，留下5个根目录脚本。Qwen修前没有parse缺参运行，修后用真实parser断言和两份lock可见负数值，完整FP只有业务一项。两种验证路径的优缺点应同时保留，不由raw1抹平。

Qwen扩展experiments测试遇到9项中5失败并截断输出；仅其中 `test_update_py_params` 在stash后的基线也失败，不能把其他4个失败一并判成已证环境问题。最终31项通过明确限定为dependency和params show两个模块，数值成立，但遗漏了扩展失败。两模型非数字一元表达式边界均未保证；这不是本轮新增实测失败或扩评分授权。完整Python表达式、任意嵌套容器或全仓无回归都不是本轮已证结论。
