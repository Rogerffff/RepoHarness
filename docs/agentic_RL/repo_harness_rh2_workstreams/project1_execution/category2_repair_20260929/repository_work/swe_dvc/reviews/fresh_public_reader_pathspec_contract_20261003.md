## 各模式的具体含义

表中表达式仅由公开 `pattern_to_regex` 分支逐步静态推导，没有导入或执行 pathspec、DVC、正则匹配或测试。它们描述相对 ignore 根的规范化字符串；`scripts/` 是表示该目录的尾斜杠形式，`scripts` 是无尾斜杠形式。依赖不自行查询该路径在磁盘上是否为目录，集成层必须正确使用目录上下文。

| 题面模式 | 静态匹配表达式 | 否定命中的路径范围 |
| --- | --- | --- |
| `!scripts` | `^(?:.+/)?scripts$` | 无尾斜杠的同名末段，例如 `scripts`、`a/scripts`；不自动匹配 `scripts/x`。 |
| `!/scripts`（两处使用，包括题面有效写法） | `^scripts$` | 仅根下无尾斜杠的 `scripts`；不匹配 `a/scripts`、`scripts/` 或 `scripts/x`。 |
| `!/scripts/` | `^scripts/.*$` | 根下目录尾斜杠形式 `scripts/` 及任意深度后代；不匹配裸名称 `scripts`。 |
| `!/scripts/*` | `^scripts/[^/]+$` | 根下 `scripts` 的单个非空直接子项，如 `scripts/x`；不匹配目录自身标识 `scripts/` 或更深的 `scripts/a/x`。 |
| `!/scripts/**` | `^scripts/.*$` | 与本固定版本的 `!/scripts/` 具有相同字符串匹配表达式。 |
| `!scripts/` | `^(?:.+/)?scripts/.*$` | 根下或任意层级的 `scripts/` 及其后代，例如 `a/scripts/`、`a/scripts/x`；与根锚定模式不同。 |

题面第一行的两种全局忽略规则也不同：`*` 静态展开为 `^(?:.+/)?[^/]+$`，`/*` 展开为 `^[^/]+$`。前者匹配任意层级的非空末段，后者匹配根下非空单段；二者的这些表达式均不直接匹配以 `/` 结束的字符串。这里说明依赖接口为什么需要妥善区分裸路径和目录表示，不能据此规定集成层仅把所有目录替换成尾斜杠字符串，也不能由某次字符串未命中断言该目录在树中必然可见。

因此，题面里的 `*` + `!scripts`、`*` + `!/scripts`、`/*` + 目录或后代否定规则，不能作为无条件等价的复现组。公开规范支持分别判断它们；仅 `!/scripts/` 与 `!/scripts/**` 在上述固定版本的路径字符串匹配集合相同。即使否定行相同，完整树结果还取决于前面的正向规则、目录身份与父路径是否允许遍历。

## 与原 DVC API、旧测试的衔接

原 `DvcIgnorePatterns.__call__(root, dirs, files)`（`ignore.py:45–49`）分开接收目录和文件，但分别调用同一个 `matches(root, basename)`；`matches`（`:51–66`）形成相对字符串，没有文件类型参数或显式目录尾斜杠处理。现在结合固定依赖的目录规则，可具体指出它需要保留目录与普通文件的语义区别：如果将目录只作为普通裸名称交给目录尾斜杠模式，就不能表达该模式的目录身份与后代匹配契约。这里定位的是公开接口与公开依赖之间的语义衔接，不规定候选实现必须采用哪种修改方法。

旧 unit 测试的简单名称过滤（`:17–32`）、否定（`:70–71`）、规则顺序（`:104–116`）、根锚定（`:58–64`）和 `*`/`**` 深度区别（`:40–44`、`:60–63`）仍是应保留的公开约束。固定依赖源码补足它们未直接列出的目录尾斜杠与否定后代边界。不能因为旧测试没有专门的六组 issue 断言，就把已公开的依赖行为当成完全未定义。

另一方面，DVC 的 `CleanTree._parents_exist`（`ignore.py:202–231`）检查父目录，`walk`（`:233–241`）过滤传给底层树的目录列表。func `test_ignore_collecting_dvcignores`（`:89–109`）也保护所示被忽略目录内的 ignore 文件不被收集。它们支持“直接匹配结果与树遍历结果不同”的判断，但未给出“父目录仍被忽略而只有其后代被否定命中”时是否需要额外搜索或重新进入父目录的规范。pathspec 的匹配器不负责这类遍历政策，METADATA 中存在 `match_tree` 使用入口也不等于规定 DVC 必须采用某种遍历策略。

## 残余条件项的影响范围

**已消解。** 不再缺少固定 GitWildMatchPattern 对尾斜杠、目录后代、否定方向、根锚定和通配符的公开定义；也不需要新私有期望才能区分上表模式。DVC API 已给出 dirs/files 上下文，使核心目录匹配修复目标具有可理解的公开依据。

**尚未确定。** 如果某项验收要求 `!/scripts/*` 之类仅命中子项的规则，在父目录被正向规则过滤且未被目录否定恢复时，仍自动令父目录可遍历并展示这些子项，应提供 DVC 关于这一行为的公开契约或原有案例。本次资料不支持把它包装成 pathspec 0.8.1 必然要求，更不支持要求六组规则全部成功或等价。该条件项只影响这种遍历政策及其衍生路径集合，不阻断按已有依赖契约修复目录识别、否定范围和规则顺序。

**复现信息限制。** 原题面仍没有实际目录树和逐次观察，无法认定作者每组试验究竟试图看到目录自身、直接子项还是全部后代。若要声称逐组原始试验已唯一重建，需补这些公开输入；若只验收某个明确公开目录树上的版本化匹配行为，可以按契约区分各模式，无须另立“所有模式同义”的规格。

可选文字建议是补一个中性目录树和检查对象，帮助读者复现；不应借环境说明添加模式期望、修法或隐藏断言。
