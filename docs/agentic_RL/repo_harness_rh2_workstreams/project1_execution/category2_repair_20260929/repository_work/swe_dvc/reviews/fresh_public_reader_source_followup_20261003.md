## 结论

新增公开依据消解了 5839 的核心精度歧义：既有 CLI help 定义 `--precision n` 为普通十进制小数点后 n 位，默认五位，旧公开测试与此一致。原题面关于科学记数法尾数精度的提议不应覆盖已有命令契约。科学记数法或固定小数格式的具体文本选择仍未由本次材料完全确定，但不影响“让参数按已有小数位契约生效”这一要求。

## 4166：可确认的公开基础与尚缺的边界

以下行号指本次指定的 `4166/dvc/ignore.py`、`4166/tests/unit/test_ignore.py` 和 `4166/tests/func/test_ignore.py`。

### 已有公开材料提供什么

- **规则来源与相对路径。** `ignore.py:26–43` 从 `.dvcignore` 读取规则并交给 `GitWildMatchPattern.pattern_to_regex`；`:51–66` 将同目录或后代路径换算为相对该 ignore 文件目录的路径，非 Unix 路径进行规范化。这里证明选用的模式解析器和 API 组织方式；解析器内部语义未包含在本次范围。
- **忽略与否定的顺序。** `ignore.py:68–73` 按规则组顺序覆盖匹配结果。unit `:70–71` 明确 `dont*` 后的 `!dont_ignore.txt` 取消忽略；`test_ignore_order`（`:104–116`）规定 `!ac*`、`a*`、`!ab*` 最终只保留 `ab`。因此，否定规则及后匹配覆盖是有公开断言的行为，不是作者修订新引入的要求。该结论适用于本次测试所示的单个 ignore 文件，不扩展成多个 ignore 文件之间的优先级承诺。
- **锚定和通配符并非一律同义。** unit `:58–64` 明确 `/*.txt` 忽略根下 `to_ignore.txt`，但不忽略 `path/to_ignore.txt`；`:40–44` 与 `:60–63` 明确 `**` 可以匹配多级中间路径，单个 `*` 的所示案例不能。func `test_match_nested`（`:131–142`）显示未锚定的 `*.backup` 和 `tmp` 规则在所示嵌套文件上也生效。现有测试支持区分模式的作用范围，不能推出题面六组写法应全部等价。
- **目录和文件均参与过滤。** unit `:17–32` 对简单名称模式同时断言 dirs/files 过滤；`ignore.py:45–49` 有相应 API。`CleanTree` 的 `exists`、`isdir`、`isfile`（`:161–197`）以及 `_parents_exist`（`:202–231`）还检查祖先目录，`walk`（`:233–241`）过滤目录与文件。它们展示必须区分直接路径匹配与树可见性的架构背景；不能把当前祖先被过滤后的结果当作问题已修复的规范。
- **既有遍历案例。** func `test_ignore`（`:21–28`）断言忽略指定子文件而保留同目录另一个文件；`test_ignore_collecting_dvcignores`（`:89–109`）断言被忽略目录内的 ignore 文件未进入所示规则集合；`test_ignore_external`（`:145–151`）保护外部目录文件不受所示仓库规则过滤。它们是既有公开约束，均未覆盖题面的全局忽略加目录否定组合。

### 为什么六种写法仍不能视为同义

题面写法涉及未锚定 `*`、根锚定 `/*`、名称否定 `!scripts`、根名称否定 `!/scripts`、目录尾斜杠 `!/scripts/`、子项 `!/scripts/*`、递归后代 `!/scripts/**`。旧测试对部分符号的范围已有区别，但没有为这些组合列出预期，也没有覆盖否定目录尾斜杠或在全局忽略下恢复目录遍历的案例。题面没有目录树，仍未说明 `scripts` 是文件还是目录、是否在 ignore 文件根下、是否存在嵌套同名目录，以及期望恢复目录自身、直接子项还是全部后代。

本次源码中 `matches(dirname, basename)` 没有文件类型参数；`__call__` 对 dirs 和 files 都调用它。这是当前接口形态，不能据此认定目录尾斜杠应等同普通名称，也不能认定不等同。`GitWildMatchPattern` 的导入表明解析器选择，但不提供其完整目录约定。应避免用“当前 basename 如何传递”替代“目录模式应如何判断”这一规范问题。

### 要确定唯一验收，还缺少什么

1. **固定公开依赖版本的模式契约。** 本轮允许读取的文件未包含 `pathspec==0.8.1` 的 `GitWildMatchPattern.pattern_to_regex` 实现或文档，尤其缺少 `/`、尾斜杠、`*`、`**`、否定和目录后代匹配的具体约定。若要以解析器语义验收，应提供该固定版本的公开依据，而不是采用其他版本记忆或推测。
2. **DVC 对解析器与遍历的衔接约定。** 需要明确目录候选传入匹配 API 的表示方式，以及“父目录被忽略时是否仍遍历、何种否定可恢复父目录或后代”。现有源码显示当前机制，但问题本就涉及该机制，不能用当前故障行为定义规范；本次旧测试也未覆盖相关恢复案例。仅有一般 gitignore 规则名称不足以确认 DVC 完整采用哪一种目录遍历语义。
3. **具体复现目标或有同等约束力的公开测试。** 明确 `.dvcignore` 所在目录、`scripts` 类型、一个最小目录树，以及各组合应可见/不可见的路径。若公开依赖与 DVC 的目录约定已唯一规定这些结果，可按该契约导出，不必要求作者为六组规则人为指定同义结果。

因此，已能按现有公开断言约束否定顺序、锚定、所示通配符和简单路径过滤；若验收涉及题面每组规则的目录与后代可见性，仍有实质条件项。这里不要求更改所有六组为成功，更不从未读取的私有测试补出答案。
