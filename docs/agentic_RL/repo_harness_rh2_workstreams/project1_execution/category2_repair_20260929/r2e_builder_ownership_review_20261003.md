# R2E 构建检查容器的归属与清理

2026-10-03，发布维护者非作者核查。候选 `runs/category2_repair_20260929/release_work_20261003/r2e_builder_ownership_v1/`。本次读完实际 builder 差异及维护测试；未连接 Docker daemon。

**可纳入下一个 CPU 候选，须做一次真实 daemon 窄验证后供题主普遍使用。** 34 项作者维护检查通过，覆盖旧材料、环境、sysconfig 及新异常路径；不把模拟测试写成实际容器已验。

新 `create → start --attach → inspect → finally` 路径保留脚本、平台、用户和断网参数，唯一 name/owner/job 绑定容器。删除前核真实 ID 和两个归属标签；删除后核不存在。无法确认归属或清理时阻断整批，不进入下一题或输出成功覆盖表。create 超时即使当前清理成功也保持不确定阻断。真实容器退出码与 attach 客户端错误均不会被吞掉。

新资源参数仅限制准备和复核容器；原 CLI 兼容，CPU 调用需显式提供本批分配的 CPU/内存/PID。没有修改 Dockerfile、配方、评分、安全选项或材料。`docker build` 的 daemon/BuildKit 内部资源不在这些容器限额之内；CLI 超时会停止整批，宿主必须另查该构建状态，不能靠删除普通容器宣称构建已终止。

真实窄验证应检查退出码、输出、实际 HostConfig、超时后自身容器删除，以及不同 owner 容器保留；验证程序不跑来源题目、不下载或重建镜像，使用现成固定镜像，并经统一作业槽。后续发生强制杀宿主进程仍要按记录的 owner 核现场，本改动不声称消除该情形。
