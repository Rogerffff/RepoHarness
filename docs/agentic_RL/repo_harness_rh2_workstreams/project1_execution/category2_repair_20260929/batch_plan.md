## 每题如何交付

负责人在同一个题级记录中串起：已有证据 → 本轮修改 → 实际对照 → 独立复核 → 用途结论。每次至少交付：

- 已解决的问题和准确生效版本，哪些旧证据仍可复用。
- 正确修法是否通过、已知错误修法是否被拒、noop是否仍暴露目标缺陷；不能用安装或收集故障替代目标失败。
- 公开开发操作和实际评分入口各自的证据；题面变更另给新公开读者和实际交付核对。
- 完整日志、安装子命令、参考状态、资源终止及清理事实；所有重要剩余事项与解除条件。

修订前后的结果分开记录。仅测试材料变化，可以复用同字节候选重评分；公开题面变化之后，后续模型尝试必须用干净上下文。转第1类后仍由题目负责人接回模型暴露的新问题，不能把它交出去便结束责任。

## 并行与共享边界

材料调查、公开阅读、独立复核可以并行；root保持唯一远端派发和公共入口修改协调者。新CPU机器与第1类线程共用、目录独立，全机最多两路actor／grader，本线程最多一路。迁移时复核镜像、配方、代码及资源等价性，不直接搬旧`/work`路径，也不因换机器一律重跑旧实验。

第1类模型探针线程已收到分工与共享文件边界。题级修复在独立目录落盘，未确认切换归属前不覆盖共享R2E摄入与生产文件。GPU、模型服务、探针预算由第1类线程统一管理；本批不会私自启动。
