# 审查标准（review-standards.md；审查维度与规范的唯一权威）

> 治理规则（谁决定什么、分歧收敛、修复循环熔断）在
> `collaboration-protocol.md`；**怎么审、审什么、产出什么形状**以本文为准。
> 修改审查要求 = T0（见协议修改权规则）。
>
> 关于执行方式：审查者（codex 或 Claude 的自检）**建议**用多个独立上下文
> 分视角检查（缓解单上下文多维度的遗漏），但本文不强制具体执行方式——
> 硬约束只落在**产出形状**上：每个维度有结论或显式 N/A、finding 符合
> §4 格式、结论分期。

## 1. 四级审查矩阵

| 级别 | 时机 | 范围 | 审查者 |
|------|------|------|--------|
| 设计审查 | 决策包 / 05 计划变更，写码前 | B/C/D/F/H + 决策包完整性 + 设计三问（§3） | codex |
| 切片审查 | 每小批（如 F2-x）完成后 | A~K 全维度，允许显式 N/A | codex（Claude 先过 §7 自检） |
| 阶段集成审查 | 大阶段末（如 FA-2A 全部切片落地） | 全链路走读：切片接缝、状态所有权、跨切片不变量、账目守恒——轮次 13 式审计的制度化 | codex |
| 训前总审计 | 正式训练闸门翻转前 | 全部临时挡板解除确认 + 四态守恒式可重建 + 闸门条件逐条核销 + FA-5 验收清单 | codex + 用户核签 |
| （豁免） | 纯 T2 改动（文档/命名/fixture） | 不要求独立 codex 审查 | — |

分级的依据：FA-1 九轮的经验是**单点审查深度已足够，系统性缺口在尺度**——
小批审查都是增量视角，没有制度化的接缝复查（轮次 13 全链路审计价值最高
但当时是偶发的）。

## 2. 审查维度定义（A~K）

每条附一个真实历史锚点（"这个维度曾抓住/漏掉什么"）。

- **A 正确性/并发/安全**：确定性探针、真实线程拓扑（不是单事件循环）、
  交错复现。锚点：轮次 10 双线程探针抓住 `task.cancel()` 跨线程无效。
- **B 训练分布影响**：每个新增拒绝/fail-closed 路径回答"系统性剔除哪类
  轨迹？偏置风险是否登记？"锚点：非零 exit 全拒 = 长度偏置（轮次 14）。
- **C 挡板审计**：任何守卫必须有移除条件+替代任务；无过期机制的守卫
  标黄。锚点：overlap fail-fast 与正式训练闸门的绑定。
- **D 所有权与配置真实性**：新共享可变状态指认 owner；新配置旋钮指认
  生产消费者；散锁增加要问"为什么不是收敛所有权"。锚点：
  `rh2_fa_limit_model_call` 曾是无消费者的配置摆设（轮次 13）。
- **E 测试有效性**：修复测试必须证明真进目标分支；反向查过度钉死
  （精确文案/大小写断言）。锚点：轮次 9 deadline 假阳性测试；
  `X-Session-ID` 大小写过度约束。
- **F 一致性**：与既有 D-决策、冻结契约、05 计划、权威状态页的冲突。
  锚点：05 计划两处重启语义矛盾（轮次 14）。
- **G 生产路径证明**：测试调的是真正生产入口还是只测了 helper。锚点：
  `assert_adapter_status_not_404` 曾只有测试调用（轮次 9）。
- **H 唯一事实来源**：同一事实是否被多个对象重复维护并可能漂移。锚点：
  artifact digest 曾有内存/外部两套字节口径（轮次 12）。
- **I 问题分期**：结论分"本轮必修 / 正式训练前修 / 可递延"三档，并
  显式列出"哪些不值得立即修"（防修复雪球）。锚点：codex 轮次 14
  "不值得现在重写 895 个测试"。
- **J 代码质量**：重复代码、圈复杂度、死代码、注释噪声（本仓注释密度
  高——逐轮修复留下的"轮次编号注释"在问题闭环后应收敛，不许无限堆积）。
- **K 演进成本**：判据 = "新增一个 X 要改几处"。例：加一个终止类别
  应该只动枚举 + 策略函数；若要动五个文件，是设计问题不是实现问题。

**风格不在任何维度里**：机器可判定的（格式、import 顺序、未用变量）
交给工具（§8），审查只管工具管不了的。

## 3. 设计审查三问（决策包/计划专属）

```text
1. 方案空间：给出的 2~3 个方案是不是对的选项集？被排除的方案是否
   说清了排除理由？（锚点：codex 否决"裸 at-least-once"——价值在
   补全选项集的缺陷暴露，不在评价既有方案）
2. 可验证性：设计的关键不变量能否本地（无 GPU）验证？验证不了的
   部分是否显式登记为真机项？（锚点：`_key` 真调用不可本地做，
   如实降级为源码 pin + GPU 递延）
3. 切片划分：批次分解是否纵向切片、单一目标？有没有一批同时动
   多个 ownership 边界？（锚点：FA-1 单批过大的教训）
```

## 4. finding 格式与回应（分歧收敛规则见协议 §5）

```text
codex finding 必须包含：
  当前行为 / 违反的不变量 / 证据 / 影响 / 建议分期

Claude 对每项只能三选一回应：
  accepted / rejected_with_evidence / deferred_with_owner_and_gate
```

## 5. 每轮必答五问（切片审查与集成审查都要答）

```text
新拒绝路径会丢掉哪类轨迹？
失败是否结构化留痕？
是否存在静默降级？
测试是否真的经过目标分支和真实线程拓扑？
本轮哪些问题不值得立即修？
```

## 6. codex 审查请求模板（按级别，用户转发时直接粘贴）

**设计审查**：

```text
请按 review-standards.md 做设计审查（对象：<决策包/计划文件>）：
维度 B/C/D/F/H + 决策包完整性 + 设计三问（方案空间/可验证性/切片划分）。
finding 按 §4 格式。
```

**切片审查**：

```text
请按 review-standards.md 做切片审查（commit <hash>）：
维度 A~K 全覆盖（允许显式 N/A），必答五问，结论按
"本轮必修/正式训练前修/可递延"分期。finding 按 §4 格式。
建议用独立上下文分视角检查（不强制）。
```

**阶段集成审查**（大阶段末）：

```text
请按 review-standards.md 做阶段集成审查（阶段：<FA-2A 等>，
含 commits <range>）：不审增量，从生产入口全链路走读——切片接缝、
状态所有权一致性、跨切片不变量、账目守恒、临时挡板登记表逐项核对。
必答五问。产出与轮次 13 审计同形（分 P0/建议/确认正确三节）。
```

## 7. Claude 交接前自检清单

**定位（诚实声明）**：自检者与实现者是同一个模型，盲区相关——自检
不降低 codex 审查强度，只为把便宜问题在交接前清掉，让 codex 火力集中
在结构问题。"自检过了"不构成任何审查豁免。

**机械清单（每批必做，历史事故的直接翻译）**：

```text
□ 改了容器/契约形状 → 全仓 grep 消费点逐个核对（轮次 11：pending
  改 list 漏了启动探针消费点）
□ 新增配置/开关 → 指认它的生产消费者（轮次 13：limiter 配置摆设）
□ 每个修复 → 配"真进目标分支"的测试断言（轮次 9：假阳性测试）
□ 文本替换式编辑 → 必须带 assert（轮次 9：静默未生效）
□ 新增拒绝路径 → 回答"剔除哪类轨迹"并在报告 ② 或决策包登记
□ 全量 pytest + inspect 账本 PASS
□ ruff check 无新增违例（§8）
```

**对抗性自检（大切片选用，小批可跳过）**：起独立上下文的 sub-agent
拿 diff 按 A~K 找茬——独立上下文缓解"作者盲区"，但对模型级盲区无效
（相关盲区声明如上）。执行方式不强制。

## 8. 风格工具化政策

- 工具：`ruff`（lint；dev 依赖组）。命令：`uv run ruff check .`
  （在 `rh2/` 下）。
- 规则集从最小集起步（E9 语法级错误 + F pyflakes：未定义名/未用
  import 等——机器可判定且无争议的），按需扩，扩规则集属 T2。
- **存量豁免、增量强制**：历史代码的违例一次性豁免（配置内 ignore 或
  基线清理的独立 T2 批次），新改动的文件不得引入新违例（自检清单项）。
- 格式化（ruff format）暂不启用：全仓格式化会与并行 S2 线程产生大面积
  冲突；待并行线程收敛后再评估（届时属 T2）。
- 审查者遇到纯风格问题：不出 finding，指向本节（"交给工具"）。
