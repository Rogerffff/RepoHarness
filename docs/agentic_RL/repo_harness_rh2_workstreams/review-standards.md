# 审查标准（review-standards.md；审查维度与规范的唯一权威）

> 治理规则（谁决定什么、分歧收敛、修复循环熔断）在
> `collaboration-protocol.md`；**怎么审、审什么、产出什么形状**以本文为准。
> 修改审查要求 = T0（见协议修改权规则）。
>
> 版本：v1-rc2（codex 审查 16 条全采纳，2026-07-24）。待用户与协议一并
> 确认生效。

## 1. 五级审查矩阵

| 级别 | 时机 | 范围 | 独立上下文 |
|------|------|------|-----------|
| 决策包审查 | 决策包起草后、用户拍板前 | §3.1 模板 + T0 完整性扫描（§3.3） | 不强制 |
| 执行计划审查 | 用户拍板后、写码前（05 计划变更） | §3.2 模板 | 不强制 |
| 切片审查 | 每小批（F2-x）完成后 | 维度 A~N 全覆盖，允许显式 N/A（N/A 要理由，§5） | 不强制 |
| 小阶段集成审查 | 小阶段末（如 FA-2A 全部切片落地） | 切片接缝全链路（§6.1 证据产物强制） | **强制 ≥1 次** |
| 大阶段验收 | 大阶段末（如 FA-2 全部完成） | 子系统组合 + 闸门条件（§6.1 产物 + 闸门核销） | **强制 ≥1 次** |
| 训前总审计 | `rh2_formal_training_allowed` 翻转前 | 全部挡板解除 + 守恒式 + FA-5 清单 + **Owner Gate Packet**（§6.2） | **强制 ≥1 次** |

- 各级检查不同的问题：切片管局部代码；小阶段管切片接缝；大阶段管子系统
  组合与闸门；训前管真实环境与正式训练风险。
- **独立上下文复核**：高风险级别（后三级）至少一次由与作者/连续审查上下文
  无关的独立上下文重查——作者与其连续上下文共享同一假设（锚点：deadline
  bug 里实现者以为参数已传入、其写的测试也相信这个前提）。多份原始报告由
  主审查者去重裁决后再交用户，不直接转发。普通切片不强制（用户 2026-07-23
  定的"执行方式不强制"仅对非高风险级别维持）。
- 豁免：纯 T2 改动不要求独立审查，但 **T2 的边界收紧**——以下**不是 T2**：
  修改测试期望值/oracle、增加 skip/xfail、改 pytest marker、改测试数据
  语义、改 acceptance evidence、改 gate fixture（这些改变"什么算正确"，
  至少 T1 强报告）。真 T2 例子：fixture 搬路径且 digest 不变、引用同步改。

## 2. 审查维度定义（A~N）

每条附真实历史锚点。切片审查全覆盖；前置审查按 §3 模板选用。

- **A 正确性/并发/安全/失败模型**：确定性探针、真实线程拓扑、交错复现；
  设计层则审 crash-consistency（例：双 checkpoint 方案必须回答"cursor 写
  成功、pending checkpoint 写失败、此刻崩溃会怎样"）。锚点：轮次 10 跨
  线程取消探针。
- **B 训练分布影响**：新增拒绝/fail-closed 路径回答"系统性剔除哪类轨迹、
  偏置是否登记"。锚点：非零 exit 全拒 = 长度偏置。
- **C 挡板审计**：守卫必须有移除条件+owner+gate；无过期机制标黄。锚点：
  ruff 豁免曾未登记（本文档 v1 自己犯的错，codex 审查 15 抓出）。
- **D 所有权与配置真实性**：共享可变状态指认 owner；配置旋钮指认生产
  消费者。锚点：limiter 配置摆设。
- **E 测试有效性**：修复测试证明真进目标分支；反查过度钉死。锚点：
  轮次 9 假阳性；`X-Session-ID` 大小写。
- **F 一致性**：与 D-决策、冻结契约、05 计划、权威状态页冲突。锚点：
  重启语义两处矛盾。
- **G 生产路径证明**：测试调真生产入口还是只测 helper；设计层则审"新
  组件如何替换真实接入点"（例：新 assembler 必须说明怎么接
  `rollout-function-path`，否则造出生产不用的 helper）。锚点：
  `assert_adapter_status_not_404` 无生产调用。
- **H 唯一事实来源**：同一事实多处维护会漂移。锚点：digest 双口径。
- **I 问题分期与止损**：结论分"本轮必修/正式训练前修/可递延"并列出
  不值得立即修的；设计层审递延是否合理（例：`_key` 本机不可 import →
  源码 pin + FA-5 真机，合理递延而非卡死本机阶段）。
- **J 代码质量（人工可读性面）**：重复、复杂度、死代码、注释噪声，以及
  **机器查不了的**：变量名是否表达真实含义（`process(x,y,z)` 而 x 是
  ExecutionIdentity）、公共 API 命名一致性、**注释与行为是否一致**（例：
  注释写"sink 失败停训"、代码却 `except OSError: pass`——格式全对但
  语义相反，只有人工能抓）、抽象层次。
- **K 演进成本**：判据 = "新增一个 X 要改几处"（例：加一个终止类别要
  动七个模块 = 终止语义没有集中管理，设计阶段就该修边界）。
- **L 性能/容量/活性/反压**：队列是否有界；event loop 有无同步阻塞
  （例：每次 model call 同步查 `/get_weight_version` → 32 并发在同一
  adapter loop 串行等待，功能测试全绿但 GPU 利用率塌）；反压是否传回
  producer（例：trainer 队列满而 worker 仍拉任务起容器 → 内存/容器/
  磁盘同涨）；内存是否随 rollout 数增长；死锁/饥饿/永久等待。**这不是
  锦上添花**：P3 实测 wait_time_ratio=0.82、尾闲 26~28%，本维度是
  fully async 是否有价值的核心。
- **M 可观测性/可诊断性**：fail-closed 会把系统性错误伪装成"样本少了
  一些"。失败记录至少携带 execution_id / prompt_group_id /
  failure_category / failed_component / policy_version / retryable /
  发生阶段 / 各阶段耗时 / evidence_ref，且**可聚合**回答"最近 1000 条
  rollout 里多少因 sandbox 失败、多少因 staleness、多少是真实
  reward=0"——否则系统可以"安全地"丢 30% 数据而没人知道。
- **N 外部兼容性与依赖漂移**：依赖（slime/SGLang/verifiers/CC CLI/
  renderers）版本是否 pin；升级时哪些契约探针必须重跑（锚点：CC
  2.1.205 行为画像——重试/404 fallback 语义换版本可能悄悄失效）；schema
  可迁移、旧 artifact 可读；外部签名漂移 fail-fast（锚点：HEAD pin
  守卫测试；httpx 大小写漂移）。

**机器可判定的不进任何维度**：缩进/引号/import 顺序/行宽/未用 import
交给 ruff（§7）；J 只管上面列的人工可读性面。

## 3. 写码前的两类审查（模板不共用）

同为写码前，对象不同：决策包审"**该采用什么语义**"，计划审"**怎么安全
地实施已定语义**"。共用模板的风险（codex 例）：正确选了单 owner，却没
发现迁移顺序会让新旧 owner 同时写状态。

### 3.1 决策包审查模板

```text
维度：B / C / D / F / H + A(失败模型) / K(演进成本)
+ 决策包完整性（协议 §2 六要素齐全）
+ 设计三问：
  方案空间——选项集对吗？被排除方案的理由说清了吗？
  可验证性——关键不变量能否本地验证？验证不了的登记真机项了吗？
  长期代价——隐藏代价（如"改起来很贵"的项）识别全了吗？
+ T0 完整性扫描（§3.3）
```

### 3.2 执行计划审查模板

```text
维度：A / F / G / I / L + 切片划分
必答：
  先改什么后改什么？迁移顺序有没有"新旧两个 owner 同时写状态"的窗口？
  每个切片的输入与产物是什么？
  失败后如何停止或回滚？
  哪些测试本机跑、哪些必须 GPU（递延登记了吗）？
  文件 ownership 如何避免与并行线程（S2）冲突？
```

### 3.3 T0 完整性扫描（决策包审查必做）

"方案空间"只能查已知问题漏没漏选项，查不出**整个问题被漏掉**（例：讨论
了 execution_id 格式，却没讨论"崩溃 replay 时是否复用同一 id"——后者
决定去重/幂等/恢复语义，是更重要的 T0）。审查输出五分类：

```text
confirmed T0        —— 确认需要用户决定
missing T0          —— Claude 漏列的 T0（审查者主动发现）
false-positive T0   —— 其实只是 T1
deferred T0         —— 现在不必决定（注明何时决定）
experiment-required —— 证据不足，先做实验再决策
```

## 4. finding 格式与回应（分歧收敛规则见协议 §5）

```text
codex finding 必须包含八要素：
  当前行为 / 违反的不变量 / 证据 / 影响 / 建议分期
  / 文件与行号 / 复现命令或最小探针 / 修复验收条件

Claude 对每项只能三选一回应：
  accepted / rejected_with_evidence / deferred_with_owner_and_gate
```

修复验收条件的价值（锚点 deadline bug）：不完整 finding 是"deadline 没
正确传播"；完整 finding 写明"send 必须执行一次、进入 abort→wait 分支、
模拟时钟不超 deadline、原因必须是 version_did_not_advance"——防止
"改了代码但新测试仍没进目标分支"。

## 5. N/A 与"未发现问题"必须给证据

```text
"G 生产路径：N/A" 不合格；
"G：N/A——本批仅新增不可变 schema 无运行时入口；生产消费者 F2-3
 接线，已登记 gate" 合格。

"A 未发现并发问题" 不合格；
"A：检查了 adapter thread → owner loop 取消路径，跑了双线程 barrier
 交错探针，未发现跨线程直接 mutation" 合格。
```

否则 N/A 会变成跳过困难问题的通道。

## 6. 集成级审查的强制产物

### 6.1 小阶段集成 / 大阶段验收必须产出

```text
生产入口 → 训练消费的调用链
进程 / 线程 / event loop / 状态 owner 图
跨切片不变量矩阵
故障注入结果（至少覆盖：crash / cancel / timeout / retry / restart /
  artifact sink failure / queue full——不是只跑成功路径）
账目守恒重建（例：分派 100 = delivered 72 + failed 18 + abandoned 6
  + in_flight 4，不平即有 execution 无账消失）
挡板状态表（对照权威状态页逐项）
未解决问题的 owner 与 gate
passed / skipped / xfailed 数量及原因
```

只写"走完了链路、检查了守恒"而无上述产物 = 审查未完成。

### 6.2 训前总审计的 Owner Gate Packet（一页，用户核签对象）

```text
准备翻转哪个闸门
每个闸门条件 PASS / FAIL
仍未解除的风险（分期标注）
真实 GPU 证据引用
模型 / slime / SGLang / Claude Code 版本
关键配置 digest
挡板是否全部解除（逐项）
需要用户明确批准的项
```

用户核签的是结构化证据，不是"917 tests passed"这句话。

## 7. Claude 交接前自检清单

**定位（诚实声明）**：自检者与实现者同模型，盲区相关——自检不降低
codex 审查强度，"自检过了"不构成豁免。

**机械清单（每批必做）**：

```text
□ 改了容器/契约形状 → 全仓 grep 消费点逐个核对（轮次 11 教训）
□ 新增配置/开关 → 指认生产消费者（轮次 13 教训）
□ 每个修复 → 配"真进目标分支"的测试断言（轮次 9 教训）
□ 文本替换式编辑 → 必须带 assert（轮次 9 教训）
□ 新增拒绝路径 → 回答"剔除哪类轨迹"并登记
□ 改了测试期望值/oracle/marker → 按 §1 收紧规则升 T1 报告，不当 T2
□ 全量 pytest + inspect 账本 PASS + ruff check 无新增违例
□ 提交拆分（§8）：协议/工具链/源码清理不混一个 commit
```

**对抗性自检（大切片选用）**：独立上下文 sub-agent 按 A~N 找茬；缓解
作者盲区，对模型级盲区无效。

## 8. 风格工具化与提交纪律

- ruff（dev 组，E9+F，line-length 120）管机器可判定问题；violation 全绿
  是**基线**不是审查结论——豁免的违例是**已登记的临时挡板**，不是不存在
  （当前唯一豁免：`s2_1_ingestion/resolve_image_digests.py` F401，owner
  = S2 线程，移除条件 = S2 收敛后清理并删豁免，gate = 训前总审计前；
  已入权威状态页挡板登记表）。
- 格式化（ruff format）暂不启用：避免与并行线程大面积冲突。
- **提交纪律**（codex 审查 16）：协议/标准变更、工具链配置、存量源码
  清理**分开提交**——混在一个 commit 里无法独立审阅与回滚（本文 v1 的
  首次提交违反了这条，不重写历史，此后强制）。
- 审查者遇到纯机器可判定问题：不出 finding，指向本节。
