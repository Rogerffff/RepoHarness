这套指南是什么

这是一套独立于 P1–P5 的代码导览系列，专为"以审查代码设计的视角追踪 RepoHarness 主链路"使用：

  • 主轴：按一次 episode 从请求到训练样本的执行时间线切成 T0–T9 共 10 个时间点。每个 T 是一个独立 HTML 章节，作为"在这一刻发生了什么"的代码 reading guide。
  • 侧栏：跨多个 T 点贯穿的横向主题（安全边界、TrainingView mask、Audit/artifact、evidence 防伪）独立成 4 个侧栏 HTML，主线章节里只点引而不展开。
  • 粒度：每个 T 章节按 contract + 关键函数 5–20 行 excerpt + 不变量收，不贴大段完整函数。这样未来 stage 改动几行不会让章节立刻过时。
  • 与 P1–P5 的关系：P1–P5 是 Stage 12 期间编写、之后经历过同步 AgentLoop → 异步框架的多轮改动，部分内容可能已过时。本系列不替换它们；引用时显式标 ⚠️ 引用前需审 P? 是否过时。
读者画像：你正在或将要审查 16G.3 / 16G.4 阶段的实施改动。你不熟悉 RepoHarness 全部代码细节，但需要快速定位"这次改动落在哪个 T 点 / 影响哪些侧栏 / 边界 contract 怎么定义的"。这套指南为此而生。

怎么读这套指南

场景 1 · 我要审查一个 16G.x 实施 PR

  1. 读 PR 描述确定主要落在哪个 T 点（通常 T4 / T5 / T8 / T9 是 16G 的高发地带）
  2. 读对应 T 章节的 contract + 不变量，知道改动应该不能破坏什么
  3. 读关联侧栏（PR 是否触及 A 安全 / B mask / C audit / D evidence）
  4. 回到完成报告里的"我观察到的风险"部分，对照是否覆盖

场景 2 · 我想知道"一个 episode 实际怎么跑完的"

从 T0 顺着读到 T9，跳过侧栏。每个 T 章节末尾有 → 下一步 T+1 链接。

场景 3 · 我想搞清楚某个具体 contract（比如 ToolResult / EpisodeResult）

用 nav 直接跳到产生 / 消费它的 T 点，contract 块在每章开头。

📖 代码阅读路径块的写法（重要）

每个 T / side 章节都必须以"代码阅读路径"开头。它是用户从"完全不熟悉代码库"走到"能独立在 IDE 里跟着读这一段"的最短路径。只读阅读路径块（不打开任何源码）就应该完整理解整条调用链。每步用分块结构展示 6 类信息：

给后续 stage 写新章节的人 — 6 条硬约束：
① 步数 6–12 步，太少不成链，太多读者读不完。
② file:line 必须能在 IDE 直接 cmd+click 跳转（写完整路径 src/repo_harness/...，行号准确）。
③ 每步至少 4 类信息：做什么 + 输入/输出 + 调用源 + → 继续看。复杂步骤补 "关键内部步骤" / "关键调用" / "失败时" 等附加标签。
④ 用 <span class="step">N</span> 标记跨步骤引用（如 "继续看 3"），形成可点击的调用图。
⑤ "只读路径块不打开源码也能搞清调用链"——这是验收标准。写完用一个 sub-agent 在不读源码的情况下审一遍，看是否能回答"请求从哪来 / 数据怎么传 / 失败怎么处理"。
⑥ CSS 类 .readpath / .rplp / .rpfn / .rpbody / .lbl / .val / .step 已在 T5 / T8 / side-A 里定义，新章节直接复制 style 块即可。

引用其他文档的写法（避免冲突）

  • 引用当前代码：直接 file_path:line，markdown 链接。
  • 引用本系列其他章节：code_guide_t<N>_*.html#anchor。
  • 引用P1–P5：必须前置 ⚠️ 需审查 标签 + 一句话说"这里引用的事实最后一次确认是 stage X，之后未复核"。
  • 引用完成报告 / 能力地图：直接链接；它们随 stage 增量更新。

哪些不写（避免重叠）

  • 每条能力的"模型怎么用 + profile 矩阵" → 见能力地图四象限卡，本系列只点引。
  • 每个 stage 的实施细节叙事 → 见对应 stage 的 completion_report.html，本系列只点引。
  • verl 外部框架细节 → 不展开。本系列止于 AgentLoopOutput / DataProto。
