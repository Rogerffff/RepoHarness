Stage 16G.0 完整阶段报告

覆盖两轮：原始盘点轮 + Follow-up 基线契约轮　·　本文是「16G.0 收集到了什么 + 当前能力 + 三方对照 + 下一步」的总报告，用于决定下一阶段　·　配套细览：发现详解、原始轮审查、follow-up 审查

16G.0 在回答一个问题：RepoHarness 当前给模型的工具，距离 Claude Code / mini-SWE-agent 这类真实 SWE agent 还差什么，会不会把模型训歪？

结论(有代码实证支撑)：RepoHarness 不是 toy —— 在「读 / 搜 / 编辑 / 沙箱隔离 / artifact 回读」上和 Claude Code 基本可比，结构化导航甚至强于只给 Bash 的 mini-SWE-agent。真正的缺口集中在「动态验证闭环」：跑定向公开测试、项目命令、写复现脚本、装依赖，以及多文件 patch、任务管理、把新工具动作接进训练目标(linkage)。

放行结论：Stage 17A(纯 schema)可做；Stage 17B 数据冻结 / 20 warm-start / 21 RL 全部阻断，要等 16G.1–16G.4 把工具面改造完 + 16G.5 实证诊断通过。下一步应进 16G.1（工具 profile 与训练资格门禁设计）。

3 · 当前 harness 真实能力（权威快照）

这是从代码盘点出的事实，不是计划假设。

3.1 · 13 个工具：可见性 + 训练资格

默认可见=训练默认 scaffold (simple_react) 里模型能看到训练资格=轨迹能否进 policy loss

工具职责默认可见训练资格备注
read_file读文本文件(行范围)是可纯文本，无多模态
grep / glob_files / list_files内容搜索 / 文件发现 / 列目录是可只读、并发安全
symbol_searchPython 符号搜索是可轻量 AST，非完整 LSP
read_tool_result_artifact长输出/大结果分页回读是可artifact replay
edit_file精确替换编辑已有文件是可exact replace，缺多文件 patch
create_file新建文件是可simple_react 有，patch_focused 无
git_diff看工作区 diff是可只读
update_working_state记假设/候选/已完成步骤是可弱于 Claude Code TodoWrite
run_tests跑配置好的公开测试反馈是conditional无参数，不能指定单个 case
bashlegacy 受限诊断命令是conditionalside-channel 风险，非 Claude Code Bash
execute_bash窄 allowlist shell(rg/grep/安全 git/pytest/受限 python)否不可仅 patch_focused_react_execute_bash
diagnostic_shell持久诊断 shell(文件持久，cwd/env 每次重置)否不可诊断侧通道，仅 diagnostic profile

读出来：10 个结构化工具默认可见且可进训练；两个最像「真 shell」的(execute_bash / diagnostic_shell)既不默认、也不进训练；run_tests 和 legacy bash 是 conditional。所以模型默认拿到的是「丰富结构化工具 + 一个 legacy 窄 bash」，而不是真实可参数化的公开命令能力。

对照的关键洞察：① 和 mini-SWE-agent 比，RepoHarness 在结构化导航/编辑上更强，唯一明显弱的是「自由 shell」——而这是有意设计(core 走结构化公开命令，持久 shell 留 extended)。② 和 Claude Code 比，差距集中在「动态验证 + 多文件编辑 + 任务管理 + 扩展能力」，而非基础读写。③ 两个基线分开看很重要：mini-SWE 是「能力下限」(必须覆盖它的动态诊断闭环)，Claude Code 是「分层工具上限」(core 不必全复刻，但主能力不能缺)。
