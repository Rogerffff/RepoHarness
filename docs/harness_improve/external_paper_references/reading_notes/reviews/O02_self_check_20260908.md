对R4使用的完成顺序绑定模式，执行了以下等价的**纯标量原理测试**。它不是导入或运行上游EF脚本：

```python
from concurrent.futures import ThreadPoolExecutor, as_completed
from threading import Event

gate = Event()
def score_a():
    gate.wait()
    return 0.1

with ThreadPoolExecutor(max_workers=2) as pool:
    futures = [pool.submit(score_a), pool.submit(lambda: 0.9)]
    ids = {futures[0]: 'A', futures[1]: 'B'}
    completed, scores, by_id = [], [], {}
    for future in as_completed(futures):
        name, value = ids[future], future.result()
        completed.append(name)
        scores.append(value)
        by_id[name] = value
        if name == 'B':
            gate.set()

assert completed == ['B', 'A']
assert dict(zip(['A', 'B'], scores)) == {'A': 0.9, 'B': 0.1}
assert by_id == {'B': 0.9, 'A': 0.1}
```

它只证明“按完成顺序存分数后，与原始顺序zip”不保身份；未证明作者最终实验实际使用该版本或触发了此次序，也未测该问题影响多少benchmark分数。
