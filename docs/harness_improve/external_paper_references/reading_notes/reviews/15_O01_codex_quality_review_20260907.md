## 3. 一处需要补充限定的代码表述

**位置：O01 §8.4，关于结束原因命中集合后将 loss mask 全置零的段落。**

该段概括了 mask 分支的意图，但还应说明它消费的具体字段及写入顺序。固定代码的 messages 兼容路径存在以下顺序：

1. `agents/base.py:360` 先把 `result["finish_reason"]` 的当时值追加进 `finish_reason_list`。
2. `:385–403` 才检查最后一条消息，可能将结果字典的原因改为 `BAD_LLM_RESPONSE` 或 `error_runtime`。
3. `:445` 将之前的列表交给 `step_finish_reason_list`。
4. `:485–488` 根据该列表构造最终 loss mask。

因此，当初始原因不在屏蔽集合中、随后才被消息检查改写时，修改字典不会自动更新已缓存的列表项。对原本包含 assistant token 的轨迹，**新增错误标记本身不能保证其 mask 被清零**。这与上游已经交付错误原因的情况不同。[固定代码：缓存与改写](https://github.com/NovaSky-AI/SkyRL/blob/0b286bacba2bb51dfe50186b6b5d6b1e0b5f5518/skyrl-agent/skyrl_agent/agents/base.py#L350-L445)、[最终消费](https://github.com/NovaSky-AI/SkyRL/blob/0b286bacba2bb51dfe50186b6b5d6b1e0b5f5518/skyrl-agent/skyrl_agent/agents/base.py#L481-L488)

建议在原段补上：

> 这里的清零以实际传入 `step_finish_reason_list` 的原因为准。messages 兼容路径先缓存原因，再可能改写结果字典为 `BAD_LLM_RESPONSE`／`error_runtime`；这些后加标记未在该路径回填缓存，因此不能概括为所有被后处理识别的坏响应都会归零。此处仅核对固定提交的数据流，未验证真实触发频率，也不据此判断论文历史训练受到影响。

这是对当前实现概括的补充，不是对论文 horizon masking 方法的反驳。§8.5 中更早发生的空消息 fallback 是另一处状态修改，不能因为这里的先后顺序问题，就直接推翻该节的条件性分析。

本轮证据为静态数据流，没有将它包装成已运行的最小复现。修订验收只需限定表述并附固定行号；若未来要采用此上游路径，再单独验证运行行为。

## 4. 两项非阻塞的成文改进

### 4.1 重要曲线可以保留数量级，不必只有趋势

O01 §7.2 和未知项表正确指出 MemAgent 没有单独的精确最终数表，也正确区分引用原作的成绩。但 Fig.6(b) 自身仍提供定量信息：验证曲线从约 0.30 升到第 20 步附近的约 0.74。可补一句并标为“原图目测近似值，非作者精确终值，无误差条”。不应擅自补成高精度百分比或显著性结论。[PDF 第 12 页，Fig.6(b)](https://arxiv.org/pdf/2511.16108v1#page=12)

后续原则是：重要曲线保留坐标、比较对象、关键趋势及必要的近似量级；有表或日志则优先用精确来源。无需对每个图点做数字化。

### 4.2 代码附查应有范围，避免每篇变成整库审计

O01 的代码附查有价值，不建议删除。但后续可以按论文主张决定深度：涉及 token 保真、样本剔除、mask、异步更新、速度等实现主张时，追实际入口到关键消费位置；与论文理解无关的通用框架细节不必逐个审计。发现更多工程问题时另附记录，保持精读正文的主线。

当前版本代码只支持当前版本实现事实；若历史实验 revision 无法恢复，明确保留缺口。不要为了让配方看起来齐全，用新代码填上旧论文的未知超参数。

## 6. 可直接补充给后续 Pro 阅读任务的约定

1. **先按原文章节完整阅读，再用项目问题查漏。** 保留所有后训练方法、实验分支、负结果及相关附录；项目不采用某一方法，不等于该部分可以略读。允许采用适合论文的结构，不要求每节填满固定模板。
2. **每个会话维护自己的笔记和自查文件。** 在共享分支上写入前读取最新版本，仅提交本任务路径；README、来源编号目录和批次总状态交给一个汇总会话更新，避免多个会话以旧副本覆盖共享文件。文件名与来源编号预先分配。
3. **重要主张保留可追踪证据。** 数值注明任务、模型、预算与比较条件；图表注明页码和 PDF 编号，目测值明确标注；实现主张注明固定提交、实际入口、关键字段的消费位置。相关未知分为未披露、未取得、未检查。
4. **按真实能力记录自查。** 没有独立 reviewer 时直接写作者自查。独立复核可集中于关键公式、反常结论、来源冲突和即将影响项目决策的内容，无需为每篇再安排一次本地全量重读。
5. **长报告可分多轮完成。** 中间记录已读与未读章节，完成剩余正文和附录后再交付；不把一次会话的篇幅限制伪装成“原文没有披露”。
6. **每篇最后给一个简短、条件明确的项目判断。** 写清它支持改变什么、什么情况下不适用、尚需哪个最小对照。一次提出少量实质候选即可，不要求每篇都发明新组件或新的训练方法。

这些约定服务于可检索、可核对、可复用的笔记，不另设逐篇批准闸门，也不要求先读完整个资料库才启动项目一实验。
