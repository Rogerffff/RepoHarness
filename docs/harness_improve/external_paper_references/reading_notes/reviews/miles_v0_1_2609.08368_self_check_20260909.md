## 4. 实际执行的隔离检查

针对buffer指标，转录固定C4的`get`／`get_metrics`控制流到本地最小类，注入`asyncio.Condition`、参数与两组fixture。外围`group_staleness`只用fixture的oldest整数返回版本差；`MetricGatherer`替为返回空额外指标的对象，方法的返回类型注解简化。**它不是字节相同源码的完整import测试**，也不替代原仓测试、producer生命周期或Ray并发验证。

输入：current version=5，max staleness=2，队列先oldest=0，再oldest=4。

实际输出：

```text
accepted_group_staleness = 1
rejected_group_staleness = 5
queue_size = 0
stale_groups_filtered = 1
avg_staleness = 3.0
max_staleness = 5
```

两组先后被pop，只有第二组返回；统计在reject前记录，所以3.0与5包含了被拒绝组。这支持“metric分母与Table2字面解释不同”，不支持“stale5组进入loss”。若要形成上游PR，仍需在最新代码与真实测试环境建立最小复现并核对维护者意图；本轮未向外部项目发送issue/PR。
