## 2. 项目背景与本次范围

用户的项目是 miles + SGLang + 外部 coding harness + 自己的 rh2：目标是可靠、高效地完成真实 Coding Agent 的后训练闭环，包括 RL，按需要探索 OPD。希望用环境/数据质量、复杂 harness 接入、训练语义正确性、端到端效率和独立学习结果，证明研究工程能力。

当前先完成“项目一”，暂不追求项目二的长期记忆、世界模型等扩展。重点覆盖 SWE 与 terminal 的环境、数据、infra、训练设计、评测。具体 SWE 数据选择和最终格式仍未定；旧的 216 题是候选资产，不是必须保住的实验设计。当前实现存在待闭合的环境、评分、训练消费与 GPU 验证事项；不能把历史 smoke、本地测试通过或设计建议写成正式训练结果。

复用上游的训练内核、推理服务、异步基础与通用能力应诚实归因。项目贡献应来自实际承担的跨层语义、环境/评分责任和可归属的结果。不要预先要求所有论文方法都实现，也不要把“读完整个目录”设为训练前置条件。

项目状态以 2026-09 的 miles 候选链为准；旧 AGENTS/阶段文档中的 verifiers、slime 自建 FA 主线叙述不能直接代表当前接线。原笔记的项目映射通常绑定 checkout `ce2009f879cf38071d7898a1387e01d4e27741d6` 与 miles integration `98a0272e4158b2c20e3a34d210c79b50159af0f6`，详细边界见 05 文件。此包没有复制整个实现，不支持据此声称完成代码审计。

## 4. 可直接交给外部 Pro 的任务说明

请作为独立研究顾问，阅读附件中的两批完整笔记，结合质量检查、审查记录、项目背景和候选目录，完成以下工作：

2. **定点回一手原文。** 对决定项目方向的关键结论和可疑之处回查官方报告、附录、博客、版本化代码或资产。明确区分你实际核过的证据、笔记作者报告的核验和你自己的推论；不要为表现“独立审查”而无差别全文重读所有资料。
3. **重新挑选后续来源。** 不受 README 已收录项目或原第三批顺序限制，也不偏好最新或最大模型。对每个建议列：它填补什么决策缺口、现有哪篇不能替代、具体官方入口与版本、适合全文精读/局部补读/暂缓、预计获得什么证据。识别同源版本、重复博客、导航页与独立论文，不用 URL 数量充当资料数量。可认为现有材料已够，应先做实验。
4. **给有限的下一步。** 先形成“项目决策问题 → 已有证据 → 缺口 → 补读来源或实测”的比较表，再建议少量优先阅读项。算法、环境质量、系统效率和评测都可成为优先项，不预设必须继续蒸馏或长程算法六篇。选题不等于批准项目实现。

## 5. 后续在外部精读的成文要求

每个独立原始来源单独写中文 Markdown；论文与配套博客可以同一任务阅读，但不同原始文章分别成文。已有稿优先补证据和纠错，版本更新先判断实质增量，不从头机械重写。

先从原文正文、附录、图表、网页交互建立覆盖范围，再回答项目相关问题。原文涉及数学、科学、多模态、偏好、安全、部署蒸馏等后训练内容时也要总结；不能因项目主要是 SWE 就跳过。没有披露的字段集中列“未披露”，并说明检查范围，不硬凑配方表。

首屏给训练主线、关键事实与最重要限定，随后放来源/版本、完整方法、数据和环境漏斗、训练与 infra、评测/消融/负结果、成本和开放资产、未知项。章节按来源调整，不用固定问题数或字数上限替代完整阅读。关键公式记录概率身份、梯度/stop-gradient、mask、分母、样本单位和阶段；关键数字紧邻模型、harness、预算、分母与原文定位。项目建议单独放文末，保持日期和前提。

正文、提取文本和原图互相核对：公式、表格、图注、动态案例或提取截断处必须回对应一手材料。论文事实、作者解释、读者推论、当前代码行为和项目建议分别表述。不能把当下代码默认值倒填历史实验，不把无法访问等同没有公开。

如果工具支持实际独立审查，可在稳定初稿后安排不继承作者推理的审查者，记录真实身份与修订；如果不支持，就明确记录自查或后续另开上下文复查。**不得声称创建了不存在的 sub agent，也不强制重复下载、hash 闸门或多轮全文复审。** 未读完的部分注明续读位置，已完成段落保留复用。
