01
MAP THE PROBLEM · ABSTRACT & INTRODUCTION

RL 在扩展什么？

不是单独放大训练集群，而是让模型经历更多、经历更广，并从经验中得到更有信息的监督。

摘要 · 图 1 · §1

两个“改进”，不是同一件事

标题使用 Towards Self-Improvement。引言将递归自我改进作为愿景，再落到 agent 与环境的多步探索和 RL 反馈；不能仅凭这个标题，就认为作者已完成无人管理的递归改进系统。

同一次交互，还是下一版模型？

理解用示意
修改代码
→
读取测试失败
→
再修复一次
模型利用当前上下文中的反馈改变下一步行动。这个过程本身不要求更新权重；“会重试”还不是“经 RL 后能力提高”的证据。

本篇主线：交互产生训练经验；评价经验；参数更新；再用更新后的模型采样。轨迹内适应与跨训练阶段的改善有关，但不能用同一个结果同时证明。

三条扩展轴，三个不同问题

把下方三个维度分别点开。一个维度做大，不能自动替另外两个维度补足缺口。

经历多少 · 经历什么 · 辨认什么

作者的三维组织

更多训练经验

扩大 batch 与吞吐，使用异步执行处理长程轨迹。这里的计算包含 rollout、grading 与 training，不只是反向传播。

它回答“能够生成和消费多少经验”，尚未回答经验是否有价值。

TASK

要做什么

例如修复某个行为错误。这是目标，不等同于整个可执行任务资产。

ENVIRONMENT

在什么世界里做

仓库版本、依赖、文件状态、可执行程序与服务决定初始世界。

HARNESS

怎样与世界交互

Agent loop、工具接口、提示组织与上下文管理影响实际交互。

解释性案例

两份补丁都通过测试：一份完整处理需求，另一份遗漏未测试的边界。它们得到同一个二元分数，并不说明质量相同。Grader 的投入旨在提供更有区分力的监督，但准确性与成本仍需后文验证。

为什么先写架构与 mid-training？

作者认为，RL 既需要合适架构，也需要足够丰富的探索空间。预训练提供知识和多模态理解，agent-centric mid-training 帮助模型发现更有效的任务轨迹。

动作空间

环境允许做什么

模型可以调用 shell，不代表它会有效调查报错；拥有完整仓库，也不代表它知道先读哪里。

实际探索

策略容易采到什么

模型已有的行为与知识基础，影响有效轨迹出现的机会。这里不是说 RL 只能重复已有答案。

Infra 不只回答“跑得快不快”

表示：实际行为怎样进入训练

统一轨迹表示与 penalty mechanism 处理多框架、多上下文和细粒度学习信号。聊天日志存在，不等于训练对象已正确恢复。

草稿验证，不是任务评分

理解用关系

平均生成成本取决于“草稿计算＋主干验证”与平均接受 token 数的比例。因此一次预测 7 个 token，不等于加速 7 倍。这里不伪造接受率或速度曲线。

数据改变探索起点

真实 agent 轨迹覆盖 coding、general、visual、research，并混合高质量文本、repo 代码和多模态数据。目标不只是把工具列表交给模型，而是更容易采到有价值的行为。

正优势为什么“鼓励”，负优势为什么“抑制”？

先把 r 和 M 设为 1，单项变为 −A log p。A 为正时，最小化它倾向增加相应行为概率；A 为负时方向相反；A=0 时该基础项没有更新信号。

这是这一项的梯度方向，不保证完整 batch 更新之后，每个正优势 token 的概率都逐一上升。其他样本、共享参数、优化器和裁剪都会参与。

Reward 是评分，advantage 是相对信号

四轨迹简化实验

下面仅使用二元 reward 和 Aᵢ = Rᵢ − 组均值，没有标准差归一化、GRS、GAR 或长度惩罚。它解释基础机制，不代表 MiMo 的所有评分分支。

点击候选，改变通过／失败

柱高只表示 toy advantage 数值，不是实测梯度范数。轨迹级 A 会广播到多个 token，不能自动区分成功轨迹中的无效步骤。

FOLLOW THE SEMANTICS

演示，不是原始日志

4 次求解

不仅看得分，还看怎样得到分数

作者复用 rollout，结合补丁与完整交互检查潜在 reward hacking。普通部分修复被漏检，与通过改变评价所依赖对象而取得分数，是不同路径；不需要推断模型的主观意图，才能发现得分与目标偏离。
