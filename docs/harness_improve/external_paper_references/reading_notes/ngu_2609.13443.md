# NGU：按当前采样结果分配探索预算，缓解 GRPO 对难题的信号不足

阅读日期：2026-09-16。论文：*Learning to Solve Hard Problems in RL for LLMs by Never Giving Up*，Michael Noukhovitch、Hamish Ivison、Nathan Lambert、Aaron Courville，arXiv **2609.13443v1**，2026-09-11。配套博客发布于 2026-09-15。

本篇以解释训练机制为主。以下明确区分原文结果、用于理解的自拟算例，以及对 RepoHarness 的建议。建议不构成项目定案。

## 1. 核心贡献与任务边界

作者观察到：RL 的平均分提高，可能主要来自模型原本就较擅长的题变得更稳定；最难的题改善很少。论文把这个现象称作 **Matthew Effect（马太效应）**，并提出一种解释：训练算力在不同难度的题之间分配不合理。

NGU 的核心是**根据当前生成结果，自适应决定同一道题还要采多少条回答**。它保留全训练集的首次抽题机会，对已经全对的题尽早结束本轮处理，对全错的题有概率追加采样，直到获得可比较的奖励。异步流水线使结束的任务能及时让出资源。

这不是给模型增加教师答案，也不是让模型在原答案上反思修改。重复尝试仍是对同一问题生成新回答；前几轮记录主要保存在训练系统中，用于组装样本和计算优势，不等于把失败回答放进模型下一次输入。

三类证据要分开：

| 范围 | 本文做了什么 | 不能据此声称什么 |
| --- | --- | --- |
| 数学、代码生成、SWE 的已有模型 | 对 Olmo、DeepCoder、DeepSWE 做按难度分组的表现分析（Fig. 1） | 这不是三个领域各做一次 NGU 训练 |
| GSM8k Platinum、DeepScaler | 真正训练 NGU，对采样、陈旧度、优势计算做实验 | 不能把一种配置视为所有数据集的最优设置 |
| Manufactoria | 在特殊程序生成任务上训练 NGU，分析部分测试通过与整题通过 | 尚未验证多轮 SWE 仓库编辑、工具调用、环境长尾 |

本文的 NGU 与 2020 年同名深度 RL 探索方法不是同一个算法；这里没有引入新颖性内在奖励。论文自己将当前训练设置描述为 contextual bandit，并把复杂多步 agent 场景留作未来工作。

## 2. 为什么固定 group size 会影响实际训练分布

论文使用仅中心化的优势：

\[
A_i=r_i-\bar r,\qquad \bar r=\frac{1}{K}\sum_{j=1}^K r_j.
\]

附录参数表写的是 `centered`，不是每组再除以奖励标准差。因此下文的优势数值不能直接套到所有名为 GRPO 的实现上。

对二值奖励，一题采 4 次：

| 奖励 | 优势 | 该题的 reward policy-gradient 信号 |
| --- | --- | --- |
| `[0,0,0,0]` | `[0,0,0,0]` | 没有 |
| `[1,1,1,1]` | `[0,0,0,0]` | 没有 |
| `[0,0,0,1]` | `[-0.25,-0.25,-0.25,0.75]` | 有正负比较 |

“没有梯度”指这里的奖励优势项，不应泛化成任何辅助项都没有梯度。作者的基线会过滤零优势组并继续补采，直到训练批次够用。

必须区分三个分布：原始题库的分布、生成尝试实际消耗的分布、过滤后进入更新的分布。即使首次抽题均匀，后两者也不会自动均匀。

以下是**自拟概率算例**，假设每次回答独立，成功率固定为 q。至少包含一个成功和一个失败的概率为：

\[
P_{\mathrm{mixed}}(q,K)=1-q^K-(1-q)^K.
\]

| 单次成功率 | K=4 的混合组概率 | K=32 的混合组概率 |
| --- | ---: | ---: |
| 易题 q=95% | 18.55% | 80.63% |
| 难题 q=1% | 3.94% | 27.50% |

增大 K 确实更容易碰到难题的罕见成功；同时也让几乎会做的题更容易碰到一次罕见失败，从而继续占据更新批次。每题采样数增加，也意味着同一预算下可覆盖的不同题目减少。

作者在 GSM8k 的固定 N×K 设置中发现 K=4 比 K=8/16/32 更好，并用训练批次难度构成解释结果（§3、Fig. 2–3）。但这不是“K 越小越好”的定理：附录 C.3 明确说，DeepScaler 上 K=8 比其余基线差，因为正解太少。

也不应把易题的少量错误一概视作无价值噪声。论文给出的是特定训练预算下的取舍，实际系统可能仍需要改善易题可靠性。

## 3. NGU 如何运行：一个完整的二值奖励例子

先暂不考虑旧样本过期，令初始 K=4，继续概率 p=0.95。

1. 从完整训练集抽一题，生成 4 个回答。
2. 第一轮全对：没有组内对比，结束本轮处理。没有把这道题永久移出题库。
3. 有对有错：形成训练组。
4. 第一轮全错：以 95% 概率将同一题重新排入生成队列，以 5% 概率结束本轮处理。
5. 每次继续都会保留此前尝试的统计；出现正解后，把可用的历史失败与本轮回答组成一组。

自拟轨迹：

```text
第 1 轮：0 0 0 0  → 继续
第 2 轮：0 0 0 0  → 继续
第 3 轮：0 0 0 0  → 继续
第 4 轮：0 0 0 1  → 形成训练组
```

此时共 16 次尝试，1 个成功，组均值为 1/16。正样本优势为 15/16=0.9375，负样本各为 -1/16。若只看最后 4 次，成功优势则为 0.75，忽略了此前 12 次失败。

因此 NGU 同时改变了**探索次数**和**构成优势的比较组**。它不是单纯“多采几次后只保留正样本”的 SFT。

更大的单条优势不等于整题总梯度一定更大：还取决于样本/组/token 归一化、重要性权重和 clipping。论文没有在一个完整公式中交代变长组进入 trainer 后的全部归一化细节，公开代码此次不可读，所以不补造这一实现结论。

NGU 也不是字面上的永不放弃。若题始终没有成功，每轮失败后才以 p 决定是否继续，平均尝试数为 K/(1-p)。K=4、p=0.95 时为 80，但这不是单题硬上限，几何尾部仍可能很长。

更精确的**自拟推导**：若成功率 q 固定，每轮全错的概率为 b=(1-q)^K，则

\[
E[\text{尝试数}]=\frac{K}{1-pb}\leq\frac{K}{1-p}.
\]

K=4、p=0.95 时：易题 q=95% 只需平均约 4.00 次；难题 q=1% 平均约 45.75 次；始终无法解出的题平均 80 次。成功会提前结束，所以不能把所有题的平均开销都写成 80。

在相同简化假设下，本轮处理结束前至少找到一次成功的概率为 `(1-b)/(1-p*b)`。q=1% 时约为 45.07%，相比一次 K=4 的 3.94% 更高，代价正是更多尝试。它没有凭空提高固定模型每一次生成的成功率。

## 4. 在线课程从哪里来

“在线”指训练进行中，系统用最新采样结果做决定；“课程”指模型实际接受训练的内容和难度结构随能力变化。

NGU 没有先建立一个固定难度排序，也没有要求第一阶段只做易题、第二阶段只做难题。举例：

- 训练早期，题 A 连续全错，会得到追加尝试的机会。
- 模型通过其他题学习后，A 越来越容易出现成功，不再需要很多轮。
- A 若经常第一轮全对，本轮很快结束，预算可用于其他题。
- 模型若遗忘 A，日后再次抽到时又会产生混合结果或全错，重新获得学习机会。

所以“同一道题需要多少次尝试”本身就是在线更新的难度反馈。它使有效训练分布自适应变化，同时仍让易题有机会重新被检查。

论文比较的是一个**静态初始难度分配基线**（附录 C.3）：先用初始模型给训练题各采 32 次，然后大致按成功次数 8/32、4/32、2/32 及更低，分别分配 K=4、8、16、32；以后固定不变。这个基线难题改善接近 NGU，但易题收益较低。

不能把结果扩大成“NGU 击败所有 curriculum learning”。NGU 本身可以理解为在线采样课程；被比较的只是具体静态基线，以及另一种永久移除已全对题的策略。后者在 Fig. 14 中出现易题退化。

## 5. 为什么异步对作者的方案重要

NGU 为每题分配的生成轮数不同。若一个同步 batch 必须等最慢的重试题结束后才能补新题，易题提前完成也可能变成等待；若允许结束的工作及时补新任务，则能把节省的资源用于其他生成，trainer 也能消费已就绪的数据。

这既是调度问题，也会带来 off-policy 问题：等待同一题的罕见成功时，模型已经通过别的题更新了，早先失败回答来自旧策略。

作者的训练后端是 DeepSpeed + vLLM，使用异步和 in-flight 权重更新（附录 D）。这不是本文新造出的推理服务。附录 C.1 的特定对照中，同步 NGU 比基线差，异步 NGU 更好。

该实验支持其异步设计价值，不能证明所有可设想的同步调度都不可能实现自适应采样。真正应保留的工程要求是：可用资源能及时补充工作，不能因为少数重试任务让整批停住。

## 6. 旧失败回答：参与统计与参与 loss 是两件事

作者发现把过旧失败直接用于更新会损害效果，GSM8k 中测试 T=1/4/8/16，T=4 较好（Fig. 6、11）。这个 4 是实验设置，不是通用训练常数；正文写小于 T，Algorithm 1 写小于等于 T，边界需要实现确认。

但丢掉旧回答的 loss，不必同时丢掉其“曾经失败一次”的统计。自拟说明，沿用博客给出的组构成：

```text
历史：4 个过期失败
当前：3 个失败 + 1 个成功
全历史：8 次尝试，成功 1 次，baseline=1/8
```

若训练仅使用当前 4 条，按历史 baseline 计算，优势是 `[-1/8,-1/8,-1/8,7/8]`，总和为 **1/2**。博客写成 3/8，是算术笔误；它把优势和写成 reward 和，也容易混淆。

作者的 **anchor positives** 保留正样本优势 7/8，让 3 个可用负样本各为 -7/24，从而恢复优势和为零：

\[
A_+=1-\bar r_{\rm hist},\qquad
A_-=-\frac{n_+}{n_-}(1-\bar r_{\rm hist}).
\]

这里 n_+、n_- 是实际参与更新的正负样本数量；公式讨论二值奖励且仍有负样本的情形。正文展示负样本优势时省略了负号，应按其“负优势且总和为零”的含义理解。

作者比较了不用旧统计、直接使用历史 baseline 不再配平、删减负样本，以及 anchor positives；最后一种在所测设置较好。**优势和为零不是无偏性的证明**。这些历史回答来自不同策略，并经历按结果停止的采样，历史 baseline 不能直接当作当前策略成功率的无偏估计。

对连续/部分奖励、没有剩余负样本等边界，不能仅凭上述二值公式推出实际处理；这也是未能读代码的具体限制。

## 7. Manufactoria：为什么部分测试奖励也会停滞

任务是按特殊规则生成工厂/程序，训练模型为 Qwen3-4B-Instruct，附录参数表进一步写明 Instruct-2507。每题有 14–30 个测试。这里是在一个生成结果上执行测试，不是多轮 SWE agent。

若 reward 是通过测试的比例，模型可能在中等难度测试上反复波动，而最难测试一直不会，导致平均通过率提升但整题通过率几乎不动。论文 Fig. 9 的 GRPO 基线约停留在 80% 的测试通过率，NGU 后期开始明显提升整题通过率。

博客用“初次 4 个回答全过 7/12，就追加采样直到超过 7/12”解释这种课程，适合直觉但不是完整形式定义。Algorithm 1 的条件是**存在本轮 reward 高于累计 baseline 的样本**，而不是严格超过历史最大 reward。

例如，若历史 4 条都是 7/12，下一轮也是 7/12，则仍无奖励差异；若下一轮出现 8/12，就有更好的行为可强化。但按算法字面，下一轮为 `[7,7,6,6]/12` 时，累计 baseline 是 6.75/12，当前 7/12 也高于 baseline，即使没有超过之前的 7/12。

所以准确含义是“寻求可用的相对奖励信号”，不能承诺每轮都突破历史最好成绩，也不能保证通过的测试集合单调扩大。公开实现不可访问，无法进一步裁定博客简写和伪代码之间的实际执行差异。

Fig. 8 还有一个与本项目有关的观察：刚开始的失败可能来自不适应提示/输出格式。作者在模型适应约 100 步后重新划分难度，才观察到更清楚的难度差异。这提示我们分开诊断 harness 适应和真实解题能力，但不能在最终测评后任意重定义分桶来挑选好看的结论。

Fig. 10 从停滞 checkpoint 继续，NGU + 部分测试奖励与改成全测试通过才奖励都能恢复改善。该结果说明这个设置仍保留可学习性；不能证明所有 LLM 后训练都没有 plasticity loss。

## 9. 原文表述、复现缺口与证据边界

1. 博客主 GSM8k 例子写 p=0.9，论文 §4 写 p=0.95；复现应先核具体 run，而不是合并为同一配置。
2. 博客 DeepScaler 图注写初始 pass@32 分桶，论文 §5 写 pass@64。后者与训练题难度 pass@32 要分开。
3. 博客旧样本优势算例 `7/8-1/8-1/8-1/8` 应为 1/2，而不是 3/8。
4. 博客称恢复实验从 6000 步 checkpoint 开始；论文 §6 写 3000 步。附录 D.3 也写 3000 步，但 Table 6 写 1500 步。
5. Table 4 写 N=32、K=16，总数为 512，而正文固定 N×K 实验为 256。其代表哪个配置没有说清，不能当作完整可运行配方。
6. Table 2 的初始模型行写 AIME=7.63、BRUMO=16.3、Average=12.6，三者不符合简单等权平均；Table 3 的 Total 提升也不能直接由该 12.6 与 Table 2 相减复原。本篇按各表分别引用，不擅自修正成一个一致基线。
7. 初始难度估计使用 temperature=0.7/top-p=0.8，训练后评测使用两者为 1（附录 D.2）。这会影响“相对初始提升”的解释，不能当作纯粹同采样协议的前后对比。NGU 与其训练后基线间的对比仍是另一个问题。
8. 小样本观测 `pass@64=0` 不代表真实成功概率为 0。若每次成功率为 1%，64 次都错的概率仍约为 52.6%。
9. 作者只说与评测的题目重叠很少，没有在本文给出完整去重审计。没有额外验证数据泄漏情况。
10. Algorithm 1 是采样侧伪代码，没有给出变长组完整 loss 归一化、连续奖励 anchor positives 的全部公式或所有过期边界。不能据此宣称实现级复现。
11. 正文若干机制归因、近 Pareto 最优、plasticity 的概括比实验直接支持的范围更广。本篇把它们作为作者解释，不作为普遍定理。

## 10. 对项目一的条件化启示

最直接值得采用的是**诊断视角**：分别统计原始抽题、生成成本、有效训练样本，按难度看谁真正获得了训练信号；同时看整题成功率，避免只有平均 reward 上涨。

如果未来考虑 SWE 的自适应采样，应先确认：

- 当前训练池里既有较容易题，也有稀疏可解的难题；若多数题几乎不可解，反复重试可能只有成本。
- harness、环境和评分已可靠。基础设施失败不能被计成模型失败后进入难度估计和 NGU 重试。
- 统计单题消耗的是 token、GPU 时间和环境时间，而不只有 attempt 次数；SWE 的一次尝试成本差异远大于短数学题。
- 重试跨策略版本，累计奖励统计与真正进 loss 的样本集合明确区分。NGU 的历史组、成员数量、重要性权重和归一化不能未经分析直接接入当前 RH2 的训练语义。
- 若用部分测试通过率，先验证评分是否可比、是否鼓励只覆盖易测例、是否存在可利用的测试缺口。本文不构成将 SWE reward 改为 test-pass ratio 的依据。

可辨识的最小研究设计，是在可信环境和固定 held-out 上，按相同 GPU/环境预算比较固定 K 与自适应追加采样，报告分难度成功率、每单位成本的有效梯度样本、过期丢弃比例、尾部重试成本和易题退化。这里只提出研究候选，不改变当前配方或启动实现。
