# Benchmark 锯齿与训练侧指标是否同步？

基于既有 2026-09-19 05:11 UTC 冻结快照的补充分析；没有把新的 live 数值混入。主要比较 Flash s16–25，这是三项离线评测完整覆盖、DeepSWE 锯齿较明显的连续十个 checkpoint。选取这个窗口是针对用户问题，不用于宣称全程统计规律或因果关系。

结论：**训练侧也有波动，但不同指标并不同步。其他 benchmark 是总体向上、局部回落；不能把 DeepSWE 的锯齿直接诊断成训练不稳定，也不能证明全是评测噪声。**

![逐 step 对齐图](aligned_flash_s16_s25.png)

左上各评测只减去自身 s16 分数，用同一分数点单位展示变化；没有做方差标准化或平滑。红色窄带标记 DeepSWE 比前一步下降的 checkpoint，灰色虚线为 s24 与 s25 之间的重启区间，不是已知因果边界。

## 1. 波动的大小与方向

Flash s16–25 的 9 个相邻变化中：

| 指标 | 起点 → 终点 | 下降次数 | 相邻变化绝对值均值 |
| --- | --- | ---: | ---: |
| DeepSWE | 63.86 → 64.90 | 5/9 | 3.62 分 |
| In-house Coding | 60.34 → 61.93 | 3/9 | 0.408 分 |
| Automation | 49.40 → 51.60 | 3/9 | 0.600 分 |
| 采样 avg@n | 0.594958 → 0.640833 | 3/9 | 0.015601 |
| 训练轨迹 mean reward | 0.568556 → 0.593547 | 6/9 | 0.007477 |
| train/passrate/avg_passrate | 0.555967 → 0.584465 | 6/9 | 0.008591 |

reward 虽然在 9 次变化中有 6 次下降，最后仍比起点高，因为少数上升的幅度足以抵消这些下降。下降次数不能代替净增益，也不能代替方差估计。

上表的“相邻变化绝对值均值”只是观察到的曲线起伏，混合了真实模型变化、任务/评分分布变化和评测随机性；**不是**同一模型重复评测的噪声标准差。不同 benchmark 的题量、难度、评分粒度不明，不能从 3.62/0.408 的比值推断噪声倍率。

## 2. DeepSWE 的五次下降，对应训练 reward 两次升、三次降

| step 变化 | Δ DeepSWE | Δ In-house | Δ Automation | Δ 训练 reward | Δ 采样 avg@n |
| --- | ---: | ---: | ---: | ---: | ---: |
| 16 → 17 | −5.75 | −0.38 | +0.70 | +0.015173 | +0.006299 |
| 18 → 19 | −2.36 | +0.17 | +0.40 | −0.004596 | +0.023898 |
| 20 → 21 | −4.13 | +0.05 | −0.30 | +0.011704 | +0.022881 |
| 22 → 23 | −2.65 | +0.51 | +0.40 | −0.007143 | +0.013692 |
| 24 → 25 | −0.88 | −0.35 | −0.70 | −0.001482 | +0.025369 |

训练 reward 与采样 avg@n 使用原始单位；不能把 reward 的差值标成成功率百分点。

五次 DeepSWE 下降时，采样 avg@n 都上升。这是此小窗口的描述，不做反相关定律、不搜索更多窗口或时移来挑相关性。

最大的 s16→17 下跌中，`train/passrate/avg_passrate` 也从 0.555967 升到 0.581716；11 个匿名 coding 来源中，9 个 `critic/code/<source>/rewards/mean` 上升，2 个下降。因此“不一致”并不只是全局均值被非 coding 任务掩盖。但各来源题目会变化，匿名 coding 来源也不等同于 DeepSWE 的评测分布。

Pro 也有反例：s12→13，DeepSWE 65.97→63.27；In-house 61.64→62.54，Automation 48.90→49.10，训练 reward 0.581967→0.587806。没有跨评测与训练 reward 一起下降。

## 3. 为什么按同一 step 对齐，也不能要求它们同步

- `dynsam/avg@n` 是该步采样 prompt 的尝试成功比例再对 prompt 平均，题目和采样构成可变。
- `critic/rewards/mean` 是该步进入训练轨迹的 reward 均值，经历筛选、carryover 和可能的额外评分处理；不是固定考试，也不必是纯二元成功率。
- `train/passrate/avg_passrate` 可作为另一条训练侧记录比较；公开资料没有补齐其所有权重和分母定义，不把它与前两者机械相减解释为 judge 的净贡献。
- 离线评测针对对应 checkpoint，而训练消费的异步轨迹由较旧策略产生。Flash s16→24 的平均 lag 从 0 升到 2.1832；因此即使日志 step 一致，也不能认为 reward 正在测更新后 checkpoint 的同一组能力。
- 各 benchmark 的任务、harness、预算与判分机制可能不同；目前缺少足够的公开题级数据来区分真实能力取舍和测评随机波动。

## 4. 联看指标的优先顺序与本段证据

| 指标组 | 想分辨什么 | 当前观察与限制 |
| --- | --- | --- |
| 任务来源的 reward、passrate、训练权重 | 总均值变化来自能力还是换题/换比例 | s17 有 9/11 coding 来源 reward 上升；仍不是固定题集比较，不能当作泛化提高的证明 |
| 长度、turns、截断、超时 | 是否出现预算利用变化或低效长轨迹 | s16→17 平均 response 94k→104k，但 turns 54.1→52.6；DeepSWE 的其他跌点也不呈统一长度方向。需要评测侧长度和失败原因才能连接到 benchmark |
| lag 分布、分桶 KL、同版本 KL、TIS clip | 更新使用的数据新鲜度与训练/推理差异 | lag 在 s16–24 大体积累，DeepSWE 却交替升降；不能用单一 lag 阈值解释锯齿 |
| penalty 的发生率、命中长度、mass、scale | 奖励/ADV 修正是否变强，是否出现行为问题 | neg_hit_tokens 的增加不总落在 DeepSWE 跌点；s22 达 7.84M 时 DeepSWE 反而从 59.59 升到 64.01。原始计数需结合相关 token 分母，不把 token 计数等同于违规轨迹率 |
| entropy、grad norm、更新是否跳过 | 是否有广泛的更新失稳迹象 | s16–25 entropy 0.4411→0.4561，中间有小幅升降；grad norm 约 0.00493–0.00905，update_successful 均为 1、skip 均为 0。未见与所有 DeepSWE 跌点一致的梯度爆炸或熵塌缩 |
| infra error、grader 成功率、重启 | 数据/系统故障是否影响观测 | s17 训练采样 infra_error/seq_rate 从 0.878% 升到 3.036%，值得调查；但这是训练侧故障，不证明离线评测也遇到同样故障，更不足以解释后续全部锯齿 |

`pg_loss` 是 clipped policy-gradient objective，不能像固定验证集上的交叉熵一样按“越低能力越高”理解。它随 advantage、mask、分布和修正项变化，应与梯度、KL、成功更新以及离线能力一起读。

## 5. s24→25：系统指标改善，也不保证下一点 eval 上涨

s24 到 s25 之间有两次重启，之后：

- 平均 lag：2.1832 → 0.319793。
- 总 train/infer KL：0.0101065 → 0.00597094。
- signed/neg_hit_tokens：6,474,280 → 846,491。
- 平均 response：123,978 → 114,444 tokens。
- 采样 avg@n 上升、训练 reward 略降，三个 benchmark 全部小幅下降。

它不能证明重启损害能力，也不能证明 KL 更低没价值；它说明更新/系统诊断值并不是 checkpoint 泛化性能的替代指标。重启还会改变队列和数据构成。

## 6. 要区分真实退化与评测噪声，还缺什么

最有价值的是同一 checkpoint 的重复评测、相邻 checkpoint 在同一任务上的 solved→failed 与 failed→solved 配对表，以及失败原因、评测侧 token/turn/超时统计。需要固定 harness、任务集合和推理预算，并检查 seed 等评测配置是否一致。

在这些证据缺失时，可以说：多个评测与训练侧指标的长期趋势仍向上，DeepSWE 的短期锯齿缺少一致的全局失稳证据。不能进一步宣布它全部是噪声、存在确定周期，或直接用平滑消除它。
