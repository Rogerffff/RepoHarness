# 已有 PDF 中尚未独立精读的环境方法

[返回总入口](README.md)。本章直接读取本地原始 PDF 的环境、数据构建及有关附录，属于**环境专题摘录，尚非全文精读或运行复现**。页码指 PDF 物理页。没有披露的配置不从同团队其他报告补入。

## R5 · GLM-5

**实际处理。** §4.2（p17–20）从 issue–PR 配对出发，规则和 LLM 筛题，补充任务要求；基于 RepoLaunch 自动安装、构建、生成测试命令，并生成分语言日志 parser 提取 F2P/P2P。Terminal 两路：种子任务→构建 agent→按人工 rubric 迭代修订；网页语料→分层采样→生成 Harbor 任务→自执行验证。幻灯片环境另以 HTML 渲染和布局反馈验证。§6.2（p24–27）的工程评测包含人工编写的单测、GUI agent 交互检查和多提交任务链，并用人工判断抽样校准 GUI judge；链式任务将配置/fixture 自动应用，逐步累加测试查回归。

**可借鉴与边界。** 将依赖适配、测试解析和题意检查分开；明确哪些非代码变化由环境提供。报告说到测试与题意对齐、反捷径，但未公开足以证明全量误判率的审计；自动生成 parser 也需要校准。链式评测不是本项目现阶段必须加入的训练任务。

来源：[本地 PDF](../pdfs/R5_glm5_agentic_engineering_2602.15763.pdf)、[原文](https://arxiv.org/abs/2602.15763)。RepoLaunch 细节另补入新资料队列。

## R6a · DeepSeek-V3.2

**实际处理。** §3.2.3 Code Agent（p11）要求 issue、gold、test patch 对应，setup agent 完成安装、依赖与执行；统一输出 JUnit，接纳条件是 gold 带来至少一个 F2P，且没有 P2F（原来通过、修后失败）。同节 General Agent 从数据库、工具函数、任务和验证函数联合合成：参考解只能通过工具访问数据，先验证参考输出，再逐步增难或补工具。原文随后描述在合成数据上进行 RL，再按非零 pass@100 保留任务，不能写成训练前的基座筛选。

**可借鉴与边界。** 统一结果格式能减少语言间 parser 差异，但不能证明测试有正确含义；“环境可执行”和“当前策略可解”是两步，后者不能替代前者。通用工具环境的筛选标准不可直接当作 SWE 题库门槛。未见逐题稳定性次数或合法替代补丁审计。

来源：[本地 PDF](../pdfs/R6_deepseek_v3_2_2512.02556.pdf)、[原文](https://arxiv.org/abs/2512.02556)。

## R6b · DeepSeek-V4

**实际处理。** §5.2.5（p35–36）披露 DSec 环境运行层：预热函数容器、Docker 容器、microVM、fullVM 共用接口；镜像分层按需加载，写入用独立层；记录命令及结果，训练抢占时保留环境，恢复时返回已完成命令的缓存结果，避免重复执行非幂等操作。§5.3.1 对 Terminal-Bench 原版和修订版结果分别报告。

**可借鉴与边界。** 保存真正执行过的环境状态和命令结果，是分析不稳定与恢复行为的参照。论文的可重放主张没有在本项目验证，尤其不能外推到未保存的公网服务状态。它主要回答运行与恢复，并未在该节给出逐题题意/测试修复流程；不应因其规模大就照搬存储平台。

来源：[本地 PDF](../pdfs/R6_deepseek_v4_pro_DeepSeek_V4.pdf)、[官方 PDF](https://huggingface.co/deepseek-ai/DeepSeek-V4-Pro/resolve/main/DeepSeek_V4.pdf)。

## R7a · Kimi K2

**实际处理。** §3.1.1（p9–11）从真实/合成工具规格构造 agent、任务和 rubric，模拟工具交互生成轨迹，judge 过滤。作者承认模拟保真度限制；coding/SWE 改用真实执行沙箱和测试反馈。§3.2.1（p12）从 GitHub PR/issue 构建带可执行测试的开发环境，以 Kubernetes 承载。其工具模拟和真实 SWE 执行是不同路径。

**可借鉴与边界。** 环境应验证真实代码行为；任务说明、工具接口与 judge 需配套。本文对 SWE 安装修复、测试筛选、网络和重复验真的细节很少，不能从“万级沙箱”推断已做完整任务质量检查。

来源：[本地 PDF](../pdfs/R7_kimi_k2_2507.20534.pdf)、[原文](https://arxiv.org/abs/2507.20534)。

## R7b · Kimi K2.5

**实际处理。** Appendix D（p22–23）把环境拆成可组合的 Toolset、Judge、提示增强模块；每个异步任务从环境池领取沙箱和工具，可递归启动子任务。对只能走标准模型 API 的黑盒环境增加 gateway 记录请求响应，另建性能和数据检查工具。

**可借鉴与边界。** 环境实例、工具、评分和 harness 可以组合，但仍需核对组合后的实际运行条件。这是运行架构披露，未公开 SWE 逐题清洗、网络资格或替代解校验配方；不能拿组件齐全代表题目已合格。

来源：[本地 PDF](../pdfs/R7_kimi_k2_5_2602.02276.pdf)、[原文](https://arxiv.org/abs/2602.02276)。

## R8 · MiniMax-M1

**实际处理。** §4.1 SWE 段（p9–10）从 GitHub issue/PR 构造定位、修复、测试合成任务，提供故障代码、问题描述和关联测试，用容器实际执行。预置或新生成测试决定反馈；编译、运行错误和回归也进入惩罚描述。其他领域用生成器和规则 verifier，而非都采用 SWE 测试。

**可借鉴与边界。** 可以参考可执行任务三件套，不能据此复制其失败归类：文中没有足够细节区分基础设施故障与候选错误，也没有稳定性、网络和题意审计细节。M2 的更完整流程不能倒填为 M1 已做。

来源：[本地 PDF](../pdfs/R8_minimax_m1_2506.13585.pdf)、[原文](https://arxiv.org/abs/2506.13585)。

## R9 · Composer 2

**实际处理。** §4（p3–4）使任务环境接近真实 Cursor 会话，覆盖改功能、调试、重构等工作。§6.2（p10–12）将有状态环境作为可保存的产物：Firecracker VM 支持文件系统和内存快照/分叉，按实时 CPU、内存、磁盘压力调度；所有互联网访问经过透明代理执行请求策略并去除敏感头。训练和数据准备共用产品工具实现及后端影子部署，但训练可收紧工具参数检查或移除部分工具。

**可借鉴与边界。** 准备环境时需要核对实际 harness 的工具后端依赖，资源测量也要涵盖启动峰值。文件系统/内存快照不等于 fresh grader，也不包含所有外部工具服务状态；报告没有公开整套 SWE 质量过滤或网络规则清单。这里的网络方案可作对照，不能说行业统一断网。

来源：[本地 PDF](../pdfs/2603.24477v2.pdf)、[原文 v2](https://arxiv.org/abs/2603.24477v2)。

## R10 · Let It Flow / ROME / ROCK

**实际处理。** §3.1（p12–15）用 Explore Agent 把 PR/issue/论坛工作流转成任务草案；Builder 推断工具链并生成 Docker、测试和说明，在沙箱内反复构建验证；Review Agent 在独立于先前执行状态的条件下跑参考解，并借外部模型审查需求覆盖、边界和假阳性。后续轨迹另经过规则、LLM、执行及专家抽审。§2 ROCK（p6–8）负责镜像、资源、隔离、每沙箱出网策略、日志和生命周期。

**可借鉴与边界。** “构建者—独立任务审查—执行证据—高风险人工抽审”与我们的讨论直接相关。报告把部分自校验描述为 formal guarantees，但本文没有提供可支持“语义完全正确”的形式证明，不照录成保证。还应保留其运行中实际观察到违规访问的负结果：有隔离设计不等于所有路径已覆盖。

来源：[本地 PDF](../pdfs/R10_let_it_flow_roll_rock_rome_2512.24873.pdf)、[原文](https://arxiv.org/abs/2512.24873)。

## R12 · ROLL 原始框架报告

**实际处理。** §4–5 将 Environment Worker 与 Reward Worker 分开；Sokoban 用不同网格、箱数和符号词表构造环境变体，FrozenLake 测导航，另外接搜索任务。运行层按负载配置并行 worker，记录成功和有效动作等反馈。

**可借鉴与边界。** 可参考环境配置与奖励执行分开，以及以可控变体检测迁移。本文不是 SWE 数据工厂：没有真实仓库依赖、gold/test patch 或任务修订流程。只作为其他环境及运行接口的短参照，不作为 SWE 筛查依据。

来源：[本地 PDF](../pdfs/R12_roll_framework_2506.06122.pdf)、[原文](https://arxiv.org/abs/2506.06122)。

## E13 · MiMo-V2-Flash

**实际处理。** §4.3（p15–16）以仓库快照自动配置开发环境并封装镜像；terminal 从 Stack Overflow/Stack Exchange 转成题面、Dockerfile、测试，先验安装，再按难度/可靠性与通过率筛选。Web 任务用 Playwright 执行并录制视频，视觉 verifier 同时评外观、行为与可执行性。Appendix B（p31）发现未来 Git commit 泄漏，更新评测镜像并清理自产训练镜像，轨迹关键词用于监测相关行为。

**可借鉴与边界。** 区分安装资格与策略通过率；回归测试应查镜像实际未来对象，而非只确认 checkout。图8是 Qwen3-32B 的实验，不是 MiMo 主模型的直接训练曲线；关键词监测不能证明没有任何作弊路径。本文也未公开详细的 terminal 可靠性阈值。

来源：[本地 PDF](../pdfs/E13_mimo_v2_flash_2601.02780.pdf)、[原文](https://arxiv.org/abs/2601.02780)。
