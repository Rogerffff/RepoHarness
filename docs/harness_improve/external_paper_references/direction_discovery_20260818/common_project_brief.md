# 第一阶段方向发现：共用项目说明

以下内容是 Blind Discovery 和 Seeded Discovery 共用的事实边界。请不要从文件名、
当前实现或已有资料反推 owner 已经选定了哪个最终方向。

## 1. 项目定位与已有基础

RepoHarness 是一个面向开放权重基座模型的 agentic post-training 研究与基础设施项目。
它不是单独复现某一种 RL 算法，也不只是一个 agent harness，更不准备从零重写训练内核
和推理服务。

当前 rh2 架构以 Prime Intellect `verifiers v1` 作为环境执行与轨迹基座，以 `slime`
作为首个在线 RL 训练后端，同时通过中立轨迹投影保留接入其他训练后端和离线导出的
能力。`slime` 是当前后端，不是项目研究边界；agent harness / policy interface 是模型
与环境交互的一层，也不是整个项目本身。

当前仓库主要自建：

- 可执行任务和 RL 环境的生产、验证、冻结与版本治理；
- 面向 SWE agent RL 的安全沙箱、评分隔离、权限边界和反作弊；
- 训练资格分级、artifact 可见性控制和 fail-closed 审计；
- 从 harness / rollout 轨迹到训练样本的中立投影与 backend adapter；
- version-aware fully async 训练链中的身份、版本、staleness、失败恢复和审计契约。

希望最终贯通的研究闭环是：

```text
模型能力命题
→ 数据、任务与可执行环境
→ agent harness / rollout 与轨迹
→ 可验证反馈、训练资格与训练样本
→ 异步 RL 后端、优化或蒸馏
→ held-out 评测、因果归因与能力回退检查
```

项目已经完成最小数据—训练闭环和一次 `30B-A3B` MoE 八卡资源探针，但正式 fully
async 训练链与环境质量门仍在建设，正式训练总闸门尚未打开，也没有可宣称的最终模型
能力结果。

## 2. 最终目标与本阶段任务

最终项目应同时形成：

- 一项可复用、可审计的数据、环境或 post-training 系统能力；
- 一个能够通过受控实验检验的模型能力或训练命题；
- 对数据、环境、harness、算法、infra 和评测之间依赖关系的诚实说明；
- 即使主指标没有提升，也能保留可复核的负结果、失败条件和资源边界。

“在一个公开 SWE 数据集上用 GRPO 训练一次，然后报告 before/after 分数”只是项目希望
避免的最低反例，不是按论文新颖度寻找更复杂算法的排序标准。基础工作也不应仅因为不够
新颖而被排除：环境质量、训练正确性、吞吐与稳定性、诊断和评测可信度本身都可能是基座
模型后训练团队的重要问题；但它们需要被转化为具体瓶颈、可复用贡献或可证伪实验，而不
只是通用工程最佳实践。

第一阶段只负责建立值得后续讨论的研究问题与系统贡献版图，不直接写完整实施计划，也不
选出唯一最终方向。候选可以只在完整链路中的一层形成主要创新，但必须说明其他层复用什么、
关键依赖是什么，以及怎样形成可信闭环。

## 3. 可用资源

- 最终训练对象目前以约 `30B-A3B` 的 MoE 模型为主要锚点；允许使用更小模型完成
  算法、系统或数据管线的 POC。
- 有一台 `8 × RTX PRO 6000 96GB`（PCIe、无 NVLink）的单节点租用条件。
- 一次已有的短实验验证了特定 `4 trainer + 4 rollout` 配置下 30B-A3B 的异步最小
  链路可以运行。当时特定工作负载下整 step 约 1,387 秒，rollout wait ratio 约 0.82。
  这只是资源锚点，不证明其他多模型共驻、长上下文或更大 batch 配置已经可行。
- 本地机器可用于 CPU、存储、Docker/容器、静态分析、数据处理、环境构建和可重放检查。
- 可以使用计费的模型 API。
- 可以使用 Codex 和 Claude 订阅中的 coding agent 进行有人监督的代码、任务、测试、
  环境、求解和审计工作。不要默认订阅 agent 是无限量批处理 API，但也不要忽略它们
  对本地数据与环境生产能力的放大。

总 GPU-hour、API 费用和人工时间尚未冻结。如果外部材料没有披露资源，请直接写
`unknown`，不需要在第一阶段强行给出精确报价。

## 4. 当前边界

- 现有异步训练链仍在建设，正式训练总闸门尚未打开；不要把已有最小闭环误写成已经完成
  正式 RL 训练。
- 现有 SWE 数据只有静态存活候选和 held-out 候选，不等于已有可无限扩展的正式 RL
  环境集。
- 当前没有已由 owner 冻结的最终研究方向。
- 不要默认研究范围只能是 SWE-Bench 式 repository repair，但也要说明跨到新工具、
  新模态或新安全边界的代价。
