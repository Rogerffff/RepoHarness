# Seeded Discovery Pro 提示词

请先阅读附件：

- `common_project_brief.md`
- `seed_source_packet.md`

你现在只做第一轮**研究方向发现**，不做最终立项、不写代码，也不需要给出完整执行
计划。请把你自己视为一名独立的开放权重模型 post-training 研究员。

`seed_source_packet.md` 只是帮助你找到起点的来源地图，不是方向清单，也不是可以直接
引用的综述。其中可能有过时项、只有代码没有训练结果的项目，也可能遗漏当前更重要的路线。

## 任务

截止 2026-08-18，通过实时网络检索，识别能够把现有“环境与 harness → 可信轨迹和
训练资格 → 异步 RL 后端 → 模型评测”链路发展成可信基座模型 agentic post-training
项目的候选研究问题与系统贡献。重点不是寻找一个比 GRPO 更新的算法名，也不是围绕 seed
拼装一份流行组件清单。

请先独立建立方向分类和初始候选，再用下面的 post-training 生命周期检查是否遗漏重要
工作面：

- 要训练和保持什么模型能力或行为；
- 数据、任务、可执行环境、verifier、可解性与难度校准；
- agent harness / interface、工具和上下文协议、rollout 与轨迹保真；
- reward、训练信号、优化算法、蒸馏、探索、信用分配和能力整合；
- 训推系统、异步调度、权重版本、容错、资源效率与训练正确性；
- held-out 评测、跨接口泛化、受控消融、污染控制、能力保持与回退诊断；
- 安全、反作弊和 reward / verifier 可靠性等跨层问题；
- 以及上述检查没有覆盖、但有一手证据支持的重要问题。

这些是检索覆盖和闭环完整性检查，不是资料包已经给定的候选分类，也不要求机械地为每层
推荐一个方向。候选可以聚焦一层或跨层设计，但应说明它与完整训练链的关系。不要把范围
限制在 SWE-Bench 式 repository repair。

请同时做两件事：

1. 核验 seed 中的论文、报告和代码实际支持什么，不支持什么；
2. 主动逃离 seed，使用不包含 seed 项目名称的广泛问题词继续搜索新论文、新报告、
   新开源项目、新数据/环境和负结果。

历史 Pro 报告的主要检索截止日是 2026-07-27；项目后来又补了少量条目，但并没有做完整的
7 月 28 日至 8 月 18 日增量检索。请重点补齐这个时间窗口，但不要只搜“更新版本号”。
如果新版本只有产品宣传、没有训练细节或受控实验，请明确降低其证据等级。

请不要只搜某一国家的基座团队，也不要只搜 arXiv。检索至少要覆盖：

- 原始论文及附录；
- 模型团队的官方技术报告、研究博客和模型卡；
- 官方开源仓库的代码、配置、release、commit、PR 和重要 issue；
- 数据集、可执行环境、benchmark 和评测实现；
- 负结果、独立复现、工程复盘和能力回退。

二手文章和社区讨论可用于找线索，但不能成为核心技术结论的唯一证据。对重要事实，请给出
直接 URL 和论文章节、表格、代码路径、commit/release 中至少一种可复核定位。

请严格区分：

```text
仅提出想法
已有代码或配置
已实际训练
有受控消融
有独立复现
```

“某个框架支持某算法”不等于“某个旗舰模型实际使用了该算法”。对未披露的硬件、数据量、
时长和费用请写 `unknown`，不要用行业印象补齐。

为了帮助我们判断提示资料是帮助了搜索还是锁死了搜索，请对承重来源标记：

```text
provided_seed
independent_search
both
```

希望你能找到约 8 个 seed 外的一手来源、覆盖若干不同团队，并提出至少两个不是对 seed
方向换名的可信候选。这是用于提醒你扩大搜索的目标，不是为了凑数的硬指标；如果没有找到，
请如实列出搜索和排除理由。

## 期望输出

### 1. 搜索与覆盖说明

简述检查了哪些研究团队、论文生态、开源项目、数据/环境项目，哪些是 seed 外发现，
以及哪些区域仍可能遗漏。

### 2. 候选方向全景

给出大约 8～12 个不重复候选。请先自行定义合理的分类法，不要照抄资料包中旧报告的
分类。至少要说清某个候选本身是能承担最终项目的研究问题，还是只有在服务其他命题时
才有意义的支持机制或基础设施。

每个候选说明：

- 核心可证伪命题；
- 它希望改善的 agentic 能力；
- 它解决的真实瓶颈，以及为什么不只是换一个公开数据集、算法名或 benchmark；
- 主要创新位于完整 post-training 链的哪一层，其他层复用什么或依赖什么；
- 会产生什么可复用的数据、环境、infra、治理或评测产物；
- 当前最强证据、主要反证和关键未知；
- 在本项目资源下是否至少有一个合理的低成本探针；
- 这个候选主要是 `seed-derived`、`seed-expanded` 还是 `independently-discovered`。

### 3. 值得继续讨论的五个候选

对证据最强或最有可证伪价值的五项进一步展开：

- 按“能力命题 → 数据/环境与反馈 → harness/轨迹 → 训练信号、算法与系统 → held-out
  评测和归因”说明闭环；不要求每层都有创新，但必须写明未创新层复用什么；
- 一手证据与负面证据；
- 最小本机/API 探针；
- 如果进入八卡实验，最小需要证明什么；
- 什么结果会推翻这个方向；
- 哪些资源数字是来源披露，哪些只能留作 unknown。

如果一篇论文、一个算法、数据集或框架无法形成上述闭环，请把它列为支持组件，并说明它
需要与什么组合；不要仅因名字新或论文结果强就把它当成顶层项目方向。

### 4. Seed 覆盖与逃离记录

- 哪些 seed 结论被一手资料支持；
- 哪些 seed 只是代码能力或官方主张，缺少训练/消融；
- 哪些新方向或新来源是 seed 中没有的；
- 哪些看似新的方向经核验后被排除，原因是什么。

### 5. 证据附录

按候选方向列出承重来源的直接链接、日期、版本、定位和 discovery origin。

本轮可以给出“高潜力 / 需要关键探针 / 当前不适合”的初步分类，但不要选出唯一最终方向。
